h3. Контекст и проблематика.

В настройках диаграммы «Граф связей» ({{chartType = "graphECharts"}}; далее — «Граф») присутствует раздел «Режим фильтра», однако, в текущей реализации, его включение не приводит к требуемой фильтрации отчёта по выбранному узлу. Расширенный режим фильтрации для графа не доступен для активации.

----
h3. Цель задачи.

Обеспечить функциональность «Режим фильтра» для диаграммы «Граф» и фильтрацию отчёта по нажатию на узел графа: 
* в обычном режиме — по значению поля с полки «Узел», 
* в расширенном режиме — дополнительно по всем связанным значениям полок «Связь» и «Категории».

----
h3. 1. Описание целевого поведения.

h4. 1.1. Настройки и состав фильтров.

Предусловие к данным: каждый отображаемый узел хотя бы один раз представлен в поле, размещённом на полке «Узел». Строка с пустым полем «Связь» не задаёт исходящую связь, но не препятствует отображению самого узла, также данный узел может быть указан как приёмник в строках «Связь» других узлов. Поле «Узел» - не пустое для каждой строки в наборе данных.

В существующем разделе «Режим фильтра» обеспечить работу общего тумблера раздела и добавить доступный для графа тумблер «Расширенный режим фильтрации». Расширенный режим определяет состав передаваемых значений при включённом общем тумблере. При выключенном общем тумблере нажатие на узел не изменяет фильтры независимо от состояния расширенного режима.

|| Состояние || Результат нажатия на узел ||
| «Режим фильтра» включён; расширенный выключен | В связанный общий фильтр передаётся значение выбранного узла из поля на полке «Узел». |
| Включены оба тумблера | Дополнительно передаются все связанные значения поля на полке «Связь» и, если полка «Категории» заполнена, все связанные значения её поля. |

---
h4. 1.2. Значения расширенного режима.

* Для выбранного узла учитываются все строки текущего набора данных с соответствующим значением поля «Узел», прошедшие действующие для графа фильтры и ограничения доступа. Лимит загрузки графа не ограничивает этот отбор: связанные значения должны включать и строки, не попавшие в загруженную выборку графа. Строки набора данных, в которых выбранный узел указан только в поле «Связь», в отбор не входят.
* Из всех отобранных строк формируются отдельные списки уникальных значений «Связь» и «Категории». Значения одного поля объединяются по «ИЛИ», ограничения разных полей — по «И», как в расширенном режиме столбчатой диаграммы.
* {{null}} и пустые строки в полях «Связь» и «Категории» пропускаются. Если у выбранных узлов нет непустых значений участвующего поля, соответствующий общий фильтр очищается; фильтрация по выбранным значениям «Узел» сохраняется.
* Если полка «Категории» пуста, расширенный режим работает по полкам «Узел» и «Связь». Дополнительные значения с полок «Свойства узлов» и «Свойства связей» в фильтрации по нажатию не участвуют.
* Используются исходные значения соответствующих полей, а не текст подписи узла, подсказки или результат форматирования.

---
h4. 1.3. Выбор узлов.

* Обычное нажатие выбирает один узел, заменяя предыдущий выбор. Повторное нажатие на единственный выбранный узел снимает выбор.
* Нажатие с удержанием Ctrl добавляет узел к выбору, а для уже выбранного узла — исключает его. При снятии последнего выбранного узла очищается отбор по полям, участвующим в текущем режиме.
* В расширенном режиме списки значений пересчитываются по всем выбранным узлам. При исключении узла значение «Связь» или «Категории» остаётся в фильтре, пока оно связано хотя бы с одним из оставшихся выбранных узлов.
* Выбранные узлы визуально выделяются. Собственный выбор не сокращает отображаемый граф: остальные узлы остаются видимыми и доступными для выбора.
* Нажатие на связь или фон, перетаскивание узла, перемещение и масштабирование графа не изменяют выбор узлов и общие фильтры.

---
h4. 1.4. Применение общих фильтров.

Передача и применение значений должны использовать действующий механизм общих фильтров отчёта (по аналогии с реализацией для «Диаграммы столбчатой» {{chartType = "barChart"}}):

* Значение каждого поля направляется в соответствующий связанный общий фильтр. Другие визуализации фильтруются по тем участвующим полям, которые размещены у них на полке «Фильтры» и связаны с общим фильтром по действующим правилам портала. Настройка «Локальный» сохраняет своё действие.
* Отсутствие связанного фильтра для одного из полей не препятствует передаче значений в остальные связанные фильтры. Автоматически добавлять пилюли на полки других визуализаций не требуется.
* Все значения одного выбора применяются совместно, с сохранением действующих правил зависимостей и обязательности фильтров. Порядок применения выбранных значений соответствует действующему режиму фильтра отчёта, включая настройку «Первичное отображение данных после нажатия кнопки „Применить“».

---
h4. 1.5. Совместимость с переходом по узлу.

Обеспечить взаимоисключение режима фильтра и перехода по узлу, описанного в связанной постановке [MB-6335|https://jira.modusbi.ru/browse/MB-6335]. Сразу при выборе режима «Переход по узлу» общий тумблер «Режим фильтра» автоматически выключается, а раздел становится недоступным для включения. Расширенный режим не обходит блокировку. Правило действует при любом порядке настройки, удалении источника ссылки и после повторного открытия отчёта.

При возврате к режиму «По визуализации» раздел снова доступен; ранее заданные параметры фильтра сохраняются. Отсутствующий источник либо пустая или недопустимая ссылка отдельного узла не должны запускать фильтрацию вместо перехода.

----
h3. 2. Сохранение и границы технической проработки.

* Состояния обоих тумблеров режима фильтра сохраняются в составе отчёта и восстанавливаются после повторного открытия (с учётом взаимоисключения режимов с настройками режима клика). При создании новой визуализации, расширенный режим по умолчанию выключен; отсутствие такого параметра в ранее сохранённом отчёте трактуется как выключенное состояние. Ранее сохранённое значение основного тумблера сохраняется.
* Доработка должна обеспечить настройку режима, определение выбранного узла и связанных с ним значений, передачу в общие фильтры и возможности применения отбора к связанным визуализациям.
* Способ получения полного набора связанных значений, необходимость изменений бэкенда и контракт обмена определяются при технической проработке. Агрегированное значение категории узла не заменяет множество категорий всех соответствующих строк.

h3. 4. Критерии приёмки (AC):

*AC.1 — Обычный режим:*
* *Дано:* поле {{Объект}} размещено на полке «Узел», {{Контрагент}} — на полке «Связь»; есть строка связи {{A}} → {{B}} и собственная строка {{B}} с пустым полем «Связь»; другая визуализация связана с общими фильтрами этих полей; полка «Категории» пуста; основной режим включён, расширенный выключен;
* *Когда:* пользователь нажимает узел {{B}};
* *Тогда:* в общий фильтр {{Объект}} передаётся {{B}}, значение фильтра {{Контрагент}} этим выбором не задаётся; другая визуализация получает отбор по {{Объект = B}} по правилам применения фильтров отчёта. При заполнении полки «Категории» состав передаваемых полей обычного режима не меняется.

*AC.2 — Все строки узла и независимые списки значений:*
* *Дано:* оба тумблера включены; среди строк набора данных есть {{(A, B, X)}}, {{(A, C, Y)}}, повтор {{(A, B, X)}}, {{(D, E, Z)}} и {{(F, A, W)}} для полок «Узел», «Связь», «Категории» соответственно; остальные узлы-приёмники также имеют собственные строки в поле «Узел»; для каждого поля настроен связанный общий фильтр; {{A}} видим на графе, но строка {{(A, C, Y)}} не попала в загрузку из-за лимита; строка {{(A, G, V)}} исключена действующим фильтром отчёта либо ограничением доступа;
* *Когда:* пользователь нажимает {{A}};
* *Тогда:* фильтры получают {{A}} для поля «Узел», {{B}} и {{C}} для поля «Связь», {{X}} и {{Y}} для поля «Категории», без повторов и без значений строк {{D}}, {{F}} и строки, исключённой фильтром или ограничением доступа. В другой визуализации с этими тремя связанными фильтрами запись {{(A, B, Y)}} проходит отбор при отсутствии других исключающих условий. При пустой полке «Категории» передаются только значения «Узел» и «Связь».

*AC.3 — Область действия и применение:*
* *Дано:* для поля «Узел» одна визуализация связана с общим фильтром, у другой фильтр настроен как локальный; оба тумблера включены, но связанный фильтр поля «Связь» отсутствует;
* *Когда:* пользователь выбирает узел; сценарий повторяется с немедленным применением и в штатном режиме отложенного применения;
* *Тогда:* связанная визуализация получает выбранное значение в установленный для отчёта момент применения; локальный фильтр не подменяется общим; отсутствие фильтра «Связь» не мешает обновлению фильтра «Узел».

*AC.4 — Неактивный режим и действия с графом:*
* *Дано:* основной тумблер выключен, расширенный включён;
* *Когда:* пользователь нажимает узел; затем при включённом основном режиме нажимает связь и фон, перетаскивает узел, перемещает и масштабирует граф;
* *Тогда:* перечисленные действия не изменяют общие фильтры; управление графом остаётся доступным.

*AC.5 — Сохранение настроек:*
* *Дано:* оба тумблера включены, режим перехода по узлу не настроен;
* *Когда:* пользователь сохраняет и повторно открывает отчёт, затем открывает отчёт, в котором параметр расширенного режима отсутствует;
* *Тогда:* в первом отчёте оба состояния восстановлены; во втором расширенный режим выключен, основной соответствует сохранённой настройке.

*AC.6 — Взаимоисключение с переходом:*
* *Дано:* оба режима фильтрации включены;
* *Когда:* пользователь выбирает «Переход по узлу», сохраняет и повторно открывает отчёт, затем возвращается к режиму «По визуализации»; проверка выполняется без источника ссылки, с выбранным источником и после удаления или потери доступности выбранного поля;
* *Тогда:* основной режим фильтра выключен и заблокирован сразу при выборе режима перехода и остаётся таким во всех проверяемых состояниях; нажатие узла не фильтрует отчёт, в том числе при недопустимой ссылке. После возврата раздел доступен, но основной тумблер остаётся выключенным до ручного включения; параметры расширенного режима сохранены.

*AC.7 — Одиночный выбор и его снятие:*
* *Дано:* режим фильтра включён; узлы {{A}} и {{D}} доступны для выбора; проверка выполняется в обычном и расширенном режимах;
* *Когда:* пользователь последовательно нажимает {{A}}, затем {{D}}, затем повторно {{D}} без Ctrl;
* *Тогда:* сначала выбран {{A}}, затем только {{D}}, а после повторного нажатия выбор снят и отбор по участвующим полям очищен. В каждом состоянии выбор визуально обозначен, остальные узлы остаются видимыми и доступными.

*AC.8 — Множественный выбор и общие значения:*
* *Дано:* оба тумблера включены; узлу {{A}} соответствуют значения «Связь» {{B, C}} и «Категории» {{X, Y}}, узлу {{D}} — {{C, E}} и {{Y, Z}}; для всех полей настроены связанные общие фильтры;
* *Когда:* пользователь выбирает {{A}}, с Ctrl добавляет {{D}}, затем с Ctrl исключает {{A}} и после этого {{D}};
* *Тогда:* при выборе двух узлов фильтры содержат «Узел» {{A, D}}, «Связь» {{B, C, E}}, «Категории» {{X, Y, Z}}. После исключения {{A}} остаются {{D}}, {{C, E}} и {{Y, Z}} соответственно, включая общие значения {{C}} и {{Y}}. После исключения {{D}} отбор по участвующим полям очищен; состав отображаемого графа собственным выбором не сокращается.

*AC.9 — Пустые связанные значения:*
* *Дано:* оба тумблера включены; для {{A}} есть строка {{(A, B, X)}} и строки с {{null}} и пустыми строками в полях «Связь» и «Категории»; для {{B}} все значения этих полей пустые; для каждого поля настроен связанный общий фильтр;
* *Когда:* пользователь выбирает {{A}}, затем обычным нажатием выбирает {{B}};
* *Тогда:* при выборе {{A}} связанные фильтры получают только {{B}} и {{X}}, без пустых значений. При выборе {{B}} фильтр «Узел» содержит {{B}}, а ранее заданные отборы полей «Связь» и «Категории» очищены.
