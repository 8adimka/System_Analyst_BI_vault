То есть основная поблема, что мы не можем отличать как обрабатывать пилюлю размещённую на полке "Значения", для свойств узлов текущая логика работает (так как значения одинаковые во всех строчках), а вот для свойств связи такая логика не подходит (для них не нужно брать первое значение, а для каждой уникальной связи (сочетание *узел-источник*+*узел-приёмник*) нужно отображать своё значение.

То есть основная проблема как понимать какую логику применять для какой пилюле на полке "Значения".

Свойства узлов будут одинаковыми для любой полученной строки и для отрисовки достаточно будет взять "первое попавшееся", а свойства для связей мы получаем сейчас не верно. 
Для упрощения доработки мы будем считать свойством связи только пилюли с полки "Значения" выбранные в настройках диаграммы "Граф" -> "Подсказки связей" -> "Шаблон" (при выборе параметра "текст подсказки") -> "Текст подсказки" (тут выбираем пилюлю с полки "Значения") -> для выбранной тут пилюли мы не применяем дообработку и не выбираем только первое значение, а должны отрисовать на диаграмме своё значение для каждого уникального сочетания "узел-источник" [node]+"узел-приёмник" [linkage].

Берём за факт, что:
* Свойства связей (для пилюль выбранных в настройках диаграммы в "Подсказки связи") для каждого сочетания "узел-источник" [node]+"узел-приёмник" [linkage] отрисовываем своё значение.
* А вот свойства узлов мы будет получать на нескольких строчках, поэтому мы просто берём первое полученное значение и используем для отрисовки узла графа, аналогично как сейчас оно и выполняется.

Сразу закрою часть возможных краевых сценариев:

1) Свойства узла реально различаются по строкам -> опускаем за скобками, мы уверенны в данных так как сценарий их сборки даёт нам уверенность, что для одинаковых узлов у нас будут строго одинаковые свойства для этого узла.
2) Нет гарантии порядка строк в SQL ->
«Первая попавшаяся» строка зависит от физического порядка возврата строк СУБД, а без явного ORDER BY этот порядок не гарантирован, но нам и не нужно его гарантировать, так как «Первая попавшаяся» подразумевает, что подойдёт любая (независимо от того какая попадётся) для свойств именно узла.
3) Узел, встречающийся только как приёмник -> Если узел никогда не попадает в столбец [node] (он всегда «приёмник») - таких узлов у нас нет и быть не может. Все узлы всегда перечислены как источник, даже если у него не заполнен "узел-приёмник" - это значит что от него связь никуда не идёт и связь не рисуется, но сам узел будет отрисован.

4) И последний краевой кейс -> например, при применении SUM - в итоговых данных ранее мы получали все строки, где использовался данный узел-источник (независимо от того с кем была связь). Например, выручка по сделке, которая должна суммироваться по всем связям - то есть для каждой сделки (связи) мы должны суммировать и получить общее значение по всем совершённым сделкам (это общее значение можно, к примеру, использовать для отрисовки радиуса узла). Ранее данная логика работала, так как в итоговые данные уходили все строки с выбранным узлом-источником (групировка по узлу). А теперь у нас суммирование будет происходить в рамках каждой уникальной пары (*узел-источник*+*узел-приёмник*) и по новой логике мы просто берём из всех строк на системном уровне первую попавшуюся строку. Т.е. если мы хотим обработать свойство связи для применения его в отрисовке конкретного узла, то тут и будет проблема. 

Т.е. Нарушение обратной совместимости наблюдается только в таких случаях, когда мы пытаемся отрисовать свойство узла на основе свойств связи данного узла, в ином случае логика берём «Первое попавшееся» - работает и даёт аналогичный результат.

Т.е. данная логика не работает для "Значений", варьирующихся по связям, агрегируемых в метрику узла -> Сумма сделки, выручка по сделке, размер конкретного контракта. Это всё не будет корректно считаться для узлов, если делать всегда групировку по паре *узел-источник*+*узел-приёмник*.

Однако, данный кейс мы тоже опускаем за скобками и если нам нужно обработать такой кейс, то просто будем использовать вычисляемое поле с выражением, например - "SUM(SUM(СуммаСделки)) OVER ()" - и вопрос решен.
