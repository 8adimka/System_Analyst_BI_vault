h3. Контекст и проблематика.

В диаграмме «Граф» пилюли, определяющие свойства узлов и свойства связей, размещаются на одной полке «Значения».

Данные диаграммы формируются с группировкой по упорядоченной паре `[node] + [linkage]`, где `[node]` — узел-источник, `[linkage]` — узел-приёмник.

Для свойств узла несколько полученных строк одного `[node]` сворачиваются до одного значения согласно существующей логике обработки узлов. Для свойств связи такая обработка неприменима: значение должно сохраняться отдельно для каждой пары `[node] + [linkage]`.

Первым шагом отдельная обработка была реализована для пилюли, используемой в текстовой подсказке связи. Для дальнейшего развития диаграммы требуется явно определять назначение каждой пилюли на полке «Значения» и использовать свойства связи для управления её отображением.

В рамках текущего шага требуется обеспечить управление:

1. цветом конкретной связи;
2. типом линии конкретной связи.

Цвет и тип линии являются независимыми свойствами и должны задаваться отдельными пилюлями.

---

h3. Цель задачи.

Требуется:

1. В настройки пилюль полки «Значения» добавить возможность явного указания, относится значение к свойству узла или свойству связи.
2. Обрабатывать свойства связи отдельно для каждой упорядоченной пары `[node] + [linkage]`.
3. Добавить возможность определять цвет каждой связи по данным.
4. Добавить возможность определять тип линии каждой связи по данным.
5. Не изменять существующую обработку свойств узлов, группировку запроса и SQL-генерацию.

---

h3. 1. Определение объекта свойства.

В настройках каждой пилюли, размещённой на полке «Значения», добавить параметр *«Объект свойства»* - тумблер, содержит два состояния:

* *Узел*;
* *Связь*.

Двухпозиционный переключатель `Узел | Связь` - рядом с переключателем отображается выбранный режим.

Параметр разместить в настройках пилюли выше выпадающего списка «Тип», ниже отчерка и настройки «Сортировка».

Значение по умолчанию — *«Узел»*.

Для ранее сохранённых пилюль, у которых новый параметр отсутствует, считать значением *«Узел»*. Существующая специальная обработка пилюли, выбранной в «Подсказках связей», в рамках данной задачи не изменяется.

h4. Логика обработки.

*Объект свойства = «Узел»:*

* применяется существующая логика обработки свойств узла;
* если один `[node]` представлен несколькими строками, сохраняется текущее правило выбора значения для узла.

*Объект свойства = «Связь»:*

* значение сохраняется для конкретной упорядоченной пары `[node] + [linkage]`;
* `[A] → [B]` и `[B] → [A]` являются разными связями;
* значение одной связи не может использоваться для другой связи того же узла-источника.

---

h3. 2. Доступные типы пилюль.

Для *«Объект свойства = Узел»* сохранить существующий набор типов:

* «Значение»;
* «Цвет»;
* «Радиус».

Для *«Объект свойства = Связь»* в рамках задачи использовать набор типов:

* «Значение» — для значений, текстовых и других универсальных свойств;
* «Цвет» — для значения цвета связи;
* «Тип линии» — для значения типа линии связи.

Тип *«Радиус»* для свойства связи недоступен.

Если пользователь переключает пилюлю с «Узел» на «Связь», когда для неё выбран несовместимый тип (например, «Радиус»), конфигурация не должна оставаться невалидной: тип необходимо переключить на «Значение».

В случае если на полках размещены несколько пилюль с селективным типом (например, «Цвет») для отображения на диаграмме используется только первая размещённая пилюла, а остальные игнорируются.
