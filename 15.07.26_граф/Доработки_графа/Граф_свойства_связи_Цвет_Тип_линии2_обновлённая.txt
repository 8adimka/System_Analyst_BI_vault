h3. Контекст и проблематика.

Полка «Значения» диаграммы «Граф» заменяется двумя полками — «Свойства узлов» и «Свойства связей» (см. [MB-5234|https://jira.modusbi.ru/browse/MB-5234]). На полке «Свойства связей» пилюля сопоставляется конкретной упорядоченной паре {{[node]}} + {{[linkage]}}, где {{[node]}} — узел-источник, а {{[linkage]}} — узел-приёмник; агрегация выполняется отдельно для каждой такой пары без схлопывания к первой строке.

На этой полке сейчас доступны только типы «Значение» и «Цвет», при этом:
* для типа «Цвет» не определено, как обрабатывать значение относительно связи (форматы, применение к маркеру направления, поведение при пустом/невалидном значении);
* управление типом линии связи по данным отсутствует — типа «Тип линии» на полке нет.

----

h3. Цель задачи.

*Требуется:*

# Добавить на полку «Свойства связей» тип «Тип линии» и обеспечить обработку его значений.
# Обеспечить корректную обработку значений типа «Цвет» для отрисовки цвета линии связи.
# Обеспечить независимое управление цветом и типом линии каждой связи по данным набора данных или вычисляемого поля.
# Добавить визуальный маркер (пиктограмму) на пилюле для типа «Тип линии».
# Сохранить действующую обработку свойств узлов, подсказок связей и существующих отчётов.

----

h3. 1. Описание целевого поведения.

|| Полка || Ключ сопоставления || Типы пилюли || Логика обработки ||
| Свойства связей | {{[node]}} + {{[linkage]}} | «Значение», «Цвет», «Тип линии» | Для каждой упорядоченной пары применяется настроенная агрегация пилюли; значение сохраняется и применяется индивидуально для этой пары |

* Тип «Значение» самостоятельно не изменяет оформление связи и может использоваться в существующих настройках, принимающих произвольное значение пилюли, в том числе в тексте подсказки связи.
* Связи {{A}} → {{B}} и {{B}} → {{A}} — разные связи и получают свойства независимо.
* Цвет и тип линии — независимые свойства, задаются двумя отдельными пилюлями.
* Набор данных или вычисляемое поле должен возвращать готовое значение цвета или типа линии. Автоматическое сопоставление бизнес-значений с визуальными стилями в диаграмме не выполняется.
* Если валидное значение свойства для связи отсутствует, для этого свойства используется действующее оформление связи по умолчанию (то, которое связь получила бы при отсутствии пилюли соответствующего типа).

----

h3. 2. Требования к реализации.

h4. 2.1. Полка и типы пилюль.

* Для пилюль на полке «Свойства связей» поддержать типы «Значение», «Цвет», «Тип линии». Для новой пилюли типом по умолчанию остаётся «Значение».
* На полке одновременно допускается *обработка системой* одной пилюли типа «Цвет» и одной пилюли типа «Тип линии». Если размещено более одной пилюли одного из этих типов, обрабатывается только первая по порядку размещения на полке пилюля соответствующего типа; остальные пилюли этого типа не влияют на диаграмму.
* Отдельные селекторы цвета и типа линии в правой панели не добавлять — активная пилюля каждого типа однозначно определяется её положением на полке.

h4. 2.2. Получение значения для пилюли.

* Значение пилюли для каждой связи определяется агрегацией по исходным строкам, прошедшим фильтры, в рамках конкретной упорядоченной пары {{[node]}} + {{[linkage]}}, согласно логике группировки полки «Свойства связей» (см. MB-5234). Результат не схлопывается к первой строке и не заменяется значением другой пары.
* Полученные значения использовать без дополнительной агрегации и пересчёта на фронтенде.
* Значение одной связи не переносить на другую связь того же узла-источника и не использовать для встречной связи.
* В модели ECharts цвет и тип линии задаётся на уровне конкретной связи, а не единым стилем всей серии.

h4. 2.3. Тип «Цвет» на полке «Свойства связей».

* Валидное значение пилюли типа «Цвет» переопределяет цвет только соответствующей связи, включая используемый диаграммой маркер направления.
* Для связей переиспользовать общий обработчик типа «Цвет», используемый для узлов. Должны одинаково поддерживаться и валидироваться уже доступные кодировки (HEX, RGB, RGBA) и строковые CSS-наименования цветов.
* Перед проверкой значения удалять пробелы по краям строки.
* {{null}}, пустая строка и невалидный цвет не должны скрывать связь, вызывать ошибку или заменяться значением другой пары. Для такой связи используется действующий цвет по умолчанию.

h4. 2.4. Тип «Тип линии».

Для значения пилюли поддержать следующий контракт:

|| Значение || Отображение связи ||
| {{solid}} | Сплошная линия |
| {{dashed}} | Штриховая линия |
| {{dotted}} | Точечная линия |

* При сопоставлении игнорировать регистр и пробелы по краям: например, {{ DASHED}} обрабатывается как {{dashed}}.
* {{null}}, пустая строка и любое значение вне указанного набора (включая {{dash}}) не должны вызывать ошибку. Для такой связи используется действующий тип линии по умолчанию.
* Тип линии применяется независимо от цвета: невалидное или отсутствующее значение одного свойства не отменяет валидное значение второго.

h4. 2.5. Маркер типа пилюли.

* При выборе для пилюли на полке «Свойства связей» типа «Тип линии» в правом нижнем углу пилюли отображается новый маркер (пиктограмма), специально разработанный для этого типа — в системе нет готового аналога, который можно переиспользовать.
* Маркер типа «Тип линии» визуально отличим от маркера типа «Цвет».
* При выборе типа «Значение» маркер не отображается.

h4. 2.6. Сохранение и обратная совместимость.

* Полка, порядок, тип, агрегация, форматирование пилюли и ссылки на неё из других настроек сохраняются и восстанавливаются при повторном открытии и копировании отчёта.
* На полке «Свойства связей» — дополнительная миграция данных не требуется.
* После удаления пилюли или изменения её типа повторно определять активную пилюлю каждого специального типа согласно правилу из п. 2.1. Если применимой пилюли не остаётся, соответствующее свойство связи возвращается к действующему значению по умолчанию.
* В рамках этой задачи не требуется изменять структуру payload запроса данных визуализации, группировку по {{[node]}} + {{[linkage]}}, SQL-генерацию и API-контракт получения данных; не добавлять отдельные HTTP-запросы для свойств связей.

----

h3. 3. Рамки задачи.

*В рамки задачи входит:*
* добавление типа «Тип линии» на полку «Свойства связей» и *маркера в пилюле* для него;
* реализация корректного поведения типа «Цвет» для свойств связи;
* применение цвета и типа линии по данным конкретной связи;
* сохранение новых настроек пилюль и обратная совместимость.

*В рамки задачи не входит:*
* изменение действующей обработки свойств узла;
* настройка толщины линии и иных новых свойств связи;
* ручное сопоставление категорий данных с цветами или типами линий в правой панели.

h3. 5. Критерии приёмки (AC):

*AC.1 — Доступные типы и маркер:*
* *Дано:* пользователь добавил пилюлю на полку «Свойства связей»;
* *Когда:* пользователь открыл настройки типа пилюли;
* *Тогда:* доступны типы «Значение», «Цвет», «Тип линии»;
* *Когда:* выбран тип «Тип линии»;
* *Тогда:* в правом нижнем углу пилюли отображается новый маркер, отличимый от маркера типа «Цвет»; при выборе «Цвет» отображается стандартный маркер цвета; при выборе «Значение» маркер отсутствует;
* *И:* изменение типа пилюли перестраивает диаграмму без сохранения прежнего оформления.

*AC.2 — Цвета разных связей одного узла:*
* *Дано:* вычисляемое поле {{Цвет_связи}} размещено на полке «Свойства связей» с типом «Цвет»; для связей {{A}} → {{B}} и {{A}} → {{C}} получены соответственно {{#ff0000}} с пробелами по краям и {{grey}};
* *Когда:* диаграмма отрисована;
* *Тогда:* связи отображаются соответственно красным, зелёным, полупрозрачным синим и серым; цвет одной связи не применяется к другой; маркер направления каждой связи окрашен тем же цветом, что и линия.

*AC.3 — Поддерживаемые типы линий и направление связи:*
* *Дано:* поле {{Тип_линии}} размещено на полке «Свойства связей» с типом «Тип линии»; для {{A}} → {{B}} получено {{solid}}, для {{A}} → {{C}} — {{DASHED}} с пробелами по краям, для {{B}} → {{A}} — {{DoTtEd}};
* *Когда:* диаграмма отрисована;
* *Тогда:* {{A}} → {{B}} отображается сплошной линией, {{A}} → {{C}} — штриховой, {{B}} → {{A}} — точечной; свойства встречных связей не смешиваются.

*AC.4 — Независимое применение цвета и типа линии:*
* *Дано:* на полке «Свойства связей» размещены отдельные пилюли {{Цвет_связи}} (тип «Цвет») и {{Тип_линии}} (тип «Тип линии»); для {{A}} → {{B}} получены {{#ff0000}} и {{dashed}};
* *Когда:* диаграмма отрисована;
* *Тогда:* связь {{A}} → {{B}} одновременно отображается красной и штриховой.

*AC.5 — Независимость свойств узла и связи:*
* *Дано:* пилюля {{Цвет_узла}} размещена на полке «Свойства узлов» с типом «Цвет», а {{Цвет_связи}} — на полке «Свойства связей» с типом «Цвет»;
* *Когда:* диаграмма отрисована;
* *Тогда:* первая пилюля влияет только на узлы (по логике MB-5234), вторая сопоставляется по {{[node]}} + {{[linkage]}} и влияет только на связи.

*AC.6 — Пустые и невалидные значения:*
* *Дано:* для {{A}} → {{B}} цвет равен {{null}}, а тип линии — {{dashed}}; для {{A}} → {{C}} цвет равен {{not-a-color}}, а тип линии — {{dash}};
* *Когда:* диаграмма отрисована;
* *Тогда:* {{A}} → {{B}} использует цвет по умолчанию и штриховую линию; {{A}} → {{C}} использует цвет и тип линии по умолчанию; значения других пар не подставляются, ошибка не возникает.

*AC.7 — Обработка множественных размещений:*
* *Дано:* на полке «Свойства связей» уже есть пилюля типа «Цвет»;
* *Когда:* пользователь добавляет вторую пилюлю с типом «Цвет» на ту же полку;
* *Тогда:* тип «Цвет» для новой пилюли доступен для выбора, но при её выборе она не влияет на диаграмму — обрабатывается только первая по порядку пилюля этого типа.

*AC.8 — Сохранение конфигурации:*
* *Дано:* отчёт содержит пилюли типов «Цвет» и «Тип линии» на полке «Свойства связей»;
* *Когда:* отчёт сохранён, повторно открыт и скопирован;
* *Тогда:* полка, порядок, тип, агрегация и форматирование каждой пилюли восстанавливаются без изменений, диаграмма отрисовывается без ошибки.

*AC.9 — Сохранение запроса и действующего поведения:*
* *Дано:* зафиксированы сетевые запросы контрольной диаграммы без пилюль цвета/типа линии связи; узел {{A}} имеет цвет {{#0000ff}} и размер {{10}}, подсказка связи {{A}} → {{B}} содержит {{X}}, а фильтр исключает связь {{A}} → {{C}};
* *Когда:* в диаграмму добавлены пилюли цвета и типа линии связи, диаграмма перестроена;
* *Тогда:* количество запросов данных не увеличилось, отдельный запрос свойств связей не отправлен, группировка по {{[node]}} + {{[linkage]}} и заданные агрегации сохранены; связь {{A}} → {{C}} отсутствует, узел {{A}} сохранил цвет {{#0000ff}} и размер {{10}}, подсказка {{A}} → {{B}} содержит {{X}}.
