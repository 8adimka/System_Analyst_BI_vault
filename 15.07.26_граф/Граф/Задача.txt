Ранее я написал постановку по переработке визуализации Граф - её текст во вложении.

Однако, в данной постановке я опирался на подход, который ранее использвоался во всех визуализациях нашего портала -> одна визуализация использует только один набор данных.

Данная постановка получилась не оптимальна и переусложнена, её нужно доработать.
Я склоняюсь к тому, чтобы использовать стандартных для Графовых визуализаций подход -> для построения одной визуализации Граф мы используем две таблицы:
1) Узлы графа - данная таблица будет содержать все узлы, которые будут отрисовываться на визуализации и их свойства.
2) Связи узлов графа - данная таблица будет содержать информацию о связях между узлами в визуализации Граф и свойства связи.

Основная текущая проблема, что для ссылок в визуализациях на поля набора данных сейчас у нас используется поле {{name}} (уникальное в рамках одного набора данных, но не уникальное в рамках всех наборов данных), такое положение вещей может вызывать проблемы при использовании более одного набора данных за раз, а именно это нам и требуется для классического построения Графа при помощи двух связанных таблиц.

Для того, чтобы обойти это ограничение я предлагаю следующую доработку - мы создадим дополнительное поле {{display_name}} и скопируем в него при помощи миграции содержимое поля {{name}}. Все визуализации продолжают ссылаться на поля набора данных через {{name}}, но во всех новых визуализациях мы записываем в поле {{name}} уникальный uuid и, по сути, используем поле {{name}} как {{id}}, а для отображения имени поля теперь используем {{display_name}}. Теперь для всех новых наборов данных мы можем безбоязненно использовать два и более датасета одновременно, полностью сохраняя обратную совместимость. Единственно, нам необходимо будет поменять отображаемое имя везде с {{name}} на {{display_name}}.

И далее мы используем две таблицы для построения визуализации Граф в классическом для этой визуализации стиле. Важно, чтобы после доработом визуализация работала с визуализацией "Таблица" и "Сводная таблица" и поддерживала все сценарии фильтрации данных. Доработать фильтрацию - это основная цель данной доработки, так как сейчас диаграмма "Граф" плохо работает при фильтрации данных, так как отрисовывается из одной таблицы.

Как системный аналитик с большим стажем, напиши постановку для реализации разработчиками всех необходимых доработок.
Постановка должна быть понятной разработчикам, достаточной, однозначной, талантливо-написанной и включать все необходимые разделы, включая критерии приёмки (AC). При написании данной постановки сохрани и используй разметку из предыдущей постановки, совместимую для публикации в JIRA.
