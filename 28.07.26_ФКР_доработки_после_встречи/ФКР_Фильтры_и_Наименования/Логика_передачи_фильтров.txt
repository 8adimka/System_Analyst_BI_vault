 
В рамках грядущего контракта у нас есть задача по наследованию фильтрации. Заказчик уточнил, что хотел бы дополнительно проработать следующую логику: 

_У нас есть фильтры множественные и с одиночным выбором. Когда пользователь переходит со страницы с множественным выбором на страницу с единственным выбором, а потом возвращается обратно — возможно ли сохранить исходный множественный выбор, чтобы при возвращении он восстанавливался?_ 

Прим. аналитик:

На страницах A и B используется один и тот же фильтр X. На странице A фильтр поддерживает множественный выбор, а на странице B — только одиночный. При переходе со страницы A на страницу B необходимо сохранить полный множественный выбор. Работа с этим фильтром на странице B не должна перезаписывать сохранённое состояние страницы A. При возврате на страницу A должен восстанавливаться исходный множественный выбор.

----

h3. Общий сценарий.

На страницах A и B настроен один и тот же сопоставляемый фильтр X. На странице A для фильтра X разрешён множественный выбор, на странице B — одиночный. Переходы между страницами выполняются с передачей контекста фильтрации.

Ниже приведены три варианта обработки ситуации, когда со страницы A передаётся несколько выбранных значений для фильтра, а конфигурация фильтра X на странице B допускает только одно значение.

----

h3. Вариант 1. Передача полного контекста фильтрации (без доработки портала).

*Логика:*

# При переходе со страницы A на страницу B портал передаёт весь текущий контекст фильтра X: все выбранные значения и режим множественного выбора.
# На странице B фильтр X применяется в переданном режиме: для текущего контекста страницы активируется множественный выбор и отображаются все значения, выбранные на странице A.
# Переключение фильтра X в множественный режим действует только для переданного контекста и не должно изменять сохранённую конфигурацию страницы B. При открытии страницы B без унаследованного множественного контекста фильтр должен продолжать работать в настроенном режиме одиночного выбора.
# При обратном переходе на страницу A передаётся текущее состояние фильтра X со страницы B. Если пользователь не изменял унаследованный выбор, на странице A восстанавливается исходный набор значений.

*Минимальные действия:*

* Использовать штатный механизм передачи контекста фильтрации.
* Для переходов между страницами включить передачу фильтров; в частности, для соответствующих элементов компонента «Панель закладок» не должна быть включена настройка «Без передачи фильтров».
* На целевой версии портала проверить, что временная активация множественного выбора не изменяет сохранённую конфигурацию фильтра X и что при обратном переходе передаётся полный набор значений.
* Возможное решение - доработка страницы B для корректной обработки сценариев передачи множественного выбора фильтров.
* При подтверждении указанного поведения доработка портала не требуется.

*Ограничения варианта:*

* На странице B фильтр X фактически работает в режиме множественного выбора. Вариант неприменим, если страница B и её визуализации должны обрабатывать строго одно выбранное значение.
* Состояния страниц A и B не изолируются. Если пользователь изменит фильтр X на странице B, при возврате на страницу A будет передано изменённое текущее состояние страницы B, а не ранее сохранённый выбор страницы A. Поэтому вариант не обеспечивает требование о сохранении исходного состояния страницы A при работе с фильтром на странице B.

----

h3. Вариант 2. Применение одного значения из исходного множественного выбора.

*Логика:*

# При переходе со страницы A на страницу B портал передаёт полный набор выбранных значений фильтра X.
# Если передано несколько значений, а фильтр X на странице B настроен на одиночный выбор, портал сохраняет исходный множественный набор в контексте перехода, но для фильтрации данных на странице B применяет только первое значение из переданного упорядоченного списка.
# Фильтр X на странице B остаётся в режиме одиночного выбора. Пользователь может изменить выбранное значение; такие изменения влияют на рабочее состояние страницы B и перезаписывают сохранённый набор страницы A. Не обеспечивает требование о сохранении исходного состояния страницы A при работе с фильтром на странице B.
# При возврате на страницу A для фильтра X используется текущий переданный набор фильтров со страницы B.
# Если (при переходе A → B) передано не более одного значения либо режимы сопоставленных фильтров совместимы, сохраняется действующая логика передачи контекста без дополнительного преобразования.

*Минимальные доработки портала:*

* Добавить обработку конфликта режимов, при котором множественный выбор передаётся в фильтр с одиночным выбором.
* Первое применяемое значение определять детерминированно — как первое среди переданных выбранных значений согласно действующему порядку или сортировке списка фильтра X на странице B. Управление этим значением возможно только косвенно, через порядок или сортировку; отдельный выбор значения для перехода в рамках варианта не добавляется.
* Не изменять сохранённые настройки режима выбора фильтров на страницах A и B и не вводить долговременное хранение состояния каждого дашборда. Сохранение исходного набора фильтров требуется только в контексте перехода (без изменений).

Вариант требует отдельной локальной доработки механизма передачи и применения контекста фильтрации при возникновении конфликта режимов и должен оцениваться отдельно от штатной передачи фильтров. Предварительно объём изменений может рассматриваться как минорный (без внедрения отдельного механизма хранения состояний дашбордов).

----

h3. Вариант 3. Сессионное сохранение контекста фильтрации для страниц.

Для обеспечения требования о сохранении исходного состояния страницы A при работе с фильтром на странице B, возможно применить сессионное сохранение состояния для отдельных страниц.
Тогда, с включеной настройкой «Без передачи фильтров» на странице B, при обратном переходе (B → A) на странице А будет применён последний используемый набор фильтров и восстановлено состояния страницы A до перехода на страницу B.

Однако, в силу дороговизны и сложности реализации такого решения, было принято решение сначала рассмотреть первые два варианта.

Также, как альтернативный вариант, можно отметить возможность открытия «Карточки ВПО» в новой вкладке браузера. Тогда состояние исходного дашборда сохраняется естественным образом.
