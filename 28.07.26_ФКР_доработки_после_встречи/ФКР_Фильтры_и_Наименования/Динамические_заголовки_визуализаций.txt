h3. Контекст и проблематика.

В основном портале заголовок визуализации задаётся статически и не зависит от данных и контекста фильтрации. Если отображаемое наименование заголовка визуализации должно меняться в зависимости от выбранных условий, в данный момент аналитик не может настроить такое поведение штатными средствами портала: заголовок приходится изменять вручную либо создавать отдельные компоненты для разных сценариев.

Требуется дать аналитику возможность использовать поле с полки «Значения» в качестве источника заголовка для визуализации. В том числе должна поддерживаться возможность выбрать вычисляемое поле, в котором аналитик может описать правила выбора текста заголовка в зависимости от доступных выражению условий (данных фильтрации, переменных и т.д.).

----

h3. Цель задачи.

*Требуется:*

# Добавить в раздел «Общие настройки» визуализаций тумблер «Динамический заголовок».
# При включённом тумблере предоставить поле «Текст заголовка» для выбора одной пилюли с полки «Значения» этой визуализации.
# Формировать заголовок по актуальному результату выбранной пилюли (в контексте фильтрации и прочих условий).
# Пересчитывать заголовок при изменении применимого контекста без пересоздания визуализации и без перезагрузки отчёта.
# Сохранять конфигурацию динамического заголовка в метаданных визуализации в составе отчёта и восстанавливать её при последующем открытии.
# Сохранить статический заголовок как резервное значение и обеспечить обратную совместимость существующих отчётов.

_Пользовательская история:_
Как аналитик, я хочу выбрать поле с полки «Значения» в качестве источника заголовка визуализации, чтобы заголовок автоматически отражал актуальные значения для выбранных фильтров или иных условий, заложенных в данных либо в выбранном вычисляемом поле.

----

h3. 1. Рамки задачи.

***
h4. 1.1. В рамках задачи:

* Настройка динамического заголовка для каждой визуализации независимо от других визуализаций отчёта.
* Поддержка всех типов визуализаций основного портала, у которых одновременно имеются:
** отображаемый заголовок компонента;
** раздел «Общие настройки»;
** полка «Значения».
* Работа динамического заголовка в режиме редактирования и в режиме просмотра отчёта.
* Использование обычных и вычисляемых полей, размещённых на полке «Значения».
* Пересчёт заголовка при серверной и при локальной обработке данных на фронтенде.
* Сохранение, чтение и перенос настройки в составе штатного жизненного цикла метаданных отчёта.

***
h4. 1.2. Не входит в рамки задачи:

* Динамическое изменение наименований отчётов, дашбордов, страниц, вкладок, столбцов, серий, легенд и элементов фильтрации.
* Добавление в выражения вычисляемых полей отдельного API для прямого чтения состояния элементов фильтрации. Зависимость заголовка от фильтров обеспечивается через результат поля в актуальном контексте данных.
* Выбор источника заголовка из полей набора данных, которые не размещены на полке «Значения» целевой визуализации.
* Формирование заголовка по отдельному шаблону с ручной подстановкой нескольких полей, префиксов или суффиксов.
* Изменение существующей логики применения фильтров и генерации SQL.

----

h3. 2. Описание текущего поведения.

* Заголовок визуализации хранится и отображается как статический текст.
* Изменение фильтров и обновление данных визуализации не меняют её заголовок.
* Поле или вычисляемое поле с полки «Значения» нельзя назначить источником текста заголовка.
* Для показа разных наименований при разных условиях аналитик должен вручную менять заголовок либо использовать несколько отдельно настроенных визуализаций.

----

h3. 3. Описание целевого поведения.

# Аналитик размещает на полке «Значения» поле, результат которого должен использоваться как заголовок. Это может быть обычное поле или вычисляемое поле.
#* Для вычисляемого поля аналитик задаёт бизнес-логику существующими средствами редактора вычисляемых полей. Например, одно значение периода должно возвращать один текст, другое значение периода — другой текст.
# В разделе «Общие настройки» аналитик включает тумблер «Динамический заголовок».
# В ставшем доступным поле «Текст заголовка» аналитик выбирает одну из пилюль, находящихся на полке «Значения» этой визуализации.
# Портал сохраняет ссылку на выбранную пилюлю в конфигурации визуализации. Выбор источника заголовка не перемещает, не копирует и не изменяет пилюлю на полке «Значения».
# При расчёте данных визуализации портал получает актуальный результат выбранной пилюли с учётом всех фильтров, которые фактически применяются к данной визуализации.
# Если результат однозначно определяет один непустой текст, этот текст отображается в области заголовка визуализации вместо сохранённого статического заголовка.
# При изменении применимого фильтра, выражения выбранного вычисляемого поля или настроек выбранной пилюли - заголовок пересчитывается вместе с очередным обновлением данных визуализации.
# Если динамический заголовок получить невозможно, в области заголовка отображается сохранённый статический заголовок.
# После сохранения и повторного открытия отчёта состояние тумблера и выбранный источник восстанавливаются, а динамический заголовок рассчитывается в актуальном контексте данных и фильтров.

----

h3. 4. Требования к реализации.

***
h4. 4.1. Интерфейс и настройка.

* В разделе «Общие настройки» каждой визуализации в рамках задачи добавить тумблер «Динамический заголовок».
* Для новых визуализаций и визуализаций из отчётов, созданных до внедрения функциональности, тумблер по умолчанию выключен.
* При выключенном тумблере:
** визуализация использует существующую логику статического заголовка;
** поле «Текст заголовка» не отображается;
** ранее выбранный источник динамического заголовка, если он сохранён в конфигурации, не влияет на отображение.
* При включённом тумблере поле «Текст заголовка» становится доступно для выбора источника.
* В поле «Текст заголовка» должен быть доступен выбор ровно одной пилюли из текущего состава полки «Значения» настраиваемой визуализации.
* В списке выбора следует отображать актуальные пользовательские наименования пилюль и доступные признаки, позволяющие различить одноимённые экземпляры, например источник, агрегацию или форматирование. Каждая позиция списка должна соответствовать конкретному экземпляру пилюли, включая случаи, когда одно поле добавлено на полку несколько раз.
* Поле выбора не должно предлагать поля, отсутствующие на полке «Значения» данной визуализации.
* Существующее поле статического заголовка должно оставаться доступным для заполнения и изменения, поскольку его значение используется как резервное.
* Включение тумблера без выбранной пилюли не должно нарушать работу или сохранение визуализации: до выбора корректного источника должен отображаться статический заголовок, а поле «Текст заголовка» должно визуально указывать на отсутствие источника.
* Выключение тумблера должно сразу возвращать статический заголовок без удаления визуализации и без перезагрузки отчёта.
* Выключение тумблера не должно очищать сохранённый источник. При повторном включении ранее выбранная пилюля восстанавливается, если она по-прежнему находится на полке «Значения» и ссылка на неё разрешается.
* Динамический текст должен отображаться в существующей области заголовка с сохранением текущих стилей, правил выравнивания, переноса, ограничения длины и видимости заголовка.
* Если отображение заголовка отключено существующей настройкой визуализации, тумблер «Динамический заголовок» не должен принудительно показывать область заголовка.

***
h4. 4.2. Источник и вычисление текста заголовка.

* Источником может быть любая пилюля, размещённая на полке «Значения», включая пилюлю обычного поля, меры или вычисляемого поля.
* В заголовке используется результат выбранной пилюли, а не её наименование, {{alias}} или системное имя.
* Выбор пилюли как источника заголовка не меняет её штатного участия в построении визуализации и не скрывает её автоматически из отображаемых значений.
* Динамический заголовок не содержит собственной бизнес-логики. Он отображает результат выбранной пилюли; зависимость от периода или иных условий аналитик задаёт в SQL-выражении набора данных либо в выражении вычисляемого поля.
* Вычисляемое поле должно обрабатываться штатным механизмом портала с сохранением действующих правил вычисления, агрегации, форматирования и поддержки SQL-диалектов.
* Результат выбранной пилюли должен рассчитываться в том же актуальном контексте данных, фильтрации и RLS, что и данные визуализации для текущего пользователя. Специальный независимый контекст фильтрации для заголовка не создаётся.
* При использовании нестрокового скалярного значения в заголовке должно отображаться его текстовое представление с учётом применимого штатного форматирования выбранной пилюли.
* Значения {{0}} и {{false}} являются допустимыми результатами и после штатного преобразования в текст не должны ошибочно считаться пустыми.
* Результат считается однозначным, если после исключения значений {{null}}, пустых строк и строк, содержащих только пробельные символы, в актуальной выборке осталось одно уникальное непустое текстовое представление. +Повторение одного и того же текста в нескольких строках не считается неоднозначностью+.
* Если в актуальной выборке получено несколько различных непустых значений, портал не должен выбирать произвольную строку, первое или последнее значение. В этом случае динамический заголовок считается невычислимым и используется статический заголовок.
* Динамический заголовок должен отображаться как обычный текст. HTML, скрипты и иная разметка из данных не должны интерпретироваться.

***
h4. 4.3. Контекст и события пересчёта.

* При расчёте заголовка должны учитываться все условия, которые фактически влияют на данные целевой визуализации, в том числе:
** фильтры, настроенные непосредственно для визуализации;
** применимые фильтры дашборда и общей панели фильтров;
** применимая межкомпонентная фильтрация;
** иные штатные условия, вызывающие обновление данных визуализации.
* Фильтр, который по существующим настройкам или связям не применяется к визуализации, не должен влиять на её динамический заголовок.
* При серверной обработке заголовок должен обновляться по результату расчёта данных с актуальным контекстом фильтров.
* Если данные получены заранее и фильтрация выполняется на фронтенде, заголовок должен пересчитываться по результату той же локальной фильтрации без обязательного повторного запроса к бэкенду.
* При изменении фильтра или иного условия заголовок должен обновляться в рамках штатного цикла обновления визуализации, без пересоздания компонента и без перезагрузки отчёта.
* С момента запуска обновления и до получения результата последнего актуального расчёта должен сохраняться ранее отображавшийся заголовок. После завершения расчёта он заменяется новым однозначным динамическим значением либо статическим резервным значением.
* При нескольких последовательно отправленных запросах результат более раннего запроса не должен заменять заголовок, уже рассчитанный для более нового контекста.
* Изменение выбранной пилюли, её выражения, агрегации, форматирования или иных настроек, влияющих на результат, должно инициировать актуализацию заголовка по штатным правилам обновления визуализации.

***
h4. 4.4. Резервное значение и обработка невалидных состояний.

Сохранённый статический заголовок должен использоваться как резервное значение в любом из следующих случаев:
* тумблер «Динамический заголовок» выключен;
* тумблер включён, но источник в поле «Текст заголовка» не выбран;
* выбранная пилюля удалена с полки «Значения», удалено связанное поле или ссылка на источник не разрешается;
* результат отсутствует, равен {{null}}, является пустой строкой либо содержит только пробельные символы;
* результат содержит несколько различных непустых значений;
* данные визуализации или выбранное поле не удалось рассчитать из-за ошибки.

* Если статический заголовок не заполнен, при невозможности получить динамическое значение должно сохраняться текущее поведение портала для пустого статического заголовка.
* Невалидное динамическое значение не должно отображаться как {{null}}, {{undefined}}, технический идентификатор, объект, текст ошибки или пустой динамический заголовок.
* Временный переход на статический заголовок не должен автоматически выключать тумблер или удалять выбранный источник. После появления однозначного корректного значения динамический заголовок должен снова отображаться.
* В режиме редактирования неразрешенная ссылка на пилюлю должна быть обозначена в поле «Текст заголовка», чтобы аналитик мог выбрать другой источник.
* Ошибка расчёта заголовка не должна приводить к ошибке отрисовки всей визуализации. Ошибки данных самой визуализации продолжают обрабатываться по существующим правилам портала.

***
h4. 4.5. Метаданные и API.

* Настройка является частью метаданных конкретной визуализации и сохраняется в составе метаданных отчёта.
* В метаданных необходимо хранить следующие логические параметры:

|| Параметр || Обязательность || Требование ||
| Признак использования динамического заголовка | Обязательный для новой конфигурации | Логическое значение. Для метаданных без параметра трактуется как «выключено». |
| Ссылка на пилюлю — источник текста | Обязательный при настроенном источнике | Стабильная ссылка на экземпляр пилюли с полки «Значения» внутри данной визуализации. |
| Статический заголовок | Существующий параметр | Хранится независимо и используется как резервное значение. |

* Ссылка на источник не должна зависеть только от отображаемого наименования пилюли. Переименование пилюли, изменение её {{alias}} или порядка на полке «Значения» не должно разрывать настройку динамического заголовка.
* При загрузке отчёта портал должен разрешить сохранённую ссылку в пределах целевой визуализации и восстановить состояние поля «Текст заголовка».
* Вычисленное отображаемое значение динамического заголовка не сохраняется в метаданных: при открытии отчёта оно заново определяется по актуальным данным, фильтрам и RLS.
* В логической модели затрагивается backend-объект {{reports}}. Для чтения и сохранения конфигурации должны использоваться действующие операции получения и обновления отчёта, соответствующие командам {{get}} и {{update}}; актуальные наименования команд и контракт необходимо подтвердить у команды разработки перед реализацией.
* Перед отправкой {{update}} фронтенд должен располагать актуальным состоянием отчёта, полученным через действующий сценарий {{get}}, и не должен терять остальные параметры визуализации и отчёта.
* Точные backend-наименования новых параметров определяются в рамках реализации в соответствии с действующей схемой метаданных отчёта; логический состав и правила значений должны соответствовать настоящей постановке.
* Копирование или дублирование визуализации и отчёта, а также штатный экспорт и импорт метаданных должны сохранять признак динамического заголовка, ссылку на источник и статический резервный заголовок, если соответствующая операция переносит остальные настройки визуализации.

***
h4. 4.6. Технические требования и ограничения.

* Динамический заголовок не должен изменять состав или логику действующих фильтров, а также правила формирования {{WHERE}}, {{HAVING}}, {{GROUP BY}} и агрегаций.
* Расчёт заголовка должен выполняться в рамках штатного обновления данных визуализации и не должен инициировать отдельную перезагрузку всего отчёта либо отдельный запрос для каждой строки результата.
* Настройка не должна изменять существующие права на редактирование и просмотр отчётов: управлять ею могут те же роли, которым уже доступно изменение общих настроек визуализации.
* Текст заголовка должен проходить штатное экранирование пользовательских и полученных из данных значений.
* Отсутствующие или повреждённые параметры динамического заголовка в метаданных не должны препятствовать открытию отчёта и отрисовке визуализации.

----

h3. 5. Пограничные сценарии:

* На полке «Значения» нет пилюль: включение тумблера не нарушает работу визуализации, список «Текст заголовка» пуст, отображается статический заголовок.
* На полке несколько пилюль с одинаковыми отображаемыми наименованиями: аналитик может различить и выбрать требуемый источник; сохраняется ссылка именно на выбранный экземпляр.
* Выбранная пилюля переименована или перемещена внутри полки: привязка сохраняется.
* Выбранная пилюля удалена с полки или соответствующее поле удалено из набора данных: отображается статический заголовок, в режиме редактирования видна невалидность источника.
* Фильтр периода даёт одно применимое наименование: отображается это наименование.
* Выбран диапазон, для которого вычисляемое поле возвращает разные наименования: отображается статический заголовок, произвольное значение не выбирается.
* После фильтрации отсутствуют строки или все значения источника пусты: отображается статический заголовок.
* Вместе с одним непустым значением возвращены значения {{null}}: непустое значение используется как динамический заголовок.
* Источник возвращает {{0}} или {{false}}: отображается его штатное текстовое представление, статический заголовок из-за «ложного» значения не подставляется.
* Несколько строк возвращают одинаковый непустой текст: этот текст используется как динамический заголовок.
* Быстрое последовательное изменение фильтра: после завершения обработки заголовок соответствует последнему актуальному состоянию фильтрации.
* Вычисляемое поле содержит ошибку либо использует неподдерживаемое источником выражение: заголовок не показывает техническую ошибку и переходит на статическое значение.
* RLS ограничивает выборку для текущего пользователя: заголовок определяется только по доступным этому пользователю данным и не раскрывает значения из недоступных строк.
* Статический заголовок не заполнен и динамическое значение недоступно: сохраняется действующее поведение визуализации с пустым статическим заголовком.

----

h3. 6. Обратная совместимость.

* Отчёты, созданные до внедрения функциональности, должны открываться и отображаться без изменения заголовков.
* Отсутствие новых параметров в метаданных трактуется как выключенный тумблер «Динамический заголовок».
* Существующие статические заголовки не должны изменяться, удаляться или автоматически преобразовываться в динамические.
* Включение функциональности для одной визуализации не должно менять заголовки и конфигурацию других визуализаций отчёта.
* После выключения динамического заголовка визуализация должна полностью вернуться к существующей логике отображения статического заголовка.

----

h3. 7. Критерии приёмки (AC):

*AC.1 — Наличие и состояние настройки по умолчанию:*
* *Дано:* открыт конструктор новой визуализации в рамках задачи или визуализации из существующего отчёта;
* *Когда:* аналитик открывает раздел «Общие настройки»;
* *Тогда:* доступен тумблер «Динамический заголовок», по умолчанию он выключен, поле «Текст заголовка» не отображается, визуализация показывает прежний статический заголовок.

*AC.2 — Выбор источника с полки «Значения»:*
* *Дано:* на полке «Значения» визуализации находятся несколько пилюль;
* *Когда:* аналитик включает «Динамический заголовок» и открывает поле «Текст заголовка»;
* *Тогда:* для выбора доступны только пилюли текущей полки «Значения», можно выбрать одну пилюлю, а сам выбор не меняет состав и порядок полки.

*AC.3 — Использование вычисляемого поля:*
* *Дано:* на полке «Значения» размещено вычисляемое поле, возвращающее один текст для одного периода и другой текст для другого периода;
* *Когда:* это поле выбрано в «Текст заголовка» и аналитик изменяет период;
* *Тогда:* после обновления данных заголовок показывает текст, рассчитанный вычисляемым полем для выбранного периода, без пересоздания визуализации и без перезагрузки отчёта.

*AC.4 — Учёт применимого контекста фильтрации:*
* *Дано:* источник динамического заголовка зависит от фильтра, который применяется к визуализации;
* *Когда:* пользователь меняет значение этого фильтра;
* *Тогда:* данные и заголовок визуализации пересчитываются в одном актуальном контексте, а заголовок соответствует результату источника для последнего выбранного состояния фильтра.

*AC.5 — Игнорирование неприменимого фильтра:*
* *Дано:* фильтр по существующим настройкам не применяется к целевой визуализации;
* *Когда:* пользователь меняет этот фильтр;
* *Тогда:* значение динамического заголовка целевой визуализации из-за данного фильтра не изменяется.

*AC.6 — Однозначный результат в нескольких строках:*
* *Дано:* выбранная пилюля возвращает одинаковый непустой текст в нескольких строках актуальной выборки;
* *Когда:* визуализация завершает расчёт;
* *Тогда:* повторяющийся текст отображается как динамический заголовок.

*AC.7 — Неоднозначный результат:*
* *Дано:* выбранная пилюля возвращает не менее двух различных непустых значений;
* *Когда:* визуализация завершает расчёт;
* *Тогда:* портал не выбирает произвольное значение и отображает сохранённый статический заголовок.

*AC.8 — Пустой результат или ошибка вычисления:*
* *Дано:* выбранная пилюля возвращает {{null}}, пустую строку, только пробельные символы, не возвращает строк либо не может быть рассчитана;
* *Когда:* портал обновляет визуализацию;
* *Тогда:* отображается сохранённый статический заголовок, а техническое значение или текст ошибки в заголовок не выводится.

*AC.9 — Удаление источника:*
* *Дано:* для динамического заголовка выбрана пилюля;
* *Когда:* пилюля удалена с полки «Значения» либо ссылка на неё стала неразрешимой;
* *Тогда:* визуализация продолжает работать со статическим заголовком, а в режиме редактирования поле «Текст заголовка» показывает невалидное состояние.

*AC.10 — Переименование и изменение порядка пилюли:*
* *Дано:* источник динамического заголовка настроен и сохранён;
* *Когда:* аналитик переименовывает выбранную пилюлю либо меняет её положение на полке «Значения»;
* *Тогда:* связь с источником сохраняется и заголовок продолжает рассчитываться по выбранной пилюле.

*AC.11 — Выключение динамического заголовка:*
* *Дано:* визуализация отображает рассчитанный динамический заголовок;
* *Когда:* аналитик выключает тумблер «Динамический заголовок»;
* *Тогда:* без перезагрузки отчёта отображается статический заголовок, дальнейшие изменения фильтров не меняют его, а при повторном включении тумблера восстанавливается ранее выбранный источник, если ссылка на него остаётся валидной.

*AC.12 — Сохранение и повторное открытие:*
* *Дано:* аналитик включил динамический заголовок, выбрал источник и сохранил отчёт;
* *Когда:* данные или контекст фильтрации изменились и отчёт открыт повторно;
* *Тогда:* состояние тумблера и выбранный источник восстановлены, при этом заголовок заново рассчитан по актуальным данным и фильтрам, а не взят из ранее вычисленного отображаемого значения.

*AC.13 — Обратная совместимость:*
* *Дано:* открыт отчёт, сохранённый до появления новых параметров метаданных;
* *Когда:* портал загружает и отображает его визуализации;
* *Тогда:* отчёт открывается без ошибок, тумблеры динамических заголовков считаются выключенными, все статические заголовки отображаются без изменений.

*AC.14 — Актуальность при последовательных запросах:*
* *Дано:* быстрое изменение фильтра запустило несколько последовательных обновлений данных визуализации;
* *Когда:* ответы получены в порядке, отличном от порядка отправки запросов;
* *Тогда:* до завершения последнего актуального расчёта сохраняется ранее отображавшийся заголовок, итоговый заголовок соответствует последнему актуальному контексту, а устаревший ответ его не заменяет.

*AC.15 — Работа при локальной фильтрации:*
* *Дано:* данные визуализации загружены на фронтенд, а применимый фильтр обрабатывается локально;
* *Когда:* пользователь изменяет фильтр;
* *Тогда:* заголовок пересчитывается по локально отфильтрованному результату и не требует перезагрузки отчёта.

*AC.16 — Безопасное отображение текста:*
* *Дано:* значение выбранной пилюли содержит HTML или исполняемую разметку;
* *Когда:* значение используется как динамический заголовок;
* *Тогда:* оно отображается как текст согласно штатному экранированию портала и не исполняется.

*AC.17 — Учёт RLS:*
* *Дано:* для двух пользователей RLS формирует разные доступные выборки по одному отчёту и одинаковому контексту фильтров;
* *Когда:* каждый пользователь открывает визуализацию с настроенным динамическим заголовком;
* *Тогда:* для каждого пользователя заголовок рассчитывается только по доступной ему выборке и не содержит значений из строк, закрытых RLS.
