# Modus BI: рабочая область аналитической системы

Все относительные ссылки разрешай от корня workspace (`/home/v/desk/work` на этом компьютере). Итог работы — точная компактная постановка на русском в Jira wiki-markup. Пользовательские материалы и решения определяют требования; код подтверждает текущую реализацию.

- Стиль: `agent-system/standards/jira-style.md`; качество: `agent-system/standards/requirements-quality.md`; независимость и обмен: `agent-system/standards/review-protocol.md`.
- Роли: `.codex/agents/analyst.toml`, `.codex/agents/reviewer.toml`. Повторяемые действия: `.agents/skills/`. Запуск и ввод промпта: `README.md`.
- Навигация по коду: `.private/knowledge/index.md`. Wiki служит указателем: для существенного вывода проверь исходный файл/символ и версию репозитория. Разделяй факт, вывод, предположение и предложение; не превращай архивный контекст в действующий контракт.
- Репозитории: `.private/repositories/bi_react/`, `.private/repositories/bi-forms/`, `.private/repositories/modusbi/`, `.private/repositories/plugins/`. Они исключены из Git: ищи явно внутри нужного пути через `rg --hidden --no-ignore`, исключая `.git` и зависимости. Поиск по корню обычно их пропускает.
- Корпоративные репозитории доступны только для чтения. Не выполняй в них изменение файлов, checkout/pull/reset/clean, install/build/test. Оба агента работают в `Sandbox.read_only`; все артефакты записывает координатор через проверяемый файловый шлюз.
- Аналитик и ревьюер используют разные Codex Thread. Сначала фиксируется независимое исследование ревьюера по исходным материалам; только после этого ему передаётся черновик. Исторические черновики и рабочие результаты не включаются в исходные данные слепой стадии.
- Секреты, `Доступы.txt`, авторизацию и пользовательские конфигурации не читай и не меняй. `.private/` полностью приватна: код, Wiki, состояния и выводы агентов нельзя автоматически публиковать. Проверка публикации обязательна также для тематических документов и `.agent/`.
- Не используй внешние сервисы для корпоративных материалов без подтверждённого разрешения компании. Не выполняй автоматически git add/commit/push; перед возможной публикацией проверь status, check-ignore и ls-files.

Сначала разрешай технические вопросы по доступным материалам и коду. Пользователю направляй только оставшиеся существенные неоднозначности. Неподтверждённые решения и незакрытые разногласия отражай в «Открытых вопросах»; не выдавай такой документ за согласованный.

Для новой постановки в интерактивном Codex используй Python-координатор по README и указанный тематический `*.txt`: ответ одной сессии не заменяет независимое ревью. Runtime роли отвечают координатору структурированными данными и повторно его не запускают.
