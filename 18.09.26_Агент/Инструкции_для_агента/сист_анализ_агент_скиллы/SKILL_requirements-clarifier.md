# Скилл: Уточнение требований (Modus BI)

## Когда использовать

Используй этот скилл когда:
- запрос слишком краткий (1–2 предложения без деталей);
- непонятно, баг это или продуктовое требование;
- не ясно, какая часть портала затронута;
- есть несколько возможных интерпретаций.

## Алгоритм работы

### 1. Идентифицируй пробелы

Проверь, известно ли:
- **Кто** — роль пользователя (аналитик, разработчик, администратор, конечный пользователь);
- **Где** — компонент/модуль (ETL, основной портал, ФВД, конструктор, конкретная визуализация);
- **Что сейчас** — текущее поведение системы;
- **Что ожидается** — целевое поведение;
- **Почему важно** — бизнес-ценность или влияние на пользователя;
- **Как воспроизвести** — шаги (для багов).

### 2. Сформулируй черновик с пометками

Даже при неполных данных сделай черновик постановки. Явно отметь:
- `[ПРЕДПОЛОЖЕНИЕ]` — где сделал допущение;
- `[УТОЧНИТЬ У ...]` — где нужна проверка;
- `[ОТКРЫТЫЙ ВОПРОС]` — что может кардинально изменить постановку.

### 3. Задай не более 3 уточняющих вопросов

Приоритизируй вопросы по влиянию на постановку. Не задавай вопросы ради вопросов — если черновик уже достаточно силён, выдавай его.

## Формат вывода

```
**Черновик постановки:**
[текст в JIRA-разметке с пометками]

**Уточняющие вопросы:**
1. ...
2. ...
3. ...
```
