В данный момент на нашем аналитическом портале наблюдается проблема при необходимости проводить поиск сразу по нескольким полям по специфической логике. Данная проблема наблюдается как на основном портале, так и для ФВД. Ранее нами уже были подготовлены ряд постановок по смежной тематике для решения этих проблеме:
1)./Постановка_Иерархические_фильтры_Поиск_по_всем_уровням_поиск_без_лимита.txt
2)./Постановка_безлимитный_поиск_в_выпадающих_списках_по_информационным_полям.txt

Эти постановки необходимо изучить для контекста, но их реализация ещё не была осуществлена и потребует дополнительных вложений времени, в особенности, со стороны бэкенда. В текущих реалиях, данные постановки были поставлены на паузу в части внедрения поиска сразу по нескольким полям со специфической логикой (ИЛИ), а систему нам нужно использовать в её текущем виде с минимальными доработками. Активировать настройку «Поиск без лимита» и активировать серверный поиск для иерархических структур мы можем, но обеспечить корректный поиск по нескольким полям потребует существенных доработок бэкенда.

На данный момент хотелось бы решить эту проблему без серьёзных доработок бекенда, а для этого нам нужно доработать фронтенд и дать возможность пользователю выбирать уровень по которому будет происходить поиск, так как проводить поиск по всех уровням мы (на данный момент) не можем в силу ограничений бэкенда.

Т.е. основная идея: при включении настройки «Поиск без лимита» с фронта передаётся только одно поле (как и было раньше), но теперь благодаря интерфейсным доработкам пользователь может сам задать какое поле передавать для осуществления поиска. 

На фронтенде в поле для поиска у нас добавляется выпадающий список, который позволяет выбрать одно из доступных полей, по которому будет происходить поиск. Дополнительный интерфейс внедряется согласно макету.

Изучи целевой макет ./Целевой_вид_поля_поиска_Иерархичнский_фильтр.png

Выбор поля для поиска выводится пользователю в виде "Искать в <Наименование Поля с полки 'Фильтры' данного Иерархического фильтра>".

После выбора пользователем одного из полей, именного это поле становится целевым для поиска совпадений после ввода пользователем поисковой фразы или слова в поле поиска. Как результаты выводятся все уровни иерархии в которых было найдено совпадение на целевом уровне (в выбранном поле).

Цель текущей доработки дать пользователю возможность выбрать поле, по которому будет происходить поиск без необходимости проводить поиск сразу по нескольким полям, что уменьшает требуемые бэкендовые доработки и даём пользователю самому задавать верное поле для поиска из доступных на данный момент в визуализации. Т.е. набор полей по которому может (и должен) происходить поиск у нас не меняет, а проводить поиск по всем полям сразу мы не можем (на данный момент) по техническим причинам, поэтому мы даём пользователю возможность самому задать целевое поле для проведения поиска.

Требуется:
* Реализовать поддержку опции «Поиск без лимита» для активации серверного поиска для иерархических структур, без существенных доработок бэкенда.
* При включении опции «Поиск без лимита» в иерархическов фильтре, для поля поиска добавить новый элемент - выпадающий список (согластно макету) для выбора целевого поля для проведения серверного поиска.
* Внедрить корректную обработку сопутствующих настроек: «Количество символов для активации режима» и «Не загружать значения».

User Story:
Как аналитик, я хочу иметь возможность включать серверный поиск в иерархическом фильтре, чтобы пользователи могли искать значения по всему справочнику на любом уровне вложенности иерархии по всему объему данных, не ограничиваясь первоначально загруженным пулом записей. Пользователи должны иметь возможность выбрать целевой уровень вложенности по которому будет происходить серверный поиск.

Как системный аналитик с большим стажем, опираясь на изученные материалы и контекст, сформулируй и подготовь понятную постановку для осуществления описанных доработок нашего портала и внедрения нового интерфейса для выбора целевого поля поиска в соответствии с макетом.
