# HTML-макет портала

Прочитай `AGENT.md`, `.private/knowledge/index.md` и `.private/knowledge/frontend/visual-system.md`. Найди реальный экран-аналог и его layout, тему, обёртки UI, иконки и состояния. Сверь нужные файлы с HEAD. Учитывай продуктовый вариант и theme overrides; базовая тема не доказывает внешний вид стенда. Если вариант не задан и источники позволяют, используй подходящий default-экран, явно назвав допущение. Предоставленный скриншот/экспорт темы уточняет визуальный референс.

Сначала определи нужный пользовательский сценарий и состояния. Перенеси визуальную систему экрана в HTML/CSS: плотность и размеры, меню/шапку, типографику, цвета, таблицы/карточки, поля, кнопки, диалоги и focus. Значения токенов фиксируй в CSS custom properties. Уместность каждого элемента определяется задачей и референсом; не добавляй произвольный лендинг, карточки или большие заголовки. Если точное начертание недоступно, выбери подтверждённый локальный fallback и укажи ограничение в ответе.

Сохрани новый UTF-8 файл `.private/mockups/<задача>/<экран>.html`, проверив resolve()/симлинки и отсутствие чужого результата. По умолчанию он открывается через `file://`: inline CSS/обычный script, без fetch локального JSON, import модулей, сервера, реального API, CDN и remote fonts. Сложный макет может иметь рядом локальные ассеты с относительными путями. Исходные репозитории не менять; корпоративные SVG/шрифты/цвета/производные макеты хранить приватно.

Используй вымышленные данные и реализуй нужные локальные взаимодействия: фильтрацию/поиск, переключение состояния, открытие/закрытие диалога, проверку ввода или обновление представления по сценарию. Не имитируй сохранение на сервере сообщением об успешной реальной операции. Дай элементам доступные названия, видимый focus, работу клавиатурой и корректное закрытие модальных окон. Проверь пустое состояние/ошибку, если они существенны для задачи.

Если доступен браузер, проверь целевой viewport, переполнение, клики, Tab/Escape, console и отсутствие сетевых запросов. Без браузера проверь структуру и JS доступными средствами, явно отдели статические проверки от визуальной. Результат — ссылка на HTML, демонстрируемые действия и существенные ограничения сходства/проверки. Jira-разметка и координатор постановок для такого запроса не нужны.
