# Исследование кодовой базы

Корень workspace на этом компьютере `/home/v/desk/work`; при переносе используй объявленный координатором корень. Прямые пути: `.private/repositories/bi_react/` (основной портал), `.private/repositories/bi-forms/` (ФВД), `.private/repositories/modusbi/` (бэкенд), `.private/repositories/plugins/` (отдельные плагины). Файлы этих репозиториев изменять запрещено; install/build/test, pull/checkout/reset/clean не выполняй.

Начни с `.private/knowledge/index.md`, найди релевантную область и перепроверь ссылку по версии исходников. Репозитории исключены из Git: обычный поиск по workspace может не увидеть их. Ищи явно, например `rg --hidden --no-ignore -g '!.git/**' -g '!node_modules/**' 'символ' .private/repositories/bi_react/`. Не используй глобальный поиск по секретам и `Доступы.txt`. Чтение git status/rev-parse/log/show допускается.

Проследи нужную цепочку: пользовательское действие → состояние/настройки → сериализация/запрос → обработчик/контракт → данные → результат. Исследуй только затронутые звенья, при необходимости сверяй фронтенд, бэкенд, ФВД и плагины. Похожее имя функции, отсутствие результата поиска и архивная Wiki не доказывают поведение.

Для существенного вывода верни evidence: path, symbol, revision (Git SHA; при dirty-файле дополнительно хеш), observation с фактом и при возможности строкой. Отдели наблюдение от вывода и неподтверждённого предположения. Отметь границы прочитанного, отсутствующие зависимости и неразрешённые вопросы. Не считай текущее поведение целевым требованием.

Результат исследования возвращай координатору; он сохраняет разрешённые артефакты и актуализирует Wiki. Не обращайся к сетевым API и LLM-сервисам с корпоративным содержимым без подтверждённого разрешения.
