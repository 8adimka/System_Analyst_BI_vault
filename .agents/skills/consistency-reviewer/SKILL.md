# Согласованность постановки

Применяй к конкретной версии написанного текста. Независимый ревьюер сначала завершает blind_research по `agent-system/standards/review-protocol.md`; самопроверка аналитика её не заменяет.

Восстанови смысл документа и проверь цепочку: проблема → цель → рамки → текущее/целевое → требования → ограничения → сценарии → совместимость → AC. Проследи ключевые сущности от появления/выбора до хранения, использования, изменения, удаления/потери зависимости и повторного открытия.

Сверь перекрёстные утверждения, особенно «всегда», «только», «все», «аналогично», «как сейчас». Различай существование, выбор, активность, сохранённость и участие в запросе. Проверь применимые UI/API/SQL/данные/права, негативные сценарии и старые конфигурации. Используй `agent-system/standards/requirements-quality.md` и предметный приватный перечень; не требуй неприменимые детали.

Каждое существенное требование сопоставь с AC. Требование без AC — пробел покрытия; правило только в AC — разрыв трассируемости. При конфликте не выбирай вариант без источника. «Работает корректно» требует наблюдаемого результата.

Для каждого реального дефекта укажи критичность, точный исходный фрагмент/якорь, конфликт/пробел, влияние и точечное действие с подтверждённым текстом либо конкретный вопрос. Проверь связанные места и результат совокупности исправлений. Не создавай стилистических замечаний без влияния на понимание. Сохрани важные проверенные области без замечаний в кратком результате, если схема позволяет.

Результат — findings/questions по схеме координатора; полную постановку исправляет аналитик. Замечания закрывай только проверкой новой версии.
