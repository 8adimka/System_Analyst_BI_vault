# Разработка портала

Работай по `AGENT.md`. Приватный индекс `.private/knowledge/index.md` ведёт к `.private/knowledge/architecture/fullstack-map.md` и `.private/knowledge/development/workflow.md`. Выбирай приложение и участок кода по реальной цепочке вызовов; версии библиотек, ограничения API и команды подтверждай в соответствующем manifest/символе. Не переноси архитектуру одного клиента на другой по сходству имён.

Эталон `.private/repositories/` только для чтения. Подготовь обычную независимую копию в `.private/development/<задача>/<репозиторий>/`, если готовой подходящей копии нет. Проверяй канонические source/target пути и компоненты пути; не копируй `.git`, `.env`, секреты, зависимости, build-output и симлинки; не делай hardlink на исходники или `git worktree`. Для полной сборки копируй необходимые исходники/manifest/lockfile/config, предварительно проверив отсутствие секретов. Сохрани baseline SHA и неизменённые версии затрагиваемых файлов приватно. Чужую копию не очищай и не перезаписывай.

Внеси точечные связанные изменения UI/состояния/сериализации/API/backend по задаче, используя существующие компоненты и контракты. Проверяй сценарии ошибок, права и совместимость там, где изменение их затрагивает. Рабочее предложение или предположение не считай подтверждённым продуктовым требованием.

Перед запуском команды прочитай её script и вызываемые утилиты. Проверки и зависимости запускай только в рабочей копии, без production-сервисов и БД; учитывай shell network policy. Не считай пустой test-script проверкой и не запускай deploy/update под видом build. Выбери проверку изменённого поведения; отсутствующую инфраструктуру явно отметь.

Верни ссылку на изменённый код/патч в приватной задаче, поведение до/после и результаты доступных проверок. Новые общие подтверждённые знания перенеси в Wiki по её `SCHEMA.md`, без черновиков текущей задачи. Координатор постановок, его роли и SDK-права ради этой разработки не изменяй.
