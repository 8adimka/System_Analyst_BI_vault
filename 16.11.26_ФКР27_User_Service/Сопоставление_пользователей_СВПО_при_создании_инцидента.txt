h3. Контекст и проблематика.
При создании инцидента на Аналитическом портале ГАСУ запрос в СВПО формируется из общих настроек интеграции и текста обращения. Инициатор и получатель услуг берутся из настроек, без сопоставления с пользователем текущей сессии.

----
h3. Цель задачи.
*Требуется:* при регистрации инцидента в СВПО указывать фактического пользователя Аналитического портала как инициатора и получателя услуг, если его учётную запись удалось сопоставить. Если сопоставление невозможно, регистрировать инцидент от технической учётной записи.

----
h3. 1. Требуемое поведение.
При создании инцидента для пользователя, вошедшего через User Service, Аналитический портал использует подтверждённый ID пользователя ГАСУ, связанный с его учётной записью портала. Идентификатор должен относиться именно к пользователю текущей сессии.

Если ID состоит из 12 цифр и начинается с {{1}}, удалить первую цифру и представить оставшиеся 11 цифр в формате {{XXX-XXX-XXX XX}}. Например, {{113599274608}} преобразуется в {{135-992-746 08}}. Полученное значение используется как внешний {{idHolder}} для сопоставления с учётной записью СВПО.

При успешном сопоставлении зарегистрировать инцидент, указав учётную запись фактического пользователя в полях {{clientEmployee}} — инициатор и {{userName}} — получатель услуг. Документация существующей интеграции допускает передачу внешнего {{idHolder}} в обоих полях сотрудника; применимость этого контракта к целевому контуру необходимо проверить.

Если ID ГАСУ отсутствует, не соответствует указанному формату либо учётную запись пользователя в СВПО сопоставить не удалось, зарегистрировать инцидент с инициатором и получателем услуг из настроенной технической учётной записи. Использование технической учётной записи не должно менять общие настройки интеграции или влиять на другие обращения.

Если невозможность сопоставления выясняется из ответа на запрос регистрации, отправить обращение от технической учётной записи только при подтверждении СВПО, что первоначальное обращение не создано. При иных подтверждённых отказах регистрации сообщить пользователю, что инцидент не зарегистрирован.

Об успешной регистрации сообщать только после подтверждения СВПО. Если результат уже отправленного запроса неизвестен, сообщить об этом пользователю; не объявлять регистрацию успешной и не создавать повторное обращение автоматически при переходе на техническую учётную запись.

Сохранить остальные данные обращения и настройки интеграции, включая передачу предусмотренных настройками дополнительных параметров {{totalValue}}.

----
h3. 2. Зависимости.
* Для индивидуального сопоставления необходима поставка авторизации через User Service с доступностью подтверждённого ID ГАСУ для текущего пользователя.
* Для проверки регистрации необходимы тестовый контур СВПО, доступ и тестовые учётные записи. На этом контуре необходимо проверить передачу {{idHolder}} в поля сотрудника и способ определения результата сопоставления и регистрации; контракт контура ещё не подтверждён.
* Аналитический признак в {{totalValue}} прорабатывается отдельной задачей.

h3. 4. Критерии приёмки (AC).
AC.1 — *Регистрация от фактического пользователя:*
* *Дано:* пользователь вошёл через User Service; подтверждённый ID ГАСУ — {{113599274608}}; в СВПО есть сопоставляемая учётная запись с {{idHolder}} {{135-992-746 08}}.
* *Когда:* пользователь создаёт инцидент и СВПО подтверждает регистрацию.
* *Тогда:* инцидент зарегистрирован с этим пользователем как инициатором и получателем услуг; пользователю показан подтверждённый результат регистрации.

AC.2 — *Отсутствующий или неподходящий ID:*
* *Дано:* у пользователя отсутствует подтверждённый ID ГАСУ либо ID не состоит из 12 цифр с начальной {{1}}; техническая учётная запись настроена.
* *Когда:* пользователь создаёт инцидент и СВПО подтверждает регистрацию.
* *Тогда:* инцидент зарегистрирован с технической учётной записью как инициатором и получателем услуг; неподходящий ID не преобразуется в {{idHolder}}.

AC.3 — *Пользователь не сопоставлен:*
* *Дано:* ID ГАСУ соответствует формату; техническая учётная запись настроена.
* *Когда:* сопоставить пользователя не удалось до отправки либо СВПО отказала в регистрации из-за невозможности сопоставления и подтвердила, что обращение не создано.
* *Тогда:* портал отправляет обращение от технической учётной записи; при подтверждённой регистрации в СВПО создан один инцидент с этой учётной записью как инициатором и получателем услуг.

AC.4 — *Изоляция обращений и сохранение данных:*
* *Дано:* два пользователя создают обращения; один сопоставлен с учётной записью СВПО, для другого применяется техническая учётная запись; в настройках заданы дополнительные параметры {{totalValue}}.
* *Когда:* оба инцидента зарегистрированы.
* *Тогда:* каждое обращение содержит соответствующего ему инициатора и получателя, текст и настроенные дополнительные параметры; общие настройки интеграции не изменены.

AC.5 — *Ошибка и неизвестный результат:*
* *Дано:* пользователь отправляет инцидент в СВПО.
* *Когда:* получен подтверждённый отказ регистрации, не связанный с сопоставлением пользователя, либо результат отправленного запроса неизвестен.
* *Тогда:* при подтверждённом отказе пользователь видит, что инцидент не зарегистрирован; при неизвестном результате пользователь уведомлён о неопределённости. Успешная регистрация не показывается без подтверждения; при неизвестном результате автоматическое повторное создание со сменой пользователя не выполняется.
