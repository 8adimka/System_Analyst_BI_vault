h3. Контекст и проблематика.

В основном портале обязательные фильтры используются для предотвращения отправки крупных аналитических запросов без необходимых ограничений данных.

Обязательный фильтр может быть глобальным и воздействовать на несколько визуализаций либо локальным и воздействовать только на визуализацию, для которой он настроен.

Действующая проверка применяет незаполненный обязательный фильтр как общее условие блокировки и не отправляет запросы всех визуализаций, даже тех, на которые этот фильтр не воздействует. В результате часть дашборда остаётся без данных, хотя обязательные условия фильтрации к ним не применяются.

Необходимо перейти к индивидуальной проверке каждой визуализации и селективно блокировать аналитический запрос только визуализаций для которых есть хотя бы один незаполненный воздействующий на неё обязательный фильтр.

----

h3. Цель задачи.

*Требуется:*
# Для каждой визуализации независимо определять набор обязательных фильтров, воздействующих на неё через полку «Фильтры».
# Не отправлять аналитический запрос конкретной визуализации, если не заполнен хотя бы один обязательный фильтр, воздействующий на неё.
# Разрешать аналитический запрос визуализации, если все *воздействующие на неё* обязательные фильтры заполнены либо отсутствуют (при условии выполнения остальных действующих правил отправки запросов).
# Использовать тип фильтра «Локальный»/«Глобальный» для определения его области воздействия и источника состояния.
# Не блокировать и не откладывать запросы других визуализаций из-за незаполненного обязательного фильтра, который на них не воздействует.
# Сохранить существующие правила определения заполненности фильтров, применения выбранных значений, работы режима «Первичное отображение данных после нажатия кнопки „Применить“», формирования payload и аналитических запросов.

_Пользовательская история:_

Как пользователь дашборда, я хочу получать данные всех визуализаций, для которых обязательные условия фильтрации выполнены, чтобы незаполненный обязательный фильтр блокировал только зависящие от него запросы.

----

h3. 1. Термины и правила определения области воздействия.

***
h4. 1.1. Ключевые понятия:

* *Проверяемая визуализация* — визуализация, для которой определяется возможность отправки аналитического запроса.
* *Экземпляр фильтра* — настроенный (глобальный либо локальный) фильтр с собственными признаками, значением и состоянием заполненности.
* *Воздействующий фильтр визуализации* — экземпляр фильтра, который, по актуальной конфигурации, связан с проверяемой визуализацией и должен применяться к её аналитическим данным при наличии выбранного значения.
* *Воздействующий обязательный фильтр* — воздействующий фильтр, для которого включён признак «Обязательный фильтр».
* *Локальный фильтр* — экземпляр фильтра, для которого включён признак «Локальный», воздействует только на визуализацию, для которой он настроен.
* *Глобальный фильтр* — экземпляр *фильтра дашборда*, который, в зависимости от конфигурации, может не воздействовать ни на одну визуализацию, либо воздействовать на одну или несколько визуализаций.
* *Заполненность фильтра* — результат проверки заполненности соответствующего экземпляра фильтра.
* *Блокировка визуализации* — запрет отправки её аналитического запроса из-за незаполненного воздействующего обязательного фильтра. Блокировка одной визуализации не должна приводить к блокировке дашборда или других визуализаций.

***
h4. 1.2. Привязка полей визуализации.

* Одна визуализация всегда работает только с одним набором данных.
* Область воздействия обязательных фильтров определяется по полям, размещённым на полке «Фильтры» проверяемой визуализации.
* Связь глобального фильтра с полем проверяемой визуализации определяется по техническому значению {{name}}. Принадлежность локального фильтра определяется конфигурацией метаданных визуализации-владельца (совпадение {{name}} с полем другой визуализации не распространяет на неё локальный экземпляр). {{name}} используется для сопоставления поля, но не для идентификации экземпляра фильтра или объединения его состояния.
* {{alias}}, отображаемый заголовок и позиция поля на полке не участвуют в сопоставлении. Изменение {{alias}} при неизменном {{name}} не изменяет область воздействия фильтра.
* Совпадение только {{alias}} или отображаемого заголовка при разных значениях {{name}} не создаёт связь.
* Наборы данных глобального фильтра и визуализации могут различаться. Если глобальный фильтр настроен по полю {{name = "A"}} набора данных {{D1}}, на полке «Фильтры» визуализации находится поле {{name = "A"}} другого набора данных {{D2}} (не локальный фильтр), глобальный фильтр воздействует на данную визуализацию. Значение берётся из глобального фильтра дашборда и применяется к полю {{A}} визуализации по существующей логике.
* Наличие совпадающего поля на полках «Строки/Категории», «Столбцы», «Значения», «Детализация» или «Дополнительные» не создаёт условие обязательности для визуализации, если поле отсутствует на её полке «Фильтры».

***
h4. 1.3. Область воздействия локальных и глобальных экземпляров.

Для определения набора воздействующих фильтров проверяемой визуализации применяются следующие правила:

|| Конфигурация относительно проверяемой визуализации || Воздействие на визуализацию ||
| Локальный фильтр настроен для проверяемой визуализации | Воздействует только на данную визуализацию |
| Глобальный фильтр имеет то же {{name}}, что и поле на полке «Фильтры» визуализации, и для этого поля в визуализации не используется локальный фильтр | Воздействует на визуализацию |
| Поле глобального фильтра отсутствует на полке «Фильтры» визуализации | Не воздействует и не участвует в проверке |
| Для поля визуализации используется локальный фильтр, а на дашборде имеется глобальный фильтр с тем же {{name}} | На данную визуализацию воздействует локальный экземпляр; глобальный экземпляр к её данным не применяется |
| Воздействующий фильтр не является обязательным | Применяется к фильтрации по существующим правилам, но не участвует в проверке допуска по обязательности |

Дополнительно должны выполняться следующие правила:

* Один глобальный фильтр может воздействовать на несколько визуализаций, но решение по каждой из них принимается независимо. При проверке конкретной визуализации не требуется учитывать, на какие другие визуализации воздействует тот же фильтр.
* Один и тот же {{name}} может использоваться локальными фильтрами нескольких визуализаций. Каждый такой локальный фильтр является самостоятельным экземпляром и относится только к своей визуализации.
* Глобальный и локальные фильтры с одинаковым {{name}} имеют независимые значения и состояния заполненности.
* Заполнение глобального фильтра не считается заполнением локального фильтра с тем же {{name}}.
* Заполнение локального фильтра одной визуализации не считается заполнением глобального фильтра либо локальных фильтров других визуализаций.
* Наличие локального фильтра по полю с определённым {{name}} исключает воздействие глобального фильтра с тем же {{name}} на данную визуализацию. Значение глобального фильтра не должно добавляться в фильтрацию её данных вместо локального значения или вместе с ним.

***
h4. 1.4. Иерархические фильтры и повторное представление условия.

* Признак обязательности может быть установлен на любом уровне иерархического фильтра.
* Обязательный уровень учитывается для визуализации, если поле этого уровня по {{name}} воздействует на неё через полку «Фильтры».
* Для проверки используется существующее состояние заполненности обязательного уровня.
* При заполнении общего иерархического фильтра существующий механизм обеспечивает заполнение обязательного уровня; обязательное условие этого уровня считается выполненным.
* Если пользователь заполняет отдельно только обязательный уровень, не заполняя остальные необязательные уровни иерархии, обязательное условие также считается выполненным.
* Если обязательными назначены несколько воздействующих уровней иерархии, для разрешения запроса должны быть заполнены все такие уровни.
* Общий иерархический контрол и отдельный самостоятельный фильтр считаются представлениями одного обязательного условия только тогда, когда по существующей модели они читают и изменяют единое состояние одного уровня. В этом случае повторное представление не создаёт дополнительного независимого требования или блокировки.
* Совпадение {{name}} само по себе не является основанием считать элементы управления представлениями одного состояния.
* Разные локальные экземпляры и глобальный экземпляр с одинаковым {{name}} не являются повторными представлениями одного условия и не должны объединять состояния заполненности.

----

h3. 2. Описание текущего поведения.

При наличии незаполненного обязательного фильтра проверка может блокировать аналитические запросы на уровне всего дашборда, включая запросы визуализаций, на которые данный фильтр не воздействует.

Из-за общей блокировки:

* незаполненный локальный обязательный фильтр одной визуализации может препятствовать загрузке других визуализаций;
* незаполненный глобальный обязательный фильтр может препятствовать загрузке визуализации, если соответствующее поле отсутствует на её полке «Фильтры»;
* одно пользовательское действие может отменять отправку всех аналитических запросов вместо исключения только запросов визуализаций с невыполненными условиями обязательной фильтрации.

----

h3. 3. Описание целевого поведения.

***
h4. 3.1. Формирование набора воздействующих обязательных фильтров.

Для каждой визуализации перед отправкой её аналитического запроса необходимо сформировать единый набор воздействующих на неё обязательных экземпляров фильтров.

Набор воздействующих обязательных фильтров формируется по актуальной конфигурации полки «Фильтры» визуализации с учётом:

# сопоставления полей по {{name}};
# области воздействия локального или глобального экземпляра;
# исключения глобального экземпляра с тем же {{name}}, если для поля проверяемой визуализации используется локальный экземпляр;
# обязательности фильтра (уровня иерархии);
# существующей идентичности состояния одного логического условия при его отображении в нескольких элементах управления; совпадение {{name}} само по себе такую идентичность не создаёт.

После формирования набора воздействующих обязательных фильтров типы «Локальный» и «Глобальный» не создают разные ветви проверки. Для каждого элемента фильтра из набора применяется проверка заполненности для принятия решения об отправке запроса визуализацией.
* не требуется строить или анализировать обратную связь «фильтр → все визуализации». Достаточно определить, входит ли конкретный обязательный экземпляр в набор воздействующих обязательных фильтров данной визуализации.

***
h4. 3.2. Единое правило допуска аналитического запроса.

Аналитический запрос визуализации разрешён с точки зрения обязательных фильтров только в одном из случаев:

* набор воздействующих обязательных фильтров данной визуализации пуст;
* все элементы Набора заполнены.

Т.е. все условия обязательной фильтрации выполнены.

Если хотя бы один элемент Набора не заполнен, аналитический запрос визуализации не должен отправляться.

|| Состояние воздействующих обязательных фильтров || Решение по запросу ||
| Воздействующие обязательные фильтры отсутствуют | Запрос разрешён по условию обязательности |
| Все воздействующие обязательные фильтры заполнены | Запрос разрешён по условию обязательности |
| Не заполнен хотя бы один воздействующий обязательный фильтр | Запрос {{V}} заблокирован |

Разрешение по условию обязательности не отменяет остальные действующие проверки и ограничения отправки запросов.

***
h4. 3.3. Несколько и смешанные обязательные фильтры.

* Если на визуализацию воздействуют несколько обязательных фильтров, для разрешения её запроса должны быть заполнены все обязательные условия фильтрации.
* Заполнение только части воздействующих обязательных фильтров не снимает блокировку.
* В единый набор одной визуализации могут входить локальные и глобальные обязательные фильтры с разными {{name}}.
* Заполнение воздействующего обязательного фильтра не отменяет незаполненность другого воздействующего обязательного фильтра этой же визуализации.
* Совпадение {{name}} не должно приводить к двойному учёту глобального и локального экземпляров: если для данного поля визуализации используется локальный экземпляр, глобальный экземпляр с тем же {{name}} не включается.
* Независимая проверка визуализации не зависит от количества других визуализаций, на которые воздействует тот же глобальный обязательный фильтр.

***
h4. 3.4. Режим без кнопки «Применить».

* При первичной загрузке дашборда возможность отправки аналитического запроса определяется отдельно для каждой визуализации.
* Разрешённые визуализации отправляют запросы и отображают результат независимо от наличия незаполненных обязательных фильтров, которые на них не воздействуют.
* Заблокированные визуализации не отправляют аналитические запросы и отображают существующее информационное состояние обязательных фильтров.
* После заполнения последнего незаполненного обязательного фильтра визуализации её запрос отправляется автоматически, если выполнены остальные условия отправки.
* Если после изменения фильтра у визуализации остаётся другое незаполненное обязательное условие, её запрос не отправляется.
* Изменение локального фильтра не должно инициировать запросы или повторную загрузку других визуализаций.
* Изменение глобального фильтра не должно инициировать запросы визуализаций, на которые он не воздействует.

***
h4. 3.5. Режим с кнопкой «Применить».

* Изменение значений фильтров до нажатия кнопки «Применить» не инициирует аналитические запросы.
* При нажатии кнопки «Применить» набор воздействующих обязательных фильтров и заполненность его элементов проверяются отдельно для каждой визуализации.
* Запросы разрешённых визуализаций отправляются с учётом выбранных значений фильтров.
* Запросы заблокированных визуализаций не отправляются.
* Наличие хотя бы одной заблокированной визуализации не должно отменять действие «Применить» для остальных визуализаций.
* Существующее общее уведомление о незаполненных обязательных фильтрах отображается, если при выполнении действия имеется хотя бы один заблокированный аналитический запрос. Уведомление не должно препятствовать отправке разрешённых запросов.

***
h4. 3.6. Очистка значения и изменение конфигурации.

* При очистке ранее заполненного воздействующего обязательного фильтра последующие аналитические запросы соответствующей визуализации блокируются до повторного выполнения всех её обязательных условий.
* Очистка локального фильтра не изменяет состояние допуска других визуализаций.
* Очистка глобального фильтра влияет только на визуализации, к которым данный глобальный экземпляр применяется по актуальной конфигурации.
* После выключения признака «Обязательный фильтр» экземпляр перестаёт участвовать в проверке обязательности, но продолжает применяться к фильтрации по существующим правилам.
* После включения или выключения признака «Локальный» область воздействия экземпляра должна определяться заново по правилам раздела 1.3.
* После добавления, удаления или замены поля на полке «Фильтры» набор воздействующих обязательных фильтров визуализации должен соответствовать актуальной конфигурации.
* Изменение {{alias}} без изменения {{name}} не должно менять набор воздействующих фильтров.
* Обработка уже отправленного запроса, сохранение либо очистка ранее загруженных данных выполняются по существующей логике.

***
h4. 3.7. Отображение состояний и доступность фильтров.

* Информационное состояние о необходимости заполнить обязательный фильтр отображается только в области заблокированной визуализации.
* Разрешённые визуализации отображаются и работают в штатном режиме.
* Маркеры обязательности и заполненности элементов управления фильтрами сохраняются по существующим правилам.
* Незаполненный обязательный фильтр, не воздействующий ни на одну визуализацию, продолжает отображаться незаполненным по существующим правилам, но не блокирует аналитические запросы и сам по себе не создаёт уведомление о заблокированной загрузке.
* Компоненты и служебные запросы, необходимые пользователю для получения доступных значений и заполнения обязательных фильтров, должны оставаться доступными по существующим правилам и не должны блокироваться проверкой аналитического запроса визуализации.
* Состав существующих компонентов-исключений не изменяется. Их структурные и служебные операции выполняются по действующим правилам, а аналитические запросы вложенных визуализаций проверяются индивидуально.
* Если разрешённый аналитический запрос успешно возвращает пустую выборку, визуализация отображает существующее состояние отсутствия данных, а не состояние незаполненного обязательного фильтра.

----

h3. 4. Требования к реализации.

***
h4. 4.1. Интерфейс и конфигурация.

* Поддержать одновременное включение и сохранение признаков «Локальный» и «Обязательный фильтр» как валидную конфигурацию.
* Включение одного из признаков не должно автоматически выключать другой признак.
* Повторное открытие и сохранение отчёта не должно изменять настроенные признаки, значения {{name}} и область локального экземпляра.
* Использовать существующую конфигурацию фильтров и полки «Фильтры».
* Сохранить существующие маркеры обязательности, правила отображения заполненного и незаполненного состояния, а также тексты уведомлений.

***
h4. 4.2. Бэкенд, совместимость и производительность.

* Новые backend-объекты и команды в рамках задачи не вводятся.
* Формат payload, API-контракты, правила формирования фильтрующих предикатов, SQL, WHERE, HAVING и GROUP BY не изменяются.
* Доработка должна выполняться до сетевого вызова и не должна увеличивать количество аналитических запросов по сравнению со штатной загрузкой тех же разрешённых визуализаций.
* Ранее созданные отчёты должны получать новое селективное поведение без миграции метаданных и обязательного повторного сохранения.
* Существующее поведение необязательных фильтров, правила множественного выбора, права доступа и видимость компонентов не изменяются.
* Если для проверки используется кэшированная конфигурация, она должна актуализироваться после изменения отчёта и не должна применяться к другой версии конфигурации.

----

h3. 5. Рамки задачи.

*В рамки задачи входит:*

* формирование для каждой визуализации единого набора воздействующих обязательных фильтров по её полке «Фильтры»;
* сопоставление полей глобального фильтра и визуализации по {{name}}, в том числе между разными наборами данных;
* учёт локальной области экземпляра и исключение влияния локального фильтра на другие визуализации;
* независимость состояний локальных экземпляров разных визуализаций и глобального экземпляра с тем же {{name}};
* применение существующей заполненности обязательных уровней иерархии без дублирования условий по элементам управления;
* индивидуальная блокировка аналитических запросов и частичная отправка разрешённых запросов;
* поддержка режимов с кнопкой «Применить» и без неё;
* сохранение существующих компонентов-исключений и служебных запросов, необходимых для заполнения фильтров.

*В рамки задачи не входит:*

* изменение правил определения заполненности фильтра или обязательного уровня иерархии;
* изменение действующих правил применения значений локальных и глобальных фильтров после допуска запроса;
* добавление новых пользовательских настроек, метаданных или междатасетных связей;
* изменение payload, API-контрактов, backend-команд и SQL-генерации;
* изменение дизайна, текстов и расположения существующих маркеров, уведомлений и информационных состояний;
* изменение состава компонентов-исключений и стратегии загрузки неактивных страниц.

----

h3. 6. Риски и пограничные сценарии:

* *Одинаковый {{name}} в разных наборах данных.* Такое совпадение является действующей привязкой поля глобального фильтра к полю визуализации и должно учитываться независимо от идентификаторов наборов данных.
* *Изменение {{alias}}.* Переименование отображаемого поля не должно разрывать связь при неизменном {{name}}.
* *Совпадение только отображаемого названия.* Одинаковый {{alias}} при разных {{name}} не должен создавать область воздействия.
* *Локальный и глобальный экземпляры с одинаковым {{name}}.* Глобальное значение не должно заполнять локальный фильтр или применяться к визуализации вместо него; локальное значение не должно изменять состояние глобального фильтра.
* *Одинаковые локальные фильтры разных визуализаций.* Совпадение {{name}} и набора данных не должно объединять их значения, заполненность или область воздействия.
* *Несколько обязательных условий.* Заполнение одного из нескольких воздействующих обязательных фильтров не должно преждевременно разрешать запрос.
* *Обязательный уровень иерархии.* Заполнение уровня любым поддерживаемым элементом управления должно выполнить одно логическое условие, а наличие нескольких представлений не должно создавать двойную блокировку.
* *Неполная конфигурация полки «Фильтры».* Обязательный фильтр, поле которого отсутствует на полке «Фильтры» визуализации, не должен неявно распространяться на неё через другие полки.
* *Изменение конфигурации.* После добавления, удаления или замены поля, а также изменения признаков фильтра решение должно приниматься по актуальной конфигурации.
* *Пакетная загрузка.* Один заблокированный запрос не должен отменять разрешённую часть загрузки и не должен попадать в сетевой вызов.
* *Доступность значений фильтра.* Блокировка аналитического запроса не должна блокировать служебный запрос, без которого пользователь не сможет заполнить обязательный фильтр.
* *Пустой результат.* Успешная пустая выборка разрешённого запроса не должна отображаться как блокировка обязательным фильтром.

h3. 7. Критерии приёмки (AC):
*Сокращения*:
* Визуализация - {{V}};
* Набор данных - {{D}}.

*AC.1 — Избирательная первичная загрузка:*

* *Дано:* режим с кнопкой «Применить» выключен; у {{V1}} имеется незаполненный воздействующий обязательный фильтр, а у {{V2}} все воздействующие обязательные фильтры заполнены либо отсутствуют;
* *Когда:* пользователь открывает дашборд;
* *Тогда:* аналитический запрос {{V1}} не отправляется и в её области отображается существующее информационное состояние, а запрос {{V2}} отправляется и результат отображается.

*AC.2 — Единая проверка смешанного набора фильтров:*

* *Дано:* на {{V1}} воздействуют локальный обязательный фильтр {{A}} и глобальный обязательный фильтр {{B}}; {{A}} заполнен, а {{B}} не заполнен;
* *Когда:* система проверяет возможность отправки запроса {{V1}};
* *Тогда:* запрос {{V1}} не отправляется;
* *Когда:* {{B}} заполнен и других незаполненных воздействующих обязательных фильтров нет;
* *Тогда:* аналитический запрос {{V1}} отправляется при выполнении остальных условий.

*AC.3 — Обязательный фильтр отсутствует на полке «Фильтры»:*

* *Дано:* глобальный обязательный фильтр {{A}} не заполнен; поле {{A}} отсутствует на полке «Фильтры» {{V1}}, но может использоваться на другой полке {{V1}};
* *Когда:* система проверяет возможность отправки запроса {{V1}};
* *Тогда:* {{A}} не воздействует на {{V1}} и не блокирует её запрос.

*AC.4 — Независимая проверка области глобального фильтра:*

* *Дано:* глобальный обязательный фильтр {{A}} не заполнен; поле {{A}} находится на полке «Фильтры» {{V1}} и {{V2}}, но отсутствует на этой полке {{V3}}; локальных фильтров {{A}} в этих визуализациях нет;
* *Когда:* возникает событие загрузки трёх визуализаций;
* *Тогда:* запросы {{V1}} и {{V2}} не отправляются, а запрос {{V3}} разрешается при выполнении её остальных обязательных условий; решение для каждой визуализации принимается независимо от количества других визуализаций, на которые воздействует {{A}}.

*AC.5 — Сопоставление по {{name}} между наборами данных:*

* *Дано:* глобальный обязательный фильтр настроен по полю {{name = "A"}} набора данных {{D1}}; визуализация {{V1}} работает с набором данных {{D2}}, и на её полке «Фильтры» находится поле {{name = "A"}}; локального фильтра {{A}} у {{V1}} нет;
* *Когда:* глобальный фильтр не заполнен;
* *Тогда:* аналитический запрос {{V1}} не отправляется;
* *Когда:* глобальный фильтр заполнен и остальные обязательные условия {{V1}} выполнены;
* *Тогда:* запрос {{V1}} разрешается, а значение глобального фильтра применяется к полю {{A}} набора данных {{D2}} по существующей логике.

*AC.6 — Независимость связи от {{alias}}:*

* *Дано:* незаполненный глобальный обязательный фильтр и поле на полке «Фильтры» {{V1}} сопоставлены по {{name = "A"}}; локального фильтра {{A}} у {{V1}} нет, остальные обязательные условия выполнены;
* *Когда:* система проверяет возможность загрузки до изменения {{alias}};
* *Тогда:* аналитический запрос {{V1}} не отправляется;
* *Когда:* аналитик изменяет {{alias}} поля визуализации, не изменяя {{name}}, сохраняет и повторно открывает отчёт;
* *Тогда:* незаполненный фильтр продолжает блокировать запрос {{V1}}, а после заполнения этого фильтра запрос {{V1}} отправляется.

*AC.7 — Совпадение только {{alias}} не создаёт связь:*

* *Дано:* глобальный обязательный фильтр настроен по полю {{name = "A"}}, а на полке «Фильтры» {{V1}} находится поле {{name = "B"}} с таким же {{alias}};
* *Когда:* глобальный фильтр не заполнен;
* *Тогда:* совпадение {{alias}} не создаёт область воздействия и данный фильтр не блокирует запрос {{V1}}.

*AC.8 — Изоляция локального обязательного фильтра:*

* *Дано:* одно и то же поле используется как локальный обязательный фильтр в {{V1}} и {{V2}}; оба локальных экземпляра не заполнены, а остальные обязательные условия визуализаций выполнены;
* *Когда:* пользователь заполняет локальный фильтр только в {{V1}};
* *Тогда:* запрос {{V1}} отправляется, запрос {{V2}} не отправляется; состояние глобальных фильтров с тем же {{name}}, при их наличии, не изменяется.

*AC.9 — Независимость глобального и локального экземпляров с одинаковым {{name}}:*

* *Дано:* у {{V1}} настроен локальный обязательный фильтр {{A}}; на дашборде также имеется глобальный обязательный фильтр {{A}}; на полке «Фильтры» {{V2}} имеется поле {{A}}, но локального фильтра {{A}} у {{V2}} нет; остальные обязательные условия обеих визуализаций выполнены;
* *Когда:* глобальный фильтр заполнен, а локальный фильтр {{V1}} не заполнен;
* *Тогда:* аналитический запрос {{V1}} не отправляется, поскольку глобальное значение не заполняет локальный экземпляр, а запрос {{V2}} разрешается по данному условию;
* *Когда:* локальный фильтр {{V1}} заполнен, а глобальный фильтр {{A}} не заполнен;
* *Тогда:* глобальный фильтр {{A}} не блокирует {{V1}} и не применяется к её данным, запрос {{V1}} отправляется, а запрос {{V2}} не отправляется.

*AC.10 — Заполнение обязательного уровня через иерархический фильтр:*

* *Дано:* уровень «Месяц» иерархического фильтра является обязательным и воздействует на {{V1}}; остальные обязательные условия {{V1}} выполнены;
* *Когда:* пользователь заполняет иерархический фильтр;
* *Тогда:* по существующей логике уровень «Месяц» получает значение, обязательное условие этого уровня считается выполненным и запрос {{V1}} разрешается по условию обязательности.

*AC.11 — Отдельное заполнение обязательного уровня и отсутствие двойной блокировки:*

* *Дано:* обязательный уровень «Месяц», воздействующий на {{V1}}, доступен через общий иерархический контрол и через отдельный самостоятельный фильтр; оба элемента управления по существующей модели читают и изменяют единое состояние этого уровня; остальные обязательные условия {{V1}} выполнены;
* *Когда:* пользователь заполняет только «Месяц» через самостоятельный фильтр, не заполняя иерархический фильтр целиком;
* *Тогда:* существующая проверка определяет обязательный уровень как заполненный, условие учитывается один раз, и запрос {{V1}} отправляется без требования отдельно заполнить второе представление этого же уровня.

*AC.12 — Несколько обязательных условий одной визуализации:*

* *Дано:* на {{V1}} воздействуют обязательные фильтры {{A}} и {{B}}; {{A}} заполнен, а {{B}} не заполнен;
* *Когда:* выполняется проверка допуска;
* *Тогда:* аналитический запрос {{V1}} не отправляется до заполнения {{B}}.

*AC.13 — Автоматическая загрузка после заполнения последнего условия:*

* *Дано:* режим с кнопкой «Применить» выключен; {{V1}} заблокирована единственным незаполненным воздействующим обязательным фильтром;
* *Когда:* пользователь заполняет этот фильтр;
* *Тогда:* запрос {{V1}} отправляется автоматически при выполнении остальных условий, а визуализации, на которые данный экземпляр не воздействует, не перезагружаются только из-за этого действия.

*AC.14 — Частичная отправка по кнопке «Применить»:*

* *Дано:* режим с кнопкой «Применить» включён; у {{V1}} имеется незаполненный воздействующий обязательный фильтр, а у {{V2}} все воздействующие обязательные фильтры заполнены;
* *Когда:* пользователь нажимает кнопку «Применить»;
* *Тогда:* запрос {{V1}} отсутствует в сетевых вызовах и в её области отображается информационное состояние обязательных фильтров, а запрос {{V2}} отправляется и результат отображается.

*AC.15 — Отсутствие запроса до нажатия кнопки «Применить»:*

* *Дано:* режим с кнопкой «Применить» включён, и пользователь заполняет последний незаполненный обязательный фильтр {{V1}};
* *Когда:* кнопка «Применить» ещё не нажата;
* *Тогда:* аналитический запрос {{V1}} не отправляется;
* *Когда:* пользователь нажимает кнопку «Применить»;
* *Тогда:* запрос {{V1}} отправляется при выполнении остальных условий.

*AC.16 — Очистка воздействующего обязательного фильтра:*

* *Дано:* данные {{V1}} и {{V2}} ранее загружены; обязательный фильтр воздействует на {{V1}} и не воздействует на {{V2}};
* *Когда:* пользователь очищает этот фильтр;
* *Тогда:* последующие аналитические запросы {{V1}} блокируются, а состояние допуска {{V2}} не изменяется и её запрос не инициируется только из-за очистки данного фильтра.

*AC.17 — Изменение конфигурации полки «Фильтры»:*

* *Дано:* обязательный фильтр воздействует на {{V1}} через поле на её полке «Фильтры»;
* *Когда:* аналитик удаляет это поле с полки, сохраняет и повторно открывает отчёт;
* *Тогда:* фильтр больше не входит в набор воздействующих обязательных фильтров {{V1}} и не блокирует её запрос; миграция метаданных не требуется.

*AC.18 — Сохранение сочетания признаков:*

* *Дано:* аналитик настраивает фильтр на полке «Фильтры» визуализации;
* *Когда:* он одновременно включает признаки «Локальный» и «Обязательный фильтр», сохраняет и повторно открывает отчёт;
* *Тогда:* оба признака сохранены, фильтр является локальным обязательным экземпляром данной визуализации и не блокирует запросы других визуализаций.

*AC.19 — Доступность фильтра для заполнения:*

* *Дано:* аналитический запрос {{V1}} заблокирован незаполненным воздействующим обязательным фильтром;
* *Когда:* пользователь открывает элемент управления фильтром и запрашивает доступные значения;
* *Тогда:* список доступных значений загружается и остаётся доступным для выбора, а аналитический запрос {{V1}} отсутствует в сетевых вызовах до выполнения обязательных условий.

*AC.20 — Отсутствие заблокированных запросов в пакетной загрузке:*

* *Дано:* одно событие инициирует загрузку нескольких визуализаций, часть из которых заблокирована, а часть разрешена;
* *Когда:* формируется набор сетевых вызовов;
* *Тогда:* аналитические запросы заблокированных визуализаций отсутствуют, а разрешённые запросы отправляются.

*AC.21 — Пустой результат разрешённого запроса:*

* *Дано:* все воздействующие обязательные фильтры {{V1}} заполнены и её запрос разрешён;
* *Когда:* бэкенд успешно возвращает пустую выборку;
* *Тогда:* {{V1}} отображает существующее состояние отсутствия данных, а не информационное состояние незаполненного обязательного фильтра.

*AC.22 — Обратная совместимость:*

* *Дано:* открыт ранее созданный отчёт с обязательными фильтрами;
* *Когда:* пользователь загружает отчёт без повторного сохранения;
* *Тогда:* область воздействия определяется по существующей конфигурации полок «Фильтры» и значениям {{name}}, новые поля метаданных и миграция отчёта не требуются.
