h3. Контекст и проблематика.

В основном портале глобальный обязательный фильтр используется для предотвращения отправки аналитических запросов до задания необходимого ограничения данных.

Действующая проверка учитывает незаполненный обязательный фильтр на уровне всего дашборда: при его наличии блокируются запросы всех обычных визуализаций, в том числе тех, в фильтрации данных которых этот фильтр не участвует.

В результате визуализации, не связанные с незаполненным обязательным фильтром, остаются без данных, хотя их запросы не требуют задания данного фильтра и могут быть безопасно выполнены.

Необходимо определять область воздействия каждого обязательного фильтра по конфигурации полки «Фильтры» отображаемых визуализаций и блокировать только запросы реально затронутых визуализаций.

----

h3. Цель задачи.

*Требуется:*

# Для каждой визуализации определять набор связанных с ней обязательных фильтров по полке «Фильтры».
# Для каждой визуализации блокировать аналитический запрос при наличии хотя бы одного незаполненного связанного глобального обязательного фильтра. Результат данной проверки объединять по правилу OR с независимым результатом проверки собственных локальных обязательных фильтров, при их наличии.
# Разрешать загрузку визуализаций, с которыми незаполненные глобальные обязательные фильтры не связаны.
# При одном пользовательском действии независимо разделять визуализации на разрешённые и заблокированные и не отправлять на бэкенд запросы заблокированных визуализаций.
# Сохранить отдельные правила отображения компонентов-исключений («Контейнер с фильтрами», «Иерархический фильтр» и т.д.) и режима «Первичное отображение данных после нажатия кнопки „Применить“».
# Не выполнять запросы к источнику данных для определения связей между фильтрами и визуализациями.

_Пользовательская история:_

Как пользователь дашборда, я хочу видеть данные визуализаций, не зависящих от незаполненного обязательного фильтра, чтобы работать с доступной частью дашборда без выполнения небезопасных неограниченных запросов затронутых визуализаций.

----

h3. 1. Термины и правила определения связи.

h4. 1.1. Ключевые понятия.

* *Глобальный обязательный фильтр* — обязательный фильтр, для которого не включён признак «Локальный».
* *Связанный глобальный обязательный фильтр визуализации* — глобальный обязательный фильтр, поле которого присутствует на полке «Фильтры» данной визуализации и по существующей конфигурации участвует в фильтрации её аналитических данных.
* *Несвязанный глобальный обязательный фильтр* — глобальный обязательный фильтр, поле которого не участвует в фильтрации данных конкретной визуализации.
* *Собственный локальный обязательный фильтр* — локальный обязательный фильтр, настроенный непосредственно для проверяемой визуализации.
* *Заблокированная визуализация* — визуализация, аналитический запрос которой не разрешён из-за незаполненного связанного глобального обязательного фильтра и/или незаполненного собственного локального обязательного фильтра.

***

h4. 1.2. Определение связи глобального фильтра с визуализацией.

Связь необходимо определять по сохранённой конфигурации визуализации до отправки аналитического запроса.

Глобальный обязательный фильтр считается связанным с визуализацией только при выполнении всех условий:

# фильтр настроен как обязательный и не является локальным;
# на полке «Фильтры» визуализации имеется действующая пилюля соответствующего поля;
# существующий механизм сопоставления полей и фильтров применяет значение данного глобального фильтра к аналитическому запросу визуализации.

При определении связи необходимо использовать устойчивую техническую привязку поля, которая уже применяется порталом при формировании фильтрации. Нельзя определять связь только по отображаемому названию, заголовку, alias или позиции поля на полке.

Если портал уже поддерживает явное сопоставление полей между наборами данных для применения одного фильтра, такое сопоставление учитывается по существующим правилам. Новое автоматическое сопоставление полей между наборами данных в рамках задачи не вводится.

Само по себе использование поля на полках «Строки/Категории», «Столбцы», «Значения», «Детализация» или «Дополнительные» не создаёт связь с глобальным обязательным фильтром. В рамках данной задачи область воздействия определяется именно через полку «Фильтры».

Совпадение отображаемых названий разных полей или наборов данных не является основанием для связи.

***

h4. 1.3. Иерархические и синхронизированные фильтры.

* Каждый обязательный уровень иерархического фильтра учитывается по полю этого уровня.
* Визуализация считается связанной с обязательным уровнем иерархии, если соответствующее поле участвует в фильтрации её данных через полку «Фильтры».
* Незаполненный обязательный уровень, поле которого не связано с визуализацией, не блокирует её запрос.
* Если одно логическое поле представлено в нескольких синхронизированных элементах управления фильтром, используется существующее единое состояние заполненности этого поля; дублирование элемента управления не должно создавать дополнительные независимые условия блокировки.
* Правила определения заполненности уровней и синхронизации одинаковых фильтров в рамках задачи не изменяются.

----

h3. 2. Описание текущего поведения.

При наличии хотя бы одного незаполненного глобального обязательного фильтра аналитические запросы обычных визуализаций блокируются на уровне дашборда.

Наличие поля обязательного фильтра на полке «Фильтры» конкретной визуализации при принятии решения не учитывается. Поэтому одинаковое состояние блокировки применяется как к визуализациям, которые реально фильтруются обязательным фильтром, так и к визуализациям, данные которых от него не зависят.

----

h3. 3. Описание целевого поведения.

h4. 3.1. Итоговое условие блокировки.

Для каждой визуализации {{V}} необходимо сформировать:

* набор глобальных обязательных фильтров, связанных с {{V}} через полку «Фильтры»;
* набор собственных локальных обязательных фильтров {{V}}.

Визуализация {{V}} блокируется, если выполняется хотя бы одно условие:

* не заполнен хотя бы один связанный с ней глобальный обязательный фильтр;
* не заполнен хотя бы один её собственный локальный обязательный фильтр.

Иными словами, обязательные условия внутри каждого набора объединяются по правилу: для разрешения запроса должны быть заполнены все применимые к визуализации обязательные фильтры. Наличие одного незаполненного применимого фильтра достаточно для блокировки.

|| Есть незаполненный связанный глобальный обязательный фильтр || Есть незаполненный собственный локальный обязательный фильтр || Состояние аналитического запроса визуализации ||
| Нет | Нет | Запрос разрешён с точки зрения обязательных фильтров. Далее применяются режим кнопки «Применить» и остальные существующие проверки. |
| Да | Нет | Запрос заблокирован связанным глобальным обязательным фильтром. |
| Нет | Да | Запрос заблокирован собственным локальным обязательным фильтром. |
| Да | Да | Запрос заблокирован по обоим условиям. |

Незаполненные глобальные обязательные фильтры, не связанные с {{V}}, при проверке {{V}} не учитываются.

***

h4. 3.2. Несколько фильтров и визуализаций.

* Один глобальный обязательный фильтр может быть связан с несколькими визуализациями. Пока он не заполнен, блокируются все и только те из них, для которых установлена связь.
* С одной визуализацией может быть связано несколько глобальных обязательных фильтров. Запрос разрешается только после заполнения всех связанных обязательных фильтров.
* Наборы связанных фильтров рассчитываются независимо для каждой визуализации.
* Визуализация без связанных глобальных обязательных фильтров не блокируется их незаполненностью в других частях дашборда.
* Незаполненный глобальный обязательный фильтр, не связанный ни с одной визуализацией, не блокирует аналитические запросы дашборда.
* Если поле обязательного фильтра удалено с полки «Фильтры» визуализации, после сохранения конфигурации фильтр перестаёт блокировать эту визуализацию.
* Если поле глобального обязательного фильтра добавлено на полку «Фильтры» визуализации, после сохранения конфигурации его заполненность участвует в допуске запросов этой визуализации.

***

h4. 3.3. Режим без кнопки «Применить».

* При первичной загрузке дашборда для каждой визуализации отдельно определяется возможность отправки аналитического запроса.
* Разрешённые визуализации отправляют запросы и отображают результат, даже если на дашборде остаются незаполненные глобальные обязательные фильтры, с которыми эти визуализации не связаны.
* Заблокированные визуализации не отправляют аналитические запросы и отображают существующее информационное состояние обязательных фильтров.
* После заполнения глобального обязательного фильтра автоматически обновляются связанные с ним визуализации, для которых выполнены все остальные обязательные условия.
* Если после заполнения одного фильтра у визуализации остаётся другой незаполненный связанный глобальный или собственный локальный обязательный фильтр, запрос этой визуализации не отправляется.
* Изменение глобального фильтра не должно само по себе инициировать запросы визуализаций, с которыми он не связан.

***

h4. 3.4. Режим с кнопкой «Применить».

* Изменение значений фильтров до нажатия кнопки «Применить» не инициирует аналитические запросы.
* При нажатии кнопки «Применить» набор обязательных условий проверяется отдельно для каждой визуализации.
* Запросы разрешённых визуализаций отправляются с учётом выбранных значений фильтров.
* Запросы заблокированных визуализаций не отправляются.
* Незаполненный обязательный фильтр одной части дашборда не должен отменять всё действие «Применить» и препятствовать запросам визуализаций, с которыми он не связан.
* Если при нажатии кнопки «Применить» хотя бы одна визуализация заблокирована, отображается существующее общее уведомление о незаполненных обязательных фильтрах. Отображение уведомления не отменяет отправку запросов разрешённых визуализаций.
* Если незаполненный глобальный обязательный фильтр не связан ни с одной визуализацией и других причин блокировки нет, нажатие кнопки «Применить» выполняет все разрешённые запросы и не должно считаться заблокированным из-за данного фильтра.

***

h4. 3.5. Очистка и изменение значений.

* При очистке заполненного глобального обязательного фильтра блокируются новые аналитические запросы только связанных с ним визуализаций.
* Очистка фильтра не переводит несвязанные визуализации в информационное состояние обязательных фильтров и не должна инициировать их повторную загрузку.
* Обработка ответа, отправленного до очистки фильтра, а также очистка либо сохранение ранее загруженных данных выполняются по существующей логике и в рамках задачи не изменяются.
* Если разрешённый запрос успешно вернул пустую выборку, визуализация отображает существующее состояние отсутствия данных, а не сообщение о незаполненном обязательном фильтре.

***

h4. 3.6. Отображение состояний и уведомлений.

* Информационное состояние о необходимости заполнить обязательные фильтры отображается только в областях заблокированных визуализаций.
* Разрешённые визуализации отображаются и работают в штатном режиме.
* Маркеры обязательности и заполненности фильтров сохраняются по существующим правилам независимо от количества связанных визуализаций.
* Незаполненный обязательный фильтр продолжает отображаться как незаполненный, даже если он не связан ни с одной визуализацией; при этом он не блокирует запросы.
* Общее пользовательское уведомление должно соответствовать факту наличия хотя бы одного заблокированного запроса и не должно создавать глобальную блокировку разрешённых визуализаций.

----

h3. 4. Требования к реализации.

h4. 4.1. Фронтенд-часть.

* До инициации загрузки построить для каждой визуализации набор связанных глобальных обязательных фильтров по её сохранённой конфигурации полки «Фильтры».
* Определять связь по существующим техническим идентификаторам и привязкам полей, а не по отображаемым строкам.
* Учитывать признак «Локальный»: локальный фильтр не должен попадать в набор глобальных обязательных фильтров других визуализаций.
* Использовать результат независимой проверки собственных локальных обязательных фильтров как второе условие блокировки, не изменяя в рамках данной задачи правила их области действия и заполненности.
* Пересчитывать набор связей после сохранённого добавления, удаления или замены поля на полке «Фильтры», а также после изменения признаков «Локальный» и «Обязательный фильтр».
* Выполнять проверку до каждого первичного, повторного, фонового или отложенного аналитического запроса визуализации.
* Отображать существующее информационное состояние только для заблокированных визуализаций.
* Не выполнять отдельные сетевые запросы для поиска связей.

***

h4. 4.2. Логика запросов и взаимодействие с бэкендом.

* Аналитический запрос заблокированной визуализации не должен отправляться на бэкенд.
* Разрешение запроса одной визуализации не должно автоматически разрешать запросы других визуализаций.
* Если текущий процесс загрузки формирует общий или пакетный запрос, заблокированные визуализации необходимо исключить из аналитической части пакета; наличие одного заблокированного компонента не должно отменять отправку разрешённой части.
* После допуска запроса выбранные значения глобальных и локальных фильтров передаются по существующей логике.
* Изменение области блокировки не должно изменять смысл фильтрующих предикатов, их объединение в WHERE/HAVING, payload, API-контракты или SQL-генерацию.
* Новые backend-объекты и команды в рамках задачи не вводятся.

***

h4. 4.3. Компоненты-исключения и «Контейнер страниц».

* Существующие компоненты, необходимые для выбора и заполнения фильтров, остаются доступными по действующим правилам. Запросы, без которых пользователь не может получить варианты значений и заполнить фильтр, не должны ошибочно блокироваться как аналитические запросы обычной визуализации.
* Для «Контейнера страниц» сохраняется структурное исключение: оболочка, навигация и структура выбранной страницы отображаются независимо от заполненности обязательных фильтров.
* Дочерние визуализации «Контейнера страниц» проверяются независимо по собственным связанным глобальным и локальным обязательным фильтрам.
* Требование заполнить все обязательные фильтры для конкретной дочерней визуализации означает необходимость заполнить все связанные с ней глобальные обязательные фильтры и все её собственные локальные обязательные фильтры, а не все обязательные фильтры дашборда.
* Если собственный аналитический запрос «Контейнера страниц», в том числе запрос динамических данных для названий вкладок, связан с незаполненным глобальным обязательным фильтром, используются сохранённые статические либо нейтральные служебные подписи, но навигация и доступ к дочерним компонентам сохраняются.
* Разрешение структурного отображения контейнера не наследуется его заблокированными дочерними визуализациями.
* Доработка не должна вводить предварительную загрузку аналитических данных неактивных страниц. При фактической инициализации страницы её компоненты проходят ту же индивидуальную проверку.

***

h4. 4.4. Обратная совместимость и производительность.

* Отчёты без обязательных фильтров работают без изменений.
* Существующие отчёты с обязательными фильтрами получают новое адресное поведение без повторного сохранения и миграции метаданных.
* Правила определения заполненности фильтров, синхронизации одинаковых фильтров, множественного выбора, иерархических фильтров, прав доступа и видимости компонентов не изменяются.
* Состав компонентов-исключений не изменяется.
* Проверка связей выполняется по конфигурации в памяти до сетевого вызова и не создаёт запросы к источникам данных.
* Доработка не должна приводить к пакетной или фоновой отправке запросов заблокированных визуализаций.
* Кэшированная карта связей, если она используется, должна актуализироваться при изменении конфигурации отчёта и не должна применяться к другой версии конфигурации.

----

h3. 5. Рамки задачи.

*В рамки задачи входит:*

* определение связи глобального обязательного фильтра с визуализацией по полке «Фильтры»;
* индивидуальная проверка обязательных условий каждой визуализации;
* частичная отправка разрешённых запросов и блокировка запрещённых;
* объединение результата адресной проверки глобальных обязательных фильтров с результатом независимой проверки собственных локальных обязательных фильтров;
* поддержка режимов с кнопкой «Применить» и без неё;
* сохранение правил компонентов-исключений и вложенных визуализаций.

*В рамки задачи не входит:*

* добавление новой пользовательской настройки связи фильтра с визуализацией;
* анализ полок, отличных от «Фильтры», для определения области воздействия глобального обязательного фильтра;
* автоматическое сопоставление полей по отображаемому имени, alias или типу данных;
* добавление новых междатасетных связей;
* изменение правил определения заполненности обязательного фильтра;
* реализация или изменение правил определения владельца, заполненности и области действия локального обязательного фильтра;
* изменение структуры payload, API-контрактов и SQL-генерации;
* изменение текстов и расположения существующих маркеров, уведомлений и информационных сообщений;
* изменение состава компонентов-исключений и стратегии загрузки неактивных страниц.

----

h3. 6. Риски и пограничные сценарии.

* *Ложная связь по названию.* Одинаковые заголовки разных полей не должны приводить к блокировке несвязанной визуализации.
* *Потеря действующей связи.* Переименование отображаемого заголовка или alias не должно разрывать техническую привязку поля.
* *Неполная конфигурация полки «Фильтры».* Если аналитик не разместил соответствующее поле на полке «Фильтры» визуализации, глобальный обязательный фильтр намеренно не защищает её запрос. Система не должна неявно расширять связь по другим полкам; корректная настройка области фильтрации остаётся ответственностью аналитика.
* *Устаревшая карта связей.* После редактирования полки «Фильтры» решение должно приниматься по актуальной сохранённой конфигурации.
* *Несколько условий.* Заполнение одного из нескольких связанных обязательных фильтров не должно преждевременно разрешать запрос.
* *Пакетная загрузка.* Один заблокированный компонент не должен отменять разрешённые запросы и не должен попасть в пакет.
* *Скрытые страницы.* Индивидуальная проверка не должна приводить к предварительной загрузке неактивных страниц.
* *Невалидная ссылка на поле.* Нельзя восстанавливать связь по отображаемому имени; существующее состояние ошибки конфигурации должно сохраняться без дополнительного аналитического запроса.
* *Смешение причин отсутствия данных.* Пустой успешный результат не должен отображаться как блокировка обязательным фильтром.
* *Разные источники и наборы данных.* Учитываются только существующие технические привязки; совпадение имени поля не создаёт связь.

h3. 7. Критерии приёмки (AC).

*AC.1 — Избирательная первичная загрузка:*

* *Дано:* кнопка «Применить» выключена, глобальный обязательный фильтр {{F}} не заполнен, поле {{F}} находится на полке «Фильтры» визуализации {{V1}} и отсутствует на полке «Фильтры» {{V2}};
* *Когда:* пользователь открывает дашборд;
* *Тогда:* запрос {{V1}} не отправляется и в её области отображается существующее информационное состояние, а запрос {{V2}} отправляется и результат отображается.

*AC.2 — Связь определяется только по полке «Фильтры»:*

* *Дано:* глобальный обязательный фильтр {{F}} не заполнен, его поле используется на полке «Значения» {{V1}}, но отсутствует на полке «Фильтры» {{V1}};
* *Когда:* система проверяет возможность загрузки {{V1}};
* *Тогда:* {{F}} не считается связанным с {{V1}} и не блокирует её запрос.

*AC.3 — Несколько связанных обязательных фильтров:*

* *Дано:* на полке «Фильтры» {{V1}} находятся поля двух глобальных обязательных фильтров {{F1}} и {{F2}}, {{F1}} заполнен, {{F2}} не заполнен;
* *Когда:* возникает событие загрузки {{V1}};
* *Тогда:* запрос {{V1}} не отправляется до заполнения {{F2}}.

*AC.4 — Один фильтр связан с несколькими визуализациями:*

* *Дано:* незаполненный глобальный обязательный фильтр {{F}} связан через полку «Фильтры» с {{V1}} и {{V2}}, но не связан с {{V3}};
* *Когда:* выполняется загрузка дашборда;
* *Тогда:* запросы {{V1}} и {{V2}} блокируются, а запрос {{V3}} разрешается при выполнении её остальных обязательных условий.

*AC.5 — Отсутствие ложной связи по названию:*

* *Дано:* глобальный обязательный фильтр использует поле набора данных {{D1}}, а на полке «Фильтры» визуализации находится поле набора данных {{D2}} с таким же отображаемым названием, но без существующей технической привязки к полю {{D1}};
* *Когда:* глобальный фильтр не заполнен;
* *Тогда:* совпадение названий не создаёт связь и не блокирует визуализацию.

*AC.5.1 — Существующее междатасетное сопоставление:*

* *Дано:* глобальный обязательный фильтр настроен по полю набора данных {{D1}}, на полке «Фильтры» визуализации находится поле набора данных {{D2}}, а существующая техническая привязка портала обеспечивает применение значения данного фильтра к запросу визуализации;
* *Когда:* глобальный обязательный фильтр не заполнен;
* *Тогда:* фильтр считается связанным с визуализацией и блокирует её аналитический запрос.

*AC.5.2 — Обязательный уровень иерархического фильтра:*

* *Дано:* в иерархическом фильтре «Год → Месяц» уровень «Месяц» является незаполненным глобальным обязательным фильтром; поле «Месяц» находится на полке «Фильтры» {{V1}}, а на полке «Фильтры» {{V2}} находится только поле «Год»;
* *Когда:* выполняется загрузка визуализаций;
* *Тогда:* запрос {{V1}} блокируется, а запрос {{V2}} не блокируется незаполненностью уровня «Месяц» при выполнении остальных условий допуска;
* *Когда:* пользователь заполняет уровень «Месяц» через синхронизированный элемент управления;
* *Тогда:* используется существующее единое состояние заполненности уровня, и запрос {{V1}} разрешается по действующей логике.

*AC.6 — Переименование отображаемого поля:*

* *Дано:* глобальный обязательный фильтр технически связан с полем на полке «Фильтры» визуализации;
* *Когда:* аналитик изменяет отображаемое название или alias поля без изменения его технической привязки;
* *Тогда:* связь сохраняется и незаполненный обязательный фильтр продолжает блокировать визуализацию.

*AC.7 — Итоговое условие с локальным обязательным фильтром:*

* *Дано:* все связанные глобальные обязательные фильтры {{V1}} заполнены, но собственный локальный обязательный фильтр {{V1}} не заполнен; у {{V2}} все собственные условия выполнены;
* *Когда:* выполняется загрузка;
* *Тогда:* запрос {{V1}} блокируется, а запрос {{V2}} разрешается.

*AC.8 — Частичное применение:*

* *Дано:* кнопка «Применить» включена, незаполненный глобальный обязательный фильтр связан с {{V1}}, но не связан с {{V2}};
* *Когда:* пользователь нажимает кнопку «Применить»;
* *Тогда:* запрос {{V1}} не отправляется, запрос {{V2}} отправляется; отображается существующее общее уведомление о незаполненных обязательных фильтрах, которое не отменяет разрешённый запрос {{V2}}.

*AC.9 — Отсутствие запроса до нажатия кнопки «Применить»:*

* *Дано:* кнопка «Применить» включена, пользователь заполняет последний связанный глобальный обязательный фильтр {{V1}};
* *Когда:* кнопка «Применить» ещё не нажата;
* *Тогда:* запрос {{V1}} не отправляется;
* *Когда:* пользователь нажимает кнопку «Применить»;
* *Тогда:* запрос {{V1}} отправляется при выполнении её остальных обязательных условий.

*AC.10 — Автоматическая загрузка после заполнения последнего связанного фильтра:*

* *Дано:* кнопка «Применить» выключена, {{V1}} заблокирована единственным незаполненным связанным глобальным обязательным фильтром, а собственные локальные обязательные фильтры {{V1}} заполнены;
* *Когда:* пользователь заполняет глобальный фильтр;
* *Тогда:* запрос {{V1}} отправляется автоматически; несвязанные визуализации не перезагружаются только из-за изменения данного фильтра.

*AC.11 — Очистка заполненного обязательного фильтра:*

* *Дано:* данные {{V1}} и {{V2}} загружены, глобальный обязательный фильтр связан только с {{V1}};
* *Когда:* пользователь очищает этот фильтр;
* *Тогда:* новые запросы {{V1}} блокируются, {{V2}} не переводится в состояние обязательных фильтров и не перезагружается из-за очистки.

*AC.12 — Глобальный обязательный фильтр без связей:*

* *Дано:* на дашборде есть незаполненный глобальный обязательный фильтр, поле которого отсутствует на полках «Фильтры» всех визуализаций;
* *Когда:* дашборд загружается либо пользователь нажимает кнопку «Применить»;
* *Тогда:* данный фильтр не блокирует ни один аналитический запрос и сам по себе не вызывает уведомление о заблокированной загрузке; маркер незаполненного обязательного фильтра сохраняется по существующим правилам.

*AC.13 — Изменение конфигурации полки:*

* *Дано:* глобальный обязательный фильтр {{F}} связан с {{V1}} через её полку «Фильтры»;
* *Когда:* аналитик удаляет соответствующее поле с полки, сохраняет и повторно открывает отчёт;
* *Тогда:* {{F}} больше не блокирует {{V1}}; отдельная миграция метаданных не требуется.

*AC.14 — «Контейнер страниц» и дочерние визуализации:*

* *Дано:* незаполненный глобальный обязательный фильтр связан с одной дочерней визуализацией «Контейнера страниц» и не связан с другой;
* *Когда:* пользователь открывает соответствующую страницу;
* *Тогда:* оболочка и навигация контейнера доступны, запрос связанной дочерней визуализации заблокирован, запрос несвязанной дочерней визуализации разрешён, исключение контейнера не наследуется детьми.

*AC.15 — Динамические данные «Контейнера страниц»:*

* *Дано:* собственный аналитический запрос «Контейнера страниц» для динамических названий вкладок связан с незаполненным глобальным обязательным фильтром;
* *Когда:* пользователь открывает дашборд;
* *Тогда:* аналитический запрос динамических названий не отправляется, используются сохранённые статические либо нейтральные служебные подписи, а оболочка, навигация и доступ к дочерним компонентам сохраняются.

*AC.16 — Отсутствие заблокированных запросов в пакетной загрузке:*

* *Дано:* одно событие инициирует загрузку нескольких визуализаций, часть из которых заблокирована, а часть разрешена;
* *Когда:* формируется набор сетевых вызовов;
* *Тогда:* аналитические запросы заблокированных визуализаций отсутствуют, а разрешённые запросы отправляются.

*AC.17 — Пустой результат разрешённого запроса:*

* *Дано:* все применимые обязательные фильтры визуализации заполнены и запрос разрешён;
* *Когда:* бэкенд успешно возвращает пустую выборку;
* *Тогда:* визуализация отображает существующее состояние отсутствия данных, а не информационное состояние незаполненного обязательного фильтра.

*AC.18 — Обратная совместимость:*

* *Дано:* открыт ранее созданный отчёт с глобальными обязательными фильтрами;
* *Когда:* пользователь загружает отчёт без его повторного сохранения;
* *Тогда:* область блокировки определяется по существующей конфигурации полок «Фильтры», новые поля метаданных и миграция отчёта не требуются.
