h3. Контекст и проблематика.

В основном портале фильтр конкретной визуализации может быть настроен как *локальный* и может быть обозначен *обязательным* для заполнения.

Локальный фильтр по смыслу ограничен визуализацией, на полке «Фильтры» которой он настроен. Однако, действующая проверка обязательных фильтров рассматривает любой обязательный фильтр как *общее* условие для допуска запросов дашборда. Из-за этого незаполненный локальный обязательный фильтр может блокировать запросы других визуализаций, данные которых он не фильтрует.

Необходимо сохранить обязательность такого фильтра для его визуализации-владельца, но исключить его влияние на остальные визуализации дашборда.

----

h3. Цель задачи.

*Требуется:*

# Поддержать одновременное использование признаков «Локальный» и «Обязательный фильтр» как валидную конфигурацию фильтра.
# Жёстко ограничить область действия локального обязательного фильтра одной визуализацией-владельцем без анализа его связей с другими визуализациями.
# Блокировать аналитический запрос визуализации-владельца, пока не заполнены все обязательные фильтры (включая её локальные).
# Не блокировать и не откладывать запросы других визуализаций из-за незаполненного локального обязательного фильтра, который им не принадлежит.
# Не изменять в рамках задачи алгоритм формирования глобального условия допуска. Результат действующей глобальной проверки должен использоваться как независимое условие блокировки визуализации и не должен дублироваться в локальной логике.
# Сохранить независимость проверки обязательных фильтров от режима «Первичное отображение данных после нажатия кнопки „Применить“».

_Пользовательская история:_

Как аналитик, я хочу назначить обязательный фильтр визуализации локальным, чтобы предотвратить запрос данных именно этой визуализации до заполнения локального фильтра и не блокировать остальные визуализации дашборда.

----

h3. 1. Термины и область действия.

* *Визуализация-владелец* — визуализация, на полке «Фильтры» которой настроен соответствующий локальный фильтр.
* *Локальный обязательный фильтр* — фильтр, для которого одновременно включены признаки «Локальный» (для визуализации-владельца) и «Обязательный фильтр».
* *Глобальный обязательный фильтр* — обязательный фильтр, для которого признак «Локальный» не включён.
* *Заполненность фильтра* определяется по уже реализованным правилам для соответствующего типа фильтра. Данная доработка эти правила не изменяет.
* *Блокировка визуализации* в рамках задачи означает запрет отправки её аналитического запроса и отображение существующего информационного состояния обязательных фильтров. Блокировка не должна запрещать структурные и служебные операции компонентов, уже отнесённых к исключениям.

Принадлежность локального обязательного фильтра определяется непосредственно конфигурацией полки «Фильтры» визуализации-владельца. Для ограничения его области действия не требуется искать совпадающие поля или анализировать связи с другими визуализациями.

----

h3. 2. Описание текущего поведения.

При наличии незаполненного обязательного фильтра общая проверка может блокировать аналитические запросы всех обычных визуализаций дашборда.

Если обязательным назначен локальный фильтр одной визуализации, блокировка распространяется за пределы его фактической области действия: другие визуализации не отправляют запросы, хотя данный локальный фильтр не участвует в фильтрации их данных.

Действующий алгоритм глобальной проверки в рамках данной задачи не изменяется: незаполненный глобальный обязательный фильтр продолжает блокировать аналитические запросы обычных визуализаций, в том числе если его поле отсутствует на полке «Фильтры». Локальная проверка должна использовать результат этого алгоритма как внешнее независимое условие, не закрепляя его реализацию внутри локальной логики.

----

h3. 3. Описание целевого поведения.

h4. 3.1. Основное правило.

Для каждой визуализации необходимо независимо проверять заполненность только тех локальных обязательных фильтров, владельцем которых она является.

Аналитический запрос визуализации блокируется по локальному условию, если не заполнен хотя бы один её собственный локальный обязательный фильтр.

Незаполненный локальный обязательный фильтр визуализации:
* блокирует аналитический запрос визуализации-владельца;
* не является условием блокировки любых других визуализаций;
* не должен инициировать вывод информационного сообщения для других визуализаций;
* не должен препятствовать отправке разрешённых запросов других визуализаций.

Итоговое решение по каждой обычной визуализации принимается по следующему правилу:

|| Действующее глобальное условие блокировки визуализации выполнено || У визуализации есть собственный незаполненный локальный обязательный фильтр || Состояние аналитического запроса визуализации ||
| Нет | Нет | Запрос разрешён с точки зрения обязательных фильтров. Далее применяется режим с кнопкой «Применить» или без неё и остальные существующие проверки. |
| Нет | Да | Запрос только этой визуализации заблокирован. Остальные визуализации проверяются независимо. |
| Да | Нет | Запрос заблокирован по результату действующей глобальной проверки. |
| Да | Да | Запрос заблокирован; одновременно не выполнены глобальное и локальное условия допуска. |

***

h4. 3.2. Несколько локальных обязательных фильтров.

* Если у одной визуализации настроено несколько локальных обязательных фильтров, для разрешения её запроса должны быть заполнены все такие фильтры.
* Заполнение только части локальных обязательных фильтров не снимает блокировку визуализации.
* После заполнения последнего незаполненного собственного локального обязательного фильтра визуализация становится доступной для загрузки, если действующая глобальная проверка разрешает её запрос и выполнены остальные условия отправки.
* Локальные обязательные фильтры разных визуализаций проверяются независимо друг от друга.

***

h4. 3.3. Режим без кнопки «Применить».

* При первичной загрузке дашборда аналитические запросы визуализаций необходимо проверять по отдельности.
* Визуализация с незаполненным локальным обязательным фильтром не отправляет запрос и отображает существующее информационное состояние обязательных фильтров.
* Визуализации, у которых нет незаполненных обязательных фильтров, отправляют запросы по существующей логике.
* После заполнения последнего собственного локального обязательного фильтра запрос визуализации-владельца отправляется автоматически, если выполнены остальные условия допуска.
* Изменение локального фильтра одной визуализации не должно само по себе инициировать запросы или повторную загрузку других визуализаций.

***

h4. 3.4. Режим с кнопкой «Применить».

* Изменение значений локальных и глобальных фильтров до нажатия кнопки «Применить» не инициирует аналитические запросы.
* При нажатии кнопки «Применить» условия допуска необходимо проверять отдельно для каждой визуализации.
* Если действующая глобальная проверка разрешает запросы, визуализации без незаполненных собственных локальных обязательных фильтров отправляют их, даже если у другой визуализации собственный локальный обязательный фильтр не заполнен.
* Визуализация с незаполненным собственным локальным обязательным фильтром не отправляет запрос и отображает существующее информационное состояние.
* Результат действующей глобальной проверки применяется независимо: выполненное локальное условие не должно отменять глобальную блокировку.
* При попытке загрузить визуализацию с незаполненным собственным локальным обязательным фильтром существующие маркеры и общее уведомление о незаполненных обязательных фильтрах отображаются по действующим правилам соответствующего режима. Отображение уведомления не должно блокировать разрешённые запросы остальных визуализаций.

***

h4. 3.5. Изменение состояния и конфигурации фильтра.

* При очистке ранее заполненного локального обязательного фильтра его визуализация-владелец снова считается заблокированной до повторного заполнения фильтра.
* Очистка локального обязательного фильтра не изменяет состояние допуска других визуализаций.
* После выключения признака «Обязательный фильтр» локальный фильтр перестаёт участвовать в проверке обязательности.
* После выключения признака «Локальный» у обязательного фильтра он рассматривается как глобальный обязательный фильтр по действующим для глобальных фильтров правилам.
* После удаления фильтра с полки «Фильтры» визуализации он перестаёт считаться её собственным локальным обязательным фильтром.
* Повторное открытие и сохранение отчёта не должно изменять сочетание признаков «Локальный» и «Обязательный фильтр».

----

h3. 4. Требования к реализации.

h4. 4.1. Интерфейс и конфигурация.

* Разрешить одновременное включение и сохранение признаков «Локальный» и «Обязательный фильтр».
* Включение одного из признаков не должно автоматически выключать второй признак.
* Использовать существующие настройки и метаданные фильтра; отдельная пользовательская настройка области действия не требуется.
* Сохранить существующие маркеры обязательности, правила отображения заполненного и незаполненного состояния, ограничения множественного выбора и тексты уведомлений.
* Информационное состояние о незаполненном локальном обязательном фильтре должно отображаться только в области заблокированной визуализации-владельца.

***

h4. 4.2. Проверка допуска и отправка запросов.

* Выполнять проверку собственных локальных обязательных фильтров до формирования и отправки аналитического запроса каждой визуализации.
* Не выполнять отдельный запрос к бэкенду или источнику данных для определения владельца либо области действия локального фильтра.
* Не включать запрос заблокированной визуализации в пакетную, каскадную или фоновую загрузку.
* Если существующий механизм объединяет запросы нескольких визуализаций, незаполненный локальный обязательный фильтр должен исключать только аналитическую часть визуализации-владельца, а не весь пакет разрешённых запросов.
* После разрешения запроса значение локального фильтра передаётся и применяется по существующим правилам.
* Формат payload, API-контракты, SQL-генерация и обработка фильтрующих условий на бэкенде в рамках задачи не изменяются.

***

h4. 4.3. Компоненты-исключения и «Контейнер страниц».

* Действующий перечень компонентов, доступных при незаполненных обязательных фильтрах, не изменяется.
* Запросы, необходимые пользователю для выбора значений фильтров, должны выполняться по существующим правилам компонентов-исключений и не должны блокироваться собственным условием, которое делает заполнение фильтра невозможным.
* Для «Контейнера страниц» сохраняется отдельное правило: оболочка, навигация и структура доступной страницы отображаются независимо от заполненности обязательных фильтров.
* Если локальный обязательный фильтр относится к собственному аналитическому запросу «Контейнера страниц», блокируется только зависящая от данных часть; доступ к навигации и дочерним компонентам сохраняется, для недоступных динамических названий используются сохранённые статические либо нейтральные служебные подписи, а дочерние визуализации проверяются независимо.

***

h4. 4.4. Обратная совместимость и производительность.

* Отчёты без локальных обязательных фильтров должны работать без изменений.
* Ранее созданные отчёты не должны требовать миграции метаданных или повторного сохранения.
* Существующее поведение необязательных локальных фильтров не изменяется.
* Доработка не должна увеличивать количество аналитических запросов по сравнению со штатной загрузкой тех же разрешённых визуализаций.
* Проверка должна выполняться по конфигурации визуализации до сетевого вызова.

----

h3. 5. Рамки задачи.

*В рамки задачи входит:*

* поддержка сочетания признаков «Локальный» и «Обязательный фильтр»;
* определение одной визуализации-владельца локального обязательного фильтра;
* индивидуальная блокировка аналитического запроса визуализации-владельца;
* независимая обработка нескольких визуализаций и нескольких локальных обязательных фильтров;
* поддержка режимов с кнопкой «Применить» и без неё;
* сохранение алгоритма действующей глобальной проверки без его дублирования в локальной логике.

*В рамки задачи не входит:*

* изменение правил заполненности фильтров;
* изменение payload фильтрации, API-контрактов или SQL-генерации;
* добавление новых способов сопоставления полей разных наборов данных;
* изменение текстов, расположения и дизайна существующих маркеров и уведомлений.

----

h3. 6. Риски и пограничные сценарии:

* Несколько локальных обязательных фильтров принадлежат одной визуализации, заполнена только часть из них.
* На дашборде несколько визуализаций, каждая со своим локальным обязательным фильтром.
* Одно и то же поле набора данных используется как локальный фильтр в нескольких визуализациях.
* У визуализации одновременно есть локальные обязательные фильтры, а на дашборде — незаполненный глобальный обязательный фильтр.
* Локальный обязательный фильтр предзаполнен при открытии дашборда.
* Пользователь очищает локальный обязательный фильтр после успешной загрузки данных.
* Аналитик выключает один из признаков либо удаляет фильтр с полки «Фильтры».
* Визуализация находится на активной или неактивной странице «Контейнера страниц».
* Один запрос обслуживает несколько визуализаций либо загрузка выполняется пакетно.
* Разрешённый запрос возвращает пустую выборку: должно отображаться существующее состояние отсутствия данных, а не состояние незаполненного обязательного фильтра.

----

h3. 7. Критерии приёмки (AC):

*AC.1 — Сохранение сочетания признаков:*

* *Дано:* аналитик настраивает фильтр на полке «Фильтры» визуализации;
* *Когда:* он одновременно включает признаки «Локальный» и «Обязательный фильтр», сохраняет и повторно открывает отчёт;
* *Тогда:* оба признака сохранены и активны, фильтр определяется как локальный обязательный фильтр данной визуализации.

*AC.2 — Локальная блокировка без кнопки «Применить»:*

* *Дано:* режим с кнопкой «Применить» выключен, глобальных обязательных фильтров нет, у визуализации {{V1}} не заполнен собственный локальный обязательный фильтр, а у {{V2}} обязательные условия отсутствуют;
* *Когда:* пользователь открывает дашборд;
* *Тогда:* аналитический запрос {{V1}} не отправляется и в её области отображается существующее информационное состояние, при этом запрос {{V2}} отправляется и её данные отображаются.

*AC.3 — Отсутствие связи по совпадающему полю:*

* *Дано:* одно и то же поле набора данных используется в локальных фильтрах визуализаций {{V1}} и {{V2}}, обязательным и незаполненным оно настроено только у {{V1}};
* *Когда:* выполняется загрузка дашборда;
* *Тогда:* незаполненный фильтр блокирует только {{V1}}; совпадение поля не распространяет обязательность на {{V2}}.

*AC.4 — Несколько собственных локальных обязательных фильтров:*

* *Дано:* у визуализации настроены два локальных обязательных фильтра и заполнен только один из них;
* *Когда:* система проверяет возможность отправки запроса;
* *Тогда:* запрос визуализации не отправляется до заполнения второго фильтра.

*AC.5 — Автоматическая загрузка после заполнения последнего локального фильтра:*

* *Дано:* кнопка «Применить» выключена, глобальная блокировка отсутствует, визуализация заблокирована единственным незаполненным собственным локальным обязательным фильтром;
* *Когда:* пользователь заполняет этот фильтр;
* *Тогда:* запрос визуализации-владельца отправляется автоматически, а запросы других визуализаций из-за данного действия не инициируются.

*AC.6 — Независимость локальной и глобальной проверок:*

* *Дано:* у {{V1}} заполнен собственный локальный обязательный фильтр, но действующее глобальное условие допуска определяет {{V1}} как заблокированную;
* *Когда:* система проверяет возможность загрузки {{V1}};
* *Тогда:* аналитический запрос {{V1}} не отправляется; выполнение локального условия не отменяет результат глобальной проверки.

*AC.7 — Частичная отправка по кнопке «Применить»:*

* *Дано:* режим с кнопкой «Применить» включён, глобальные обязательные фильтры отсутствуют либо заполнены, у {{V1}} собственный локальный обязательный фильтр не заполнен, у {{V2}} собственные локальные обязательные фильтры заполнены;
* *Когда:* пользователь нажимает кнопку «Применить»;
* *Тогда:* запрос {{V1}} не отправляется, незаполненный локальный обязательный фильтр отмечается и общее уведомление отображается по действующим правилам, запрос {{V2}} отправляется; уведомление не отменяет разрешённый запрос {{V2}}.

*AC.8 — Отсутствие запросов до нажатия кнопки «Применить»:*

* *Дано:* режим с кнопкой «Применить» включён и пользователь заполняет последний собственный локальный обязательный фильтр визуализации;
* *Когда:* кнопка «Применить» ещё не нажата;
* *Тогда:* аналитические запросы не отправляются; после нажатия кнопки запрос визуализации разрешается при выполнении остальных условий.

*AC.9 — Независимая очистка локального фильтра:*

* *Дано:* данные {{V1}} и {{V2}} ранее загружены, у {{V1}} есть заполненный локальный обязательный фильтр;
* *Когда:* пользователь очищает этот фильтр;
* *Тогда:* новые аналитические запросы {{V1}} блокируются по существующим правилам отображения состояния, а состояние допуска {{V2}} не изменяется.

*AC.10 — Изменение конфигурации:*

* *Дано:* у визуализации настроен локальный обязательный фильтр;
* *Когда:* аналитик выключает признак «Обязательный фильтр» либо удаляет фильтр с полки «Фильтры» и сохраняет отчёт;
* *Тогда:* данный фильтр больше не блокирует запрос визуализации как локальный обязательный фильтр.

*AC.10.1 — Выключение признака «Локальный»:*

* *Дано:* у визуализации настроен незаполненный локальный обязательный фильтр;
* *Когда:* аналитик выключает только признак «Локальный», сохраняет отчёт и открывает его в режиме просмотра;
* *Тогда:* фильтр перестаёт считаться собственным локальным обязательным фильтром визуализации и участвует в проверке как глобальный обязательный фильтр по действующим правилам глобальной проверки.

*AC.10.2 — Доступность локального обязательного фильтра для заполнения:*

* *Дано:* аналитический запрос визуализации заблокирован её незаполненным локальным обязательным фильтром;
* *Когда:* пользователь открывает элемент управления фильтром и запрашивает доступные значения;
* *Тогда:* фильтр отображается и остаётся доступным для заполнения, необходимые для выбора значений запросы выполняются по существующим правилам компонентов-исключений, при этом аналитический запрос визуализации не отправляется до выполнения условий обязательности.

*AC.11 — Сохранение доступности «Контейнера страниц»:*

* *Дано:* собственный аналитический запрос «Контейнера страниц» зависит от незаполненного локального обязательного фильтра;
* *Когда:* пользователь открывает дашборд;
* *Тогда:* зависящий от данных запрос не отправляется, для недоступных динамических названий используются сохранённые статические либо нейтральные служебные подписи, но оболочка контейнера, навигация и доступные дочерние компоненты отображаются по действующим правилам; дочерние визуализации проверяются независимо.

*AC.12 — Отсутствие запроса заблокированной визуализации:*

* *Дано:* у визуализации не заполнен собственный локальный обязательный фильтр;
* *Когда:* дашборд загружается, обновляется либо пользователь нажимает кнопку «Применить»;
* *Тогда:* в сетевых вызовах отсутствует аналитический запрос данной визуализации, при этом разрешённые запросы других визуализаций не удаляются из пакетной или каскадной загрузки.

*AC.13 — Пустой результат разрешённого запроса:*

* *Дано:* все обязательные условия визуализации выполнены и её аналитический запрос разрешён;
* *Когда:* бэкенд успешно возвращает пустую выборку;
* *Тогда:* визуализация отображает существующее состояние отсутствия данных, а не сообщение о незаполненном обязательном фильтре.

*AC.14 — Обратная совместимость:*

* *Дано:* открыт ранее созданный отчёт без локальных обязательных фильтров;
* *Когда:* пользователь загружает данные и взаимодействует с локальными необязательными фильтрами;
* *Тогда:* отчёт работает по существующей логике без изменения конфигурации или миграции метаданных.
