h3. Контекст и проблематика.

В основном портале реализован механизм обязательных фильтров: пока на дашборде не заполнены все обязательные фильтры, запросы к данным визуализаций блокируются. При этом компоненты, необходимые для заполнения фильтров, остаются доступными пользователю.

Визуализация «Контейнер страниц» может содержать страницы/вкладки с другими визуализациями, в том числе с обязательными фильтрами. Сейчас при наличии незаполненного обязательного фильтра блокируется загрузка самого «Контейнера страниц»: вместо его страниц и вложенных компонентов отображается сообщение о необходимости заполнить обязательные фильтры.

Если незаполненный обязательный фильтр расположен внутри «Контейнера страниц», возникает взаимная блокировка: для доступа к фильтру требуется отобразить контейнер, но контейнер не отображается до заполнения этого фильтра.

----

h3. Цель задачи.

*Требуется:*

# Отображать оболочку «Контейнера страниц», его навигацию и структуру активной страницы независимо от заполненности обязательных фильтров.
# Для каждого компонента активной страницы отдельно определять отображаемое состояние и возможность отправки запроса данных с учётом заполненности всех обязательных фильтров и принадлежности типа компонента к действующему перечню исключений.
# Применять данное правило на каждом уровне вложенности, не передавая исключение родительского «Контейнера страниц» обычным дочерним визуализациям.
# Не допускать отправку на бэкенд запросов данных от заблокированных дочерних визуализаций.
# Сохранить действующую независимую логику обязательных фильтров и кнопки «Применить».

_Пользовательская история:_

Как пользователь дашборда, я хочу открывать страницы «Контейнера страниц» и иметь доступ к расположенным в них обязательным фильтрам, чтобы получить данные после выполнения всех обязательных условий фильтрации.

----

h3. 1. Описание поведения.

h4. Шаги воспроизведения.

# Добавить на дашборд визуализацию «Контейнер страниц».
# Разместить внутри одной из страниц контейнера фильтр и настроить его как обязательный.
# Оставить обязательный фильтр незаполненным.
# Открыть дашборд в режиме просмотра.

*Фактический результат:*

* запрос, необходимый для загрузки «Контейнера страниц», блокируется общей проверкой обязательных фильтров;
* структура контейнера, страницы/вкладки и вложенные компоненты не отображаются;
* вместо всего контейнера отображается информационное сообщение о необходимости заполнить обязательные фильтры;
* пользователь не может открыть и заполнить обязательный фильтр, расположенный внутри контейнера.

*Ожидаемый результат:*

* «Контейнер страниц» и его навигация доступны пользователю;
* обязательные фильтры внутри доступных страниц отображаются и остаются интерактивными;
* для каждой вложенной визуализации отдельно определяется возможность отображения и отправки запроса к данным;
* обычные визуализации не отправляют запросы к данным, пока не заполнены все обязательные фильтры;
* исключение родительского контейнера не распространяется автоматически на его дочерние визуализации.

*Отчёт для воспроизведения:* [https://test315.modusbi.ru/analytic/report/42]

h3. 2. Описание целевого поведения.

h4. 2.1. Разделение структурной отрисовки и запросов данных.

В рамках данной задачи необходимо различать:

* *структурную отрисовку* — отображение оболочки «Контейнера страниц», заголовков и элементов переключения страниц, компоновки активной страницы и состояний расположенных на ней компонентов;
* *запрос данных обычной визуализации* — обращение к набору данных для формирования и отображения результата конкретной диаграммы, таблицы или иной визуализации;
* *запрос компонента-исключения* — запрос, необходимый для работы компонента, который уже допускается действующим механизмом при незаполненных обязательных фильтрах.

Разрешение структурной отрисовки «Контейнера страниц» не является разрешением на отправку запросов данных его дочерних компонентов.

***
h4. 2.2. Основное правило принятия решений.

Состояние обязательных фильтров определяется для дашборда в целом по уже реализованным правилам. Место размещения фильтра — включая страницу «Контейнера страниц» — не изменяет его признак обязательности и заполненности.

Для каждого компонента отображаемой страницы решение принимается отдельно:

|| Все обязательные фильтры заполнены || Тип компонента || Отображение || Запрос данных ||
| Нет | «Контейнер страниц» | Оболочка, навигация и содержимое активной страницы отображаются; для каждого дочернего компонента выполняется отдельная проверка | Разрешается чтение конфигурации контейнера (состав страниц, навигация, компоновка). Запросы к наборам данных не разрешаются самим исключением контейнера; каждый дочерний компонент проверяется отдельно |
| Нет | Компонент из действующего перечня исключений | Отображается и остаётся интерактивным по действующим для его типа правилам | Сохраняется действующее поведение данного типа компонента |
| Нет | Обычная визуализация | Отображается в действующем состоянии ожидания заполнения обязательных фильтров; данные не отображаются | Запрос данных блокируется и не отправляется на бэкенд |
| Да | Любой компонент | Применяется действующее поведение компонента | Применяется действующая логика отправки запросов с учётом наличия кнопки «Применить» |

Компонент считается исключением только в том случае, если его собственный тип входит в действующий перечень исключений. Нахождение внутри «Контейнера страниц» не изменяет тип дочернего компонента и не освобождает его от проверки.

***
h4. 2.3. Рекурсивная обработка вложенных контейнеров.

# «Контейнер страниц» отображается независимо от состояния обязательных фильтров.
# При отрисовке активной страницы каждый дочерний компонент обрабатывается отдельно.
# Если дочерний компонент является «Контейнером страниц», его оболочка и навигация также отображаются, после чего то же правило применяется рекурсивно к его дочерним компонентам.
# Если дочерний компонент входит в действующий перечень исключений — он отображается по действующим правилам своего типа.
# Если дочерний компонент не входит в перечень исключений и существует хотя бы один незаполненный обязательный фильтр — запрос данных этого компонента блокируется.
# Разрешение отображения родительского контейнера не наследуется его потомками и не действует на всё поддерево.

Правило применяется одинаково на всей глубине вложенности, поддерживаемой текущей конфигурацией дашборда.

***
h4. 2.4. Активные и неактивные страницы.

* Заголовки страниц и элементы навигации «Контейнера страниц» доступны при незаполненных обязательных фильтрах.
* Пользователь может перейти на любую страницу (в том числе, содержащую незаполненный обязательный фильтр, и заполнить его).
* Переключение страницы само по себе не разрешает запросы данных обычных визуализаций при наличии незаполненных обязательных фильтров.
* Если обязательные фильтры находятся на разных страницах, пользователь может последовательно заполнить их, перемещаясь между страницами.
* Доработка не изменяет действующую стратегию загрузки неактивных страниц. Предварительная загрузка данных визуализаций неактивных страниц не вводится. Чтение структурной конфигурации страниц для общей проверки обязательных фильтров допускается.

***
h4. 2.5. Взаимодействие с кнопкой «Применить».

* *Без кнопки «Применить»:* после заполнения последнего незаполненного обязательного фильтра запросы к данным разрешённых визуализаций отправляются автоматически по действующей логике. Визуализации неактивных страниц загружаются по действующей стратегии при их открытии.
* *С кнопкой «Применить»:* заполнение обязательных фильтров само по себе не инициирует запросы данных. Нажатие кнопки при наличии незаполненного обязательного фильтра не отправляет запросы; при этом «Контейнер страниц» и доступ к его страницам сохраняются. Запросы данных обычных визуализаций разрешаются только после нажатия кнопки «Применить» при условии заполненности всех обязательных фильтров.

***
h4. 2.6. Состояния интерфейса.

* При наличии незаполненных обязательных фильтров «Контейнер страниц» не заменяется целиком сообщением о необходимости их заполнить.
* Обязательные фильтры и другие компоненты-исключения внутри контейнера отображаются и сохраняют интерактивность с действующими маркерами заполненности.
* Обычная вложенная визуализация с заблокированным запросом отображается в том же состоянии, что аналогичная визуализация на корневом уровне дашборда:
** без кнопки «Применить» — _Данные отобразятся после заполнения обязательных фильтров_;
** с кнопкой «Применить» — _Данные отобразятся после заполнения обязательных фильтров и нажатия кнопки «Применить»_.
* Для заблокированных визуализаций не отображаются моковые данные и не показывается индикатор загрузки. Индикатор загрузки отображается только после отправки разрешённого запроса и на время его выполнения.
* Успешный запрос с пустой выборкой не является состоянием незаполненных обязательных фильтров: если запрос был разрешён, отправлен и вернул пустой результат — отображается действующее состояние отсутствия данных.

h3. 3. Требования к реализации.

h4. 3.1. Фронтенд-часть.

* Добавить «Контейнер страниц» в действующий механизм определения компонентов, отображаемых при незаполненных обязательных фильтрах.
* Не прекращать обработку дерева компонентов после допуска «Контейнера страниц» к структурной отрисовке.
* Выполнять проверку отдельно для каждого дочернего компонента при первичной отрисовке, переключении страниц, изменении состояния обязательных фильтров и повторной отрисовке.
* Не передавать дочерним компонентам признак исключения родительского «Контейнера страниц».
* Для обычных заблокированных визуализаций использовать существующий компонент состояния ожидания заполнения обязательных фильтров.
* Сохранить действующую загрузку значений и интерактивность фильтров, расположенных внутри «Контейнера страниц».
* Новая пользовательская настройка управления исключением для «Контейнера страниц» не вводится: правило применяется автоматически для всех компонентов данного типа.

***
h4. 3.2. Запросы и взаимодействие с бэкендом.

* При незаполненных обязательных фильтрах разрешается чтение конфигурации «Контейнера страниц»: состава страниц, навигации, компоновки и описаний дочерних компонентов. Это разрешение не распространяется на запросы данных потомков: каждый дочерний компонент проверяется отдельно.
* Запросы к наборам данных от обычных вложенных визуализаций не отправляются на бэкенд при наличии хотя бы одного незаполненного обязательного фильтра.
* Независимо от способа группировки запросов операции получения аналитических данных для заблокированных обычных визуализаций не должны формироваться или выполняться в виде SQL.
* Запросы компонентов из действующего перечня исключений выполняются по существующим для них правилам.
* Семантика обязательных фильтров, структура условий фильтрации и SQL-логика получения данных не изменяются.

***
h4. 3.3. Обратная совместимость.

* Существующие отчёты с «Контейнером страниц» получают целевое поведение без ручной перенастройки или пересохранения.
* Дашборды без обязательных фильтров и дашборды без «Контейнера страниц» работают без изменений.
* Поведение и условия допуска ранее поддержанных типов компонентов-исключений не изменяются.
* Доработка не создаёт запросов к наборам данных обычных визуализаций, которые были бы заблокированы для аналогичной визуализации вне «Контейнера страниц» при том же состоянии обязательных фильтров.

h3. 4. Рамки задачи.

h4. 4.1. В рамках задачи:

* Добавление «Контейнера страниц» в действующий перечень компонентов-исключений.
* Структурная отрисовка «Контейнера страниц» при незаполненных обязательных фильтрах.
* Доступность навигации контейнера и обязательных фильтров на его страницах.
* Индивидуальная и рекурсивная проверка дочерних компонентов на всей поддерживаемой глубине вложенности.
* Сохранение блокировки аналитических запросов обычных визуализаций.
* Поддержка сценариев с кнопкой «Применить» и без неё.
* Сохранение существующих информационных состояний и уведомлений.

***
h4. 4.2. Не входит в рамки задачи:

* Изменение правил настройки, заполненности, визуальных маркеров и ограничений обязательных фильтров.
* Изменение состава или поведения действующих компонентов-исключений, кроме добавления «Контейнера страниц».
* Введение пользовательской настройки, разрешающей или запрещающей отображение «Контейнера страниц» при незаполненных обязательных фильтрах.
* Автоматическое переключение пользователя на страницу с незаполненным обязательным фильтром; добавление новых маркеров на заголовки страниц.
* Изменение текстов действующих уведомлений, логики формирования условий фильтрации, SQL и обработки ошибок запросов.
* Принудительная инициализация и предварительная загрузка данных неактивных страниц.
* Автоматическое разрешение конфигурации, при которой обязательный фильтр размещён на полке самого «Контейнера страниц».

h3. 5. Ограничения и пограничные сценарии.

h4. 5.1. Обязательный фильтр на полках «Контейнера страниц».

«Контейнер страниц» может получать данные (например, для отображения наименований вкладок страниц) через полку «Значения». Если одно поле набора данных используется на полке «Значения» и размещёно на полке «Фильтры», то поведение визуализации не меняется даже если данные фильтр является обязательным к заполнению. Поведение динамически-именуемых вкладок страниц не зависит от обязательности такого фильтра и корректное разрешение таких ситуаций является ответственностью аналитика.

При незаполненном обязательном фильтре целевое поведение должно быть таким:
* контейнер отображается;
* страницы можно переключать;
* обязательные фильтры внутри страниц доступны;
* обычные вложенные визуализации не отправляют запросы;
* динамические названия вкладок, требующие заблокированного запроса, временно недоступны;
вместо них могут использоваться сохранённые статические названия либо нейтральные служебные подписи вроде «Страница 1», «Страница 2»;
* после заполнения всех обязательных фильтров и, при необходимости, нажатия «Применить» выполняется разрешённый запрос и динамические названия обновляются.

*Важно:* служебное название страницы — это техническая подпись, позволяющая сохранить доступ к навигации.

h4. 5.2. Пограничные сценарии:

* Обязательный фильтр расположен на активной странице «Контейнера страниц».
* Обязательный фильтр расположен на неактивной странице; пользователь переходит на неё и заполняет фильтр.
* Обязательные фильтры расположены на разных страницах одного или нескольких вложенных контейнеров.
* Обязательный фильтр расположен вне «Контейнера страниц», а обычные визуализации — внутри него.
* На одной странице одновременно расположены компоненты-исключения и обычные визуализации.
* Один «Контейнер страниц» вложен в другой на одном или нескольких поддерживаемых уровнях.
* Пользователь переключает страницы при незаполненных обязательных фильтрах.
* Все обязательные фильтры предзаполнены при открытии дашборда.
* Пользователь очищает обязательный фильтр после ранее выполненной загрузки данных.
* Разрешённый запрос выполнен и вернул пустую выборку.
* Разрешённый запрос завершился ошибкой.
* В отчёте отсутствуют обязательные фильтры.
* Страница контейнера пуста либо содержит только компоненты-исключения.

h3. 7. Критерии приёмки (AC):

*AC 1 — Доступность «Контейнера страниц» и обязательного фильтра на активной странице:*
* *Дано:* на активной странице «Контейнера страниц» расположены незаполненный обязательный фильтр и обычная визуализация; кнопка «Применить» не используется;
* *Когда:* пользователь открывает дашборд;
* *Тогда:* «Контейнер страниц», его навигация и обязательный фильтр отображаются; фильтр доступен для взаимодействия; контейнер не заменяется сообщением об обязательных фильтрах; запрос данных обычной визуализации не отправляется; внутри неё отображается сообщение «Данные отобразятся после заполнения обязательных фильтров».

*AC 1.1 — Доступность при обязательном фильтре вне «Контейнера страниц»:*
* *Дано:* незаполненный обязательный фильтр расположен вне «Контейнера страниц», а на активной странице контейнера расположена обычная визуализация;
* *Когда:* пользователь открывает дашборд;
* *Тогда:* «Контейнер страниц», его навигация и активная страница отображаются; запрос данных вложенной обычной визуализации не отправляется; визуализация отображается в состоянии ожидания заполнения обязательных фильтров.

*AC 2 — Рекурсивная обработка вложенного «Контейнера страниц»:*
* *Дано:* внешний «Контейнер страниц» содержит вложенный «Контейнер страниц»; во вложенном контейнере расположены «Контейнер с фильтрами» с незаполненным обязательным фильтром и обычная визуализация;
* *Когда:* пользователь открывает дашборд и переходит к странице вложенного контейнера;
* *Тогда:* оболочка и навигация обоих контейнеров, «Контейнер с фильтрами» и обязательный фильтр отображаются и доступны; запрос данных обычной визуализации заблокирован; исключение родительского и вложенного контейнеров не передаётся обычной визуализации.

*AC 3 — Переход к обязательному фильтру на другой странице:*
* *Дано:* незаполненный обязательный фильтр расположен на неактивной странице «Контейнера страниц»;
* *Когда:* пользователь переключается на страницу с обязательным фильтром;
* *Тогда:* переключение выполняется; фильтр отображается и доступен для заполнения; переключение страницы не инициирует запросы данных обычных визуализаций на открываемой или ставшей неактивной странице.

*AC 4 — Обязательные фильтры на нескольких страницах:*
* *Дано:* незаполненные обязательные фильтры расположены на разных страницах одного «Контейнера страниц»; кнопка «Применить» не используется;
* *Когда:* пользователь последовательно открывает страницы и заполняет фильтры;
* *Тогда:* ранее выбранные значения сохраняются при переключении страниц; до заполнения последнего обязательного фильтра запросы данных обычных визуализаций не отправляются; после заполнения последнего фильтра автоматически загружаются только визуализации, подлежащие загрузке по действующей стратегии.

*AC 5 — Автоматическая загрузка после заполнения последнего обязательного фильтра (без кнопки «Применить»):*
* *Дано:* кнопка «Применить» не используется; все обязательные фильтры, кроме одного фильтра внутри «Контейнера страниц», заполнены;
* *Когда:* пользователь заполняет последний обязательный фильтр;
* *Тогда:* система автоматически отправляет запросы разрешённых визуализаций по действующей стратегии загрузки страниц; принудительная загрузка неактивных страниц не производится.

*AC 6 — Блокировка при незаполненных фильтрах с кнопкой «Применить»:*
* *Дано:* используется кнопка «Применить»; внутри «Контейнера страниц» остаётся незаполненный обязательный фильтр;
* *Когда:* пользователь нажимает кнопку «Применить»;
* *Тогда:* запросы данных обычных визуализаций не отправляются; «Контейнер страниц», его страницы и расположенные в них фильтры остаются доступными; отображаются действующие уведомления и маркеры незаполненных обязательных фильтров.

*AC 6.1 — Успешная загрузка с кнопкой «Применить»:*
* *Дано:* используется кнопка «Применить»; все обязательные фильтры заполнены;
* *Когда:* пользователь нажимает кнопку «Применить»;
* *Тогда:* система отправляет разрешённые запросы данных и отображает результаты во вложенных визуализациях по действующим правилам.

*AC 7 — Пустой результат разрешённого запроса:*
* *Дано:* все обязательные фильтры заполнены; запрос данных вложенной визуализации разрешён и отправлен;
* *Когда:* бэкенд возвращает успешный ответ с пустой выборкой;
* *Тогда:* визуализация отображает действующее состояние отсутствия данных; сообщение об обязательных фильтрах не отображается.

*AC 8 — Отсутствие запросов данных от заблокированных потомков:*
* *Дано:* при открытии страницы «Контейнера страниц» присутствуют обычные визуализации и компоненты-исключения; не все обязательные фильтры заполнены;
* *Когда:* формируются запросы для отображения страницы;
* *Тогда:* на бэкенд не отправляются операции получения данных заблокированных обычных визуализаций и для них не формируется SQL; запросы компонентов-исключений выполняются по действующим правилам.

*AC 9 — Учёт обязательного фильтра на неактивной странице:*
* *Дано:* незаполненный обязательный фильтр расположен на неактивной странице «Контейнера страниц»; на исходной активной странице расположена обычная визуализация;
* *Когда:* пользователь открывает дашборд, не переходя на страницу с обязательным фильтром;
* *Тогда:* «Контейнер страниц», его навигация и активная страница отображаются; запрос данных обычной визуализации не отправляется; визуализация находится в состоянии ожидания заполнения обязательных фильтров.

*AC 10 — Очистка обязательного фильтра после загрузки данных:*
* *Дано:* кнопка «Применить» не используется; все обязательные фильтры были заполнены и данные вложенных визуализаций загружены;
* *Когда:* пользователь очищает один из обязательных фильтров;
* *Тогда:* новый запрос данных вложенных обычных визуализаций не отправляется; их состояние изменяется по тем же правилам, что для аналогичных визуализаций вне «Контейнера страниц»; оболочка, навигация и страницы контейнера остаются доступными.

*AC 11 — Отсутствие регрессии без обязательных фильтров:*
* *Дано:* дашборд с «Контейнером страниц» не содержит обязательных фильтров;
* *Когда:* пользователь открывает дашборд и переключает страницы;
* *Тогда:* контейнер, страницы, дочерние компоненты и запросы данных работают по действующим правилам; дополнительных блокировок не возникает.

*AC 12 — Отсутствие регрессии на дашборде без «Контейнера страниц»:*
* *Дано:* дашборд не содержит «Контейнер страниц», но содержит незаполненный обязательный фильтр и обычные визуализации;
* *Когда:* пользователь открывает дашборд и заполняет обязательные фильтры;
* *Тогда:* поведение визуализаций, уведомления и маркеры обязательных фильтров не изменяются по сравнению с текущим.
