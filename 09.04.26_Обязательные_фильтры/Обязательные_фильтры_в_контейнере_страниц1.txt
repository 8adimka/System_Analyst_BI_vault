h3. Контекст и проблематика.

В основном портале реализован механизм обязательных фильтров: пока на дашборде не заполнены все обязательные фильтры, запросы к данным визуализаций блокируются. При этом компоненты, необходимые для заполнения фильтров, остаются доступными пользователю.

Визуализация «Контейнер страниц» может содержать страницы/вкладки с другими визуализациями, в том числе с обязательными фильтрами. Сейчас при наличии незаполненного обязательного фильтра блокируется загрузка самого «Контейнера страниц»: вместо его страниц и вложенных компонентов отображается сообщение о необходимости заполнить обязательные фильтры.

Если незаполненный обязательный фильтр расположен внутри «Контейнера страниц», возникает взаимная блокировка: для доступа к фильтру требуется отобразить контейнер, но контейнер не отображается до заполнения этого фильтра.

----

h3. Цель задачи.

*Требуется:*

# Отображать оболочку «Контейнера страниц», его навигацию и структуру активной страницы независимо от заполненности обязательных фильтров.
# Для каждого компонента активной страницы отдельно определять отображаемое состояние и возможность отправки запроса данных с учётом заполненности всех обязательных фильтров и принадлежности типа компонента к действующему перечню исключений.
# Применять данное правило на каждом уровне вложенности, не передавая исключение родительского «Контейнера страниц» обычным дочерним визуализациям.
# Не допускать отправку на бэкенд запросов данных от заблокированных дочерних визуализаций.
# Сохранить действующую независимую логику обязательных фильтров и кнопки «Применить».

_Пользовательская история:_

Как пользователь дашборда, я хочу открывать страницы «Контейнера страниц» и иметь доступ к расположенным в них обязательным фильтрам, чтобы получить данные после выполнения всех обязательных условий фильтрации.

----

h3. 1. Описание поведения.

h4. Шаги воспроизведения.

# Добавить на дашборд визуализацию «Контейнер страниц».
# Разместить внутри одной из страниц контейнера фильтр и настроить его как обязательный.
# Оставить обязательный фильтр незаполненным.
# Открыть дашборд в режиме просмотра.

*Фактический результат:*

* запрос, необходимый для загрузки «Контейнера страниц», блокируется общей проверкой обязательных фильтров;
* структура контейнера, страницы/вкладки и вложенные компоненты не отображаются;
* вместо всего контейнера отображается информационное сообщение о необходимости заполнить обязательные фильтры;
* пользователь не может открыть и заполнить обязательный фильтр, расположенный внутри контейнера.

*Ожидаемый результат:*

* «Контейнер страниц» и его навигация доступны пользователю;
* обязательные фильтры внутри доступных страниц отображаются и остаются интерактивными;
* для каждой вложенной визуализации отдельно определяется возможность отображения и отправки запроса к данным;
* обычные визуализации не отправляют запросы к данным, пока не заполнены все обязательные фильтры;
* исключение родительского контейнера не распространяется автоматически на его дочерние визуализации.

*Отчёт для воспроизведения:* [https://test315.modusbi.ru/analytic/report/42]

----

h3. 2. Описание целевого поведения.

h4. 2.1. Основное правило.

Состояние обязательных фильтров определяется для дашборда по уже реализованным правилам. Место размещения фильтра — «Контейнер с фильтрами», «Иерархический фильтр» или размещение данных компонентов на странице «Контейнера страниц» — не изменяет признак его обязательности и заполненности.

Для каждого компонента дашборда, включая каждый дочерний компонент «Контейнера страниц», решение принимается независимо:

|| Все обязательные фильтры заполнены || Компонент относится к исключениям || Целевое поведение ||
| Нет | Да | Компонент отображается и остаётся доступным по существующим для его типа правилам. Если компонент содержит другие компоненты, каждый дочерний компонент проходит такую же отдельную проверку. |
| Нет | Нет | Запрос к данным компонента не отправляется. В области визуализации отображается существующее информационное состояние, предусмотренное для незаполненных обязательных фильтров. |
| Да | Не имеет значения | Ограничение обязательных фильтров снято. Далее действует существующая логика загрузки компонента, в том числе отдельное условие кнопки «Применить». |

Для «Контейнера страниц» необходимо:

* отображать контейнер, его страницы/вкладки и навигацию;
* не заменять весь контейнер общим информационным сообщением о незаполненных обязательных фильтрах;
* отображать содержимое выбранной страницы с индивидуальной обработкой каждого дочернего компонента;
* отображать и сохранять работоспособность дочерних компонентов-исключений, включая компоненты, через которые пользователь может заполнять фильтры;
* не отправлять запросы к данным обычных дочерних визуализаций;
* отображать существующее информационное сообщение внутри области каждой заблокированной обычной визуализации.

***
h4. 2.2. Рекурсивная обработка вложенных контейнеров.

* Если дочерний компонент является «Контейнером страниц», он также отображается независимо от заполненности обязательных фильтров.
* После отображения вложенного «Контейнера страниц» правило из п. 2.2 применяется отдельно к каждому его дочернему компоненту.
* Проверка применяется на любом уровне вложенности, который поддерживается текущей моделью дашборда.
* Разрешение на отображение контейнера действует только для самого контейнера и не наследуется расположенными внутри него обычными визуализациями.
* При переключении страницы/вкладки компоненты выбранной страницы проходят ту же проверку. Переключение страницы при незаполненных обязательных фильтрах не должно инициировать запросы к данным обычных визуализаций.

***
h4. 2.4. Взаимодействие с кнопкой «Применить».

* *Без кнопки «Применить»:* после заполнения последнего незаполненного обязательного фильтра запросы к данным обычных визуализаций выполняются автоматически по существующей логике.
* *С кнопкой «Применить»:* заполнение всех обязательных фильтров само по себе не инициирует запросы к данным. Запросы выполняются после нажатия кнопки «Применить».
* Нажатие кнопки «Применить» при наличии хотя бы одного незаполненного обязательного фильтра по-прежнему не отправляет запросы к данным.
* Если пользователь повторно очищает обязательный фильтр, дочерние компоненты «Контейнера страниц» переходят в те же состояния, что и аналогичные компоненты верхнего уровня дашборда. Существующие правила очистки либо сохранения ранее загруженных данных в рамках задачи не изменяются.
* Состояние блокировки определяется до отправки запроса к данным и не зависит от результата запроса. Если разрешённый запрос выполнен и вернул пустую выборку, визуализация должна отображать существующее состояние отсутствия данных, а не сообщение о необходимости заполнить обязательные фильтры.

***
h4. 2.5. Активные и неактивные страницы.

* Заголовки страниц и элементы навигации «Контейнера страниц» доступны при незаполненных обязательных фильтрах.
* Пользователь может перейти на любую страницу (в том числе, содержащую незаполненный обязательный фильтр, и заполнить его).
* Переключение страницы само по себе не разрешает запросы данных обычных визуализаций при наличии незаполненных обязательных фильтров.
* Если обязательные фильтры находятся на разных страницах, пользователь может последовательно заполнить их, перемещаясь между страницами.
* Доработка не изменяет действующую стратегию загрузки неактивных страниц. Предварительная загрузка данных визуализаций неактивных страниц не вводится. Чтение структурной конфигурации страниц для общей проверки обязательных фильтров допускается.

----

h3. 3. Требования к реализации.

h4. 3.1. Фронтенд-часть.

* Добавить «Контейнер страниц» в действующий механизм определения компонентов, отображаемых при незаполненных обязательных фильтрах.
* Не применять к «Контейнеру страниц» блокировку, которая заменяет весь компонент информационным сообщением о незаполненных обязательных фильтрах.
* Обеспечить структурную отрисовку контейнера и доступность переключения его страниц/вкладок при любом состоянии обязательных фильтров.
* При формировании содержимого выбранной страницы выполнять проверку допуска отдельно для каждого дочернего компонента.
* Для обычной дочерней визуализации при незаполненных обязательных фильтрах:
** не инициировать запрос к данным;
** сохранить место компонента в структуре страницы;
** отобразить существующее информационное состояние для заблокированного запроса.
* Для дочернего компонента-исключения при незаполненных обязательных фильтрах сохранить существующее для его типа отображение и поведение.
* Для вложенного «Контейнера страниц» повторять ту же обработку рекурсивно.
* Сохранять выбранные значения фильтров при переключении между страницами/вкладками в соответствии с текущей логикой состояния дашборда. Пользователь должен иметь возможность последовательно заполнить обязательные фильтры, расположенные на разных страницах.
* Сохранить текущие визуальные маркеры обязательности, состояния заполненности фильтров и логику пользовательских уведомлений.

***
h4. 3.2. Логика запросов и взаимодействие с бэкендом.

* Проверка обязательных фильтров должна блокировать запросы к аналитическим данным обычных визуализаций, но не должна препятствовать операциям, необходимым исключительно для получения структуры и конфигурации «Контейнера страниц», его страниц и навигации.
* Существующие запросы, необходимые для работы фильтров и других уже поддерживаемых компонентов-исключений, должны выполняться по текущим правилам.
* Разрешение операции, необходимой для отображения «Контейнера страниц», не должно автоматически разрешать, объединять или инициировать запросы к данным его дочерних обычных визуализаций.
* Если текущий процесс загрузки контейнера одновременно инициирует получение структуры и аналитических данных дочерних визуализаций, необходимо обеспечить независимую проверку и блокировку аналитической части для каждого дочернего компонента.
* При незаполненных обязательных фильтрах не допускается пакетная, каскадная или фоновая загрузка аналитических данных обычных дочерних визуализаций на любой поддерживаемой глубине вложенности.
* Структурная отрисовка и рекурсивная обработка «Контейнера страниц» не должны создавать дополнительные запросы к аналитическим данным конкретных дочерних визуализаций по сравнению с существующим поведением такой же визуализации верхнего уровня при одинаковом состоянии фильтров и одинаковом пользовательском действии.
* Формирование payload фильтрации, логика SQL и обработка значений обязательных фильтров на бэкенде в рамках задачи не изменяются.

***
h4. 3.3. Режим с кнопкой «Применить».

* Логика обязательных фильтров и режим «Первичное отображение данных после нажатия кнопки „Применить“» не меняется и они остаются независимыми условиями отправки запросов.

***
h4. 3.4. Производительность и обратная совместимость.

* Сохранить существующую стратегию инициализации страниц «Контейнера страниц». Доработка не должна включать принудительную предварительную загрузку аналитических данных всех неактивных страниц.
* При ленивой загрузке страницы её дочерние компоненты должны проходить проверку обязательных фильтров до отправки запросов к данным.
* Отчёты без обязательных фильтров должны работать без изменений.
* Существующее поведение визуализаций верхнего уровня и текущих компонентов-исключений должно сохраниться.
* Ранее созданные отчёты с «Контейнером страниц» не должны требовать повторного сохранения, изменения конфигурации или миграции метаданных.
* Настройки обязательности фильтров, правила определения их заполненности, маркировка, синхронизация одинаковых фильтров, ограничения множественного выбора, права доступа и видимость страниц в рамках задачи не изменяются.

----

h3. 4. Рамки задачи.

*В рамки задачи входит:*

* отображение «Контейнера страниц» при незаполненных обязательных фильтрах;
* доступ к обязательным фильтрам на любой доступной пользователю странице контейнера;
* индивидуальная и рекурсивная проверка дочерних компонентов;
* сохранение блокировки аналитических запросов обычных визуализаций;
* поддержка сценариев с кнопкой «Применить» и без неё;
* сохранение существующих информационных состояний и уведомлений.

*В рамки задачи не входит:*

* изменение способа назначения фильтра обязательным;
* изменение правил определения заполненности обязательного фильтра;
* пересмотр состава ранее реализованных компонентов-исключений, кроме добавления «Контейнера страниц»;
* изменение текстов и расположения существующих уведомлений;
* изменение payload фильтрации, SQL-генерации или бизнес-логики получения аналитических данных;
* предварительная загрузка аналитических данных всех страниц контейнера.

h3. 5. Риски и пограничные сценарии.

h4. 5.1. Обязательный фильтр на полке «Фильтры» в «Контейнере страниц».

«Контейнер страниц» может получать данные (например, для отображения наименований вкладок страниц) через полку «Значения». Если одно поле набора данных используется на полке «Значения» и размещёно на полке «Фильтры», то поведение визуализации не меняется даже если данный фильтр является обязательным к заполнению. Корректное разрешение таких ситуаций является ответственностью аналитика.

При незаполненном обязательном фильтре целевое поведение должно быть таким:
* контейнер отображается;
* страницы можно переключать;
* «контейнер с фильтрами» и другие исключительные визуализации внутри страниц отображаются и доступны для заполнения;
* обычные вложенные визуализации не отображаются (текущее поведение) и не отправляют запросы;
* динамические названия вкладок, в случае блокировки запроса, временно недоступны;
вместо них могут использоваться сохранённые статические названия либо нейтральные служебные подписи вроде «Страница 1», «Страница 2»;
* после заполнения всех обязательных фильтров (и, при необходимости, нажатия «Применить») выполняется разрешённый запрос и динамические названия обновляются.

*Важно:* служебное название страницы — это техническая подпись, позволяющая сохранить доступ к навигации.

***
h4. 5.2. Риски.

* *Наследование исключения дочерними компонентами.* Если разрешение для «Контейнера страниц» распространить на всю вложенную ветку, обычные визуализации смогут отправить тяжёлые запросы до заполнения обязательных фильтров.
* *Блокировка до обработки содержимого.* Если проверка по-прежнему будет завершаться на уровне родительского контейнера, расположенные внутри обязательные фильтры останутся недоступными.
* *Смешение структурных и аналитических запросов.* Если разрешённая загрузка структуры контейнера одновременно запустит получение данных дочерних визуализаций, защита от неограниченных запросов будет нарушена.
* *Лишние запросы и потеря состояния.* Повторный рендеринг и переключение страниц могут привести к дублированию запросов либо сбросу ранее выбранных значений фильтров.
* *Предварительная загрузка скрытых страниц.* Инициализация всех страниц после добавления исключения может увеличить нагрузку и отправить запросы, которых не было в текущем сценарии.
* *Смешение причин отсутствия данных.* Пустой результат выполненного запроса не должен ошибочно переводить визуализацию в состояние незаполненных обязательных фильтров.

***
h4. 5.3. Пограничные сценарии

* Обязательный фильтр расположен на активной странице «Контейнера страниц».
* Обязательный фильтр расположен на неактивной странице; пользователь открывает эту страницу и заполняет фильтр.
* Несколько обязательных фильтров расположены на разных страницах одного или нескольких контейнеров.
* Обязательный фильтр расположен вне «Контейнера страниц», а обычные визуализации — внутри него.
* На одной странице одновременно расположены компоненты-исключения и обычные визуализации.
* Один «Контейнер страниц» вложен в другой на одном или нескольких поддерживаемых уровнях.
* Пользователь переключает страницы при незаполненных обязательных фильтрах.
* Все обязательные фильтры предзаполнены при открытии дашборда.
* Пользователь очищает обязательный фильтр после ранее выполненной загрузки данных.
* После заполнения всех обязательных фильтров запрос возвращает пустую выборку.
* В отчёте отсутствуют обязательные фильтры.
* Страница контейнера пуста либо содержит только компоненты-исключения.

h3. 7. Критерии приёмки (AC):

*AC.1 — Доступность обязательного фильтра на активной странице:*

* *Дано:* на активной странице «Контейнера страниц» расположены незаполненный обязательный фильтр и обычная визуализация;
* *Когда:* пользователь открывает дашборд;
* *Тогда:* «Контейнер страниц», его навигация и обязательный фильтр отображаются, фильтр доступен для заполнения, запрос к данным обычной визуализации не отправляется, а в её области отображается существующее информационное сообщение о необходимости заполнить обязательные фильтры.

*AC.2 — Исключение не наследуется дочерними визуализациями:*

* *Дано:* обязательный фильтр вне «Контейнера страниц» не заполнен, а внутри контейнера расположено несколько обычных визуализаций;
* *Когда:* контейнер и выбранная страница отображаются;
* *Тогда:* разрешение на отображение «Контейнера страниц» не разрешает запросы к данным его дочерних обычных визуализаций; для каждой из них запрос заблокирован независимо.

*AC.3 — Доступ к обязательному фильтру на другой странице:*

* *Дано:* незаполненный обязательный фильтр расположен на неактивной странице «Контейнера страниц»;
* *Когда:* пользователь открывает дашборд и переключается на страницу с обязательным фильтром;
* *Тогда:* навигация контейнера доступна, страница открывается, обязательный фильтр отображается и доступен для заполнения; переключение страницы не инициирует запросы к данным обычных визуализаций при наличии незаполненных обязательных фильтров.

*AC.4 — Обязательные фильтры на нескольких страницах:*

* *Дано:* обязательные фильтры расположены на разных страницах одного «Контейнера страниц»;
* *Когда:* пользователь последовательно открывает страницы и заполняет фильтры;
* *Тогда:* ранее выбранные значения сохраняются при переключении страниц, и пользователь может заполнить все обязательные фильтры.

*AC.5 — Смешанное содержимое страницы:*

* *Дано:* обязательный фильтр не заполнен, а выбранная страница содержит существующий компонент-исключение, например «Контейнер с фильтрами» или «Иерархический фильтр», и обычную визуализацию;
* *Когда:* страница отображается;
* *Тогда:* компонент-исключение отображается и работает по существующим правилам, а обычная визуализация не отправляет запрос к данным и показывает существующее информационное состояние.

*AC.6 — Вложенный «Контейнер страниц»:*

* *Дано:* один «Контейнер страниц» вложен в другой, внутри вложенного контейнера расположены обязательный фильтр и обычная визуализация;
* *Когда:* обязательный фильтр не заполнен и пользователь открывает соответствующие страницы обоих контейнеров;
* *Тогда:* оба контейнера и их навигация отображаются, обязательный фильтр доступен, а запрос к данным обычной визуализации заблокирован; правило применяется независимо на каждом уровне вложенности.

*AC.7 — Загрузка данных без кнопки «Применить»:*

* *Дано:* режим «Первичное отображение данных после нажатия кнопки „Применить“» выключен, обычные дочерние визуализации заблокированы незаполненными обязательными фильтрами;
* *Когда:* пользователь заполняет последний обязательный фильтр;
* *Тогда:* по существующей логике автоматически отправляются запросы к данным разрешённых визуализаций, включая визуализации внутри «Контейнера страниц» (в соответствии с текущей стратегией инициализации страниц), и отображаются полученные результаты.

*AC.8 — Отсутствие запроса до нажатия кнопки «Применить»:*

* *Дано:* режим «Первичное отображение данных после нажатия кнопки „Применить“» включён, а все обязательные фильтры внутри и/или вне «Контейнера страниц» заполнены;
* *Когда:* пользователь заполняет последний обязательный фильтр, но ещё не нажимает кнопку «Применить»;
* *Тогда:* запросы к данным обычных визуализаций не отправляются, при этом «Контейнер страниц» и расположенные в нём компоненты-исключения остаются доступными для пользователя.

*AC.8.1 — Загрузка данных после нажатия кнопки «Применить»:*

* *Дано:* режим «Первичное отображение данных после нажатия кнопки „Применить“» включён и все обязательные фильтры заполнены;
* *Когда:* пользователь нажимает кнопку «Применить»;
* *Тогда:* запросы к данным разрешённых визуализаций отправляются по существующей логике, включая визуализации внутри «Контейнера страниц»(в соответствии с текущей стратегией инициализации страниц).

*AC.9 — Отсутствие запросов при незаполненных обязательных фильтрах:*

* *Дано:* режим с кнопкой «Применить» включён и хотя бы один обязательный фильтр внутри «Контейнера страниц» не заполнен;
* *Когда:* пользователь нажимает кнопку «Применить»;
* *Тогда:* запросы к данным обычных визуализаций не отправляются, а существующие маркеры и уведомления обязательных фильтров отображаются по текущим правилам; сам «Контейнер страниц» и доступ к его фильтрам сохраняются.

*AC.10 — Пустой результат разрешённого запроса:*

* *Дано:* все обязательные фильтры заполнены и запрос к данным визуализации внутри «Контейнера страниц» разрешён;
* *Когда:* бэкенд успешно возвращает пустую выборку;
* *Тогда:* визуализация отображает существующее состояние отсутствия данных; сообщение о необходимости заполнить обязательные фильтры не отображается.

*AC.11 — Отсутствие лишних запросов:*

* *Дано:* на дашборде есть незаполненный обязательный фильтр, а «Контейнер страниц» содержит обычные визуализации, в том числе на неактивных страницах и во вложенных контейнерах;
* *Когда:* дашборд загружается, пользователь переключает страницы и взаимодействует с доступными компонентами-исключениями;
* *Тогда:* в сетевых вызовах отсутствуют запросы к аналитическим данным от заблокированных обычных визуализаций; отображение контейнеров не вызывает пакетную, каскадную или фоновую загрузку их аналитических данных.

*AC.12 — Обратная совместимость:*

* *Дано:* открыт ранее созданный отчёт с «Контейнером страниц», в котором отсутствуют незаполненные обязательные фильтры;
* *Когда:* пользователь открывает контейнер и переключает его страницы;
* *Тогда:* контейнер и его дочерние визуализации работают по существующей логике без повторного сохранения отчёта или изменения его конфигурации.
