h3. Контекст и проблематика.

В аналитическом портале переменные могут использоваться в выражениях набора данных, вычисляемых полях и в иных местах, влияющих на результат визуализации. Пользователь выбирает значения переменных в отчёте, после чего данные визуализации пересчитываются с учётом этих значений.

Сейчас при экспорте данных в XLSX пользователь получает результат, уже рассчитанный с учётом выбранных переменных, но в выгруженном файле не видит, какие значения переменных были применены. Из-за этого экспортированный файл сложнее интерпретировать вне портала.

Дополнительно переменная может задаваться через фильтр/контрол в контейнере фильтров, где используется настройка "Значения по другому полю": в вычисление передаётся техническое значение переменной, а пользователь видит человекочитаемое значение. При экспорте в XLSX нужно выводить именно то значение, которое пользователь видел в отчёте, а не технический код, если для переменной доступно отображение по другому полю.

При этом портал не может надёжно определить, в каком именно выражении, вычисляемом поле, условии или другом контексте была использована переменная и какой логический оператор к ней применялся. Поэтому в XLSX должен выводиться не разбор выражений, а плоский список используемых в отчёте переменных и их текущих значений.

Задача завершает цикл доработок по единообразному отображению значений фильтров и переменных в интерфейсе и XLSX-экспорте.

----
h3. Цель задачи.

*Требуется:*
# Добавить отображение используемых в визуализации переменных при экспорте данных в XLSX.
# Выводить переменные отдельным блоком "Переменные" по аналогии с блоком фильтров, но без попытки интерпретировать условия и места использования переменных.
# Для переменных, выбранных через контрол с настройкой "Значения по другому полю", отображать в XLSX человекочитаемые значения по полю отображения, а не технические значения, передаваемые в расчёт.
# Поддержать вывод переменных в общем XLSX-шаблоне и в частном шаблоне Таблицы.
# Сохранить текущую логику расчёта данных, подстановки переменных и экспорта для отчётов, где переменные не используются.

_Пользовательская история:_
Как пользователь отчёта, я хочу видеть в XLSX-выгрузке значения переменных, с которыми были рассчитаны экспортированные данные, чтобы корректно интерпретировать файл вне портала.

----
h3. 1. Описание текущего поведения.

* В отчёте могут быть настроены переменные, значения которых выбираются пользователем через элементы управления отчёта/контейнер фильтров.
* Значения переменных передаются в запросы данных визуализаций и влияют на результат расчёта.
* Например:
{code:json}
"variables": [
  {
    "name": "var",
    "values": ["Накопительно"]
  }
]
{code}

* В выражениях вычисляемых полей переменная может использоваться через текущий синтаксис подстановки, например:
{code}
{!env.var!;''}
{code}
* В JSON такой фрагмент может быть экранирован, например:
{code}
{\u0021env.var\u0021;''}
{code}
* При экспорте в XLSX текущий запрос {{exports.reportToXlsx}} содержит переменные в {{dataset.params.variables}} для расчёта данных, но в {{export.parameters}} для оформления XLSX передаются только фильтры, заголовок отчёта и заголовок визуализации.
* В результате блок фильтров может быть выведен в XLSX, а блок переменных отсутствует.
* Если пользователь выбрал значение переменной через контрол с отображением значений по другому полю, в расчёт может уходить техническое значение, а человекочитаемое значение не выводится в XLSX.

----
h3. 2. Описание целевого поведения.

* При экспорте данных в XLSX портал должен формировать список переменных, которые используются в текущем отчёте/дашборде и имеют актуальные значения на момент экспорта.
* В XLSX должен выводиться отдельный блок "Переменные".
* Для каждой переменной в блоке нужно выводить:
** отображаемое название переменной;
** выбранное значение или список выбранных значений.
* Если для переменной доступно отображение значений по другому полю, в XLSX должны выводиться значения по полю отображения.
* Если отображение по другому полю не задано или недоступно, значение переменной должно выводиться по текущему значению, которое используется в расчёте.
* Если переменная используется в нескольких местах отчёта/дашборда, она должна выводиться в блоке "Переменные" один раз.
* В XLSX не нужно выводить:
** место использования переменной;
** имя вычисляемого поля, где переменная встретилась;
** выражение, в котором переменная использована;
** SQL-условие или оператор сравнения;
** трактовку диапазона как "с/по", "больше либо равно", "меньше либо равно", если такая информация не является явной частью названия/значения переменной.
* Если в отчёте/дашборде нет используемых переменных с актуальными значениями, блок "Переменные" не должен выводиться.
* Фильтры и переменные должны выводиться как разные сущности:
** блок "Фильтры" продолжает работать по логике задач по XLSX-экспорту фильтров;
** блок "Переменные" выводит только переменные и их значения.

----
h3. 3. Требования к реализации:

h4. 3.1. Логика XLSX-экспорта.

* Затрагиваемый backend-объект: {{exports}}.
* Основная команда экспорта: текущая команда XLSX-экспорта, например {{reportToXlsx}}.
* При формировании XLSX-файла экспорт должен получать или определять список используемых переменных и их значений.
* Экспорт должен использовать этот список только для отображения блока "Переменные" в XLSX.
* Подстановка переменных в запросы данных должна работать по текущей логике без изменений.
* Доработка не должна менять результат расчёта экспортируемой визуализации.
* Ошибка получения отображаемого значения переменной не должна прерывать экспорт всего XLSX-файла.

---
h4. 3.2. Определение списка используемых переменных.

* Требуется выводить переменные, которые фактически используются в текущем отчёте/дашборде, из которого выполняется экспорт, а не весь список переменных, которые когда-либо были заведены в отчёте.
* Если экспортируется отдельная визуализация, список переменных всё равно должен формироваться на уровне текущего отчёта/дашборда, а не только по локальным метаданным экспортируемой визуализации.
* Для определения используемых переменных необходимо опираться на существующий механизм подстановки переменных в запросы/выражения либо на результат этой подстановки.
* Минимально ожидаемая логика:
** собрать имена переменных, которые были обнаружены/использованы механизмом подстановки при подготовке запросов данных для текущего отчёта/дашборда;
** сопоставить найденные имена переменных с актуальными значениями, переданными из фронтенда или доступными бэкенду при экспорте;
** исключить переменные без фактического использования в выражениях/запросах отчёта, если они присутствуют только как настройки или элементы управления.
* Если одна и та же переменная используется в нескольких выражениях или нескольких визуализациях дашборда, в XLSX она должна попадать один раз.
* Если переменная используется с суффиксами/производными именами, например для диапазонного контрола, выводить те переменные, которые фактически используются механизмом подстановки и имеют текущие значения.
* Не требуется определять логический смысл переменной в выражении. Например, если переменная используется внутри условия диапазона, в XLSX всё равно выводится только имя переменной и её значение.

---
h4. 3.3. Передача переменных в параметры экспорта.

* Фронтенд должен передавать в экспорт актуальные значения переменных, доступные в состоянии отчёта на момент экспорта.
* Переменные должны быть доступны не только в {{dataset.params.variables}}, используемом для расчёта данных, но и в параметрах, из которых формируется информационная часть XLSX-файла.
* Рекомендуемый целевой состав данных для каждой переменной:
** системное имя переменной, используемое в подстановке, например {{var}};
** отображаемое название переменной, если оно задано;
** технические значения, которые используются для расчёта;
** отображаемые значения для XLSX, если они отличаются от технических;
** признак/ссылка на поле отображения, если значение получено через настройку "Значения по другому полю" и это требуется текущей реализации.
* Конкретное имя поля в {{export.parameters}} необходимо согласовать с командой разработки до реализации. Рекомендуемый вариант - {{variables}}.
* Пример целевой структуры приведён как ориентир и не фиксирует окончательный контракт:
{code:json}
"parameters": {
  "filter": [],
  "variables": [
    {
      "name": "var",
      "title": "Вычисление",
      "values": "[Накопительно]"
    }
  ],
  "reportCaption": "Переменные_тест",
  "title": "Линейная диаграмма"
}
{code}
* Если в текущей реализации удобнее передавать значения переменных в структурированном виде, а строку для XLSX формировать на бэкенде, необходимо сохранить возможность множественных значений и значений по другому полю.

---
h4. 3.4. Учет настройки "Значения по другому полю" для переменных.

* Если переменная выбирается через контрол/фильтр, для которого задана настройка "Значения по другому полю", в XLSX нужно выводить значения по полю отображения.
* Техническое значение переменной должно продолжать использоваться для расчёта данных.
* Значение по другому полю не должно подменять системное имя переменной.
* Значение по другому полю не должно менять синтаксис подстановки переменной в выражениях.
* Для получения отображаемого значения необходимо переиспользовать подход, подготовленный в задачах по фильтрам:
** основное значение остаётся значением, которое передаётся в расчёт;
** поле отображения используется только для вывода пользователю;
** при невозможности сопоставления используется безопасная fallback-логика.
* Если для одного технического значения найдено одно отображаемое значение, в XLSX выводится отображаемое значение.
* Если для нескольких технических значений доступны отображаемые значения, они выводятся списком с текущими разделителями XLSX-экспорта.
* Если отображаемое значение не найдено, необходимо вывести техническое значение переменной либо применить существующую обработку невалидных значений.

---
h4. 3.5. Поддерживаемые XLSX-шаблоны.

* *Общий XLSX-шаблон:*
** если список используемых переменных не пустой, блок "Переменные" должен выводиться автоматически по аналогии с текущим поведением блока фильтров;
** если переменных нет, блок "Переменные" не выводится;
** блок переменных должен быть отделён от блока фильтров визуально и текстово;
** порядок, базовое форматирование и расположение блока необходимо согласовать с текущей логикой общего XLSX-шаблона.
* *Частный шаблон Таблицы:*
** необходимо поддержать маркер {{Variables}} для вывода переменных в одну строку по аналогии с {{Filters}};
** необходимо поддержать маркер {{VariablesByRows}} для вывода переменных по строкам по аналогии с {{FiltersByRows}};
** если в частном шаблоне Таблицы отсутствуют {{Variables}} и {{VariablesByRows}}, переменные не должны добавляться в XLSX автоматически;
** существующие маркеры {{Filters}} и {{FiltersByRows}} должны продолжить работать без изменений;
** если в шаблоне одновременно используются маркеры фильтров и переменных, каждый маркер должен заполнять только свой тип данных.
* Формат вывода значений переменных должен быть согласован с текущим форматом фильтров:
** для одной строки - название переменной и список значений;
** для построчного вывода - одна переменная в строке или текущий аналогичный формат, применяемый для {{FiltersByRows}}.

---
h4. 3.6. Бэкенд-часть и API.

* Затрагиваемые backend-объекты и механизмы:
** {{exports}} - формирование XLSX-файла;
** {{reports}} - чтение метаданных отчёта при необходимости;
** {{filtersets}} - получение состояния фильтров/контролов отчёта при необходимости;
** существующий механизм подстановки переменных в запросы данных;
** существующий механизм получения значений фильтра/набора данных для сопоставления значений по другому полю, если он требуется реализации.
* Бэкенд должен иметь доступ к списку текущих значений переменных при выполнении экспорта.
* Бэкенд должен определить, какие из переданных переменных реально использованы в отчёте/дашборде.
* Для определения используемых переменных необходимо использовать тот же механизм, который подставляет переменные в выражения и запросы, либо общий сервис/функцию на его основе, чтобы список соответствовал фактически использованным переменным.
* Если для отображения значения по другому полю требуется запрос к данным набора данных, необходимо использовать существующий пакетный механизм получения значений и не выполнять отдельный запрос на каждое значение переменной, если можно получить значения пакетно.
* Ошибки определения/сопоставления переменных не должны приводить к падению экспорта. Для проблемной переменной нужно применить fallback-логику или исключить её из блока, если значение невозможно определить безопасно.

---
h4. 3.7. Технические требования и ограничения.

* Не менять SQL-логику и результат расчёта данных при экспорте.
* Не менять синтаксис переменных в выражениях.
* Не пытаться парсить бизнес-смысл выражений с переменными сверх определения факта использования переменной.
* Не выводить в XLSX условия сравнения для переменных, так как они не являются частью явного контракта переменной.
* Не добавлять переменные в блок "Фильтры".
* Не менять поведение отчётов без переменных.
* Сохранить обратную совместимость с существующими XLSX-шаблонами:
** общий шаблон должен продолжить экспортировать данные и фильтры по текущей логике;
** частные шаблоны Таблицы без новых маркеров переменных не должны менять результат;
** существующие маркеры фильтров не должны менять назначение.
* При множественном выборе переменной сохранять текущие правила разделителей и форматирования значений XLSX-экспорта.
* Если значение переменной имеет тип дата/дата-время/число/строка, использовать существующее форматирование значения, доступное в портале/экспорте. Новую сложную настройку форматирования переменных в рамках задачи не вводить.

----
h3. 4. Пограничные сценарии:

* В отчёте/дашборде нет используемых переменных.
* В отчёте есть заведённая переменная, но она не используется в выражениях/запросах.
* Одна переменная используется в нескольких вычисляемых полях или нескольких запросах данных.
* Переменная используется в вычисляемом поле визуализации.
* Переменная используется в выражении набора данных или условии, влияющем на выборку.
* Переменная используется в выражении, где невозможно определить оператор сравнения или бизнес-смысл условия.
* Переменная имеет одно выбранное значение.
* Переменная имеет несколько выбранных значений.
* Переменная выбрана через диапазонный контрол и фактически используется как несколько переменных/значений.
* Для переменной задано отображение значений по другому полю.
* Для переменной задано отображение значений по другому полю, но поле отображения удалено или недоступно.
* Для технического значения переменной не найдено отображаемое значение.
* В частном шаблоне Таблицы есть {{Variables}}, но нет {{VariablesByRows}}.
* В частном шаблоне Таблицы есть {{VariablesByRows}}, но нет {{Variables}}.
* В частном шаблоне Таблицы нет маркеров переменных.
* В XLSX одновременно выводятся фильтры и переменные.
* Экспорт выполняется для визуализации, данные которой зависят от переменной.
* Экспорт выполняется для визуализации, данные которой не зависят от переменной, но переменная используется в другом месте текущего дашборда.

----
h3. 5. Что не входит в рамки задачи:

* Изменение механизма создания и настройки переменных отчёта.
* Изменение синтаксиса обращения к переменным в выражениях.
* Парсинг выражений для определения точного поля, вычисляемого поля, оператора или бизнес-условия применения переменной.
* Отображение мест использования переменной в XLSX.
* Добавление отдельного UI для настройки блока "Переменные" в рамках конструктора отчётов, если это не требуется текущим механизмом XLSX-шаблонов.
* Изменение логики фильтрации данных и SQL-генерации.
* Изменение уже реализованной логики отображения фильтров по другому полю в XLSX, боковой Панели фильтров и Панели индикации фильтров.
* Экспорт переменных в форматы, отличные от XLSX.

h3. 7. Предположения.

* Под "используемыми переменными" понимаются переменные, которые фактически встречаются в выражениях/запросах текущего отчёта/дашборда и участвуют в механизме подстановки переменных.
* Текущие значения переменных доступны фронтенду на момент экспорта и уже передаются в запрос данных через {{dataset.params.variables}}.
* Для отображения значений по другому полю можно переиспользовать механизм, подготовленный в задачах по фильтрам, либо согласовать эквивалентный способ передачи отображаемых значений в {{export.parameters.variables}}.
* Финальный формат поля {{variables}} в {{export.parameters}} должен быть подтверждён командой разработки до реализации.

----
h3. 8. Открытые вопросы.

* Нужно подтвердить финальные названия маркеров частного шаблона Таблицы: {{Variables}} и {{VariablesByRows}} либо другие названия, если в коде уже есть устоявшийся нейминг.
* Нужно подтвердить расположение блока "Переменные" в общем XLSX-шаблоне относительно блока фильтров и заголовка визуализации.

----
h3. 9. Критерии приёмки (AC):

AC.1 — *Общий XLSX-шаблон выводит блок переменных:*
* *Дано:* в отчёте есть переменная {{var}}, которая используется в выражении визуализации или отчёта;
* *И:* для переменной выбрано значение "Накопительно";
* *Когда:* пользователь экспортирует данные в XLSX с общим шаблоном;
* *Тогда:* в XLSX отображается отдельный блок "Переменные";
* *И:* в блоке отображается переменная {{var}} или её пользовательское название;
* *И:* значение переменной отображается как "Накопительно".

AC.2 — *Переменные не смешиваются с фильтрами:*
* *Дано:* в отчёте одновременно применены фильтры и используются переменные;
* *Когда:* пользователь экспортирует данные в XLSX;
* *Тогда:* фильтры отображаются в блоке фильтров по текущей логике;
* *И:* переменные отображаются в отдельном блоке "Переменные";
* *И:* переменные не добавляются как элементы блока фильтров.

AC.3 — *Используемая переменная выводится один раз:*
* *Дано:* переменная {{var}} используется в нескольких выражениях отчёта/дашборда;
* *Когда:* пользователь экспортирует данные в XLSX;
* *Тогда:* переменная {{var}} отображается в блоке "Переменные" один раз;
* *И:* её значение соответствует актуальному значению на момент экспорта.

AC.4 — *Неиспользуемая переменная не выводится:*
* *Дано:* в отчёте есть заведённая переменная, которая не используется в выражениях/запросах текущего отчёта/дашборда;
* *Когда:* пользователь экспортирует данные в XLSX;
* *Тогда:* такая переменная не отображается в блоке "Переменные".

AC.5 — *Значение по другому полю выводится для переменной:*
* *Дано:* переменная выбирается через контрол, где техническое значение используется для расчёта;
* *И:* для контрола задана настройка "Значения по другому полю";
* *И:* пользователь видит и выбирает значение "Миллионы рублей", а в расчёт передаётся техническое значение;
* *Когда:* пользователь экспортирует данные в XLSX;
* *Тогда:* в блоке "Переменные" отображается значение "Миллионы рублей";
* *И:* техническое значение не отображается вместо человекочитаемого, если сопоставление доступно.

AC.6 — *Расчёт данных при экспорте не меняется:*
* *Дано:* визуализация зависит от значения переменной {{var}};
* *Когда:* пользователь экспортирует данные в XLSX после доработки;
* *Тогда:* данные в XLSX рассчитаны по той же логике, что и до доработки;
* *И:* доработка влияет только на информационный блок переменных в XLSX.

AC.7 — *Частный шаблон Таблицы с {{Variables}} выводит переменные в одну строку:*
* *Дано:* Таблица использует частный XLSX-шаблон с маркером {{Variables}};
* *И:* в отчёте есть используемые переменные;
* *Когда:* пользователь экспортирует Таблицу в XLSX;
* *Тогда:* на месте маркера {{Variables}} выводится список переменных по формату одной строки;
* *И:* значения по другому полю учитываются при наличии соответствующей настройки.

AC.8 — *Частный шаблон Таблицы с {{VariablesByRows}} выводит переменные по строкам:*
* *Дано:* Таблица использует частный XLSX-шаблон с маркером {{VariablesByRows}};
* *И:* в отчёте есть используемые переменные;
* *Когда:* пользователь экспортирует Таблицу в XLSX;
* *Тогда:* на месте маркера {{VariablesByRows}} переменные выводятся по строкам;
* *И:* каждая переменная отображается с названием и текущим значением.

AC.9 — *Частный шаблон Таблицы без маркеров переменных не меняет поведение:*
* *Дано:* Таблица использует частный XLSX-шаблон без {{Variables}} и {{VariablesByRows}};
* *Когда:* пользователь экспортирует Таблицу в XLSX;
* *Тогда:* переменные не добавляются в файл автоматически;
* *И:* существующий результат экспорта по шаблону сохраняется.

AC.10 — *Множественные значения переменной отображаются списком:*
* *Дано:* используемая переменная имеет несколько выбранных значений;
* *Когда:* пользователь экспортирует данные в XLSX;
* *Тогда:* в блоке "Переменные" отображаются все выбранные значения переменной;
* *И:* используются текущие разделители и форматирование XLSX-экспорта.

AC.11 — *Диапазонная переменная выводится без интерпретации условий:*
* *Дано:* переменная или группа переменных выбрана через диапазонный контрол;
* *И:* эти переменные используются в выражениях отчёта/дашборда;
* *Когда:* пользователь экспортирует данные в XLSX;
* *Тогда:* в блоке "Переменные" выводятся фактически используемые переменные и их значения;
* *И:* портал не добавляет условия "больше либо равно", "меньше либо равно", "с/по", если они не являются явной частью названия/значения переменной.

AC.12 — *Безопасная деградация при недоступном значении по другому полю:*
* *Дано:* для переменной настроено отображение значения по другому полю;
* *И:* отображаемое значение не удалось получить или поле отображения недоступно;
* *Когда:* пользователь экспортирует данные в XLSX;
* *Тогда:* экспорт завершается успешно;
* *И:* для проблемной переменной выводится техническое значение либо применяется существующая fallback-логика;
* *И:* ошибка одной переменной не ломает весь XLSX-файл.

AC.13 — *Экспорт отдельной визуализации учитывает переменные дашборда:*
* *Дано:* пользователь экспортирует отдельную визуализацию из отчёта/дашборда;
* *И:* в текущем отчёте/дашборде есть используемая переменная с актуальным значением;
* *Когда:* выполняется экспорт в XLSX;
* *Тогда:* переменная отображается в блоке "Переменные";
* *И:* портал не требует определять точное место использования переменной в экспортируемой визуализации.

AC.14 — *Отчёты без используемых переменных работают без изменений:*
* *Дано:* в отчёте/дашборде нет используемых переменных;
* *Когда:* пользователь экспортирует данные в XLSX;
* *Тогда:* блок "Переменные" не выводится;
* *И:* экспорт выполняется по текущей логике без визуальных и функциональных изменений, не связанных с другими задачами цикла.
