h3. Контекст и проблематика.

Сейчас в портале есть настройка "Значения по другому полю": фильтр может применяться по техническому полю, а в интерфейсе пользователь видит значения из другого поля того же набора данных. Например, в отчёте [https://dev.modusbi.ru/report/796] фильтр "Месяц" применяет значения {{month_num}} = {{2}}, {{3}}, но пользователю должны отображаться значения из {{month_name}}.

Команда ФКТ запросила возможность видеть при экспорте в XLSX те же значения фильтров, которые пользователь видит в отчёте.

*Текущее ограничение:* при экспорте данных визуализации в XLSX блок фильтров выводит технические значения основного поля, например "Месяц = 2, 3". Для пользователя это расходится с тем, что он видел в отчёте, и снижает читаемость экспортируемого файла.

Задача выполняется на основании технической основы из связанной задачи [https://jira.modusbi.ru/browse/MB-4774], где настройка "Значения по другому полю" выносится на уровень глобальных фильтров.

----

h3. Цель задачи.

*Требуется:*
# При экспорте данных в XLSX отображать значения глобальных фильтров по другому полю, если для фильтра задана соответствующая глобальная настройка ("Значения по другому полю").
# Сохранять текущую логику фильтрации: данные экспортируемой визуализации фильтруются по основному полю фильтра.
# Поддержать отображение значений в XLSX для общего шаблона экспорта и для частных табличных шаблонов, где выводятся фильтры.
# Не менять поведение фильтров, для которых настройка "Значения по другому полю" не задана.

_Пользовательская история:_
Как пользователь отчёта, я хочу, чтобы в XLSX-выгрузке были указаны человекочитаемые значения фильтров, которые я видел в отчёте, чтобы экспортированный файл можно было использовать без дополнительного сопоставления технических кодов.

----

h3. 1. Описание текущего поведения.

* При экспорте визуализации в XLSX портал добавляет информацию о применённых фильтрах.
* В отчёте используются разные варианты вывода фильтров:
** общий шаблон экспорта для визуализаций;
** частный шаблон таблицы с выводом фильтров в одну строку через {{Filters}};
** частный шаблон таблицы с выводом фильтров по строкам через {{FiltersByRows}}.
* В частном табличном шаблоне фильтры выводятся только если в шаблоне указан соответствующий маркер. Если маркер фильтров отсутствует, фильтры не выводятся.
* Для фильтра, настроенного по другому полю, в XLSX сейчас выводятся значения основного поля фильтрации.
* К примеру, в отчёте [https://dev.modusbi.ru/report/796] для фильтра "Месяц" при выбранных значениях февраль и март в XLSX выводится {{2}}, {{3}}.

----

h3. 2. Описание целевого поведения.

* При экспорте в XLSX для каждого применённого глобального фильтра нужно проверять наличие настройки "Значения по другому полю".
* Если настройка задана, в блоке фильтров XLSX должны выводиться значения из поля отображения, а не технические значения основного поля.
* Если настройка не задана, фильтр должен отображаться в XLSX по текущей логике.
* Название фильтра в XLSX должно соответствовать текущему отображаемому названию фильтра или заголовку глобального фильтра. Поле отображения значений не должно подменять название фильтра.
* Порядок фильтров, разделители, формат вывода в одну строку или по строкам - должны сохранять текущую логику экспорта. Меняется только текст отображаемых значений для фильтров с настройкой "Значения по другому полю".
* Если значение не удалось сопоставить с полем отображения, экспорт не должен завершаться ошибкой. Для такого значения нужно использовать безопасную деградацию: вывести исходное значение основного поля или применить существующую обработку невалидных значений.

----

h3. 3. Требования к реализации:

h4. 3.1. Логика XLSX-экспорта.

* Использовать глобальную настройку фильтра "Значения по другому полю", подготовленную в задаче [https://jira.modusbi.ru/browse/MB-4774].
* Не получать настройку только из метаданных экспортируемой визуализации, так как экспортируемый компонент может не хранить локально настройку {{nameBy}}.
* Для фильтра с настройкой:
** основное поле остаётся полем фильтрации;
** выбранные значения основного поля используются для фильтрации данных;
** для вывода в XLSX значения основного поля сопоставляются со значениями поля отображения.
* Для фильтра без настройки:
** значения выводятся по текущей логике без дополнительного сопоставления.
* Если несколько технических значений сопоставляются с одинаковым отображаемым значением, использовать текущую логику вывода множественных значений и не менять правила дедупликации, если они уже существуют в экспорте.
* Сохранять текущие правила форматирования значений, разделителей и переноса строк в XLSX.

---
h4. 3.2. Поддерживаемые шаблоны экспорта и типы вывода фильтров.

* Общий шаблон экспорта:
** фильтры должны отображаться по текущей логике общего шаблона;
** для фильтров с настройкой "Значения по другому полю" должны выводиться отображаемые значения.
* Частный табличный шаблон: 
** с {{Filters}}:
*** фильтры должны выводиться в одну строку по текущей логике шаблона;
*** значения фильтров с настройкой должны заменяться на значения из поля отображения.
** с {{FiltersByRows}}:
*** фильтры должны выводиться по строкам по текущей логике шаблона;
*** значения фильтров с настройкой должны заменяться на значения из поля отображения.
** без {{Filters}} и {{FiltersByRows}}:
*** фильтры не должны появляться в XLSX, поведение остаётся текущим.

---
h4. 3.3. Бэкенд-часть и API.

* Затрагиваемый backend-объект: {{exports}}.
* Также используются данные отчёта / глобальных фильтров из {{reports}} и {{filtersets}}, если это требуется текущей реализацией экспорта.
* Перед формированием XLSX экспорт должен иметь доступ к актуальным выбранным значениям фильтров и к настройке поля отображения из глобального фильтра.
* Команды API экспорта требуется использовать из текущей реализации.
* Если для сопоставления значений требуется запрос к данным набора данных, использовать существующий механизм получения значений фильтра/{{recordsets}} и не выполнять отдельный запрос на каждое выбранное значение, если значения можно получить пакетно для фильтра.
* Ошибка сопоставления отображаемых значений не должна ломать экспорт всей визуализации.

---
h4. 3.4. Технические требования и ограничения.

* Не менять SQL-условия фильтрации данных экспортируемой визуализации.
* Не менять формат XLSX-шаблонов и названия существующих маркеров {{Filters}} и {{FiltersByRows}}.
* Не добавлять в рамках задачи новые маркеры для переменных отчёта.
* Не менять боковую Панель фильтров и Панель индикации фильтров в рамках этой задачи.
* Сохранить обратную совместимость с отчётами созданными до данной доработки.

----

h3. 4. Учитывать пограничные сценарии:

* Выбранное техническое значение не найдено в результате сопоставления с полем отображения.
* Выбрано несколько значений фильтра.
* Выбранные значения содержат пустое значение / {{null}}, если такие значения поддерживаются текущим фильтром.
* Экспортируется визуализация не хранит локально настройку {{nameBy}}, но глобальный фильтр отчёта её имеет.
* В частном шаблоне таблицы отсутствуют маркеры {{Filters}} и {{FiltersByRows}}.
* В отчёте есть фильтры с одинаковыми наименованиями из разных наборов данных - поведение должно соответствовать текущей логике глобальных фильтров.
* Настройка "Значения по другому полю" отсутствует.
* Поле отображения значений удалено или недоступно.

h3. 6. Критерии приёмки (AC):

AC.1 — *Общий шаблон выводит отображаемые значения фильтра:*
* *Дано:* в отчёте настроен глобальный фильтр "Месяц", который фильтрует по {{month_num}} и отображает значения по {{month_name}};
* *И:* выбраны значения февраль и март;
* *Когда:* пользователь экспортирует визуализацию в XLSX с общим шаблоном экспорта;
* *Тогда:* в блоке фильтров XLSX для фильтра "Месяц" отображаются значения февраль и март;
* *И:* технические значения {{2}} и {{3}} не отображаются как значения этого фильтра.

AC.2 — *Частный табличный шаблон {{Filters}} выводит отображаемые значения:*
* *Дано:* таблица использует частный XLSX-шаблон с маркером {{Filters}};
* *И:* для глобального фильтра задано отображение значений по другому полю;
* *Когда:* пользователь экспортирует таблицу в XLSX;
* *Тогда:* фильтр выводится в одну строку по текущему формату шаблона;
* *И:* значения фильтра выводятся по полю отображения.

AC.3 — *Частный табличный шаблон {{FiltersByRows}} выводит отображаемые значения:*
* *Дано:* таблица использует частный XLSX-шаблон с маркером {{FiltersByRows}};
* *И:* для глобального фильтра задано отображение значений по другому полю;
* *Когда:* пользователь экспортирует таблицу в XLSX;
* *Тогда:* фильтры выводятся по строкам по текущему формату шаблона;
* *И:* значения фильтра с настройкой выводятся по полю отображения.

AC.4 — *Шаблон без маркеров фильтров не меняет поведение:*
* *Дано:* частный табличный XLSX-шаблон не содержит {{Filters}} и {{FiltersByRows}};
* *Когда:* пользователь экспортирует таблицу;
* *Тогда:* фильтры не добавляются в XLSX автоматически.

AC.5 — *Фильтры без настройки отображаются по текущей логике:*
* *Дано:* в отчёте есть фильтр "Год" без настройки "Значения по другому полю";
* *Когда:* пользователь экспортирует визуализацию в XLSX;
* *Тогда:* значения фильтра "Год" отображаются по текущей логике без дополнительного сопоставления.

AC.6 — *Экспорт использует глобальную настройку, а не локальные поля визуализации:*
* *Дано:* глобальный фильтр имеет настройку "Значения по другому полю";
* *И:* экспортируемая визуализация не хранит локально поле отображения значений в своих настройках;
* *Когда:* пользователь экспортирует визуализацию в XLSX;
* *Тогда:* значения фильтра в XLSX всё равно выводятся по глобальной настройке.

AC.7 — *Безопасная деградация при ошибке сопоставления:*
* *Дано:* у фильтра задано поле отображения значений, но одно из выбранных значений не удалось сопоставить;
* *Когда:* пользователь экспортирует визуализацию в XLSX;
* *Тогда:* экспорт завершается успешно;
* *И:* несопоставленное значение выводится по безопасной fallback-логике, без ошибки всего файла.

AC.8 — *Фильтрация данных при экспорте не меняется:*
* *Дано:* для фильтра {{month_num}} выбраны значения, отображаемые пользователю как февраль и март;
* *Когда:* пользователь экспортирует визуализацию;
* *Тогда:* данные визуализации фильтруются по основному полю {{month_num}};
* *И:* доработка влияет только на текст значений фильтра в XLSX.
