h3. Контекст и проблематика.

В аналитическом портале переменные могут использоваться в выражениях набора данных, вычисляемых полях и в иных местах, влияющих на результат визуализации. Пользователь выбирает значения переменных в отчёте, после чего данные визуализации пересчитываются с учётом этих значений.

Сейчас при экспорте данных в XLSX пользователь получает результат, уже рассчитанный с учётом выбранных переменных, но в выгруженном файле не видит, какие значения переменных были применены. Из-за этого экспортированный файл сложнее интерпретировать вне портала.

При экспорте в XLSX портал обращается к конкретной визуализации и выгружает данные именно этой визуализации. Поэтому в XLSX нужно выводить не все переменные отчёта, а только те переменные, которые используются при расчёте экспортируемой визуализации.

Дополнительно переменная может задаваться через фильтр/контрол в контейнере фильтров, где используется настройка "Значения по другому полю": в вычисление передаётся техническое значение переменной, а пользователь видит человекочитаемое значение. При экспорте в XLSX нужно выводить именно то значение, которое пользователь видел в отчёте, а не технический код, если для переменной доступно отображение по другому полю.

При этом портал не может надёжно определить, в каком именно выражении, вычисляемом поле, условии или другом контексте была использована переменная и какой логический оператор к ней применялся. Поэтому в XLSX должен выводиться не разбор выражений, а плоский список используемых в экспортируемой визуализации переменных и их текущих значений.

Задача завершает цикл доработок по единообразному отображению значений фильтров и переменных в интерфейсе и XLSX-экспорте.

----
h3. Цель задачи.

*Требуется:*
# Добавить отображение переменных, которые используются при расчёте экспортируемой визуализации, при экспорте данных в XLSX.
# Выводить переменные отдельным блоком "Переменные" по аналогии с блоком фильтров, но без попытки интерпретировать условия, операторы и места использования переменных.
# Для переменных, выбранных через контрол с настройкой "Значения по другому полю", отображать в XLSX человекочитаемые значения по полю отображения, а не технические значения, передаваемые в расчёт.
# Ввести и поддержать новый маркер XLSX-шаблонов {{\{Variables\}}}.
# Поддержать вывод переменных через {{\{Variables\}}}:
** в общем XLSX-шаблоне экспорта;
** в частном XLSX-шаблоне Таблицы.
# Сохранить текущую логику расчёта данных, подстановки переменных и экспорта для визуализаций, где переменные не используются.

_Пользовательская история:_
Как пользователь отчёта, я хочу видеть в XLSX-выгрузке значения переменных, с которыми были рассчитаны экспортированные данные, чтобы корректно интерпретировать файл вне портала.

----
h3. 1. Описание текущего поведения.

* В отчёте могут быть настроены переменные, значения которых выбираются пользователем через элементы управления отчёта/контейнер фильтров и т.д.
* Значения переменных передаются в запросы данных визуализаций и влияют на результат расчёта, если переменные используются в выражениях, участвующих в расчёте конкретной визуализации.
* При экспорте визуализации в XLSX переменные уже могут присутствовать в части payload, отвечающей за расчёт данных.

* В фактическом запросе экспорта переменные передаются в {{export.dataset.params.variables}}, но не передаются в {{export.parameters}} как данные для информационной части XLSX-файла.

* Экспортируемые данные рассчитываются с учётом используемых переменных, но пользователь не видит значения этих переменных в XLSX.
* Если пользователь выбрал значение переменной через контрол с отображением значений по другому полю, в расчёт может уходить техническое значение, а человекочитаемое значение не выводится в XLSX.
* В общем XLSX-шаблоне сейчас используются фиксированные ячейки для стилей и параметров вывода:
** {{A1}} - стиль шапки таблицы с данными;
** {{A2}} - стиль строк таблицы с данными;
** {{A3}} - стиль заголовка визуализации;
** {{A4}} - стиль и режим вывода фильтров;
** {{A5}} - стиль заголовка отчёта.
* В частном XLSX-шаблоне Таблицы сейчас поддерживается определённый набор маркеров заголовков и фильтров, но отдельного маркера для переменных нет.

----
h3. 2. Описание целевого поведения.

* При экспорте данных в XLSX портал должен формировать список переменных, которые используются при расчёте экспортируемой визуализации и имеют актуальные значения на момент экспорта.
* Список переменных должен формироваться в рамках экспортируемой визуализации, а не всего отчёта/дашборда.
* Вводится новый маркер для отображения переменных {{\{Variables\}}} для частного шаблона и отдельная ячейка ({{A6}}) в общем шаблоне для настройки отображения и вывода списка используемых переменных и их значений.
* При выгрузке в XLSX выводится отдельный блок «Переменные», если
** используется частный XLSX-шаблон, содержащий маркер {{\{Variables\}}}
** используется общий шаблон экспорта XLSX
* Для каждой переменной в блоке нужно выводить:
** отображаемое название переменной, если оно доступно;
** системное имя переменной, если отображаемое название недоступно;
** выбранное значение или список выбранных значений.
* Если в контейнере с фильтрами используются переменные и настроено отображение значений по другому полю, в XLSX должны выводиться значения по полю отображения.
* Если отображение по другому полю не задано или недоступно, значение переменной должно выводиться по текущему значению, которое используется в расчёте.
* Если одна и та же переменная используется в нескольких выражениях экспортируемой визуализации, она должна выводиться в блоке "Переменные" один раз.
* Если переменная заведена в отчёте, имеет выбранное значение, но используется в другой визуализации дашборда и не участвует в расчёте экспортируемой визуализации - она не должна выводиться в XLSX-выгрузке данной экспортируемой визуализации.
* В XLSX не нужно выводить:
** место использования переменной;
** имя вычисляемого поля, где переменная встретилась;
** выражение, в котором переменная использована;
** SQL-условие или используемый оператор сравнения;
** иную информацию, если она не является явной частью названия/значения переменной.
* Если в экспортируемой визуализации нет используемых переменных с актуальными значениями, блок "Переменные" не должен выводиться.
* Фильтры и переменные должны выводиться как разные сущности:
** блок "Фильтры" продолжает работать по реализованной логике;
** блок "Переменные" выводит только переменные и их значения;
** переменные не должны добавляться в блок "Фильтры".

----
h3. 3. Требования к реализации.

h4. 3.1. Логика XLSX-экспорта.

* Затрагиваемый backend-объект: {{exports}} и текущая команда XLSX-экспорта.
* Экспорт выполняется для конкретной визуализации, выбранной пользователем. Состав переменных для XLSX должен определяться в рамках данных и выражений этой визуализации.
* При формировании XLSX-файла экспорт должен получать или определять список переменных, использованных при расчёте экспортируемой визуализации, и их актуальные значения.
* Экспорт должен использовать этот список только для отображения блока "Переменные" в XLSX.
* Подстановка переменных в запросы данных должна работать по текущей логике без изменений.
* Доработка не должна менять результат расчёта экспортируемой визуализации.
* Ошибка получения отображаемого значения переменной не должна прерывать экспорт всего XLSX-файла.
* Если список переменных пустой, маркер {{\{Variables\}}} не должен приводить к выводу технического текста маркера в итоговый XLSX-файл. Маркер должен заменяться пустым значением либо обрабатываться по текущей логике пустых шаблонных маркеров.

---
h4. 3.2. Определение списка используемых переменных.

* Требуется выводить переменные, которые фактически используются в запросе/выражениях экспортируемой визуализации, а не весь список переменных, которые заведены в отчёте или доступны в состоянии отчёта.
* Нельзя формировать список переменных на уровне всего отчёта/дашборда, если экспортируется только конкретная визуализация.
* Для определения используемых переменных необходимо опираться на существующий механизм подстановки переменных в запросы/выражения.

* Предлагаемая минимально-достаточная логика:
** взять payload экспорта выбранной визуализации, в том числе {{export.dataset.params}};
** определить имена переменных, которые были использованы механизмом подстановки при подготовке запроса данных для экспорта именно этой визуализации;
** сопоставить найденные имена переменных с актуальными значениями, переданными из фронтенда или доступными бэкенду при экспорте;
** исключить переменные, которые присутствуют только как настройки отчёта, элементы управления или значения в состоянии отчёта, но не используются в выражениях/запросе экспортируемой визуализации.

* Если переменная используется в вычисляемом поле, которое входит в состав экспортируемой визуализации, такая переменная должна считаться используемой в экспортируемой визуализации.
* Если переменная используется в выражении набора данных, пользовательском SQL, условии или ином выражении, которое участвует в подготовке данных экспортируемой визуализации, такая переменная должна считаться используемой в экспортируемой визуализации.
* Если переменная используется только в другой визуализации текущего дашборда, такая переменная не должна попадать в блок "Переменные" текущего XLSX-файла.
* Если одна и та же переменная используется в нескольких выражениях экспортируемой визуализации, в XLSX она должна попадать один раз.
* Если переменная используется с суффиксами/производными именами, например для диапазонного контрола, выводить нужно те переменные/производные значения, которые фактически использованы механизмом подстановки в рамках экспортируемой визуализации и имеют текущие значения.
* Не требуется определять логический смысл переменной в выражении. Например, если переменная используется внутри условия диапазона, в XLSX всё равно выводится только имя переменной и её значение.
* Рекомендуемый технический подход: механизм подстановки переменных должен уметь возвращать не только итоговый запрос/выражение, но и список переменных, которые были реально использованы при подстановке для конкретного payload экспорта визуализации.

---
h4. 3.3. Передача переменных в параметры экспорта.

* Фронтенд должен передавать в экспорт актуальные значения переменных, доступные в состоянии отчёта на момент экспорта, в объёме, достаточном для формирования блока "Переменные" по экспортируемой визуализации.
* Переменные должны быть доступны не только в {{export.dataset.params.variables}}, используемом для расчёта данных, но и в параметрах, из которых формируется информационная часть XLSX-файла.
* Целевое место передачи для информационной части XLSX: {{export.parameters.variables}}.
* Рекомендуемый целевой состав данных для каждой переменной:
** системное имя переменной, используемое в подстановке, например {{var}};
** отображаемое название переменной, если оно задано;
** технические значения, которые используются для расчёта;
** отображаемые значения для XLSX, если они отличаются от технических;
** признак/ссылка на поле отображения, если значение получено через настройку "Значения по другому полю" и это требуется текущей реализации.
* Рекомендация: если фронтенд передаёт в {{export.parameters.variables}} больше переменных, чем используется в экспортируемой визуализации, бэкенд должен отфильтровать их по факту использования в payload экспортируемой визуализации.
* Если фронтенд может заранее определить состав используемых переменных по выбранной визуализации, он должен передавать в {{export.parameters.variables}} только эти переменные.

* Если в текущей реализации удобнее передавать значения переменных в структурированном виде, а строку для XLSX формировать на бэкенде, необходимо сохранить возможность множественных значений и значений по другому полю.
* Если команда разработки выберет другое внутреннее имя поля вместо {{export.parameters.variables}}, внешнее поведение должно сохраниться: маркер {{\{Variables\}}} в XLSX-шаблонах должен заполняться списком переменных экспортируемой визуализации.

---
h4. 3.4. Новый маркер XLSX-шаблонов {{\{Variables\}}}.

* В рамках задачи вводится новый шаблонный маркер {{\{Variables\}}}, означает: "вывести список переменных, которые использованы при расчёте экспортируемой визуализации".
* Маркер {{\{Variables\}}} не должен выводить:
** переменные всего отчёта или других визуализаций;
** технические данные о использовании переменных;
** SQL-выражения или операторы.
* Формат значения маркера должен быть единообразным для общего шаблона и частного шаблона Таблицы:
** заголовок блока - "Переменные";
** далее список пар "название переменной: значение";
** при множественных значениях переменной использовать текущие разделители XLSX-экспорта;
** при нескольких переменных сохранять стабильный порядок вывода.
* Рекомендуемый порядок вывода переменных - порядок фактического использования в payload экспортируемой визуализации или передачи переменных в {{export.parameters.variables}};
** при отсутствии стабильного порядка - сортировка по отображаемому названию/системному имени, чтобы результат не менялся случайно между экспортами.
* Если список переменных пустой, маркер {{\{Variables\}}} должен заменяться пустым значением, а технический текст маркера не должен попадать в итоговый файл.
* Существующие маркеры {{Filter}}, {{Filters}}, {{Filters_by_rows}}, {{Title}}, {{Report_title}} должны продолжить работать без изменений.

---
h4. 3.5. Общий XLSX-шаблон экспорта.

* Общий XLSX-шаблон сейчас использует фиксированные ячейки {{A1}}-{{A5}} для стилей и режима вывода данных. В рамках задачи нужно расширить общий шаблон новой ячейкой {{A6}}.
* Назначение ячеек общего шаблона после доработки:

|| Ячейка || Назначение ||
| {{A1}} | стиль шапки таблицы с данными |
| {{A2}} | стиль строк таблицы с данными |
| {{A3}} | стиль заголовка визуализации |
| {{A4}} | стиль и режим вывода фильтров |
| {{A5}} | стиль заголовка отчёта |
| {{A6}} | стиль и место вывода блока переменных {{\{Variables\}}} |

* В ячейке {{A6}} общего шаблона должен поддерживаться маркер {{\{Variables\}}}.
* Если в общем шаблоне в {{A6}} указан маркер {{\{Variables\}}} и экспортируемая визуализация использует переменные, в итоговом XLSX должен выводиться блок "Переменные".
* Блок "Переменные" должен выводиться в информационной части XLSX перед таблицей с данными:
** после заголовка отчёта и заголовка визуализации;
** после блока "Фильтры", если фильтры выводятся;
** перед пустой строкой, которая отделяет информационную часть от таблицы данных.
* Если фильтров нет, но переменные есть, блок "Переменные" выводится после заголовка визуализации и перед таблицей данных.
* Если переменных нет, блок "Переменные" не выводится, а таблица данных должна начинаться по текущим правилам с учётом заголовков и фильтров.
* Стиль ячейки {{A6}} должен применяться к блоку переменных по аналогии с тем, как стиль {{A4}} применяется к блоку фильтров.
* Наличие маркера {{\{Variables\}}} в {{A6}} должно управлять выводом переменных в общем шаблоне:
** если маркер задан - переменные выводятся при наличии используемых переменных;
** если маркер не задан - существующие загруженные общие шаблоны не должны начинать выводить переменные автоматически.
* Для системного общего шаблона/шаблона по умолчанию портала необходимо добавить поддержку {{A6}} и маркера {{\{Variables\}}}, чтобы новый блок был доступен без частного шаблона Таблицы.
* Нельзя менять назначение существующих ячеек {{A1}}-{{A5}}.
* Тег {{Filters_by_rows}} в {{A4}} должен продолжить работать по текущей логике и не должен влиять на вывод переменных.

---
h4. 3.6. Частный XLSX-шаблон Таблицы.

* Для частного XLSX-шаблона Таблицы необходимо поддержать маркер {{\{Variables\}}}.
* В частном шаблоне пользователь сам определяет место вывода переменных: блок "Переменные" должен выводиться в той ячейке/области первого листа шаблона, где размещён маркер {{\{Variables\}}}.
* Если частный шаблон Таблицы содержит {{\{Variables\}}} и экспортируемая Таблица использует переменные, при экспорте маркер заменяется списком переменных этой Таблицы.
* Если частный шаблон Таблицы содержит {{\{Variables\}}}, но экспортируемая Таблица не использует переменные, маркер заменяется пустым значением либо обрабатывается по текущей логике пустых маркеров шаблона.
* Если частный шаблон Таблицы не содержит {{\{Variables\}}}, переменные не должны добавляться в XLSX автоматически.
* Если в частном шаблоне одновременно используются маркеры фильтров и переменных:
** {{Filter}}, {{Filters}}, {{Filters_by_rows}} заполняются только фильтрами;
** {{\{Variables\}}} заполняется только переменными;
** порядок и формат фильтров не меняются.
* Маркер {{\{Variables\}}} должен обрабатываться только на первом листе частного шаблона Таблицы по аналогии с существующей логикой переноса данных таблицы. Дополнительные листы шаблона должны переноситься "как есть", если текущий механизм частных шаблонов не обрабатывает на них другие маркеры.
* Для частного шаблона Таблицы не требуется автоматически вставлять блок "Переменные" рядом с фильтрами, если пользователь не разместил маркер {{\{Variables\}}}.
* В рамках этой задачи не вводится отдельный обязательный маркер построчного вывода переменных по аналогии с {{Filters_by_rows}}. Если такой режим потребуется отдельно, его нужно оформлять как самостоятельное расширение шаблонов.

---
h4. 3.7. Учёт настройки "Значения по другому полю" для переменных.

* Если переменная выбирается через контрол/фильтр, для которого задана настройка "Значения по другому полю", в XLSX нужно выводить значения по полю отображения.
* Техническое значение переменной должно продолжать использоваться для расчёта данных экспортируемой визуализации.
* Значение по другому полю не должно подменять системное имя переменной.
* Значение по другому полю не должно менять синтаксис подстановки переменной в выражениях.
* Для получения отображаемого значения необходимо переиспользовать подход, подготовленный в задачах по фильтрам:
** основное значение остаётся значением, которое передаётся в расчёт;
** поле отображения используется только для вывода пользователю;
** при невозможности сопоставления используется безопасная fallback-логика.
* Если для одного технического значения найдено одно отображаемое значение, в XLSX выводится отображаемое значение.
* Если для нескольких технических значений доступны отображаемые значения, они выводятся списком с текущими разделителями XLSX-экспорта.
* Если отображаемое значение не найдено, необходимо вывести техническое значение переменной либо применить существующую обработку невалидных значений.
* Если переменная выбрана через контрол с отображением по другому полю, но такая переменная не используется при расчёте экспортируемой визуализации, она не должна выводиться в XLSX только из-за наличия выбранного значения в контроле.

---
h4. 3.8. Фронтенд-часть.

* При запуске XLSX-экспорта фронтенд должен формировать payload экспорта для конкретной выбранной визуализации, как это происходит сейчас.
* Фронтенд должен передавать текущие значения переменных, доступные в состоянии отчёта на момент экспорта, в объёме, достаточном для:
** расчёта данных экспортируемой визуализации;
** вывода блока "Переменные" в XLSX;
** отображения значений по другому полю, если переменная выбрана через соответствующий контрол.
* Если переменная связана с контролом/фильтром, где включена настройка "Значения по другому полю", фронтенд должен передать или обеспечить доступность:
** технического значения, используемого в расчёте;
** отображаемого значения, которое видел пользователь;
** данных для сопоставления технического и отображаемого значения, если отображаемое значение не передаётся напрямую.
* Фронтенд должен поддержать добавление/сохранение маркера {{\{Variables\}}} в частном XLSX-шаблоне Таблицы без попытки интерпретировать его на стороне интерфейса как обычный текст.
* Если в интерфейсе есть подсказки/документация по XLSX-шаблонам, необходимо добавить описание нового маркера {{\{Variables\}}} и ячейки {{A6}} общего шаблона.

---
h4. 3.9. Бэкенд-часть и API.

* Затрагиваемые backend-объекты и механизмы:
** {{exports}} - формирование XLSX-файла;
** {{reports}} - чтение метаданных отчёта при необходимости;
** {{filtersets}} - получение состояния фильтров/контролов отчёта при необходимости;
** существующий механизм подстановки переменных в запросы данных;
** существующий механизм получения значений фильтра/набора данных для сопоставления значений по другому полю, если он требуется реализации.
* Бэкенд должен иметь доступ к списку текущих значений переменных при выполнении экспорта.
* Бэкенд должен определить, какие из переданных/доступных переменных реально использованы в payload экспортируемой визуализации.
* Бэкенд не должен определять состав переменных для XLSX путём сканирования всех визуализаций отчёта/дашборда, если экспорт выполняется по одной выбранной визуализации.
* Для определения используемых переменных необходимо использовать тот же механизм, который подставляет переменные в выражения и запросы, либо общий сервис/функцию на его основе, чтобы список соответствовал фактически использованным переменным при расчёте экспортируемой визуализации.
* Если переменная используется в выражениях набора данных, которые влияют на запрос экспортируемой визуализации, такая переменная должна считаться используемой в экспортируемой визуализации.
* Если переменная используется только в другой визуализации текущего отчёта/дашборда, такая переменная не должна попадать в блок "Переменные" текущего XLSX-файла.
* Если для отображения значения по другому полю требуется запрос к данным набора данных, необходимо использовать существующий пакетный механизм получения значений и не выполнять отдельный запрос на каждое значение переменной, если можно получить значения пакетно.
* Бэкенд должен поддержать обработку маркера {{\{Variables\}}}:
** в общем шаблоне через ячейку {{A6}};
** в частном шаблоне Таблицы через фактическое расположение маркера на первом листе шаблона.
* Ошибки определения/сопоставления переменных не должны приводить к падению экспорта. Для проблемной переменной нужно применить fallback-логику или исключить её из блока, если значение невозможно определить безопасно.
* При множественном выборе переменной сохранять текущие правила разделителей и форматирования для её значений при XLSX-экспорте.
* Если значение переменной имеет тип дата/дата-время/число/строка, использовать существующее форматирование значения, доступное в портале/экспорте.

h3. 4. Пограничные сценарии.

* В экспортируемой визуализации нет используемых переменных.
* В отчёте есть заведённая переменная, но она не используется в экспортируемой визуализации.
* Переменная используется в другой визуализации текущего дашборда, но не используется в экспортируемой визуализации.
* Одна переменная используется в нескольких вычисляемых полях или нескольких выражениях экспортируемой визуализации.
* Переменная используется в вычисляемом поле экспортируемой визуализации.
* Переменная используется в выражении набора данных или условии, влияющем на выборку экспортируемой визуализации.
* Переменная используется в выражении, где невозможно определить оператор сравнения или бизнес-смысл условия.
* Переменная имеет одно выбранное значение.
* Переменная имеет несколько выбранных значений.
* Переменная выбрана через диапазонный контрол и фактически используется как несколько переменных/значений.
* Для переменной задано отображение значений по другому полю.
* Для переменной задано отображение значений по другому полю, но поле отображения удалено или недоступно.
* Для технического значения переменной не найдено отображаемое значение.
* В общем шаблоне есть ячейка {{A6}} с маркером {{\{Variables\}}}.
* В общем шаблоне отсутствует {{A6}} или в {{A6}} не указан {{\{Variables\}}}.
* В частном шаблоне Таблицы есть маркер {{\{Variables\}}}.
* В частном шаблоне Таблицы нет маркера {{\{Variables\}}}.
* При экспорте XLSX одновременно выводятся фильтры и переменные.
* Экспорт выполняется для визуализации, данные которой зависят от переменной.
* Экспорт выполняется для визуализации, данные которой не зависят от переменной, при этом переменная используется в другом месте текущего дашборда.
* Маркер {{\{Variables\}}} расположен на дополнительном листе частного шаблона Таблицы.
* Экспорт превышает лимит строк/листов XLSX и создаются дополнительные листы/файлы по текущей логике экспорта.

h3. 6. Предположения:

* Под "используемыми переменными" понимаются переменные, которые фактически встречаются в выражениях/запросе экспортируемой визуализации и участвуют при расчёте этой визуализации.
* Текущие значения переменных доступны фронтенду на момент экспорта и уже передаются в запрос данных через {{export.dataset.params.variables}}.
* Для отображения значений по другому полю можно переиспользовать механизм, подготовленный в задачах по фильтрам, либо согласовать эквивалентный способ передачи отображаемых значений в {{export.parameters.variables}}.
* Для общего XLSX-шаблона в рамках задачи резервируется ячейка {{A6}}, так как {{A1}}-{{A5}} уже заняты текущими стилями заголовков, фильтров и таблицы данных.
* Целевое имя поля для информационной части экспорта - {{export.parameters.variables}}. Если в реализации будет выбран другой внутренний ключ, нужно будет внести корректировки.

h3. 7. Критерии приёмки (AC):

AC.1 - *Общий XLSX-шаблон выводит блок переменных экспортируемой визуализации:*
* *Дано:* в отчёте есть визуализация, в расчёте которой используется переменная {{var}};
* *И:* для переменной выбрано значение "Накопительно";
* *И:* общий XLSX-шаблон содержит маркер {{\{Variables\}}} в ячейке {{A6}};
* *Когда:* пользователь экспортирует эту визуализацию в XLSX с общим шаблоном;
* *Тогда:* в XLSX отображается отдельный блок "Переменные";
* *И:* в блоке отображается переменная {{var}} или её пользовательское название;
* *И:* значение переменной отображается как "Накопительно".

AC.2 - *Переменные выводятся только для экспортируемой визуализации:*
* *Дано:* в текущем отчёте/дашборде есть две визуализации;
* *И:* переменная {{var}} используется только во второй визуализации;
* *Когда:* пользователь экспортирует первую визуализацию, которая не использует {{var}};
* *Тогда:* переменная {{var}} не отображается в XLSX первой визуализации.

AC.3 - *Переменные не смешиваются с фильтрами:*
* *Дано:* к экспортируемой визуализации применены фильтры и при её расчёте используются переменные;
* *Когда:* пользователь экспортирует визуализацию в XLSX;
* *Тогда:* фильтры отображаются в блоке фильтров по текущей логике;
* *И:* переменные отображаются в отдельном блоке "Переменные";
* *И:* переменные не добавляются как элементы блока фильтров.

AC.4 - *Используемая переменная выводится один раз:*
* *Дано:* переменная {{var}} используется в нескольких выражениях экспортируемой визуализации;
* *Когда:* пользователь экспортирует эту визуализацию в XLSX;
* *Тогда:* переменная {{var}} отображается в блоке "Переменные" один раз;
* *И:* её значение соответствует актуальному значению на момент экспорта.

AC.5 - *Неиспользуемая в экспортируемой визуализации переменная не выводится:*
* *Дано:* в отчёте есть заведённая переменная, которая не используется в выражениях/запросе экспортируемой визуализации;
* *Когда:* пользователь экспортирует эту визуализацию в XLSX;
* *Тогда:* такая переменная не отображается в блоке "Переменные".

AC.6 - *Значение по другому полю выводится для переменной:*
* *Дано:* переменная выбирается через контрол, где техническое значение используется для расчёта экспортируемой визуализации;
* *И:* для контрола задана настройка "Значения по другому полю";
* *И:* пользователь видит и выбирает значение "Миллионы рублей", а в расчёт передаётся техническое значение;
* *Когда:* пользователь экспортирует визуализацию в XLSX;
* *Тогда:* в блоке "Переменные" отображается значение "Миллионы рублей";
* *И:* техническое значение не отображается вместо человекочитаемого, если сопоставление доступно.

AC.7 - *Расчёт данных при экспорте не меняется:*
* *Дано:* экспортируемая визуализация зависит от значения переменной {{var}};
* *Когда:* пользователь экспортирует визуализацию в XLSX после доработки;
* *Тогда:* данные в XLSX рассчитаны по той же логике, что и до доработки;
* *И:* доработка влияет только на информационный блок переменных в XLSX.

AC.8 - *Частный шаблон Таблицы с {{\{Variables\}}} выводит переменные в указанном месте:*
* *Дано:* Таблица использует частный XLSX-шаблон с маркером {{\{Variables\}}};
* *И:* в расчёте этой Таблицы используются переменные;
* *Когда:* пользователь экспортирует Таблицу в XLSX;
* *Тогда:* на месте маркера {{\{Variables\}}} выводится список переменных этой Таблицы;
* *И:* значения по другому полю учитываются при наличии соответствующей настройки.

AC.9 - *Частный шаблон Таблицы без {{\{Variables\}}} не меняет поведение:*
* *Дано:* Таблица использует частный XLSX-шаблон без маркера {{\{Variables\}}};
* *Когда:* пользователь экспортирует Таблицу;
* *Тогда:* переменные не добавляются в файл автоматически;
* *И:* существующий результат экспорта по шаблону сохраняется.

AC.10 - *Существующие маркеры фильтров работают без изменений:*
* *Дано:* Таблица использует частный XLSX-шаблон с маркерами {{Filters}} или {{Filters_by_rows}};
* *И:* в шаблон добавлен маркер {{\{Variables\}}};
* *Когда:* пользователь экспортирует Таблицу в XLSX;
* *Тогда:* маркеры фильтров заполняются только фильтрами;
* *И:* маркер {{\{Variables\}}} заполняется только переменными;
* *И:* формат и порядок вывода фильтров не меняются.

AC.11 - *Множественные значения переменной отображаются списком:*
* *Дано:* используемая в экспортируемой визуализации переменная имеет несколько выбранных значений;
* *Когда:* пользователь экспортирует визуализацию в XLSX;
* *Тогда:* в блоке "Переменные" отображаются все выбранные значения переменной;
* *И:* используются текущие разделители и форматирование XLSX-экспорта.

AC.12 - *Диапазонная переменная выводится без интерпретации условий:*
* *Дано:* переменная или группа переменных выбрана через диапазонный контрол;
* *И:* эти переменные используются в выражениях экспортируемой визуализации;
* *Когда:* пользователь экспортирует визуализацию в XLSX;
* *Тогда:* в блоке "Переменные" выводятся фактически используемые переменные и их значения;
* *И:* портал не добавляет условия "больше либо равно", "меньше либо равно", "с/по", если они не являются явной частью названия/значения переменной.

AC.13 - *Безопасная деградация при недоступном значении по другому полю:*
* *Дано:* для переменной, используемой в экспортируемой визуализации, настроено отображение значения по другому полю;
* *И:* отображаемое значение не удалось получить или поле отображения недоступно;
* *Когда:* пользователь экспортирует визуализацию в XLSX;
* *Тогда:* экспорт завершается успешно;
* *И:* для проблемной переменной выводится техническое значение либо применяется существующая fallback-логика;
* *И:* ошибка одной переменной не ломает весь XLSX-файл.

AC.14 - *Визуализации без используемых переменных работают без изменений:*
* *Дано:* экспортируемая визуализация не использует переменные;
* *Когда:* пользователь экспортирует её в XLSX;
* *Тогда:* блок "Переменные" не выводится;
* *И:* экспорт выполняется по текущей логике без визуальных и функциональных изменений, не связанных с другими задачами цикла.

AC.15 - *Маркер {{\{Variables\}}} не попадает в итоговый XLSX как текст:*
* *Дано:* XLSX-шаблон содержит маркер {{\{Variables\}}};
* *И:* экспортируемая визуализация не использует переменные либо список переменных не удалось сформировать безопасно;
* *Когда:* пользователь экспортирует визуализацию в XLSX;
* *Тогда:* в итоговом файле не остаётся технический текст маркера {{\{Variables\}}};
* *И:* экспорт завершается успешно.
