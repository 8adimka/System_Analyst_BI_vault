h3. Контекст и проблематика.

Панель индикации фильтров показывает пользователю активные фильтры отчёта и выбранные значения. После выноса настройки "Значения по другому полю" на уровень глобальных фильтров панель должна использовать эту настройку при отображении активных значений.

Сейчас фильтр может быть настроен так, что фактическая фильтрация выполняется по техническому полю, а пользователь в контейнере фильтров видит человекочитаемые значения из другого поля. Панель индикации фильтров при этом не использует глобальную настройку отображения и может показывать технические значения.

Задача выполняется после реализации технической основы в рамках [https://jira.modusbi.ru/browse/MB-4774].

----

h3. Цель задачи.

*Требуется:*
# Доработать Панель индикации фильтров так, чтобы она отображала значения активных фильтров с учётом глобальной настройки "Значения по другому полю".
# Сохранить текущую логику применения и сброса фильтров по основному полю фильтрации.
# Обеспечить корректное отображение значений независимо от того, где пользователь выбрал фильтр: в контейнере фильтров, боковой Панели фильтров или через восстановленное состояние отчёта.
# Сохранить текущую логику панели для фильтров с неактивной настройкой "Значения по другому полю".

_Пользовательская история:_
Как пользователь отчёта, я хочу видеть в Панели индикации фильтров человекочитаемые значения активных фильтров, чтобы быстро понимать, какие фильтры применены к данным.

----

h3. 1. Описание текущего поведения.

* Панель индикации фильтров отображает активные фильтры отчёта.
* Для фильтра, настроенного по другому полю, панель не использует глобальную настройку отображения значений.
* Для примера, в рамках отчёта [https://dev.modusbi.ru/report/796], для _"Месяц"_ фильтрация выполняется по полю {{month_num}}, включена настройка "Значения по другому полю" для отображения значений из {{month_name}}.
* Если фильтр "Месяц" применяет значения {{month_num}} = {{2}}, {{3}}, панель может показывать технические значения вместо значений из {{month_name}}.
* Отображение активного фильтра может отличаться от того, что пользователь видит в контейнере фильтров.

----

h3. 2. Описание целевого поведения.

* Панель индикации фильтров должна читать настройку "Значения по другому полю" из глобального фильтра.
* Панель индикации фильтров не должна требовать, чтобы поле отображения значений было добавлено на полки визуализации.
* Отображение должно быть одинаковым для значений, выбранных в контейнере фильтров, боковой Панели фильтров или восстановленных при открытии отчёта.
* Если для активного фильтра задана настройка "Значения по другому полю":
** название фильтра отображается по текущему названию глобального фильтра/заголовку фильтра;
** выбранные значения отображаются по полю отображения;
** операции сброса/удаления активного фильтра выполняются по текущей логике глобального фильтра.
* Если настройка не задана, активный фильтр отображается по текущей логике без изменений.

----

h3. 3. Требования к реализации:

h4. 3.1. Фронтенд-часть.

* При построении элементов Панели индикации фильтров использовать глобальные настройки фильтров отчёта.
* Для каждого активного фильтра проверять наличие настройки "Значения по другому полю".
* Если настройка есть, сопоставлять выбранные значения основного поля со значениями поля отображения.
* В панели показывать пользователю значения из поля отображения, а не технические значения основного поля.
* При удалении значения/сбросе фильтра из Панели индикации фильтров применять действие к глобальному фильтру по основному полю.
* Не подменять название фильтра названием поля отображения.
* Если поле отображения недоступно или настройка невалидна, панель не должна падать. Необходимо применить безопасную fallback-логику: отображение по основному полю или существующая обработка невалидных метаданных.
* Если фильтр имеет множественный выбор, все выбранные значения должны отображаться по полю отображения с текущими разделителями.

---
h4. 3.2. Бэкенд-часть и API.

* Затрагиваемые backend-объекты: {{reports}}, {{filtersets}}, существующий механизм получения значений фильтра из набора данных.
* Панель индикации фильтров должна использовать настройку, подготовленную в [https://jira.modusbi.ru/browse/MB-4774].
* Если для сопоставления выбранных значений требуется получить данные набора данных, следует использовать текущий механизм получения значений фильтра и не вводить отдельный API-контракт в рамках этой задачи.
* Перед изменением сохранённых настроек отчёта, если такое изменение потребуется, необходимо читать актуальное состояние через {{get}}/{{list}}.

---
h4. 3.3. Логика выбора набора данных.

* Не менять текущий механизм выбора основного/первого источника данных глобального фильтра.
* Если одинаковое имя фильтра используется в разных наборах данных, поведение Панели индикации фильтров должно соответствовать текущей логике глобальных фильтров.
* Конфликты одинаковых наименований из разных наборов данных остаются ответственностью настройки отчёта и не решаются новой логикой в рамках этой задачи.

---
h4. 3.4. Технические требования и ограничения.

* Не менять SQL-логику фильтрации.
* Не менять правила применения, снятия и синхронизации глобальных фильтров, кроме отображения значений.
* Не менять XLSX-экспорт в рамках этой задачи.
* Не менять боковую Панель фильтров в рамках этой задачи.
* Не менять работу переменных отчёта.
* Сохранить обратную совместимость со старыми отчётами (до текущей доработки) и с отчётами без настройки "Значения по другому полю".

----

h3. 4. Пограничные сценарии:

* У активного фильтра отсутствует настройка "Значения по другому полю".
* У активного фильтра настройка задана, но поле отображения удалено или недоступно.
* Выбранное значение основного поля не удалось сопоставить со значением поля отображения.
* У фильтра выбран один элемент.
* У фильтра выбран несколько элементов.
* Значение выбрано в контейнере фильтров.
* Значение выбрано в боковой Панели фильтров.
* Значение восстановлено при открытии отчёта/применении сохранённого состояния.
* Поле отображения отсутствует на полках визуализации.
* В отчёте есть одинаково названные фильтры из разных наборов данных.
** В рамки данной задачи не входит изменение логики объединения глобальных фильтров по одинаковым именам.

h3. 6. Критерии приёмки (AC):

AC.1 — *Панель индикации показывает значения по другому полю:*
* *Дано:* глобальный фильтр "Месяц" фильтрует по {{month_num}} и имеет настройку отображения по {{month_name}};
* *И:* выбраны значения февраль и март;
* *Когда:* пользователь открывает отчёт с включённой Панелью индикации фильтров;
* *Тогда:* в панели для фильтра "Месяц", при попытке выбора значений, отображаются "Февраль" и "Март";
* *И:* технические значения {{2}} и {{3}} не показываются как значения этого фильтра.

AC.2 — *Сброс значения работает по основному фильтру:*
* *Дано:* в Панели индикации фильтров отображается активный фильтр со значениями по другому полю;
* *Когда:* пользователь удаляет значение или сбрасывает фильтр через панель;
* *Тогда:* сбрасывается соответствующее значение глобального фильтра по основному полю;
* *И:* визуализации пересчитываются по текущей логике фильтрации.

AC.3 — *Выбор значения из Контейнера с фильтрами отображается в панели индикации:*
* *Дано:*  в контейнере с фильтрами на полке размещено поле {{month_num}} и настройка "Значения по другому полю" активна - по полю {{month_name}, пользователь выбрал "февраль" и "март";
* *Когда:* Панель индикации фильтров отображает активные фильтры;
* *Тогда:* выбранные значения отображаются как "февраль" и "март".

AC.4 — *Выбор из боковой Панели фильтров отображается в панели индикации:*
* *Дано:* в контейнере с фильтрами включена настройка "Значения по другому полю", боковая Панель фильтров отображает значения фильтра в соответствии с выбранным полем для отображения;
* *Когда:* пользователь выбирает значение фильтра в боковой Панели фильтров;
* *Тогда:* Панель индикации фильтров показывает выбранное значение по полю отображения.

AC.5 — *Восстановленные значения отображаются по глобальной настройке:*
* *Дано:* отчёт открывается с уже применёнными значениями глобального фильтра;
* *И:* для фильтра задано отображение по другому полю;
* *Когда:* Панель индикации фильтров строит список активных фильтров;
* *Тогда:* восстановленные значения отображаются по полю отображения.

AC.6 — *Фильтры без настройки отображаются по текущей логике:*
* *Дано:* активный фильтр не имеет настройки "Значения по другому полю";
* *Когда:* Панель индикации фильтров отображает активные фильтры;
* *Тогда:* значения такого фильтра отображаются по текущей логике без изменений.

AC.7 — *Поле отображения не обязано быть на полке визуализации:*
* *Дано:* поле {{month_name}} выбрано как поле отображения значений глобального фильтра;
* *И:* поле {{month_name}} не добавлено на полки визуализации;
* *Когда:* Панель индикации фильтров отображает активный фильтр;
* *Тогда:* значения отображаются по {{month_name}}.

AC.8 — *Безопасная деградация при невалидной настройке:*
* *Дано:* у глобального фильтра указано поле отображения значений, которое было удалено или стало недоступно;
* *Когда:* Панель индикации фильтров строит активные фильтры;
* *Тогда:* отчёт не падает;
* *И:* фильтр отображается по основному полю (либо обрабатывается существующим механизмом невалидных метаданных).
