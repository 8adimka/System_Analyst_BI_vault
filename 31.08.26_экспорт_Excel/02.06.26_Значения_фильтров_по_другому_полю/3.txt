h3. Контекст и проблематика.  В аналитическом портале переменные могут использоваться в выражениях набора данных, вычисляемых полях и в иных местах, влияющих на результат визуализации. Пользователь выбирает значения переменных в отчёте, после чего данные визуализации пересчитываются с учётом этих значений.  Сейчас при экспорте данных в XLSX пользователь получает результат, уже рассчитанный с учётом выбранных переменных, но в выгруженном файле не видит, какие значения переменных были применены. Из-за этого экспортированный файл сложнее интерпретировать вне портала.  Дополнительно переменная может задаваться через фильтр/контрол в контейнере фильтров, где используется настройка "Значения по другому полю": в вычисление передаётся техническое значение переменной, а пользователь видит человекочитаемое значение. При экспорте в XLSX нужно выводить именно то значение, которое пользователь видел в отчёте, а не технический код, если для переменной доступно отображение по другому полю.  При этом портал не может надёжно определить, в каком именно выражении, вычисляемом поле, условии или другом контексте была использована переменная и какой логический оператор к ней применялся. Поэтому в XLSX должен выводиться не разбор выражений, а плоский список используемых в отчёте переменных и их текущих значений.  Задача завершает цикл доработок по единообразному отображению значений фильтров и переменных в интерфейсе и XLSX-экспорте.  ---- h3. Цель задачи.  *Требуется:* # Добавить отображение переменных, которые используются при расчёте экспортируемой визуализации, при экспорте данных в XLSX. # Выводить переменные отдельным блоком "Переменные" по аналогии с блоком фильтров, но без попытки интерпретировать условия, операторы и места использования переменных. # Для переменных, выбранных через контрол с настройкой "Значения по другому полю", отображать в XLSX человекочитаемые значения по полю отображения, а не технические значения, передаваемые в расчёт. # Поддержать вывод переменных в общем XLSX-шаблоне и в частном шаблоне Таблицы. # Сохранить текущую логику расчёта данных, подстановки переменных и экспорта для визуализаций, где переменные не используются.  _Пользовательская история:_ Как пользователь отчёта, я хочу видеть в XLSX-выгрузке значения переменных, с которыми были рассчитаны экспортированные данные, чтобы корректно интерпретировать файл вне портала.  ---- h3. 1. Описание текущего поведения.  * В отчёте могут быть настроены переменные, значения которых выбираются пользователем через элементы управления отчёта/контейнер фильтров. * Значения переменных передаются в запросы данных визуализаций и влияют на результат расчёта, если переменные используются в выражениях, участвующих в расчёте конкретной визуализации. * Например:  {code:json} "variables": [   {     "name": "var",     "values": ["Накопительно"]   } ] {code}  * Экспортируемые данные рассчитываются с учётом используемых переменных, но пользователь не видит значение этих переменних в XLSX. * Если пользователь выбрал значение переменной через контрол с отображением значений по другому полю, в расчёт может уходить техническое значение, а человекочитаемое значение не выводится в XLSX.  ---- h3. 2. Описание целевого поведения.  * При экспорте данных в XLSX портал должен формировать список переменных, которые используются при расчёте экспортируемой визуализации и имеют актуальные значения на момент экспорта. * В XLSX должен выводиться отдельный блок "Переменные". * Для каждой переменной в блоке нужно выводить: ** отображаемое название переменной, если оно доступно; ** системное имя переменной, если отображаемое название недоступно; ** выбранное значение или список выбранных значений. * Если в контейнере с фильтрами используются переменные и настроено отображение значений по другому полю, в XLSX должны выводиться значения по полю отображения. * Если отображение по другому полю не задано или недоступно, значение переменной должно выводиться по текущему значению, которое используется в расчёте. * Если одна и та же переменная используется в нескольких выражениях экспортируемой визуализации, она должна выводиться в блоке "Переменные" один раз. * Если переменная заведена в отчёте, имеет выбранное значение или используется в другой визуализации дашборда, но не участвует в расчёте экспортируемой визуализации, она не должна выводиться в XLSX выгрузке экспортируемой визуализации. * В XLSX не нужно выводить: ** место использования переменной; ** имя вычисляемого поля, где переменная встретилась; ** выражение, в котором переменная использована; ** SQL-условие или или используемый оператор сравнения; ** И иную информацию, если она не является явной частью названия/значения переменной. * Если в экспортируемой визуализации нет используемых переменных с актуальными значениями, блок "Переменные" не должен выводиться. * Фильтры и переменные должны выводиться как разные сущности: ** блок "Фильтры" продолжает работать по реализованной логике; ** блок "Переменные" выводит только переменные и их значения.  ---- h3. 3. Требования к реализации:  h4. 3.1. Логика XLSX-экспорта.  * Затрагиваемый backend-объект: {{exports}} и текущая команда XLSX-экспорта. * Экспорт выполняется для конкретной визуализации, выбранной пользователем. Состав переменных для XLSX должен определяться в рамках данных и выражений этой визуализации. * При формировании XLSX-файла экспорт должен получать или определять список переменных, использованных при расчёте экспортируемой визуализации, и их актуальные значения. * Экспорт должен использовать этот список только для отображения блока "Переменные" в XLSX. * Подстановка переменных в запросы данных должна работать по текущей логике без изменений. * Доработка не должна менять результат расчёта экспортируемой визуализации. * Ошибка получения отображаемого значения переменной не должна прерывать экспорт всего XLSX-файла.  --- h4. 3.2. Определение списка используемых переменных.  * Требуется выводить переменные, которые фактически используются в запросе/выражениях экспортируемой визуализации, а не весь список переменных, которые заведены в отчёте или доступны в состоянии отчёта. * Нельзя формировать список переменных на уровне всего отчёта/дашборда, если экспортируется только конкретная визуализация. * Для определения используемых переменных необходимо опираться на существующий механизм подстановки переменных в запросы/выражения либо на результат этой подстановки. * Минимально ожидаемая логика: ** взять payload экспорта выбранной визуализации, в том числе {{export.dataset.params}}; ** определить имена переменных, которые были использованы механизмом подстановки при подготовке запроса данных для экспорта именно этой визуализации, и значения этих переменных;".
