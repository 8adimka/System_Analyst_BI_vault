h3. Контекст и проблематика.

В аналитическом портале боковая Панель фильтров позволяет пользователю просматривать и изменять значения фильтров отчёта. После выноса настройки "Значения по другому полю" на уровень глобальных фильтров панель должна использовать эту настройку при отображении и выборе значений.

Сейчас настройка отображения значений по другому полю работает в контейнере с фильтрами, но боковая Панель фильтров не использует её как глобальную настройку. В результате пользователь может видеть в контейнере человекочитаемые значения, а в боковой панели — технические значения основного поля или некорректный набор значений.

Задача выполняется после реализации технической основы в рамках [https://jira.modusbi.ru/browse/MB-4774].

----

h3. Цель задачи.

*Требуется:*
# Доработать боковую Панель фильтров так, чтобы она использовала глобальную настройку "Значения по другому полю".
# При активации этой настройки отображать пользователю значения из поля _отображения_, а фильтрацию выполнять по _основному полю_.
# Обеспечить синхронизацию между контейнером фильтров, глобальным фильтром и боковой Панелью фильтров.
# При отсутствии активации настройки "Значения по другому полю", сохранить текущую логику работы панели для фильтров.

_Пользовательская история:_
Как пользователь отчёта, я хочу видеть и выбирать в боковой Панели фильтров те же человекочитаемые значения, что и в контейнере фильтров, чтобы не работать с техническими кодами и идентификаторами.

----

h3. 1. Описание текущего поведения.

* В контейнере с фильтрами может быть настроено отображение значений по другому полю.
* Для примера, в рамках отчёта [https://dev.modusbi.ru/report/796], для _"Месяц"_ фильтрация выполняется по полю {{month_num}}, а отображаемые значения берутся из {{month_name}}.
* Боковая Панель фильтров сейчас не использует эту настройку как глобальную настройку фильтра.
* При открытии боковой Панели фильтров, значения отображаются по основному полю даже при использовании настройки "Значения по другому полю".

----

h3. 2. Описание целевого поведения.

* Боковая Панель фильтров должна читать настройку "Значения по другому полю" из глобального фильтра.
* Если для фильтра настройка задана:
** в списке доступных значений отображаются значения из поля отображения;
** выбранные значения отображаются пользователю по полю отображения;
** при применении фильтра в {{payload}} остаются значения основного поля фильтрации.
* Если для фильтра настройка не задана, боковая Панель фильтров работает по текущей логике.
* Название фильтра в боковой панели должно соответствовать названию глобального фильтра или настроенному заголовку фильтра.
* Боковая Панель фильтров не должна требовать, чтобы поле отображения значений было добавлено на полку визуализации.
* Выбор, снятие выбора и сброс фильтра в боковой панели должны работать синхронно с контейнером фильтров и остальными потребителями глобального фильтра.

----

h3. 3. Требования к реализации:

h4. 3.1. Фронтенд-часть.

* При построении списка фильтров боковой Панели фильтров использовать глобальные настройки фильтров отчёта.
* Для каждого фильтра проверять наличие настройки "Значения по другому полю".
* Если настройка есть, при загрузке доступных значений получать пары:
** значение основного поля, которое используется для фильтрации;
** значение поля отображения, которое показывается пользователю.
* В UI боковой панели фильтров пользователь должен видеть отображаемое значение, но фильтрация должна происходить по значению основного поля.
* При уже выбранных значениях фильтра боковая панель должна показывать их по полю отображения.
* При выборе значения в контейнере фильтров боковая панель должна показывать актуальный выбор по полю отображения.
* Поиск значений в боковой панели, если он доступен для фильтра, должен работать по отображаемым значениям.
* При сбросе фильтра из боковой панели должен сбрасываться глобальный фильтр по основному полю.
* Если поле отображения недоступно или настройка невалидна, панель не должна падать. Необходимо применить безопасную fallback-логику: отображение по основному полю или существующая обработка невалидных метаданных.

---
h4. 3.2. Бэкенд-часть и API.

* Затрагиваемые backend-объекты: {{reports}}, {{filtersets}}, существующий механизм получения значений фильтра из набора данных.
* Боковая Панель фильтров должна использовать настройку, подготовленную в [https://jira.modusbi.ru/browse/MB-4774], а не локальную настройку отдельной визуализации.
* Если для получения значений используется запрос к данным набора данных, запрос должен получать значения так, чтобы можно было сопоставить основное поле фильтрации с полем отображения.
* Использовать, по возможности, текущие команды чтения отчёта/фильтрсетов (если они достаточны).

---
h4. 3.3. Логика выбора набора данных.

* В рамках этой задачи не планируется вводить новую логику разрешения конфликтов одинаковых имён глобальных фильтров.
* Если для глобального фильтра уже выбран основной набор данных, боковая панель должна использовать его.
* Если основной набор данных выбирается автоматически, использовать текущий механизм портала, включая выбор главного/первого источника.
* Если одинаковое имя фильтра используется в разных наборах данных, поведение должно соответствовать текущей логике глобальных фильтров: такой фильтр считается одним фильтром, а конфликты настройки остаются ответственностью автора отчёта.

---
h4. 3.4. Технические требования и ограничения.

* Не менять SQL-логику фильтрации визуализаций.
* Не менять правила синхронизации глобальных фильтров между компонентами, кроме необходимости отображать значения по другому полю.
* Сохранить обратную совместимость с отчётами без настройки "Значения по другому полю".
* Не менять XLSX-экспорт, Панель индикации фильтров и работу переменных отчёта в рамках этой задачи (решается в рамках другой задачи).

----

h3. 4. Пограничные сценарии:

* У фильтра задана настройка "Значения по другому полю", но поле отображения удалено из набора данных.
* Для выбранного значения основного поля не найдено отображаемое значение.
* Фильтр поддерживает множественный выбор.
* Фильтр сбрасывается из боковой панели.
* Значение выбирается в контейнере фильтров, а затем проверяется в боковой панели.
* Значение выбирается в боковой панели, а затем проверяется в контейнере фильтров.
* Поле отображения отсутствует на полках визуализации.
* В отчёте есть несколько наборов данных и глобальные фильтры с одинаковыми именами.

h3. 6. Критерии приёмки (AC):

AC.1 — *Боковая панель показывает значения по другому полю:*
* *Дано:* глобальный фильтр "Месяц" фильтрует по {{month_num}} и имеет настройку отображения по {{month_name}};
* *Когда:* пользователь открывает боковую Панель фильтров;
* *Тогда:* в списке значений фильтра отображаются значения из {{month_name}}, а не технические значения {{month_num}}.

AC.2 — *Выбор в боковой панели применяет фильтрацию по основному полю:*
* *Дано:* пользователь открыл боковую Панель фильтров для фильтра "Месяц";
* *Когда:* пользователь выбирает отображаемое значение февраль;
* *Тогда:* глобальный фильтр применяет соответствующее значение основного поля {{month_num}};
* *И:* визуализации фильтруются по основному полю.

AC.3 — *Синхронизация выбора из контейнера фильтров:*
* *Дано:* пользователь выбрал февраль и март в контейнере фильтров;
* *Когда:* пользователь открывает боковую Панель фильтров;
* *Тогда:* выбранные значения отображаются как февраль и март;
* *И:* технические значения {{2}} и {{3}} не показываются пользователю как выбранные значения фильтра.

AC.4 — *Синхронизация выбора из боковой панели:*
* *Дано:* пользователь выбрал значения фильтра в боковой Панели фильтров;
* *Когда:* пользователь смотрит контейнер фильтров;
* *Тогда:* контейнер фильтров показывает тот же выбор по текущей логике отображения значений.

AC.5 — *Фильтры без настройки работают по текущей логике:*
* *Дано:* глобальный фильтр не имеет настройки "Значения по другому полю";
* *Когда:* пользователь открывает боковую Панель фильтров;
* *Тогда:* значения фильтра отображаются и выбираются по текущей логике без изменений.

AC.6 — *Поле отображения не обязано быть на полке визуализации:*
* *Дано:* поле {{month_name}} выбрано как поле отображения значений глобального фильтра;
* *И:* поле {{month_name}} не добавлено на полки визуализации;
* *Когда:* пользователь открывает боковую Панель фильтров;
* *Тогда:* панель всё равно отображает значения фильтра по {{month_name}}.

AC.7 — *Безопасная деградация при невалидной настройке:*
* *Дано:* поле отображения значений удалено или недоступно;
* *Когда:* пользователь открывает боковую Панель фильтров;
* *Тогда:* панель не падает;
* *И:* фильтр отображается по основному полю (либо обрабатывается существующим механизмом невалидных метаданных).

AC.8 — *Сохранение текущей логики одинаковых имён фильтров:*
* *Дано:* в отчёте есть одинаково названные фильтры из разных наборов данных;
* *Когда:* пользователь открывает боковую Панель фильтров;
* *Тогда:* фильтры обрабатываются по текущей логике глобальных фильтров;
* *И:* новая логика выбора {{datasetId}} для каждой пилюли не требуется.
