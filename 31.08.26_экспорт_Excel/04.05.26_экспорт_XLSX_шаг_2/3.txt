В рамках доработки нашего аналитического портала Modus BI, была составлена постановка - "h3. Контекст:

Данная задача является вторым этапом доработки механизма экспорта в XLSX. 
В рамках первого этапа была восстановлена работа шаблонов с преднастроенными визуализациями и обеспечено сохранение дополнительных листов шаблона выгрузки.
Цель текущего этапа — улучшить читаемость и визуальное оформление значений применяемых фильтров в экспортируемых файлах без изменения текущей логики отбора данных.
----
h3. Проблематика (AS IS):
 * Значения фильтров выводятся в квадратных скобках, что визуально перегружает отчет.
 * Отсутствует понятное разделение между разными фильтрами, если они выводятся в одну строку.
 * Строковые и числовые значения не разделяются синтаксически-однозначно, что может вызывать путаницу.
 * Диапазонные фильтры читаются неочевидно.
 * При выборе всех значений в фильтре выводится длинный список из всех возможных вариантов.
 * Большие числа выводятся без разделителей разрядов, а даты могут иметь непредсказуемый формат.
 * Колонки в Общем шаблоне приходится раздвигать вручную.

----
h3. Требования к реализации (TO BE):
h4. 1. Типизация и разделение значений в фильтрах со списком.
 * Квадратные скобки при выводе значений должны быть удалены.
 * *Формат вывода фильтра:* `{{{}Название фильтра{}}}: {{{}Значение1{}}}, {{{}Значение2`{}}}.
 * *Строковые значения:* Каждое строковое значение необходимо оборачивать в одинарные кавычки.
Пример: `Поставщик: 'АвтоВАЗ', 'O'Reilly'`.
 ** Если внутри значения есть одинарная кавычка - оставляем её без изменений.
 * *Числовые значения:* Выводятся без кавычек.
Пример: `ID менеджера: 10, 15, 22`.
 * *Даты и дата-время:* Выводятся без кавычек, в формате, определяемом в п. 3.
 * *Разделитель фильтров в одной строке:* Для `{{{}Filter{}}}` и `{{{}Filters{}}}` между разными фильтрами используется разделитель `; `.
Пример: `Регион: 'Москва'; Год: 2024; Менеджер: 10`.

h4. 2. Форматирование числовых значений.
 * Для числовых значений применять разделение разрядов по правилам текущей локализации платформы.
Пример: `1 500 000` или `1 500 000,50`.
 * При форматировании чисел не выполнять дополнительное округление и не изменять точность значения сверх текущей логики формирования значения фильтра.
 * Числовое форматирование не применяется к строкам и датам.
 * {*}Опционально, но желательно{*}, ввести исключение для {*}года{*}: Если значение является годом (система должна определять это по типу/семантике поля), то разделители разрядов применяться {*}не должны{*}.
Пример: `Год: 2024`, а не `Год: 2 024`.

h4. 3. Форматирование дат.
 * При экспорте фильтров с датами в первую очередь брать *формат даты* из «Общих настроек» экспортируемой визуализации.
 * Если в настройках визуализации формат не задан/недоступен или для данного типа визуализации не поддерживается — применяется формат по умолчанию: `ДД.ММ.ГГГГ`.
 * Если формат визуализации включает время — выводить дату со временем.
 * Даты выводятся без одинарных кавычек, разделители разрядов не применяются.

h4. 4. Формат отображения диапазонных и сравнительных фильтров.
 * Для диапазонных и сравнительных фильтров использовать отдельный формат — *без двоеточия* перед оператором.
 * Поддерживаемые операторы: `=`, `<>`, `>`, `>=`, `<`, `<=`, `~` (последний - это поиск по части строки, аналог LIKE).
 * Значения внутри диапазонного фильтра соединяются союзами ` И ` или ` ИЛИ ` (заглавными буквами, с пробелами).
 * Для строковых значений использовать одинарные кавычки; для чисел и дат — без кавычек.
 ** Пример 1 (одно условие): `Сумма продаж > 1 000 000`
 ** Пример 2 (диапазон И): `Дата заказа >= 01.01.2025 И < 31.01.2025`
 ** Пример 3 (диапазон ИЛИ): `Дата заказа >= 01.01.2025 ИЛИ <= 31.01.2025`
 ** Пример 4 (строковый поиск): `Регион ~ 'Волгогр'`
 ** Пример 5 (точное совпадение, строка): `Название = 'Тест'`

h4. 5. Общие правила применения.
 * Все правила из данной задачи применяются одинаково в _Общем шаблоне_ и в {_}Частном шаблоне{_}.
 * В экспорт должны попадать только те фильтры, которые фактически применены к выбранной визуализации, согласно текущей реализованной логике.
 * Если для выбранной визуализации отсутствуют применённые фильтры, соответствующий плейсхолдер должен заменяться на пустую строку без служебных разделителей.
 * Логика вывода названия фильтра остаётся без изменений и использует следующий приоритет:
 ## Заголовок поля, заданный на полке «Фильтры»;
 ## Если заголовок не задан — алиас поля из Набора данных;
 ## Если алиас недоступен — использовать текущее поведение системы (системное наименование поля из Набора данных).
 * В плейсхолдерах {{Filter}} и {{Filters}} — вывод всех фильтров в одну строку с разделителем `; `.
 * В плейсхолдере {{Filters_by_rows}} и Общем шаблоне — вывод каждого фильтра с новой строки.
 * *Вычисляемые поля:* Для вычисляемых полей использовать итоговый тип результата — числовой, строковый или дата/дата-время — и применять соответствующее правило форматирования из данной задачи.
 * *Fallback:* Если тип значения надёжно определить невозможно: использовать текущее строковое представление значения без добавления разделителей разрядов и без попытки привести его к дате.

----
h3. Границы задачи:

Доработка обязательна для:
 * Общего шаблона экспорта XLSX;
 * Частного шаблона экспорта XLSX компонента «Таблица».

Доработка не должна:
 * менять состав фильтров, попадающих в экспорт;
 * менять порядок фильтров;
 * менять текущую логику локальных и невидимых фильтров;
 * ломать ранее реализованную поддержку {{{}Report_title{}}}, много-листовых шаблонов с преднастроенными визуализациями, сохранения дополнительных листов/файлов с данными и прочую реализованную логику выгрузки.

h3. Критерии приемки (AC):
 * *AC 1: Вывод строк и чисел в списочных фильтрах*
 ** *Дано:* Применен фильтр по строковому полю «Город» (значения: Москва, Санкт-Петербург) и числовому полю «ID» (значения: 1, 2).
 ** *Когда:* Выполняется экспорт таблицы в XLSX с построчным выводом фильтров ({{{}Filters_by_rows{}}}).
 ** *Тогда:* В XLSX фильтры отображаются на разных строках:
Строка 1: `Город: 'Москва', 'Санкт-Петербург'`
Строка 2: `ID: 1, 2`

 * *AC 2: Вывод фильтров в одну строку*
 ** *Дано:* Применены те же фильтры, что и в AC 1. В шаблоне используется плейсхолдер {{{}Filters{}}}.
 ** *Когда:* Выполняется экспорт в XLSX.
 ** *Тогда:* Фильтры отображаются в одной ячейке: `Город: 'Москва', 'Санкт-Петербург'; ID: 1, 2`

 * *AC 3: Разделители разрядов*
 ** *Дано:* Применен фильтр по сумме (значение 1500000).
 ** *Когда:* Происходит экспорт в XLSX.
 ** *Тогда:* Значение суммы форматируется с разделителями разрядов: `Сумма: 1 500 000`.

 * *AC 4: Форматирование дат*
 ** *Дано:* В Общих настройках визуализации задан формат даты `ДД.ММ.ГГ`. Применен фильтр по дате.
 ** *Когда:* Выполняется экспорт.
 ** *Тогда:* Значение фильтра выводится в формате `ДД.ММ.ГГ`. Если формат в визуализации не задан — применяется дефолтный `ДД.ММ.ГГГГ`.

 * *AC 5: Диапазонные и сравнительные фильтры*
 ** *Дано:* Применен фильтр по дате с условием «от 01.01.2024 до 31.12.2024» и фильтр по тексту «Тест» (оператор =).
 ** *Когда:* Выполняется экспорт.
 ** *Тогда:* Фильтры отображаются в формате:
`Дата >= 01.01.2024 И <= 31.12.2024`
`Название = 'Тест'`

 * *AC 6: Вычисляемые поля форматируются по итоговому типу*
 ** *Дано:* Применён фильтр по вычисляемому полю с итоговым типом numeric.
 ** *Когда:* Производится экспорт в XLSX.
 ** *Тогда:* Значение фильтра форматируется как число с разделителями разрядов.
 ** *И:* Если вычисляемое поле возвращает string-тип — строковое форматирование с кавычками; если date-тип — форматирование по правилу дат из AC 4.

 * *AC 7: Регресс по ранее реализованным XLSX-доработкам отсутствует*
 ** *Дано:* Используются {{{}Report_title{}}}, много-листовый шаблон, дополнительные листы с преднастроенными объектами и ранее реализованные правила именования файла.
 ** *Когда:* Выполняется экспорт после реализации данной задачи.
 ** *Тогда:* Новая логика меняет только оформление значений фильтров и авто-ширину в Общем шаблоне, не ломая ранее реализованные механизмы.

 * *AC 8: Отсутствие применённых фильтров*
 ** *Дано:* Для экспортируемой визуализации отсутствуют применённые фильтры.
 ** *Когда:* Выполняется экспорт в XLSX с использованием {{{}Filter{}}}, {{Filters}} или {{{}Filters_by_rows{}}}.
 ** *Тогда:* Плейсхолдер заменяется на пустую строку.
 ** *И:* В ячейке не остаются служебные разделители, квадратные скобки, `{{{}null{}}}`, `{{{}undefined{}}}` или иные технические значения.

 * *AC 9: Исключение для Года*
 ** *Дано:* Применен фильтр по году (значение 2024).
 ** *Когда:* Происходит экспорт в XLSX.
 ** *Тогда:* Значение года форматируется без разделителей: `Год: 2024`.

# Анализ форматирования дат в HsTable

## Где находится логика для таблицы

Формат даты из настроек компонента приходит в таблицу не напрямую как `config.dateFormat`, а через объект спецификации таблицы `spec`.

Цепочка начинается в генераторе спецификации:

- `src/adaptors/ReactabularChartAdaptor/ReactabularSpecGenerator.js`

В этом файле значение из конфигурации компонента переносится в спецификацию таблицы:

```js
spec.dateFormat = config.dateFormat;
```

После этого `HsTable` работает уже с `spec.dateFormat`.

Основная логика таблицы находится в:

- `src/components/HsTable/HsTable.js`

При построении колонок таблица вызывает метод `getCellFormatters`:

```js
const cellFormatters = this.getCellFormatters(column, props.data?.data, spec);
```

Метод расположен в `src/components/HsTable/HsTable.js` и отвечает за набор форматтеров ячейки. Среди прочих форматтеров он добавляет форматтер дат:

```js
addDateFormatCellFormatter({ cellFormatters, column, spec });
```

## Какой метод используется

Форматтер дат добавляется функцией:

- `src/components/HsTable/cellFormatters.js`
- `addDateFormatCellFormatter`

Код функции:

```js
export const addDateFormatCellFormatter = ({ cellFormatters, column, spec }) => {
  const dateFormat = column.dateFormat || spec.dateFormat;
  if (!(dateFormat === '-')) {
    cellFormatters.push((value) => {
      return dateFormatFunction(value, column.dateFormat || spec.dateFormat);
    });
  }
};
```

Эта функция определяет актуальный формат даты по приоритету:

```text
column.dateFormat -> spec.dateFormat
```

Где:

- `column.dateFormat` - формат даты на уровне конкретной колонки;
- `spec.dateFormat` - общий формат даты таблицы, полученный из `config.dateFormat`.

Если итоговый формат равен `'-'`, форматтер даты не добавляется.

## Где расположен метод форматирования даты

Непосредственное преобразование значения выполняет функция:

- `src/constants/formatOptions.js`
- `dateFormatFunction`

Она импортируется в `cellFormatters.js`:

```js
import { dateFormatFunction } from 'constants/formatOptions';
```

И вызывается так:

```js
dateFormatFunction(value, column.dateFormat || spec.dateFormat);
```

## Как работает логика форматирования

`dateFormatFunction` принимает два аргумента:

```js
dateFormatFunction(label, fmt)
```

Где:

- `label` - исходное значение ячейки;
- `fmt` - формат даты, например `DD.MM.YYYY`, `YYYY-MM-DD HH:mm`, `MMMM YYYY`.

Внутри функции выбирается шаблон форматирования:

```js
const template = fmt && fmt !== '-' ? fmt : 'DD.MM.YYYY';
```

То есть если формат не задан или равен `'-'`, используется дефолтный формат:

```text
DD.MM.YYYY
```

Дальше поведение зависит от типа значения:

1. Если значение пустое, функция возвращает пустую строку.

```js
if (!label) return '';
```

2. Если значение является объектом `Date`, оно форматируется через `moment`.

```js
ret = moment(label);
if (ret.isValid()) {
  ret = ret.format(template);
  return ret;
}
```

3. Если значение является строкой и в строке есть не только цифры, функция пытается распарсить ее как ISO 8601.

```js
ret = moment(label, [moment.ISO_8601], 'ru', true);
```

Если строка успешно распознана как дата, она форматируется по шаблону:

```js
if (ret.isValid()) ret = ret.format(template);
```

Если строка не распознана как дата, она возвращается без изменений:

```js
else ret = val;
```

4. Все остальные значения возвращаются как есть.

## Итоговая схема

```text
config.dateFormat
  -> ReactabularSpecGenerator.js
  -> spec.dateFormat
  -> HsTable.getColumns()
  -> HsTable.getCellFormatters()
  -> addDateFormatCellFormatter()
  -> dateFormatFunction()
  -> moment(...).format(...)
```

## Важные особенности

- `config.dateFormat` не используется напрямую внутри `HsTable.js`; туда он попадает как `spec.dateFormat`.
- Формат колонки `column.dateFormat` имеет приоритет над общим форматом таблицы `spec.dateFormat`.
- Значение `'-'` отключает добавление форматтера даты в `cellFormatters`.
- `addDateFormatCellFormatter` не проверяет `column.fieldType === 'date'`, поэтому форматтер может добавляться ко всем колонкам.
- Фактически изменяются только значения типа `Date` и строки, которые строго распознаются как ISO 8601.
- Обычные строки, которые не распознаны как даты, остаются без изменений.
