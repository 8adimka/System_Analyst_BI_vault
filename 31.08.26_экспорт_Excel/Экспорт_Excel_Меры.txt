h3. Контекст и проблематика.

В аналитическом портале реализована сущность *«Мера»*. Общий backend-механизм (SQL-builder) уже поддерживает объекты типа {{"measure"}} в блоках {{select}}, {{group}}, {{where}}, {{having}}, {{order}}, а также может раскрывать ссылки на Меры внутри выражений вычисляемых полей и других Мер.

Так как экспорт использует общий механизм построения запроса, *сами значения строк* данных визуализации уже рассчитываются корректно для Мер при экспорте в Excel.

Однако, поверх сырых данных в экспорте в Excel работает отдельный *информационный слой*, который отвечает за заголовки колонок, форматирование значений по типу данных, блок «Фильтры» и блок «Переменные». На данный момент он оптимизирован для обычных и вычисляемых полей и *не учитывает* Меры:
* не определён источник человекочитаемого названия Меры для заголовка колонки и для подписи фильтра в экспорте;
* не определено форматирование (число/строка/дата) для фильтра по Мере;
* не описано поведение экспорта, если используемая Мера имеет {{status = invalid}} на момент формирования файла;
* не описано взаимодействие Мер с блоком «Переменные» и с настройкой «Значения по другому полю».

Настоящая постановка призвана закрыть этот разрыв и приводит работу с Мерами в информационном слое экспорта в Excel к единообразному виду с обычными и вычисляемыми полями.

----
h3. Цель задачи.

*Требуется:*
# Обеспечить корректное отображение заголовков колонок и итогов/подытогов для Мер, размещённых на полках визуализации, при экспорте в Excel — по актуальному {{alias}} Меры и правилам форматирования по {{data_type}}.
# Обеспечить корректное отображение значений фильтров по Мере ({{WHERE}} и {{HAVING}}) в блоке «Фильтры» экспорта — по правилам форматирования, аналогичным обычным полям, на основе явного типа данных ({{data_type}}) Меры.
# Сохранить единообразную обработку Мер, используемых внутри выражений вычисляемых полей, при определении типа фильтра по такому вычисляемому полю.
# Определить поведение экспорта при использовании Меры со статусом {{invalid}}, согласованное с runtime-контрактом запроса данных визуализации.
# Определить взаимодействие Мер с блоком «Переменные», при использовании переменных в выражении Меры, и с настройкой «Значения по другому полю».
# Сохранить полную обратную совместимость экспорта визуализаций, где Меры не используются.

_Пользовательская история:_
Как аналитик и пользователь портала, я хочу видеть в выгрузке Excel те же названия и корректно отформатированные значения Мер и фильтров по Мерам, что и в самой визуализации, чтобы уверенно интерпретировать выгруженные данные.

----
h3. 1. Ключевые понятия, используемые в постановке.

* В данной задаче *{{alias}}* — единственный источник человекочитаемого отображения Меры в экспорте; {{name}} используется только как технический ключ поиска определения.
* *Прямое использование Меры* — размещение объекта {{type = "measure"}} на полке визуализации, в фильтре или в сортировке.
* *Ссылочное использование Меры* — упоминание {{"Мера.<name>"}} внутри выражения вычисляемого поля ({{calc}}) или выражения другой Меры.
* *Информационный слой экспорта* — часть логики экспорта в Excel, не относящаяся к расчёту сырых данных визуализации: заголовки колонок, блок «Фильтры», блок «Переменные» в общем и частных XLSX-шаблонах.

----
h3. 2. Границы задачи.

---
h4. В рамках задачи реализуется:
* определение заголовка колонки и подписи фильтра для Меры на основе актуального {{alias}};
* классификация Меры по {{data_type}} для форматирования значений в столбцах и в блоке «Фильтры» экспорта Excel;
* поддержка фильтров по Мере в режиме {{WHERE}} и {{HAVING}} в блоке «Фильтры», включая списочные и диапазонные/сравнительные фильтры;
* корректное форматирование итогов/подытогов по агрегированным Мерам;
* сохранение действующего правила определения типа результата для вычисляемого поля, ссылающегося на Меру;
* поведение экспорта при использовании Меры со {{status = invalid}} на момент формирования файла;
* взаимодействие Мер с блоком «Переменные» (если выражение Меры содержит переменные) и с настройкой «Значения по другому полю»;
* поддержка описанной логики в частных XLSX-шаблонах Таблицы и в общем шаблоне экспорта для всех визуализаций, где уже реализована поддержка Мер.

---
h4. Не входит в рамки задачи:
* расчёт значений Мер в самих данных визуализации уже реализован общим SQL-builder'ом и переиспользуется экспортом без доработки;
* подключение Мер к визуализациям, где механизм Мер ещё не реализован;
* поддержка Мер для простых и составных наборов данных;
* изменение правил валидации, статусов и зависимостей Мер;
* изменение форматов, маркеров и правил уже реализованных доработок экспорта для обычных и вычисляемых полей, кроме явно описанных ниже точек интеграции.

----
h3. 3. Отображение Мер в столбцах данных экспорта.

---
h4. 3.1. Источник заголовка.
Для колонки экспорта, соответствующей прямому размещению Меры на полке визуализации, заголовок определяется по действующему приоритету, что уже применяется для обычных и вычисляемых полей:
# заголовок, заданный пользователем на полке (подпись пилюли), если задан;
# {{alias}} Меры из актуальных метаданных набора данных на момент экспорта;
# fallback — {{name}} Меры, если {{alias}} недоступен (аварийный случай, не ожидается в штатной работе).

В штатной работе, заголовок не должен содержать системное имя {{name}} или префикс {{Мера.}}, если пользователь не задал его явно как собственный заголовок.

---
h4. 3.2. Форматирование значений.
Значения колонки Меры форматируются по правилам, действующим для соответствующего типа данных:

|| {{data_type}} Меры || Правило форматирования в ячейке Excel ||
| {{number}} | Число с точностью и разделителями разрядов по текущим настройкам компонента, аналогично обычному числовому полю |
| {{string}} | Текстовое значение без модификации |
| {{date}} | Дата в формате из общих настроек визуализации, либо в формате по умолчанию |
| {{datetime}} | Дата со временем по формату визуализации |

Правило форматирования значения ячейки для Меры совпадает с действующим правилом форматирования обычного поля того же типа данных; отдельный алгоритм форматирования для Мер не создаётся.

{{null}} и пустой результат агрегированной Меры обрабатываются так же, как {{null}} обычного или вычисляемого поля того же типа данных.

---
h4. 3.3. Итоги и подытоги.
Если для колонки Меры на полке визуализации настроен вывод итога/подытога, значение итога форматируется по правилам того же типа данных, что и сама колонка. Доработка не меняет правил расчёта итога — только форматирование итогового значения в Excel.

---
h4. 3.4. Несколько размещений одной Меры.
Если одна и та же Мера размещена на нескольких полках или в нескольких пилюлях с разными локальными настройками, каждое размещение экспортируется как отдельная колонка/значение со своим заголовком и форматированием, независимо от других размещений той же Меры.

----
h3. 4. Отображение Мер в блоке «Фильтры» экспорта.

---
h4. 4.1. Определение категории форматирования.
В отличие от вычисляемого поля, для Меры категория форматирования фильтра определяется однозначно и без обращения к результирующей схеме основного запроса: {{data_type}} Меры известен заранее из метаданных набора данных ({{datasets.measures[].data_type}}).

Классификация {{data_type}} Меры в категорию форматирования фильтра:

|| {{data_type}} Меры || Категория форматирования фильтра ||
| {{string}} | {{string}} |
| {{number}}, {{integer}} | {{number}} |
| {{date}} | {{date}} |
| {{datetime}} | {{datetime}} |

Правила отображения значений внутри каждой категории (кавычки для строк, разделители разрядов для чисел, формат дат) не создаются заново, а применяются по правилам, уже зафиксированным в постановках MB-4129 и MB-5165.

---
h4. 4.2. Передача типа фильтра по Мере с фронтенда на бэкенд.
Для фильтра, применённого по Мере, фронтенд передаёт в {{export.parameters.filter}} тот же объект фильтра, что и для обычного поля, определяя {{filterType}} напрямую по {{data_type}} Меры из метаданных набора данных, без введения отдельного значения для Мер:

{code:json}
{
  "name": "Мера.Валовая_прибыль",
  "values": "[0]",
  "filterType": "number"
}
{code}

Если фронтенд не может надёжно определить {{filterType}} Меры на момент экспорта (например, метаданные набора данных временно недоступны), применяется стандартное для отсутствующего {{filterType}} поведение: строковая деградация без ошибки экспорта.

---
h4. 4.3. Название фильтра.
Название фильтра по Мере в блоке «Фильтры» определяется по действующему приоритету названия фильтра (заголовок на полке «Фильтры» → алиас поля из набора данных → системное наименование), где источником алиаса выступает актуальный {{alias}} Меры.

---
h4. 4.4. Диапазонные и сравнительные фильтры, {{WHERE}} и {{HAVING}}.
Фильтр по Мере в режиме {{WHERE}} (неагрегированная Мера) и фильтр по Мере в режиме {{HAVING}} (агрегированная Мера) отображаются в блоке «Фильтры» единообразно: используется общий формат диапазонных/сравнительных или списочных фильтров, уже реализованный для обычных полей. Признак {{WHERE}}/{{HAVING}} является техническим и не выводится пользователю в тексте фильтра.

---
h4. 4.5. Мера внутри выражения вычисляемого поля.
Если фильтр применён к вычисляемому полю, выражение которого ссылается на одну или несколько Мер, результат экспорта вычисляемого поля приводится по актуальному правилу (к строковому виду). Отдельное правило для случая, когда вычисляемое поле ссылается именно на Меру, не вводится.

На фронтенде для вычисляемых полей используется единый маркер {{filterType = "calculated"}}.

----
h3. 5. Мера со статусом {{invalid}} на момент экспорта.

Если экспортируемая визуализация содержит прямое использование Меры или ссылку на Меру внутри вычисляемого поля, и на момент формирования запроса данных экспорта эта Мера имеет {{status = invalid}}, экспорт должен завершаться так же, как обычный запрос данных визуализации с невалидной Мерой: запрос не выполняется, пользователю возвращается ошибка с человекочитаемой причиной невалидности Меры. Экспорт не должен формировать частично заполненный или искажённый Excel-файл.

Отдельная деградация (например, вывод пустой колонки вместо ошибки) для экспорта не вводится — поведение экспорта должно быть согласовано с поведением обычного запроса данных визуализации.

----
h3. 6. Взаимодействие с блоком «Переменные».

Если выражение Меры содержит поддерживаемые глобальные переменные, такие переменные должны попадать в блок «Переменные» экспортируемой визуализации на тех же основаниях, что переменные, использованные в выражении набора данных или вычисляемых полей: переменная считается используемой в экспортируемой визуализации, если она используется в выражении Меры, размещённой на полке визуализации, либо упомянутой внутри {{calc}} вычисляемого поля визуализации, в том числе через цепочку ссылок Мера-на-Меру.

Определение состава переменных должно учитывать раскрытое (развёрнутое) выражение Меры — то есть механизм определения используемых переменных должен пройти по цепочке разрешения Мер так же, как это делает backend при формировании итогового SQL.

----
h3. 7. Общие правила единообразия.

* Правила данной задачи не создают новых XLSX-маркеров шаблона и не меняют существующие маркеры — Меры используют те же маркеры, что обычные и вычисляемые поля.
* Правила применяются одинаково в общем шаблоне экспорта и в частных XLSX-шаблонах Таблицы.
* Правила применяются одинаково независимо от того, разбивается ли экспорт на несколько листов/файлов (партиционирование) — категория форматирования Меры не переопределяется по частям экспорта.
* Визуализации, где Меры не используются ни напрямую, ни через вычисляемые поля, не должны менять текущее поведение экспорта.

----
h3. 8. Открытые вопросы:

* Следует обсудить должен ли столбец, соответствующий Мере, помечаться в Excel каким-либо визуальным признаком. Рабочий вариант, что заголовок колонки не содержит служебных обозначений.
* Требуется уточнить у команды бэкенда, разворачивает ли текущий механизм определения переменных для блока «Переменные» цепочку ссылок Мера-на-Меру, либо это отдельная доработка механизма подстановки переменных, вводимая данной задачей.

----
h3. 9. Критерии приёмки (AC):

AC.1 — *Заголовок колонки Меры в экспорте:*
* Дано: на полке визуализации размещена Мера с {{alias = "Валовая прибыль"}}, пользователь не задавал собственный заголовок колонки.
* Когда: выполняется экспорт визуализации в Excel.
* Тогда: заголовок соответствующей колонки — «Валовая прибыль»; технические {{name}} и префикс {{Мера.}} не выводятся.

AC.2 — *Форматирование числовой Меры:*
* Дано: агрегированная Мера с {{data_type = number}} возвращает значение {{1500000.5}}.
* Когда: выполняется экспорт в Excel.
* Тогда: начение отображается с разделителями разрядов и точностью по текущим настройкам компонента визуализации, полностью аналогично тому, как было бы отформатировано это же значение для обычного числового поля с идентичными настройками (включая округление, если оно предусмотрено настройками точности компонента).

AC.3 — *Форматирование фильтра по Мере (список значений):*
* Дано: применён фильтр {{WHERE}} по неагрегированной Мере с {{data_type = string}}, выбраны значения «Опт» и «Розница».
* Когда: выполняется экспорт визуализации в Excel с выводом фильтров.
* Тогда: в блоке «Фильтры» отображается `<alias меры>: 'Опт', 'Розница'`.

AC.4 — *Диапазонный фильтр по агрегированной Мере ({{HAVING}}):*
* Дано: применён фильтр {{HAVING}} по агрегированной Мере с {{data_type = number}}, оператор {{>}}, значение {{1000000}}.
* Когда: выполняется экспорт визуализации в Excel.
* Тогда: в блоке «Фильтры» отображается `<alias меры> > 1 000 000`, без указания режима {{HAVING}} в тексте.

AC.5 — *Мера внутри вычисляемого поля:*
* Дано: вычисляемое поле визуализации ссылается на Меру и поле присутствует в результирующей схеме основного запроса.
* Когда: применён фильтр по такому вычисляемому полю, и выполняется экспорт.
* Тогда: значение фильтра приводится к строке, аналогично любому другому вычисляемому полю.

AC.6 — *Экспорт визуализации с невалидной Мерой:*
* Дано: визуализация использует Меру, у которой на момент экспорта {{status = invalid}}.
* Когда: пользователь инициирует экспорт в Excel.
* Тогда: экспорт завершается ошибкой с человекочитаемой причиной невалидности Меры; частично сформированный Excel-файл не выдаётся пользователю.

AC.7 — *Переменные внутри выражения Меры:*
* Дано: выражение Меры, размещённой на полке визуализации, содержит глобальную переменную с выбранным значением.
* Когда: выполняется экспорт визуализации в Excel с маркером {{Variables}}.
* Тогда: переменная и её текущее значение выводятся в блоке «Переменные» ровно один раз, независимо от количества Мер и вычисляемых полей, где она фактически использована.

AC.8 — *Несколько размещений одной Меры:*
* Дано: одна и та же Мера размещена дважды на разных полках с разными локальными настройками (например, «Значение» и «Отсечка» индикатора).
* Когда: выполняется экспорт в Excel.
* Тогда: каждое размещение экспортируется как самостоятельная колонка/значение со своим заголовком и форматированием, без взаимного влияния.

AC.9 — *Обратная совместимость:*
* Дано: визуализация не использует Меры ни напрямую, ни через вычисляемые поля.
* Когда: выполняется экспорт в Excel.
* Тогда: результат экспорта полностью соответствует поведению до данной доработки.
