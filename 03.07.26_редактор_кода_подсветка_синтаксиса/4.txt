Есть требование добавить кнопку "Превью данных", чтобы пользователь мог получить образец даных по данному запросу и увидеть уже заполненную таблицу с данными по его запросу.

Рабочая решение: Кнопку «Превью данных» расположить рядом с существующей кнопкой «Проверить запрос» (той же серии кнопок справа от SQL-редактора) и открывать по её нажатию отдельную сворачиваемую панель с таблицей результата, для изучения примеров данных.

* Кнопку «Превью данных» сделать визуально второстепенной, чтобы не конкурировать с основной («Проверить запрос»).

* По клику открывать не модальное окно, а раскрывающуюся панель под блоком SQL-запроса (аккордеон), которая сдвигает вниз блок «Настройки RLS» и таблицу описания полей — так пользователь не теряет контекст запроса и легко может итеративно править SQL и жать превью повторно.

* Ограничить выборку 100 строк (по умолчанию) с возможностью явно указать «показать ещё» или задать лимит — это защищает от долгих запросов и больших объёмов на больших источниках.

* В гриде превью показывать имя поля, алиас и тип из уже настроенной таблицы "Описание полей набора данных", расположенной ниже.

* Добавить лёгкий индикатор состояния: спиннер во время выполнения, счётчик «Показано N из первых M строк», и явную обработку ошибок SQL прямо в панели (текст ошибки от БД).

* Кнопку «Превью данных» держать неактивной (disabled) до успешной проверки запроса («Проверить запрос»), чтобы не гонять невалидный SQL. Кнопку «Превью данных» - это логичное дополнение к уже существующей кнопке «Проверить запрос», а не замена ей.

* Панель превью должна быть сворачиваемой и не сохраняющей состояние при сохранении набора данных — то есть это чисто debug/preview-инструмент, не влияющий на конфигурацию источника.

Где размещать «Показать ещё»:
* Разместить под таблицей результата, по центру, сразу под последней строкой грида — рядом со счётчиком (например, «Показано 100 из 500 строк»).
* Сделать её вторичной кнопкой-ссылкой (text-button, не outline и не filled), чтобы визуально не спорить ни с «Проверить запрос», ни с «Превью данных» — это точечное действие внутри уже открытой панели, а не новый уровень навигации.
* По клику дозагружать следующую порцию (например, ещё +100 строк) без пересчёта запроса с нуля.
* Когда достигнут технический потолок (например, максимум 500–1000 строк, зафиксированный на backend «для безопасности» — кнопку скрывать или заменять на неактивную с подсказкой «Достигнут максимум предпросмотра».

Где размещать настройку лимита:
* Вынести иконку-шестерёнку (настройки) в правый верхний угол самой панели превью, рядом с кнопкой сворачивания/закрытия панели — то есть на уровне заголовка панели, а не внутри грида.
* По клику открывать компактный popover с предустановленными ограничениями вывода данных (100 / 200 / 500 / 1000) и явным потолком, чтобы пользователь не мог случайно запросить весь источник целиком.
* Не размещать это как отдельное постоянно видимое поле на панели — это настройка "для продвинутых", которая не нужна большинству пользователей при первом клике на «Превью данных», поэтому она должна быть скрыта за один клик, а не занимать пространство по умолчанию.
* Изменение лимита в настройках должно требовать повторного нажатия «Превью данных», а не триггерить автоматический перезапрос — это предотвращает случайные тяжёлые запросы при переборе кнопок.
