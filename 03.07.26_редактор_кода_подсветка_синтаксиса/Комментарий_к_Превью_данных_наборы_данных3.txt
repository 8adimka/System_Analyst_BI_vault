По варианту макета с пагинацией - поддерживаю, хороший вариант для реализации. 

* *По пагинации.* Ориентируемся на [^modus_sql_editor_updated_v13.html]: страницы заменяют «Показать ещё 100» и настройку начального объёма. Размер страницы — 25, 50, 100 или 200 строк, по умолчанию 50; изменение применяется сразу, предпочтение сохраняется в текущем браузере. Нумерация строк сквозная. Новая успешная проверка и изменение сортировки открывают первую страницу; при смене размера страницы также предлагаю переход на первую страницу. Оба режима редактора используют единое состояние пагинации.

Также хочу обратить внимания на обсуждённые с Александром Селантьевым детали:
* *Объём превью.* Фронтенд запрашивает не более 1000 строк; отдельный жёсткий потолок на бэкенде не требуется. Размер страницы определяет отображение, а не лимит запроса. Листание и смена размера страницы работают с тем же результатом без повторного выполнения SQL. Полное количество строк исходного SQL отдельно не подсчитываем. Счётчик не должен выдавать объём превью за полный размер результата SQL; вариант из v13 вполне допустим («1–50 из первых 1000», а при меньшем результате, например — «1–37 из 37»).
* *Сортировка.* Изменение или снятие сортировки формирует новое превью по всему результату SQL до ограничения выдачи, а не переупорядочивает уже полученную тысячу строк. Текст SQL при этом не меняется. После редактирования SQL последнее превью сохраняется с предупреждением об устаревании: просмотр и перелистывание доступны, сортировка заблокирована до новой успешной проверки. Первая проверка SQL выполняются без сортировки, а повторная допускается с сортировкой прежнего превью; сортировка доступна по актуальным столбцам результата. В заголовках используем {{name}} результата запроса, без подмены пользовательским алиасом; алиасы внутри самого SQL сохраняют свой смысл.

*Для согласования фронтенда и бэкенда:* требуется определить контракт получения строк и актуальных столбцов с передачей от фронтенда лимита запроса и сортировки через общие опции запроса. Последний обсуждаемый вариант - получать до 1000 строк и перелистывать их на фронтенде; сортировка запрашивает новый результат. Финальный способ технической реализации получения и хранения выборки остаётся за разработчиками.

Остальные требования постановки сохраняются.
