*Цель:*
Обеспечить пользователям доступ к перечню мер реагирования при недостижении целевых показателей через модальные окна в «Групповой панели показателей» и «Сводной таблице».

+Реализовать две новые функциональности:+
 # В виджете «Групповая панель показателей» — опциональная кнопка «Как улучшить значение» с возможностью открытия модального окна по клику.
 # В сводной таблице — новая колонка «Меры реагирования, ед.» с возможностью открытия модального окна при клике на ячейку.

Все данные по мерам реагирования приходят в готовом виде (уровни 1–3).
{panel}
 * *1 уровень — РПО (региональный проектный офис) / ВПО (ведомственный проектный офис)*
В его состав входят:
 ** *2 уровень — Национальные проекты*
Которые состоят из:
 *** *3 уровень — РП (региональные проекты) / ФП (федеральные проекты)*{panel}
Никакого маппинга справочника мер на нашей стороне не требуется.

*Примерная структура логики ROW_LEVEL (адаптировать):*
{code:sql}
{
CASE
  WHEN !ROW_LEVEL! IN ('"Ответственный РПО"', '"Ответственный ВПО"') 
    THEN "mer_count_level1"   -- из Level 1 (РПО/ВПО)
  WHEN !ROW_LEVEL! = '"Наименование НП"' 
    THEN "mer_count_level2"   -- из Level 2 (Нацпроект)
  WHEN !ROW_LEVEL! IN ('"Наименование РП"', '"Наименование ФП"') 
    THEN "mer_count_level3"   -- из Level 3 (РП/ФП)
  ELSE 0
END
}
{code}

 * Для колонки «Меры реагирования, ед.» используем вычисляемое поле по логике ROW_LEVEL + скрытое поле со списком наименований мер.

 -- Поле для отображения количества мер (`mer_count_levelX`)

*Данные:*
 * 3 отдельные таблицы от заказчика (Level 1, Level 2, Level 3).
 * ETL-процесс: таблицы объединяются в одну витрину (горизонтальное расширение), меры парсятся для дальнейшего вывода.
 * Поля, которые нам нужны:
 ** Level 1 (групповые панели + верхний уровень таблицы):
 *** {*}count_mer{*}, *mer_name*
 *** Все *factor_XX_mer_count* + *factor_XX_mer_name*
 ** Level 2 и Level 3
 *** {*}count_mer{*}, *mer_name* - по уровням.

*Мы не суммируем сами — берём готовый count_mer и mer_name из строки соответствующего уровня.*
