Резюме встречи "ФКР. Меры реагирования: старт постановки" 12 марта 2026

Участники: Роман Чернышов, Владислав Харченко, Владимир Кудрин, Вадим Мединцев

- Заказчик предоставил новые вводные, которые касаются методики расчета мер реагирования для групповых панелей показателей. Роман Чернышов показал финальный макет, прикрепленный к задаче, которую создала Арина.
- Обсуждались уровни иерархии данных: РПО (региональный проектный офис) и ВПО (ведомственный проектный офис). РПО отвечает за реализацию национальных и региональных проектов в рамках конкретного региона, ВПО — ведомственных проектов.
- Заказчик прислал 6 таблиц с данными. Важны данные уровня 1, которые содержат информацию о мерах реагирования в разрезе РПО, национальных проектов и региональных проектов.
- В таблицах содержатся сырые данные, включая год, квартал и регион. Для сводной таблицы важны общие сведения, а для групповых панелей показателей — информация о мерах реагирования.
- Меры реагирования представлены в виде списка, который можно распарсить из JSON-формата. В таблицах указаны факторы качества планирования, администрирования, уровня достижений, работы в СВПО и информационного сопровождения.

- Заказчик ожидает, что при нажатии на кнопку "Улучшить значение" для фактора 11 будет выводиться список мер для улучшения качества планирования. Если мер нет, кнопки не будет, и будет стоять прочерк или 0.
- Для уровня достижения и качества работы в СВПО поведение аналогичное.
- Фильтр только по кварталу, иерархический фильтр нужен с годом и кварталом.
- Фильтры регионального проекта не влияют на групповую панель показателей, влияют только фильтры по периоду.
- Данные приходят уже рассчитанными, меры реагирования приходят в виде массива, который нужно распарсить.
- Список мер реагирования выводится отдельными элементами при нажатии на кнопку.
- Внутри мер могут быть запятые и двойные кавычки, которые нужно экранировать. Решение по сохранению кавычек будет согласовано с заказчиком.
- Фильтр по региону всегда установлен по умолчанию, выбор только одного региона.
- ID мер реагирования и сами значения мер реагирования должны быть доступны для чтения и переноса.

- Справочник Мета работает корректно, если все данные приходят.
- Первый столбец "Мера, ID" не изменяется и имеет бизнесовое значение, особенно на 4-м уровне.
- Компоненты идентифицируются по номеру, который не меняется.
- Пороговое значение 100% пока не планируется менять, хотя ранее была такая потребность.
- Если данные приходят уже обработанными, то выборка будет делаться на их стороне, что упрощает нашу работу.
- Сводная таблица содержит 2 уровня иерархии: национальный и региональный проекты.
- Для сводной таблицы используются 3 таблицы, объединяемые в одну, что увеличивает количество столбцов.
- Логика вычислений в сводной таблице зависит от уровня иерархии, и данные берутся из разных колонок в зависимости от уровня.
- Заказчик использует свою методику для расчета процентов на разных уровнях, что не позволяет использовать простую агрегацию.

- Уникальные ID мер уже предрасчитаны, дубли отсутствуют, заказчик предоставляет данные без повторений.
- Для дашборда карточка РПО и сводная таблица на 2-м и 3-м уровнях иерархии, а для главного экрана РПО и ВПО сводная таблица на 3-м уровне.
- Главный экран РПО и ВПО включает сводную таблицу, где показаны меры реагирования, но для групповых панелей показателей меры не выводятся.
- Вопрос по групповым панелям показателей решается через опциональный флажок, который позволяет выводить меры реагирования или нет.
- Для каждого уровня иерархии есть количество мер и список мер, которые нужно отобразить в модальном окне.
- Настройки сводной таблицы показывают уровни агрегации, где можно фильтровать по национальным и региональным проектам.
- Интерфейс и настройки для мер реагирования требуют дополнительного обсуждения.

- Групповая панель показателей является кастомным визуальным компонентом для конкретного заказчика, поэтому можно свободно настраивать её, не нарушая текущую конфигурацию. Добавление новых настроек в сводную таблицу важно для их переиспользования другими заказчиками.

- В сводной таблице планируется добавить вычисляемое поле с мерами, которое будет кликабельным. Также обсуждалась возможность добавления всплывающей подсказки или информационного сообщения, которое будет открываться при нажатии на колонку.

- Владислав Харченко упомянул о встрече по ркс на следующей неделе, предложив 9:30 утра в качестве возможного слота для обсуждения.

- Обсуждался вопрос о предоставлении Вадиму данных из закрытого Контур Гасу. Роман предложил экспортировать данные из таблиц в CSV-формате, чтобы Вадим мог их просмотреть.

- Уровень 4 данных не будет включён в сводную таблицу, так как он используется для другого дашборда.

- Вадим отметил, что таблица с мерами реагирования будет присылаться в готовом виде, что упрощает задачу.

- Необходимо обсудить интерфейс управления настройками в сводной таблице и групповой панели показателей. Также обсуждалась реализация всплывающего окна, которое будет переиспользуемым и удобным для различных полей и колонок.
