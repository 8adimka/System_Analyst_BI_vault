Постановка задачи: Автоматическое создание пользователей и назначение прав через LDAP
1. Автоматическое создание пользователя при LDAP-аутентификации
Аутентификация через LDAP: при входе приложение связывается с AD по защищённому каналу (например, LDAPS/TLS) и выполняет bind по введённым логину/паролю. Пароль не хранится локально и передаётся по SSL/TLS, согласно требованиям безопасности.
Получение атрибутов: после успешного bind система получает из AD атрибуты пользователя: sAMAccountName или userPrincipalName (логин), displayName (полное имя), givenName/sn (имя/фамилия), mail, department (отдел), title (должность), memberOf (группы пользователя) и др. В AD userPrincipalName обычно имеет формат user@domain.com и служит основным логином, а sAMAccountName – короткое имя (до 20 символов) для обратной совместимости
. Эти поля мы будем использовать для создания/обновления учётной записи.
Поиск и создание пользователя: в БД ищем пользователя по уникальному ключу (логин или SID/глобальный ID из AD). Если учётная запись существует – обновляем её атрибуты (имя, email, отдел, должность и пр.) по данным из AD. Если не найдена и включено auto_create_user=true, создаём новую запись: заполняем login = sAMAccountName (или UPN), email = mail, name = displayName (или givenName+sn), отдел = department, должность = title, устанавливаем статус «active» и источник «LDAP». Также сохраняем уникальный идентификатор AD (например, objectGUID или objectSid) для надёжной привязки. Пароль при этом остаётся в AD и не хранится в системе.
Блокировка при отключённом авто-создании: если auto_create_user=false и пользователь в локальной БД отсутствует, отказать во входе.
Критерии приёмки:

При включённом авто-создании новый LDAP-пользователь, ранее не существовавший в системе, создаётся в БД с корректными полями (логин, email, ФИО, отдел, должность) из атрибутов LDAP.
При выключенном авто-создании попытка входа LDAP-пользователя без локальной учётной записи приводит к отказу (вход закрывается).
Аутентификация через LDAP реализована по LDAPS/TLS (пароль защищён).
Поля login (используем userPrincipalName или sAMAccountName), email, name заполняются из LDAP-атрибутов в соответствии с рекомендациями AD.
В учётной записи сохраняются статус «active», метка источника «LDAP» и уникальный AD-идентификатор (SID/GUID) для последующей синхронизации.
2. Назначение ролей и прав по LDAP-группам
Получение групп: при каждом входе после успешного LDAP-bind приложение получает список LDAP-групп пользователя. Для учёта вложенных групп рекомендуется использовать конструируемый атрибут tokenGroups, который возвращает все SID групп в токене пользователя.
Сопоставление групп: заранее настраивается таблица маппинга (ldap_group_mapping), связывающая идентификаторы LDAP-групп и локальные группы доступа портала. Для каждой LDAP-группы из списка memberOf система ищет соответствующую portal-группу и добавляет туда пользователя (обновляет запись в user_groups).
Назначение ролей: группы портала связаны с ролями (Portal Group → Role → Permissions). После маппинга пользователь автоматически получает все роли, ассоциированные с присвоенными ему группами доступа. Права (permissions) наследуются из этих ролей.
Синхронизация: при каждом входе пользователя следует актуализировать его группы: добавлять новые группы по результатам LDAP и удалять те, что больше не возвращаются (урезанные права).
Отсутствие маппинга: LDAP-группы без настроенного соответствия игнорируются (пользователь либо остаётся с ролями по умолчанию, либо доступ ограничен в соответствии с политикой безопасности).
Критерии приёмки:

При создании нового LDAP-пользователя система автоматически присваивает ему portal-группу и роль в соответствии с его LDAP-группами (с учётом настроенного маппинга).
Список групп пользователя включает все вложенные группы (проверить работу через tokenGroups или аналог).
Администратор может задать в интерфейсе системы соответствия между LDAP-группами и группами портала (и, при необходимости, роли).
После применения маппинга у пользователя в системе доступны только разрешённые объекты и действия (роль и права соответствуют его LDAP-учёту).
При изменении членства пользователя в LDAP-группах (например, добавлении/удалении групп) после следующего входа его роли в портале обновляются в соответствии с актуальными группами.
Источники: LDAP-рекомендации (авто-провиженинг учётных записей и защита паролей по SSL), описание атрибутов Active Directory (sAMAccountName, userPrincipalName), а также использование tokenGroups для получения всех групп пользователя.
