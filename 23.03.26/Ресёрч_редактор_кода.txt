
Заголовок: [MB-3973] Исследование и выбор библиотеки для встраиваемого редактора кода
Исполнитель: Алексей Меркушенков
Постановщик: Вадим Мединцев
Дата: Понедельник 23.03.2026

Описание:
*Контекст и цель задачи:*
На данный момент в системе отсутствует единый удобный инструмент для написания кода (SQL, JS) с подсветкой синтаксиса. Цель данной задачи — провести финальное исследование готовых библиотек редакторов кода, опираясь на собранные требования, и подготовить почву для интеграции.

Нам необходимо выбрать одну максимально подходящую библиотеку или решение, которое мы сделаем стандартом и будем переиспользовать во всех модулях портала.

*Места использования редактора в системе.*
Единый редактор будет внедряться поэтапно:

# Поле SQL-запроса в наборах данных (Основной приоритет на старте. Сейчас это окно неудобное).
# Вычисляемые поля в отчётах (По кнопке «Редактировать»).
# JavaScript-код в формах ввода данных (Автозаполнение FWD).
# Правила загрузки / сбора данных и подключения.

*Функциональные требования.*
При выборе библиотеки необходимо ориентироваться на следующий функционал.


*Обязательные фичи (Must-have):*

* Подсветка синтаксиса: SQL и JavaScript из коробки + возможность легкого подключения других языков в будущем.

* Автодополнение:
** Ключевые слова SQL/JS.
** Имена таблиц и колонок (на основе подключенного источника данных).
** Контекстное автодополнение после точки (например, при вводе table. должен выпадать список полей этой таблицы).

* Базовый UX разработчика:
** Нумерация строк.
** Подсветка парных скобок.
** Автоматическое закрытие скобок и кавычек.

* Масштабируемость: Библиотека должна быть универсальной для внедрения во всех точках использования.


*Дополнительные фичи (Nice-to-have):*

* Интеграция с браузером метаданных: Левая боковая панель с деревом объектов (таблицы → колонки из текущего источника).

* Drag-and-drop: Возможность перетащить таблицу или колонку из браузера метаданных в окно редактора с автоматической вставкой текста (в позицию курсора) с соблюдением синтаксиса.

* Интеграция ИИ-помощника: Поддержка custom completion provider для генерации или автодополнения запросов по тексту (через LLM API). Мы планируем предоставлять эту функцию опционально (пользователь вводит свой API-ключ, мы за токены не отвечаем).



*Требования к UI / Формат окна*

* Вариант 1 (Предпочтительный на старте): Встроенное укрупнённое вниз окно. Оно должно быть выше и шире текущего, иметь внутренний скролл для длинных запросов и не закрывать таблицу результатов, расположенную ниже.

* Вариант 2 (Запасной): Pop-up (модальное окно). Рассматриваем если первый вариант технически неоправдан (больше накладных расходов на UX).

*Предварительный анализ рынка*
В качестве эталона UX мы ориентируемся на десктопный DBeaver (семантический движок автодополнения, анализ контекста, браузер схем, мгновенная подсветка ошибок).

*Кандидаты для твоего исследования:*

* Monaco Editor (ядро VS Code): 
** Плюсы: UX знаком всем разработчикам, мощное автодополнение, готовые обертки, отлично ложится на интеграцию ИИ и custom provider для SQL-метаданных.
** Минусы: Крупный размер бандла.

* CodeMirror 6:
** Плюсы: Легковесный, современная архитектура, отличная поддержка SQL.
** Минусы: Требует больше ручной настройки.

*Задачи разработчика:*

*Ревью требований: Ознакомиться с постановкой и предварительным списком библиотек.

* Сравнительный анализ: Провести анализ кандидатов (включая свои варианты). Сравнить по весу, простоте интеграции в нашу систему, кастомизации (drag-and-drop, ИИ, подсказки схемы) и удобству ресайза окна.

* Выбор и аргументация: Предложить 1–2 лучших варианта с аргументами, почему это лучше всего подходит под наши задачи.

* (Опционально) Демо-прототип *или* визуализация работы (картинки, gif).
Базовая инициализация редактора, моковое React-дерево метаданных сбоку, Drag-and-drop из дерева в редактор, подсказки при вводе и т.д.
