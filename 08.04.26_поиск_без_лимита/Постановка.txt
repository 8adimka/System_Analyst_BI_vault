----

[ФВД][РСХН] Реализация режима «Поиск без лимита» для компонента «Выпадающий список»

*Тип задачи:* Улучшение (Improvement) / Новая функциональность (New Feature)
*Эпик:* Формы ввода данных (ФВД) / Проект РСХН
*Теги:* `ФВД`, `RSKhN`, `Frontend`, `Select`
*Target Fix Version:* Спецсборка 3.12 (для РСХН), Основная ветка 3.14

h3. Контекст и проблематика:
На данный момент в Формах ввода данных (ФВД) выпадающие списки имеют ограничение на вывод и поиск элементов (лимит в 5000 записей, по факту для оптимизации рендеринга может подгружаться около 500). Поиск осуществляется только силами фронтенда по уже загруженному пулу данных. В условиях больших справочников, это делает невозможным поиск и выбор нужных записей, не попавших в первоначальную выборку.

----
h3. Цель задачи:
Аналогичная проблема раньше существовала в фильтрах основного портала. Она решена через опцию «Режим поиска без лимита» в настройках отображения фильтра (контейнер фильтров → настройки отображения).

*Требуется:*
Реализовать в ФВД для компонента «Выпадающий список» функционал *«Поиск без лимита»* (серверный поиск), аналогичный тому, который уже успешно реализован и применяется в контейнере Фильтров основного портала. 

*User Story:* > *Как аналитик, я хочу иметь возможность включать серверный поиск для выпадающих списков в ФВД, чтобы пользователи могли искать значения по всему справочнику, не ограничиваясь первыми 5000 записями.*

----
h3. Описание реализации:

В настройки отображения компонента «Выпадающий список» (в конструкторе ФВД) необходимо добавить новые опции (по аналогии с фильтрами):

# *Переключатель (Toggle switch) «Режим поиска без лимита» (_по умолчанию выключен_)*
#* *Описание:* Снимает фронтовые ограничения на количество получаемых уникальных значений. Переводит работу компонента с локального поиска на серверный (отправка запросов на бэкенд при вводе текста).
#* *При активации этого переключателя должны отображаться две дополнительные настройки - пункты 2 и 3:*
# *Поле «Количество символов для активации режима» (числовое)*
#* *Описание:* Задает минимальное количество введенных символов, после которых инициируется запрос к БД (глобальный поиск).
#* *Поведение:* Пока введено меньше символов, чем указано в настройке, поиск не триггерится.
# *Переключатель «Не загружать значения»*
#* *Описание:* Если опция включена, при открытии формы выпадающий список изначально пуст (значения не подгружаются). 
Список ожидает ввода пользователя и начинает заполняться только результатами поиска после ввода необходимого количества символов (п. 2).

----
h3. Технические требования и ограничения

Задача требует аккуратной адаптации существующего кода из основного портала. Компонент в ФВД имеет легаси-особенности.

# *Компонент UI:* Используется {{ReSelect}}. Необходимо перенести *только логику* из доработанного компонента фильтров (автор правок: Валерий Маланин), а не заменять компонент целиком.
# *Проблема потери фокуса:* При вводе символов компонент *не должен терять фокус* (курсор не должен сбрасываться). 
#* Не ииспользовать динамический {{key}} для компонента, чтобы избежать лишних ререндеров всего узла. (Учесть правки, которые ранее делались для портала).
# *Обратная совместимость:* Сохранить текущую стилизацию компонента в ФВД (старый стиль).
#* Сохранить работу *всплывающих подсказок* («Подсказка по заполнению поля»), которые настраиваются в ФВД. Текст подсказки не должен сломаться при внедрении новой логики поиска.
# *Зависимости:* Учесть, что ФВД использует старые версии пакетов. Возможны конфликты, требуется проверка совместимости.
# *Запросы на backend:* Серверный поиск должен _дебаунситься_, чтобы не спамить бэкенд запросами при каждом нажатии клавиши до достижения нужного лимита символов или при быстром вводе.

----
h3. Критерии приёмки (AC)

* AC1. *Настройки:* В режиме редактирования ФВД для выпадающего списка доступны новые настройки: тумблер «Режим поиска без лимита», поле «Колличество символов для активации режима» и тумблер «Не загружать значения» - последние два доступны только при активации тумблера «Режим поиска без лимита».
* AC2. *Локальный поиск (по умолчанию):* Если настройка отключена, компонент работает по старому сценарию (локальный поиск *по загруженному лимиту*).
* AC3. *Отложенный поиск:* Если задано, «Количество символов = _n_», запросы на бэкенд не уходят если введено менее _n_ символов.
Например, при установке «Количество символов = 3», запросы на бэкенд не уходят при вводе 1 или 2 символов. Запрос отправляется только после ввода 3-го символа.
* AC4. *Ленивая загрузка:* Если включена опция «Не загружать значения», при клике на пустой селект - список пуст. При вводе нужного количества символов появляются релевантные данные с бэкенда.
* AC5. *UX ввода:* При вводе текста в строку поиска курсор остаётся на месте, фокус с поля не сбрасывается (нет перерендера компонента из-за изменения {{state/key}}).
* AC6. *Сохранность легаси:* Всплывающие подсказки к полю и прочие дополнительные элементы отображаются корректно. Визуальный стиль компонента не изменился.
* AC7. *Производительность:* Ввод текста не вызывает «фризов» интерфейса браузера.
