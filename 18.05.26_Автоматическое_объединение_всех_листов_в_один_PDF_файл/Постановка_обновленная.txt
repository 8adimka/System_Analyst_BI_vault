*Текущая реализация (As Is):*
В текущей реализации портала, экспорт дашбордов в PDF работает только в рамках одной активной страницы (одного дашборда). Пользователю, которому необходимо подготовить раздаточный материал по одному срезу данных (например, по региону «Москва»), приходится вручную применять фильтр в нескольких разных отчетах, экспортировать их по отдельности, а затем склеивать PDF-файлы.
Дополнительная проблема: для компонентов типа «Таблица» применяется WYSIWYG-подход (экспортируется только видимая область — viewport). Если таблица длинная и имеет вертикальный скролл, пользователю приходится делать экспорт, скроллить таблицу вручную, делать повторный экспорт и так далее.

*Цель доработки (To Be):*
Реализовать механизм пакетного (группового) экспорта, позволяющий объединять несколько разных дашбордов аналитического портала в единый многостраничный PDF-файл. Пакетная выгрузка должна инициироваться из интерфейса конкретного отчета с автоматической передачей (наследованием) выбранного контекста фильтрации на все остальные выгружаемые отчеты.
Также необходимо решить проблему «обрезанных» таблиц, реализовав механизм, при котором в итоговый PDF-документ попадают все данные таблицы (в виде последовательности страниц), а не только ее видимая часть.

h3. 1. Точка входа и интерфейс выбора отчетов для пакетного экспорта.

# В интерфейсе просмотра отчета (дашборда), в меню дополнительных действий (рядом с текущим экспортом компонента/отчета), необходимо добавить новую опцию *«Пакетный экспорт в PDF»*.
# При нажатии на кнопку *«Пакетный экспорт в PDF»* открывается модальное окно, отображающее иерархическую структуру (дерево) папок (групп) и входящих в них дашбордов:
#* *Важно:* В дереве должны отображаться *только* те папки и отчеты, на которые у текущего пользователя есть права доступа.
#* Корневыми элементами дерева являются наименования групп/папок с иконкой сворачивания/разворачивания {{[>]}} / {{[v]}}. Дочерними элементами являются конкретные дашборды.
# Возле каждой папки и каждого дашборда в дереве должен отображаться чекбокс ({{Checkbox}}):
#* Выделение чекбокса папки автоматически проставляет чекбоксы для всех вложенных в неё дашбордов.
#* Снятие выделения с папки снимает выделение со всех дочерних элементов.
#* Поддерживается частичное выделение папки ({{indeterminate state}}), если выбрана только часть дашбордов внутри неё.
# В нижней части интерфейса выбора доступны две кнопки:
#* *«Экспортировать»* — запускает процесс сборки единого PDF-файла.
#* *«Отмена»* — закрывает модальное окно без сохранения изменений.

h3. 2. Механизм сквозной передачи фильтров (Контекст фильтрации).

* Отчет, из которого была вызвана функция пакетного экспорта (материнский отчет), является «донором» контекста фильтрации.
* При нажатии кнопки «Экспортировать» система считывает текущие значения всех примененных фильтров в материнском отчете.
* При рендеринге каждого выбранного дашборда из дерева система пытается применить к нему собранный массив фильтров:
#* Если в целевом отчете *присутствует* фильтр с аналогичным ключом/сущностью (например, «Регион»), система применяет к нему переданное значение (например, «Москва»).
#* Если в целевом отчете *отсутствует* такой фильтр, система просто *игнорирует* его и рендерит отчет с его настройками по умолчанию, не прерывая процесс выгрузки и не выдавая ошибок.

----
h3. 3. Решение проблемы выгрузки объемных таблиц (Варианты для архитектурного ревью).
Для решения проблемы выгрузки данных таблицы, не помещающихся в один экран (вертикальный скролл), разработчикам предлагается оценить и выбрать один из двух вариантов реализации:

*Вариант А (Приоритетный): Внедрение пагинации таблиц.*
* В настройки компонента «Таблица» добавляется режим включения/выключения пагинации с возможностью задать количество строк на страницу и т.д.
* При пакетном экспорте в PDF: если у таблицы включена пагинация, генератор PDF последовательно переключает страницы таблицы и рендерит каждую новую страницу таблицы на *новом листе* PDF-документа.
* *Опционально (к обсуждению):* Добавить в настройки экспорта галочку «Выводить элементы с пагинацией на отдельных листах», чтобы у пользователя была возможность гибко управлять: печатать ли всю таблицу (дублируя листы) или только первую страницу.

*Вариант Б (Альтернативный): Механизм автоскролла (Автоматическая прокрутка).*
* Таблица остается с виртуальным скроллом (без явной пагинации).
* При экспорте система автоматически высчитывает высоту скрытой области, делает снимок (рендерит страницу в PDF), программно прокручивает таблицу вниз на высоту видимой области, делает следующий снимок на новый лист PDF, и так до достижения конца таблицы.
* Все полученные снимки (состояния одной таблицы) вставляются в PDF как последовательные страницы.

h3. 4. Функциональные требования к логике сборки документа.

# *Применение индивидуальных настроек оформления:* Для каждого дашборда, участвующего в пакетной выгрузке, должны применяться его *индивидуальные* настройки экспорта, заданные в его редакторе (Цвет фона, Формат листа А3/А4, Ориентация, Отображение заголовка, Отступы).
# *Алгоритм сборки:* Страницы/буферы документов объединяются в один многостраничный файл в порядке их следования в структуре дерева отчетов (сверху вниз). 
#* Альтернативный вариант: Страницы/буферы документов объединяются в один многостраничный файл в порядке их выбора в структуре дерева отчетов.
# *Наименование файла:* По окончании сборки пользователю отдается на скачивание один файл формата {{.pdf}}. Наименование по умолчанию: {{Пакетный_экспорт_[Имя_Материнского_Отчета]_[Дата_Время].pdf}}.

h3. 5. Критерии приёмки (AC):

# В меню отчета присутствует кнопка «Пакетный экспорт в PDF», клик по которой открывает дерево групп и отчетов.
# В дереве отчетов отображаются строго те элементы, на которые у пользователя есть права доступа.
# Выбор чекбокса папки корректно управляет дочерними чекбоксами отчетов.
# Кнопка «Отмена» закрывает форму, сбрасывая состояние дерева.
# При запуске экспорта значения фильтров из исходного отчета успешно применяются ко всем выбранным отчетам, где существуют аналогичные фильтры. Несовпадающие фильтры игнорируются без ошибок.
# Итоговый PDF-файл является многостраничным, где каждый выбранный дашборд начинается с новой страницы. На каждой странице соблюдаются индивидуальные настройки оформления (формат, поля, фон, видимость заголовка).
# Компоненты «Таблица», имеющие скрытые за пределами видимости строки, корректно экспортируются полностью, формируя дополнительные листы в итоговом PDF (согласно выбранному техническому решению: пагинация или автоскролл).

h3. 6. Технические риски и ограничения:

# *Риск тайм-аута (Memory Limit) при рендере:* Генерация многостраничного PDF путем одновременного рендеринга множества тяжелых дашбордов приведет к зависанию вкладки или падению памяти.
#* *Минимизация:* Использовать очередь рендеринга (ограничение конкурентности). Желательно внедрение Progress Bar при сборке.
# *Специфика пагинации (расползание строк):* При выборе «Варианта А» (Пагинация) фиксация количества строк на страницу (например, 6 строк) может привести к появлению скроллбара, если текстовое содержимое одной из ячеек слишком длинное и переносится на несколько визуальных строк.
#* *Минимизация:* Потребуется ввести настройку ограничения высоты строки (например, обрезка текста с многоточием) или динамический расчет высоты блоков при рендере в PDF, чтобы избежать появления артефактов скроллбара на печати.
# *Рассинхронизация состояния фильтров:* Сервис рендеринга должен явно дожидаться события окончания загрузки данных (выполнения SQL-запросов к BI ядру) для каждого дашборда после применения унаследованных фильтров, и только затем делать снимок экрана.
