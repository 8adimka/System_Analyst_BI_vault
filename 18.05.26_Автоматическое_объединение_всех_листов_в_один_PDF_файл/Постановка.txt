ФКР26. Кампусы. Пакетный экспорт группы дашбордов в PDF-файл

{panel:title=Описание бизнес-требований.|borderStyle=solid|borderColor=#ccc|titleBGColor=#f5f5f5}
*Текущая реализация (As Is):*
Экспорт дашбордов в PDF работает в рамках одной активной страницы (одного дашборда). Пользователь может настроить параметры вывода (формат А3/А4, ориентацию, поля, цвет фона, отображение служебного заголовка) и получить файл только текущего экрана. Для компонентов типа «Таблица» с виртуальным скроллом применяется WYSIWYG-подход: экспортируется строго видимая область (viewport) без полной подгрузки датасета во избежание утечек памяти и падения производительности.

*Цель доработки (To Be):*
Реализовать механизм пакетного (группового) экспорта, позволяющий объединять несколько разных дашбордов (страниц/отчетов) аналитического портала в единый многостраничный PDF-файл в рамках выбранного контекста фильтрации (например, по конкретному Кампусу).
Каждый выбранный дашборд должен рендериться как отдельная страница (или серия страниц) итогового документа с сохранением всех ранее реализованных правил оформления (фон, центровка, отступы, скрытие заголовков, WYSIWYG-логика таблиц).

*Ограничение текущей итерации:* В рамках данной постановки *НЕ решается* задача выгрузки скрытых виртуализацией строк длинных таблиц. Сохраняется ранее утвержденное допущение: таблицы попадают в документ в том виде, в каком они рендерятся на экране в момент захвата (WYSIWYG), фокус задачи — на агрегации и последовательной склейке нескольких дашбордов.

h3. Ориентировочный предлагаемый подход.

# В боковой панели аналитического портала на вкладке «Отчёты» необходимо добавить новую кнопку *«Пакетный экспорт в PDF»*.

# При нажатии на кнопку *«Пакетный экспорт в PDF»* открывается модальное окно, отображающее иерархическую структуру (дерево) доступных пользователю папок (групп) и входящих в них дашбордов:

#* Корневыми элементами дерева являются наименования групп/папок. Папки имеют иконку сворачивания/разворачивания `[>]` / `[v]`.
#* Дочерними элементами являются конкретные дашборды, привязанные к этим группам.

# Возле каждой папки и каждого дашборда в дереве должен отображаться чекбокс ({{Checkbox}}):

#* Выделение чекбокса папки автоматически проставляет чекбоксы для всех вложенных в неё дашбордов.
#* Снятие выделения с папки снимает выделение со всех дочерних элементов.
#* Поддерживается частичное выделение папки ({{indeterminate state}}), если выбрана только часть дашбордов внутри неё.

# В нижней части интерфейса выбора (модального окна) должны быть доступны две управляющие кнопки:

#* *«Экспортировать»* — запускает процесс формирования единого PDF-файла.
#* *«Отмена»* — закрывает интерфейс выбора без сохранения изменений и генерации файлов.

h3. Функциональные требования к логике генерации и фильтрации.

*Необходимо продумать: 
# Механизм переноса контекста фильтрации (Глобальные фильтры).
# Применение индивидуальных настроек оформления отчета.
#* Для каждого дашборда, участвующего в пакетной выгрузке, должны применяться его индивидуальные настройки экспорта, заданные в его редакторе (Цвет фона, Формат листа А3/А4, Ориентация, Отображение заголовка, Отступы).
#* Если для конкретного отчета настройки не переопределены, используются дефолтные значения (А4, Альбомная, Заголовок Вкл, Отступы по 2 мм, цвет фона из Темы интерфейса).

# *Алгоритм сборки единого PDF-файла:*
#* Система должна инициировать последовательный или параллельный (с ограничением конкурентности для сохранения производительности) рендеринг выбранных страниц дашбордов.
#* Рендеринг каждого дашборда выполняется с учетом правил масштабирования, центрирования и сплошной заливки фона листа, включая области полей.
#* Полученные страницы/буферы документов объединяются (конкатенируются) в один многостраничный файл в порядке их следования в структуре дерева отчетов (сверху вниз).
#* По окончании сборки пользователю отдается на скачивание один файл формата {{.pdf}}. Наименование файла по умолчанию формируется по маске, например: {{Пакетный_экспорт_[Дата_Время].pdf}}.

h3. Критерии приёмки (AC):

# В боковой панели на вкладке «Отчёты» присутствует кнопка «Пакетный экспорт в PDF», клик по которой открывает дерево групп и отчетов.
# Кнопка «Отмена» корректно закрывает форму, сбрасывая выбранные чекбоксы.
# Выбор чекбокса папки корректно управляет дочерними чекбоксами отчетов. Возможен выбор отдельных отчетов из разных папок.
# При формировании PDF-файла данные на всех страницах (разных дашбордах) соответствуют глобальному фильтру (например, Кампусу), который был выбран на портале перед стартом экспорта.
# Итоговый PDF-файл является многостраничным, где каждый выбранный дашборд начинается с новой страницы.
# На каждой странице файла строго соблюдаются индивидуальные настройки оформления соответствующего дашборда:
#* Нет белых технологических полей по краям, если задан фоновый цвет.
#* Отступы соответствуют конфигурации конкретного отчета (или равны 2 мм по умолчанию).
#* Служебные шапки (заголовки дашбордов) скрыты на тех страницах, где в настройках отчета тумблер отображения заголовка был выключен.
# Таблицы с виртуальным скроллом на страницах пакетного отчета экспортируются в режиме WYSIWYG (захватывается текущее отрендеренное состояние диапазона строк), пустые "дыры" и смещения верстки отсутствуют (Кейсы 1-4 из предыдущей постановки выполняются в рамках многостраничного файла).

h3. Технические риски и ограничения:

# *Риск тайм-аута и падения производительности (Memory Limit):* Генерация многостраничного PDF-документа на клиенте или на сервере путем одновременного рендеринга множества тяжелых дашбордов с графиками (Echarts) и таблицами может привести к утечке оперативной памяти или зависанию вкладки браузера.
#* *Предложение по минимизации:* Необходимо предусмотреть очередь рендеринга (ограничение параллельных задач до 2-3 страниц одновременно) и визуальный индикатор прогресса для пользователя (Progress Bar с процентом выполнения или счетчиком "Обработано страниц Х из Y").
# *Риск рассинхронизации состояния фильтров:* При последовательном переключении контекста отчетов для скрытого рендеринга, компоненты могут не успеть выполнить повторный SQL-запрос к ядру BI, что приведет к рендеру старых или неполных данных.
#* *Предложение по минимизации:* Сервис рендеринга должен явно дожидаться события окончания загрузки данных для каждого дашборда перед снятием снимка экрана.
# *Специфичность бизнес-логики:* Механизм сквозной фильтрации затачивается под структуру фильтров Кампусов. Если у какого-то из выбранных дашбордов отсутствует сущность (параметр фильтрации) "Кампус", необходимо корректно обрабатывать этот сценарий (игнорировать фильтр для данного отчета или выводить дефолтное состояние без падения процесса генерации).
