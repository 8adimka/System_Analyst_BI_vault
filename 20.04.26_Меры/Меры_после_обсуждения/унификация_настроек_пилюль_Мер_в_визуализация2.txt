h3. Контекст и цель.

*Требуется:* унифицировать настройки пилюль-Мер с обычными полями во всех встроенных визуализациях аналитического портала (и подключаемой визуализации «Граф связей»).

Текущее меню настроек пилюли зависит от визуализации, полки, типа данных поля и т.д. Целевое соответствие охватывает состав настроек, элементы управления, варианты выпадающих списков, значения по умолчанию, видимость и доступность настроек, а также их сохранение.

В качестве *эталона* для поведения пилюли-Меры можно использовать *обычное поле* того же типа на той же полке в одинаковом контексте использования. 

В постановке перечислено поведение настроек для типов «Строка», «Число», «Дата». *Для остальных поддерживаемых типов*, включая «Файл» и «Изображение», *действует тот же принцип* доработок с переносом логики обычных полей с такими типами, но без отдельной детализации в рамках этой постановки. 

Сохраняются стандартное поведение визуализаций, фильтрации и настройки боковой панели фильтров.

----
h3. 1. Общие требования.

* Переиспользуемые компоненты с Мерами добавляются в соответствии с текущей реализацией.
* Настройка «Имя поля» изменяет локальный заголовок размещения; «Тип» — роль размещения. Определение Меры и другие её характеристики не изменяются. Ссылка сохраняется по {{name}} согласно общему контракту.
* После изменения полки, роли или типа результата применимость настроек пересчитывается как у поля. Уровень вычисления, скрытие результата и дрилл отображаются только в предусмотренных ролях.
* Начальные значения относятся к новому размещению. Сохранённые допустимые значения восстанавливаются при открытии и копировании; отсутствующие параметры старых конфигураций обрабатываются штатной нормализацией.

---
h4. 1.1. Агрегация.

Используются наработки по постановке [MB-5654|https://jira.modusbi.ru/browse/MB-5654]. Для {{is_aggregated = false}} функции, порядок вариантов, место управления и допустимость для Мер повторяют поведение обычных полей соответствующего типа и в аналогичном контексте.

|| Тип || Доступные функции агрегации || Стандартная функция агрегации по умолчанию ||
| Строка; Дата | «-», MIN, MAX, COUNT, COUNT D | MAX |
| Число | «-», AVG, MIN, MAX, SUM, COUNT, COUNT D | SUM |

* В общем механизме SUM/MAX назначаются незаданным значениям при активной категории или серии с сохранением проверок совпадения с полем группировки: SUM для числа, MAX для строки и даты. Безусловный дефолт для всех полок не вводится.
* «Солнечные лучи» при добавлении значений используют SUM для числа, COUNT для строки и даты. Сводная таблица сохраняет отдельный {{pivotAgg}} с начальными SUM для числа на полке «Значения», для даты и строки функция агрегации не отображается и не доступны для выбора.
* На полках без автоматического назначения сохраняется «-» (отсутствие локальной агрегации): в частности, координаты пузырьковой диаграммы, значения Контейнера страниц, Параллельных координат, IFrame и Организационной диаграммы.
* Для {{is_aggregated = true}} отображается {{AGR}}, применяются ограничения размещения на некоторых полках и запрет повторной локальной агрегации.
* Типозависимые настройки учитывают эффективный результат размещения: COUNT строковой Меры даёт число без изменения определения Меры.
* При переходе {{false → true}} локальная функция снимается, совместимость проверяется повторно; при обратном переходе применяются правила неагрегированного поля.

---
h4. 1.2. Дополнительные источники.

Селекторы «…по другому полю» поддерживают поля и допустимые Меры текущего набора данных по ограничениям конкретной настройки. Поддерживаются сочетания «поле — поле», «поле — Мера», «Мера — поле», «Мера — Мера». Предварительное размещение источника требуется только там, где предусмотрено действующим механизмом.

Отсутствие выбранного источника сохраняет стандартное поведение текущей пилюли и штатную подпись пустого выбора («Все»). Допускается выбор исходно агрегированной Меры в этих настройках.

Для подписей и подсказок фильтров сохраняются ограничения связанных контрактов и локига объединения одинаковых подписей. Отображаемое значение не подменяет исходное условие отбора.

h3. 2. Матрица настроек.

---
h4. 2.1. Именованные профили.

|| Профиль || Настройки ||
| Б | Имя поля; Сортировка |
| З | Б; + Тип; Уровень вычисления; Скрыть результат; Агрегация |
| К | Б; + Сортировка по другому полю; Функция агрегации источника сортировки |
| Ф | Стандартный фильтр по п. 2.2 |

* Состояния сортировки: «Без сортировки» (по умолчанию), «По возрастанию», «По убыванию». Специальные правила компонента сохраняются.
* Тип — список ролей из матрицы, начальная роль «Значение», кроме специальных ролей компонента. 
* Уровень вычисления — числовой переключатель 0/1, начальное значение 0; 
* Скрыть результат — переключатель, изначально выключен. 
* Дрилл — множественный выбор уровней настроенной иерархии; отсутствие ограничения означает все уровни.

---
h4. 2.2. Стандартный фильтр.

Профиль Ф: 
* Имя поля; Уровень отбора (0/1, начальное 0); 
* Тип фильтра («По значению» — начальный, «По диапазону», «По сравнению»); 
* Автофильтр («-» — начальное значение, MIN, MAX); 
* Зависит от; 
* Сброс (изначально выключен); 
** Значение при сбросе (ВСЕ, MIN, MAX - недоступно до включения настройки «Сброс»); 
* Сортировка по другому полю; 
* Невидимый (тумблер - изначально выключен); 
* Локальный (тумблер - изначально выключен).

Зависимости и источники сортировки используют действующие списки и ограничения. Локальный фильтр влияет только на свою визуализацию.

При смене режима состав настроек меняется как у поля: диапазон даты использует штатные автонастройки дат и зависимые параметры; диапазон и сравнение — соответствующие настройки условий. Применяются эффективный тип результата и общие правила WHERE/HAVING.

h3. 3. Сохранение и ошибки.

Сохраняются независимые настройки размещений и дополнительные источники. Изменение {{alias}} переопределяет фильтрацию, но не затрагивает локальные заголовки и сохраняет ссылки на оригинальные поля или Меры по {{name}}. Перенос и обновление метаданных запускают штатную нормализацию и проверку совместимости.

Невалидная Мера недоступна для нового размещения и нового выбора в поддерживающих Меры селекторах. Новое несовместимое использование отклоняется *по действующему интерфейсу*. При отказе конфигурация сохраняет прежнее состояние: новая пилюля не создаётся, выбранный дополнительный источник не заменяется. Отклонённое размещение не инициирует новый запрос данных.

Сохранённые ошибки обрабатываются по постановке MB-5884: пилюля остаётся доступной для исправления или удаления; построение блокируется только при фактическом участии ошибочного размещения или активного дополнительного источника в запросе. Ошибка локальной функции валидной Меры не меняет статус определения.

Валидация и зависимости backend-Шага 3 учитываются как зависимость от поставки MB-5046.

h3. 5. Критерии приёмки (AC):

AC.1 — *Матрица настроек:*
* *Дано:* каждая полка раздела 2, допустимая валидная Мера и эквивалентное поле каждого основного типа в одинаковом контексте;
* *Когда:* открывают меню и меняют настройки, включая роли, сортировку, дрилл, итоги и специальные переключатели;
* *Тогда:* состав, варианты, начальные значения, зависимости и результат соответствуют матрице; несовместимые типы не становятся допустимыми. Для остальных поддерживаемых типов действует такое же соответствие.

AC.2 — *Агрегация:*
* *Дано:* Меры трёх типов без исходной агрегации; конфигурации без группировки, с категорией/серией, Солнечные лучи, сводная таблица и полки без автоматического назначения;
* *Когда:* добавляют пилюли и меняют группировку или локальную функцию;
* *Тогда:* функции и автоматическое назначение совпадают с полями по п. 1.1; COUNT даёт числовые настройки, исходно агрегированная Мера повторно не агрегируется.

AC.3 — *Дополнительные источники:*
* *Дано:* основная пилюля поля или Меры и допустимые дополнительные источники;
* *Когда:* выбирают, меняют и снимают источник сортировки, цвета, значения или подсказки;
* *Тогда:* поддерживаются применимые сочетания по п. 1.2; функции сортировки зависят от источника; снятие восстанавливает штатное поведение, исходное условие отбора сохраняется.

AC.4 — *Фильтры:*
* *Дано:* фильтры по Мерам трёх типов и две визуализации отчёта;
* *Когда:* меняют режим, сброс, видимость, локальность и производный фильтр контейнера;
* *Тогда:* настройки соответствуют п. 2.2 и матрице; значение сброса недоступно до включения сброса; локальный фильтр влияет только на свою визуализацию; параметры производного фильтра видны только при его включении. Специальные фильтры сохраняют правила подписей и взаимодействия с получателями.

AC.5 — *Жизненный цикл:*
* *Дано:* два размещения одной Меры с разными настройками и старая конфигурация без новых параметров;
* *Когда:* сохраняют, открывают, копируют, переносят пилюли и обновляют alias, тип или агрегированность определения;
* *Тогда:* независимые допустимые настройки и ссылки восстанавливаются; применяются нормализация, эффективный тип и переходы агрегированности по разделу 1; отсутствующие параметры получают штатное поведение.

AC.6 — *Ошибка и восстановление:*
* *Дано:* участвующее размещение или дополнительный источник стали невалидными, отсутствующими либо несовместимыми; отдельно имеется ошибочное неучаствующее размещение;
* *Когда:* строят визуализацию, затем исправляют или удаляют проблемное размещение;
* *Тогда:* применяется MB-5884: участвующая ошибка блокирует построение, неучаствующая — нет; размещения сохраняются для исправления; после устранения причины построение возобновляется с оставшимися настройками.

AC.7 — *Запрет нового использования:*
* *Дано:* визуализация с настроенными пилюлями и дополнительным источником; Мера со статусом {{invalid}} и валидная Мера, несовместимая с выбранной полкой либо селектором;
* *Когда:* проверяют возможность нового размещения невалидной Меры, пытаются разместить валидную Меру на несовместимой полке и выбрать запрещённую Меру дополнительным источником;
* *Тогда:* невалидная Мера недоступна для нового размещения и выбора; несовместимые действия отклоняются с пояснением причины по действующему интерфейсу. Новая пилюля не создаётся, прежний источник и остальные настройки сохраняются, конфигурация не изменяется; отклонённое размещение не инициирует новый запрос данных.
