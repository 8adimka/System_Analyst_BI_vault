h3. Контекст и проблематика.
Полное описание продуктовой логики приведено в Эпике по Мерам [https://jira.modusbi.ru/browse/MB-4364].
Общее описание *Шага 2* внедрения Мер описано в постановке [https://jira.modusbi.ru/browse/MB-4481].

В рамках этой Истории требуется подключить Меры к пользовательским сценариям столбчатой диаграммы: отображение Мер в левой панели, размещение на полках диаграммы, использование в совместимых настройках, сохранение ссылок в метаданных визуализации и формирование runtime payload для backend-а по уже описанным контрактам.

Сейчас аналитик может использовать в столбчатой диаграмме обычные поля набора данных и вычисляемые поля виджета, но не может выбрать Меру из набора данных, разместить её на полках диаграммы или использовать в совместимых настройках диаграммы, где выбираются вычисляемые поля. Из-за этого единые бизнес-показатели, вынесенные в Меры, остаются недоступны в пользовательском сценарии построения столбчатой диаграммы.

----
h3. Цель задачи:
# Добавить поддержку Мер в визуализацию *«Диаграмма столбчатая»* для размещения на стандартных полках диаграммы и использования в совместимых настройках правой боковой панели.
# Отобразить Меры в стандартной левой боковой панели визуализации отдельной секцией *«Меры»* ниже секции *«Поля»*.
# Сохранять в конфигурации диаграммы только ссылку на Меру по {{type = "measure"}}, {{name}} и {{datasetId}}, без копирования выражения Меры и других полей определения Меры.
# Формировать runtime payload по текущим контрактам, чтобы backend мог раскрыть Меру и встроить её выражение в нужный SQL-контекст.
# Сохранить текущее поведение столбчатых диаграмм, в которых Меры не используются.

_Пользовательская история:_
Как аналитик, я хочу использовать Меры в столбчатой диаграмме так же, как поля и вычисляемые поля, чтобы переиспользовать единые бизнес-показатели набора данных без дублирования формул внутри каждой визуализации.

----
h3. 1. Область применения.

h4. 1.1. Визуализация и набор данных.
Доработка выполняется для визуализации *«Диаграмма столбчатая»*:
* {{chartType = "barChart"}};
* {{visualType = "column"}}.

Меры доступны только при работе диаграммы с *произвольным* набором данных, в метаданных которого backend возвращает массив {{measures}}.

Для простых и составных наборов данных секция *«Меры»* в конструкторе столбчатой диаграммы не отображается.

---
h4. 1.2. Места использования Мер в рамках этой истории.
В рамках столбчатой диаграммы Меры должны поддерживаться:
* на полке *«Значения»* ({{name = "values"}});
* на полке *«Категории»* ({{name = "categories"}});
* на полке *«Серии»* ({{name = "series"}});
* на полке *«Фильтры»* ({{name = "filters"}});
* в правой боковой панели во вкладке *«Стиль элементов»* в селекторе *«Объект данных»*, если этот селектор доступен по текущим правилам диаграммы.

Целевой объём дополнительных selector-ов правой панели ограничен селектором *«Объект данных»* на вкладке *«Стиль элементов»*. Другие блоки правой панели не требуют расширения под Меры, если они не позволяют пользователю выбирать обычные или вычисляемые поля.

----
h3. 2. Исходные правила модели Мер.
Визуализация использует уже созданные Меры текущего набора данных.

Ключевые правила:
* Мера хранится в {{datasets.measures[]}} только для *произвольного* набора данных.
* {{name}} — ключ связи с Мерой во внешних ссылках.
* {{alias}} — используется для отображения пользователю и не является ключом связи.
* {{id}} из {{measures[]}} не используется как внешний ключ в визуализации.
* Локальный {{id}} пилюли в визуализации является идентификатором размещения, а не идентификатором Меры из набора данных.
* {{expression}} Меры не копируется в конфигурацию диаграммы и не передаётся frontend-ом в runtime payload как источник выражения.
* {{aggregation_kind = 1}} означает агрегированную Меру; {{aggregation_kind = 0}} — неагрегированную Меру.
* Для Мер с {{aggregation_kind = 1}} в интерфейсе отображается ярлык {{AGR}}.
* Меры со {{status = "invalid"}} отображаются пользователю с причиной ошибки, но недоступны для нового размещения и выбора.

Пример определения Меры в метаданных набора данных:
{code:json}
{
  "id": "847b1ec3-bbf8-4365-85fb-c4fca2a06e2e",
  "name": "Мера.Валовая_прибыль",
  "alias": "Валовая прибыль",
  "description": "Разница между выручкой и себестоимостью",
  "expression": "SUM(\"revenue\") - SUM(\"cost\")",
  "aggregation_kind": 1,
  "data_type": "number",
  "hierarchy": "Финансовые показатели",
  "level": 10,
  "status": "valid",
  "status_message": ""
}
{code}

----
h3. 3. Описание текущего поведения.
В конструкторе столбчатой диаграммы пользователь работает с полями набора данных и вычисляемыми полями виджета.

Стандартная левая боковая панель не содержит разделения на секции, все поля выводятся единым списком, Меры не отображаются. Пользователь не может перетащить Меру на полку диаграммы и не может выбрать Меру в настройке *«Объект данных»*.

Для столбчатой диаграммы используются полки:
* *«Значения»* — задаёт показатели, отображаемые столбцами. На полке есть тумблер:
** *«Первое»* — для отображения используется только первая активная пилюля полки;
** *«Все»* — для отображения используются все активные пилюли полки.
* *«Категории»* — задаёт разбиение значений по категориям. Активно используется только первая пилюля полки.
* *«Серии»* — задаёт дополнительное разбиение внутри категорий. На полке есть тумблер:
** *«Вкл»* — пилюли полки участвуют в построении диаграммы;
** *«Выкл»* — пилюли полки сохраняются в настройках, но не влияют на визуализацию и runtime payload.
* *«Фильтры»* — задаёт фильтрацию данных визуализации.

В правой боковой панели на вкладке *«Стиль элементов»* есть селектор *«Объект данных»*. Селектор доступен для выбора полей или мер только если для полки *«Серии»* тумблер находится в положении *«Выкл»*. Если *«Серии»* включены, селектор *«Объект данных»* недоступен.

----
h3. 4. Описание целевого поведения.
Пользователь открывает столбчатую диаграмму на основе произвольного набора данных и видит в левой боковой панели две секции:
* *«Поля»* — новая секция, сохраняет текущее поведение для обычных полей;
* *«Меры»* — новая секция с Мерами из выбранного набора данных.

Секция *«Меры»* отображается ниже секции *«Поля»*, сразу в развёрнутом виде и без возможности свернуть (аккордеон). Если Меры сгруппированы по иерархии ({{hierarchy}}), display-группы внутри секции также должны быть доступны пользователю аналогично как в обычных полях.

Пользователь может перетаскивать валидные Меры на полки столбчатой диаграммы с учётом матрицы допустимости. На полках Меры отображаются как отдельный тип пилюли: по {{alias}}, светло-синим цветом {{#3491F7}}, с ярлыком {{AGR}} для агрегированных Мер.

В селекторе *«Объект данных»* на вкладке *«Стиль элементов»*, если селектор доступен, пользователь может выбрать валидную Меру там же, где сейчас выбирает обычное или вычисляемое поле. Выбор Меры в этом селекторе сохраняется по тем же правилам ссылок: {{type = "measure"}}, {{name}}, {{datasetId}}.

Runtime payload диаграммы передаёт backend-у объекты {{type = "measure"}}. Backend находит актуальное определение Меры в {{datasets.measures[]}}, раскрывает выражение Меры ({{expression}}) и строит SQL по правилам описанным в Шаге 2 backend-доработок ([https://jira.modusbi.ru/browse/MB-5035]).

----
h3. 5. Требования к интерфейсу.
---
h4. 5.1. Левая боковая панель.
Для столбчатой диаграммы на основе произвольного набора данных левая боковая панель должна отображать секцию *«Меры»* ниже секции *«Поля»*.

Требования:
* секция *«Меры»* отображается развёрнутой;
* пользовательское сворачивание/разворачивание секции *«Меры»* на этом этапе не реализуется;
* список Мер строится только из {{measures}} текущего набора данных;
* Меры отображаются по {{alias}};
* системное {{name}} может отображаться в tooltip как справочная техническая информация;
* для Мер указывается выбранный тип данных, аналогично отображению для обычных полей;
* для Мер с {{aggregation_kind = 1}} отображается ярлык {{AGR}};
* Меры со {{status = "invalid"}} отображаются в error-состоянии и недоступны для drag-and-drop.

Если левая панель реализована как общий компонент для визуализаций, включение секции *«Меры»* должно быть управляемым и на текущем шаге активироваться только для столбчатой диаграммы.

---
h4. 5.2. Группировка, сортировка и поиск Мер.
Если у Меры заполнено {{hierarchy}}, она отображается в соответствующей display-группе внутри секции *«Меры»*.

Порядок отображения:
# Меры с заполненной {{hierarchy}}, групируются по значению {{hierarchy}} и отображаются в списке Мер аналогично обычным полям;
#* внутри группы — сортировка по {{level}} по возрастанию, затем по {{alias}};
# Меры без {{hierarchy}} — в корневом уровне секции, сортировка по {{alias}}.

Поиск по полям, также должен находить Меры:
* по {{alias}} и {{name}};
** по логике {{OR}}.

В результатах поиска Меры должны визуально отличаться от обычных полей.

---
h4. 5.3. Tooltip и error-состояния.
Tooltip Меры в левой панели и на пилюле должен содержать:
* {{description}}, если заполнено;
* {{data_type}};
* системное {{name}};
* признак агрегированности;
* {{status_message}}, если Мера невалидна.

Если Мера стала {{invalid}} после сохранения диаграммы:
* сохранённая пилюля Меры не удаляется автоматически из конфигурации диаграммы;
* пилюля отображается в error-состоянии;
* запрос данных блокируется только если эта Мера участвует в активной полке или активной настройке, попадающей в построение диаграммы;
* пользователю показывается сообщение с {{alias}}/названием Меры и причиной ошибки, если причина известна.

---
h4. 5.4. Визуальное отличие пилюль Мер.
На полках столбчатой диаграммы Мера отображается как отдельный тип объекта.

Требования:
* основной цвет пилюли Меры — светло-синий {{#3491F7}};
* цвет должен применяться на полках *«Значения»*, *«Категории»*, *«Серии»*, *«Фильтры»*;
* для Мер с {{aggregation_kind = 1}} отображается ярлык {{AGR}};
* на пилюле не должно быть доступно ручное изменение {{aggregation_kind}};
* настройки локальной агрегации {{agg}}/{{aggr}} для Меры не должны применяться поверх выражения Меры.

---
h4. 5.5. Селектор «Объект данных» на вкладке «Стиль элементов».
На вкладке *«Стиль элементов»* правой боковой панели столбчатой диаграммы необходимо поддержать Меры в селекторе *«Объект данных»*.

Правила доступности селектора не меняются:
* если тумблер полки *«Серии»* находится в положении *«Выкл»*, селектор *«Объект данных»* доступен для использования полей и Мер;
* если тумблер полки *«Серии»* находится в положении *«Вкл»*
** и на полке *«Серии»* отсутствуют добавленные пилюли, селектор *«Объект данных»* доступен для использования полей и Мер;
** и на полке *«Серии»* присутствуют добавленные пилюли, селектор *«Объект данных»* недоступен.

Правила выбора Меры:
* список кандидатов селектора формируется для обычных и вычисляемых полей добавленных на полку *«Значения»* (с выбранным типом "Значение"); Меры добавляются в этот список, но выделяются как отдельный тип объекта;
* валидная Мера доступна для выбора;
* невалидная Мера не показывается для нового выбора;
* в списке отображается {{alias}} Меры, ярлык {{AGR}} для агрегированной Меры и визуальный признак типа *«Мера»*;
* выбранная Мера сохраняется как ссылка по {{type = "measure"}}, {{name}}, {{datasetId}}.

Если пользователь включил *«Серии»*, селектор *«Объект данных»* становится недоступен, если на полке *«Серии»* есть добавленные пилюли полей или Мер, по текущей логике диаграммы. Сохранённое значение селектора *«Объект данных»* и связанных селекторов (например, «Привязка к оси») при этом не должно повреждаться; при возврате тумблера *«Серии»* в положение *«Выкл»* выбранная ранее Мера или поле должно отобразиться снова. Если к этому моменту Мера отсутствует или имеет {{status = "invalid"}}, значение selector-а сбрасывается.

----
h3. 6. Правила использования Мер на полках.
---
h4. 6.1. Матрица допустимости.
|| Полка / настройка || Runtime-контекст || {{aggregation_kind = 0}} || {{aggregation_kind = 1}} || Правило ||
| *Значения* | {{select}} | Допускается с предупреждением | Допускается | Мера используется как значение диаграммы |
| *Категории* | {{group}} + {{select}} | Допускается | Блокируется | Активна только первая пилюля полки |
| *Серии* | {{group}} + {{select}} при режиме *«Вкл»* | Допускается | Блокируется | При режиме *«Выкл»* не попадает в runtime payload |
| *Фильтры* / {{WHERE}} | {{where}} | Допускается | Блокируется | Режим определяется по {{aggregation_kind}} |
| *Фильтры* / {{HAVING}} | {{having}} | Блокируется | Допускается | Режим определяется по {{aggregation_kind}} |
| *Объект данных* в *«Стиль элементов»* | По текущей логике selector-а | Допускается | Допускается | Доступно только при выключенных сериях |

---
h4. 6.2. Полка «Значения».
Мера на полке *«Значения»* используется как показатель, отображаемый столбцами.

Правила:
* {{aggregation_kind = 1}} допускается без дополнительной локальной агрегации;
* {{aggregation_kind = 0}} допускается с предупреждением: *«Мера "[alias]" является неагрегированной. Убедитесь, что её использование в значениях диаграммы даст корректный результат»*;
* предупреждение не блокирует размещение и построение диаграммы;
* режим *«Первое»* передаёт в runtime payload только первую активную пилюлю полки;
* режим *«Все»* передаёт в runtime payload все активные пилюли полки в порядке размещения;
** каждая Мера значения получает отдельный технический alias результата по текущей стратегии диаграммы, например {{[values][0]}}, {{[values][1]}}.

Если на полке *«Значения»* используется пилюля с {{valueType = "tooltip"}}, Мера должна поддерживаться в этом режиме по той же логике, что обычное или вычисляемое поле: она участвует в данных для всплывающей подсказки, но не становится отдельным столбцом диаграммы.

---
h4. 6.3. Полка «Категории».
Мера на полке *«Категории»* используется как вычисляемое измерение для разбиения данных.

Правила:
* активно используется только первая пилюля полки;
* неагрегированная Мера ({{aggregation_kind = 0}}) допускается;
* агрегированная Мера ({{aggregation_kind = 1}}) блокируется;
* при блокировке пользователь видит сообщение: *«На полке "Категории" допустимы только неагрегированные Меры»*;
* активная Мера категории передаётся в {{group}} и, если текущая логика диаграммы возвращает категорию в результате, в {{select}} с техническим alias категории.

---
h4. 6.4. Полка «Серии».
Мера на полке *«Серии»* используется как вычисляемая серия для дополнительного разбиения данных внутри категорий.

Правила:
* неагрегированная Мера ({{aggregation_kind = 0}}) допускается;
* агрегированная Мера ({{aggregation_kind = 1}}) блокируется независимо от текущего положения тумблера серий;
* при блокировке пользователь видит сообщение: *«На полке "Серии" допустимы только неагрегированные Меры»*;
* если тумблер *«Серии»* находится в положении *«Вкл»*, активные Меры серии передаются в {{group}} по текущей стратегии alias-ов серии, например {{[series][0]}};
* если тумблер *«Серии»* находится в положении *«Выкл»*, сохранённые Меры на полке *«Серии»* не попадают в {{group}}, {{select}} и {{order}} и не влияют на количество столбцов.

---
h4. 6.5. Полка «Фильтры».
Мера на полке *«Фильтры»* отображается как фильтрующая пилюля с признаком типа *«Мера»*.

Правила:
* для {{aggregation_kind = 0}} режим фильтра — {{WHERE}};
* для {{aggregation_kind = 1}} режим фильтра — {{HAVING}};
* режим {{WHERE}}/{{HAVING}} определяется автоматически по {{aggregation_kind}} и не должен вручную переключаться пользователем в несовместимое значение;
* условие фильтра хранится структурно: оператор, значение, тип значения;
* список операторов и правила ввода значения должны соответствовать текущему фильтру по полям с учётом {{data_type}} Меры;
* фильтр с незаполненным обязательным значением считается неактивным и не попадает в runtime payload до заполнения.

Несколько фильтров по Мерам допускаются. Условия WHERE-Мер объединяются с другими WHERE-условиями по текущим правилам backend-а, базово через {{AND}}. Условия HAVING-Мер объединяются с другими HAVING-условиями по текущим правилам backend-а, базово через {{AND}}.

----
h3. 7. Хранение Меры в конфигурации диаграммы.
При размещении Меры на полке или выборе в selector-е диаграмма хранит объект использования Меры, а не определение Меры.

Минимальный объект использования Меры:
{code:json}
{
  "id": "visual_measure_4f9b7e2d",
  "type": "measure",
  "name": "Мера.Валовая_прибыль",
  "datasetId": 244,
  "alias": "Валовая прибыль",
  "valueType": "value"
}
{code}

|| Поле || Обязательность || Описание ||
| {{id}} | Да | Локальный идентификатор размещения/выбора. Не равен {{measures[].id}} |
| {{type}} | Да | Для Меры всегда {{measure}} |
| {{name}} | Да | Системное имя Меры из {{datasets.measures[].name}}. Ключ связи |
| {{datasetId}} | Да | Идентификатор набора данных Меры |
| {{alias}} | Нет | Кэш отображаемого названия на момент размещения. Не используется как ключ связи |
| {{valueType}} | Нет | Используется там, где текущая диаграмма различает {{value}} и {{tooltip}} |

Локальные настройки размещения, например сортировка, форматирование, цвет, точность, подпись, параметры фильтра или настройки *«Стиля элементов»*, хранятся рядом с объектом использования Меры по текущей модели конфигурации диаграммы и не записываются обратно в {{datasets.measures[]}}.

h3. 8. Формирование runtime payload.
---
h4. 8.1. Общие правила.
Frontend формирует runtime payload для {{/v1/api/recordsets/<dataset_id>}} из активных полок и настроек диаграммы.

Минимальный runtime-объект Меры:
{code:json}
{
  "type": "measure",
  "name": "Мера.Валовая_прибыль",
  "alias": "[values][0]",
  "id": "visual_measure_4f9b7e2d",
  "fieldAlias": "Валовая прибыль"
}
{code}

|| Поле || Назначение ||
| {{type}} | Для Меры всегда {{measure}} |
| {{name}} | Ключ поиска Меры в {{datasets.measures[]}} |
| {{alias}} | Технический alias результата запроса, не {{alias}} Меры |
| {{id}} | Локальный frontend-id пилюли, не ключ связи с Мерой |
| {{fieldAlias}} | Отображаемое название для диагностики/отладки, не источник выражения |

Frontend не должен передавать для {{type = "measure"}} непустые {{calc}}, {{expression}}, {{agg}} или {{aggr}} как источник выражения Меры.

---
h4. 8.2. Соответствие полок runtime-блокам.
|| Размещение Меры || Runtime-блок || Правило ||
| *Значения*, режим *«Первое»* | {{select}} | Передаётся только первая активная пилюля значения |
| *Значения*, режим *«Все»* | {{select}} | Передаются все активные пилюли значения |
| *Значения* с {{valueType = "tooltip"}} | По текущей логике tooltip-данных | Мера доступна для шаблона tooltip и не создаёт отдельный столбец |
| *Категории* | {{group}} + при необходимости {{select}} | Передаётся только первая активная неагрегированная Мера |
| *Серии*, режим *«Вкл»* | {{group}} + при необходимости {{select}} | Передаются активные неагрегированные Меры серии |
| *Серии*, режим *«Выкл»* | Не передаётся | Полка не влияет на runtime payload |
| *Фильтры*, {{aggregation_kind = 0}} | {{where}} | Передаётся структурное условие {{condition}} |
| *Фильтры*, {{aggregation_kind = 1}} | {{having}} | Передаётся структурное условие {{condition}} |
| *Объект данных* в *«Стиль элементов»* | По текущей логике selector-а | Если обычное/вычисляемое поле из этого selector-а добавляется в payload, Мера передаётся по тому же правилу через {{type = "measure"}} |

Backend определяет SQL-контекст не по названию полки, а по runtime-блоку, в котором frontend передал объект {{type = "measure"}}.

---
h4. 8.3. Пример payload для Меры на полке «Значения».
{code:json}
{
  "group": [
    {
      "name": "fed_okrug_full_name",
      "calc": "",
      "alias": "[categories]"
    }
  ],
  "select": [
    {
      "type": "measure",
      "name": "Мера.Валовая_прибыль",
      "alias": "[values][0]",
      "id": "visual_measure_4f9b7e2d",
      "fieldAlias": "Валовая прибыль"
    }
  ],
  "where": [],
  "having": {
    "condition": ""
  },
  "order": [],
  "variables": [],
  "series": {
    "enable": 0
  }
}
{code}

---
h4. 8.4. Пример payload для фильтра по Мере.
WHERE-фильтр по неагрегированной Мере:
{code:json}
{
  "where": [
    {
      "type": "measure",
      "name": "Мера.Маржа_строки",
      "condition": {
        "operator": ">",
        "value": 0,
        "value_type": "number"
      }
    }
  ],
  "having": {
    "condition": ""
  }
}
{code}

HAVING-фильтр по агрегированной Мере:
{code:json}
{
  "having": {
    "condition": "",
    "items": [
      {
        "type": "measure",
        "name": "Мера.Валовая_прибыль",
        "condition": {
          "operator": ">",
          "value": 0,
          "value_type": "number"
        }
      }
    ]
  }
}
{code}

Если backend в актуальной реализации использует эквивалентный структурный формат {{having}} как массив условий, frontend должен использовать формат, согласованный в backend-Шаге 2, без изменения семантики: агрегированная Мера попадает в {{HAVING}}, неагрегированная — в {{WHERE}}.

h3. 9. Backend и API.
Задача по столбчатой диаграмме должна переиспользовать backend-механизмы, описанные в backend-Шагах 1-3.

Затрагиваемые контракты:
|| Контракт/ бъект || Требуемое поведение в рамках этой истории ||
| {{datasets}} | При чтении произвольного набора данных возвращает актуальный массив {{measures}} со статусами и метаданными |
| {{/v1/api/recordsets/<dataset_id>}} | Принимает {{type = "measure"}} в runtime-блоках {{select}}, {{group}}, {{where}}, {{having}}, {{order}} и раскрывает {{expression}} Меры |
| Экспорт диаграммы | Если экспорт использует тот же runtime payload и SQL-builder, Меры обрабатываются тем же способом, что экранное построение |

Backend должен вернуть контролируемую ошибку, если:
* Мера с переданным {{name}} не найдена;
* Мера имеет {{status = "invalid"}};
* {{datasetId}} Меры не соответствует текущему набору данных;
* агрегированная Мера передана в {{group}} или {{where}};
* неагрегированная Мера передана в {{having}};
* в runtime payload для {{type = "measure"}} передан непустой {{calc}}, {{expression}}, {{agg}} или {{aggr}};
* условие фильтра по Мере содержит неподдержанный оператор или некорректный тип значения;
* итоговый SQL не может быть построен.

Сообщение ошибки должно быть пригодно для отображения пользователю и диагностики аналитиком. Рекомендуемый минимум технических деталей: {{measure_name}}, {{runtime_block}}, {{reason}}, {{status_message}} при наличии.

h3. 10. Права доступа.
Новые отдельные права на использование Мер в столбчатой диаграмме не вводятся.

Используются существующие права:
* чтение Мер — по праву чтения соответствующего набора данных и отчёта;
* изменение конфигурации диаграммы с добавлением/удалением Мер — по праву редактирования отчёта/виджета;
* создание, редактирование и удаление самих Мер — в настройках набора данных по правам на набор данных.

----
h3. 11. Обратная совместимость и ограничения.
* Существующие столбчатые диаграммы без Мер должны продолжить работать без изменения результата и конфигурации.
* Отсутствие массива {{measures}} в старых метаданных произвольного набора данных трактуется как пустой список Мер.
* Существующие обычные поля и вычисляемые поля виджета продолжают работать по текущим правилам.
* Текущий формат хранения полок и настроек диаграммы не нормализуется и не переносится в отдельную структуру в рамках этой истории.
* Frontend не должен копировать {{expression}} Меры в конфигурацию диаграммы или runtime payload.

h3. 15. Критерии приёмки (AC).
*AC.1* — Секция «Меры» в левой панели:
* *Дано:* пользователь открыл конструктор столбчатой диаграммы на произвольном наборе данных;
* *Когда:* backend вернул массив {{measures}};
* *Тогда:* ниже секции *«Поля»* отображается секция *«Меры»*;
* *И:* секция *«Меры»* отображается развёрнутой и без пользовательского аккордеона.

*AC.2* — Секция «Меры» не отображается для неподдержанного набора:
* *Дано:* столбчатая диаграмма использует простой или составной набор данных;
* *Тогда:* секция *«Меры»* в левой панели не отображается;
* *И:* пользователь не может добавить новую Меру на полки диаграммы.

*AC.3* — Визуальное представление Меры:
* *Дано:* валидная Мера размещена на полке столбчатой диаграммы;
* *Тогда:* пилюля отображается по {{alias}};
* *И:* цвет пилюли Меры — {{#3491F7}};
* *И:* для {{aggregation_kind = 1}} отображается ярлык {{AGR}}.

*AC.4* — Невалидная Мера недоступна для нового использования:
* *Дано:* Мера имеет {{status = "invalid"}};
* *Когда:* пользователь видит её в секции *«Меры»*;
* *Тогда:* Мера отображается с error-состоянием;
* *И:* drag-and-drop и выбор в selector-е заблокированы;
* *И:* tooltip показывает {{status_message}}.

*AC.5* — Мера на полке «Значения» в режиме «Первое»:
* *Дано:* на полке *«Значения»* размещено несколько пилюль, первая активная пилюля — Мера;
* *И:* тумблер полки находится в положении *«Первое»*;
* *Когда:* диаграмма запрашивает данные;
* *Тогда:* в {{select}} runtime payload попадает только первая активная Мера с {{type = "measure"}} и техническим alias значения.

*AC.6* — Меры на полке «Значения» в режиме «Все»:
* *Дано:* на полке *«Значения»* размещено несколько активных Мер;
* *И:* тумблер полки находится в положении *«Все»*;
* *Когда:* диаграмма запрашивает данные;
* *Тогда:* каждая активная Мера передаётся отдельным объектом {{type = "measure"}} в {{select}};
* *И:* каждая Мера получает отдельный технический alias результата.

*AC.7* — Неагрегированная Мера на полке «Значения»:
* *Дано:* пользователь размещает на полке *«Значения»* Меру с {{aggregation_kind = 0}};
* *Тогда:* размещение не блокируется;
* *И:* пользователь видит предупреждение о неагрегированной Мере.

*AC.8* — Мера на полке «Категории»:
* *Дано:* пользователь размещает на полке *«Категории»* Меру с {{aggregation_kind = 0}};
* *Когда:* диаграмма запрашивает данные;
* *Тогда:* Мера передаётся в {{group}} и при необходимости в {{select}} как вычисляемое измерение.

*AC.9* — Агрегированная Мера не допускается на полку «Категории»:
* *Дано:* пользователь пытается разместить на полке *«Категории»* Меру с {{aggregation_kind = 1}};
* *Тогда:* размещение блокируется;
* *И:* пользователь видит сообщение *«На полке "Категории" допустимы только неагрегированные Меры»*.

*AC.10* — Мера на полке «Серии» при включённых сериях:
* *Дано:* на полке *«Серии»* размещена валидная Мера с {{aggregation_kind = 0}};
* *И:* тумблер *«Серии»* находится в положении *«Вкл»*;
* *Когда:* диаграмма запрашивает данные;
* *Тогда:* Мера передаётся в {{group}} как серия;
* *И:* диаграмма строит столбцы с детализацией по этой серии.

*AC.11* — Мера на полке «Серии» при выключенных сериях:
* *Дано:* на полке *«Серии»* размещена Мера;
* *И:* тумблер *«Серии»* находится в положении *«Выкл»*;
* *Когда:* диаграмма запрашивает данные;
* *Тогда:* Мера серии не попадает в {{group}}, {{select}} и {{order}};
* *И:* не влияет на количество столбцов и результат диаграммы.

*AC.12* — Агрегированная Мера не допускается на полку «Серии»:
* *Дано:* пользователь пытается разместить на полке *«Серии»* Меру с {{aggregation_kind = 1}};
* *Тогда:* размещение блокируется;
* *И:* пользователь видит сообщение *«На полке "Серии" допустимы только неагрегированные Меры»*.

*AC.13* — Фильтр по неагрегированной Мере:
* *Дано:* на полке *«Фильтры»* размещена Мера с {{aggregation_kind = 0}} и заполненным условием;
* *Когда:* диаграмма запрашивает данные;
* *Тогда:* Мера передаётся в {{where}} как объект {{type = "measure"}} со структурным {{condition}}.

*AC.14* — Фильтр по агрегированной Мере:
* *Дано:* на полке *«Фильтры»* размещена Мера с {{aggregation_kind = 1}} и заполненным условием;
* *Когда:* диаграмма запрашивает данные;
* *Тогда:* Мера передаётся в структурную часть {{having}} как объект {{type = "measure"}} со структурным {{condition}}.

*AC.15* — Селектор «Объект данных» поддерживает Меры:
* *Дано:* тумблер полки *«Серии»* находится в положении *«Выкл»*;
* *И:* пользователь открыл вкладку *«Стиль элементов»*;
* *Когда:* пользователь открывает селектор *«Объект данных»*;
* *Тогда:* в селекторе доступны валидные Меры текущего набора данных;
* *И:* Меры отображаются по {{alias}}, с признаком типа *«Мера»* и ярлыком {{AGR}} для агрегированных Мер.

*AC.16* — Селектор «Объект данных» недоступен при включённых сериях:
* *Дано:* тумблер полки *«Серии»* находится в положении *«Вкл»* и не пуст;
* *Когда:* пользователь открывает вкладку *«Стиль элементов»*;
* *Тогда:* селектор *«Объект данных»* недоступен по общей логике диаграммы;
* *И:* сохранённое значение selector-а не повреждается.

*AC.17* — Конфигурация диаграммы хранит ссылку на Меру:
* *Дано:* Мера размещена на полке или выбрана в selector-е *«Объект данных»*;
* *Когда:* пользователь сохраняет диаграмму;
* *Тогда:* в конфигурации сохраняются {{type = "measure"}}, {{name}}, {{datasetId}} и локальный {{id}} размещения;
* *И:* {{expression}}, {{aggregation_kind}}, {{status}} и {{status_message}} не копируются в конфигурацию диаграммы.

*AC.18* — Runtime payload не подменяет выражение Меры:
* *Дано:* диаграмма строит запрос с Мерой;
* *Когда:* frontend формирует runtime payload;
* *Тогда:* объект {{type = "measure"}} содержит {{name}} Меры и технический alias результата;
* *И:* frontend не передаёт непустые {{calc}}, {{expression}}, {{agg}} или {{aggr}} как источник выражения Меры.

*AC.19* — Открытие диаграммы после изменения Меры:
* *Дано:* в сохранённой диаграмме используется Мера;
* *И:* у Меры изменился {{alias}}, но {{name}} остался прежним;
* *Когда:* пользователь открывает диаграмму;
* *Тогда:* связь по {{name}} сохраняется;
* *И:* в интерфейсе отображается актуальный {{alias}} из метаданных набора данных.

*AC.20* — Открытие диаграммы с отсутствующей или невалидной Мерой:
* *Дано:* сохранённая диаграмма имеет на полках Меру, которая отсутствует в наборе данных или имеет {{status = "invalid"}};
* *Когда:* пользователь открывает диаграмму;
* *Тогда:* пилюля Меры отображается в error-состоянии;
* *И:* конфигурация не очищается автоматически;
* *И:* построение диаграммы блокируется только если эта Мера активно используется для построение запроса.

*AC.21* — Обратная совместимость:
* *Дано:* существующая столбчатая диаграмма не использует Меры;
* *Когда:* пользователь открывает, редактирует, строит или экспортирует диаграмму после внедрения доработки;
* *Тогда:* поведение диаграммы и результат запроса данных не меняются.

h3. 9. Загрузка и синхронизация при открытии диаграммы.
При открытии столбчатой диаграммы frontend должен:

# построить секцию *«Меры»* в левой панели;
# сопоставить все сохранённые объекты {{type = "measure"}} в конфигурации диаграммы с актуальными Мерами по {{name}} и {{datasetId}};
# отобразить актуальный {{alias}}, {{aggregation_kind}}, {{data_type}}, {{status}} и {{status_message}};
# перепроверить совместимость сохранённой Меры с полкой или selector-ом, если изменился {{aggregation_kind}} или {{status}};
# не удалять автоматически сохранённые ссылки на отсутствующие или невалидные Меры.

Если {{alias}} изменился без изменения {{name}}, диаграмма продолжает ссылаться на прежнее {{name}} и отображает актуальный {{alias}} из метаданных набора данных.

Если {{expression}} Меры изменилось, следующий runtime-запрос диаграммы использует актуальное выражение из набора данных. Копия старого выражения в визуализации не хранится.
