Нужно внести в описанный интерфейс работы с мерами следующие изменения, исправления и доработки:
"## 1. Терминология и модель данных меры.

Нужно явно разделить два поля меры и закрепить в постановке:

Поле `alias` - человекочитаемое название меры, вводится пользователем при создании меры. Пользователь может переименовывать alias, а поле name - не меняется после создания меры. Т.е. у нас нет ограничений теперь на переименование Мер (т.к. пользователь меняет только alias Меры, а связь происходит по прежнему через поле name).

Поле `name` - системное наименование меры и не вводится пользователем вручную.

Пример:

```text
alias = "Дата отчёта"
name = "Мера.Дата_отчёта"
```

---

## 2. Создание меры.

При создании меры пользователь заполняет только поле:
Алиас Меры


Текущее поле:
Наименование


нужно переименовать в:
Алиас Меры


Поле `Наименование меры` / `name` вручную не заполняется.

В постановке можно сформулировать так:

> При создании меры пользователь вводит только `Алиас Меры`. Системное наименование меры `name` формируется автоматически на основании введённого alias по правилу генерации `name`:

name = "Мера." + alias, приведённый к формату системного имени


Правила преобразования:

1. Префикс всегда добавляется автоматически:

```text
Мера.
```

2. Пробелы в alias заменяются на подчёркивания.

3. Кириллица в `name` допускается.

4. Системное имя формируется в одно слово.

Пример:

```text
Алиас Меры (alias): Дата отчёта
Наименование меры (name): Мера.Дата_отчёта
```

Ещё пример:

```text
Алиас Меры (alias): Валовая прибыль
Наименование меры (name): Мера.Валовая_прибыль
```

---

## 3. Кто формирует `name`.

Нужно явно указать, что `name` формирует бэк.

Фронт:

```text
передаёт alias
```

Бэк:

```text
генерирует name
сохраняет alias и name
возвращает alias и name на фронт
```

Фронт не должен самостоятельно добавлять `Мера.` при вставке меры в редактор. Он должен использовать уже готовое системное имя, полученное от бэка.


---

## 5. Отображение в таблице мер.

В таблице мер нужно показать оба значения, потому что пользователь будет сталкиваться с `name` в редакторе при дропе меры.

Таблица «Меры»:

Новый порядок столбцов:

```text
1. Наименование меры
2. Алиас
```

Где:

```text
Наименование меры = name
Алиас = alias
```

Пример строки:

| Наименование меры | Алиас       |
| ----------------- | ----------- |
| Мера.Дата_отчёта  | Дата отчёта |

---

## 5. Унификация с таблицей полей.

Для единообразия нужно обновить таблицу «Поля».

Было:

```text
Имя поля
```

Стало:

```text
Наименование поля
```

Следующий столбец (без изменений):

```text
Алиас
```

Итого для таблицы **«Поля»**:

```text
1. Наименование поля
2. Алиас
```

Итого для таблицы **«Меры»**:

```text
1. Наименование меры
2. Алиас
```

---

## 6. Отображение в боковой панели полей / мер

В боковой панели пользователь должен видеть человекочитаемые названия, то есть `alias`.

Нужно зафиксировать:

> В списках полей и мер, доступных для выбора отображается alias, а после перетаскивания в редактор отображается name.

То есть пользователь видит:

```text
Дата отчёта
```

а в редакторе:

```text
"Мера.Дата_отчёта"
```

Мы выделяем меры как обычные поля двойными кавычками, но у нас появляется приставка "Мера." по которой мы можем определить, что это Мера. Мы не используем квадратные скобки и т.д.

---

## 7. Дроп меры в редактор.

При перетаскивании меры в редактор нужно вставлять не alias, а системное имя `name`.

Пример:

Пользователь видит в панели:

```text
Дата отчёта
```

При дропе в редактор вставляется:

```text
"Мера.Дата_отчёта"
```

Важно: вставка должна быть в кавычках.

---

## 8. Дроп поля в редактор.

Для полей поведение остаётся аналогичным текущему поведению в вычисляемых полях:

Пользователь видит alias (если доступен, а иначе name) в боковой панеле и на полках (поведение остаётся без изменений):

```text
Дата отчёта
```

В редактор вставляется системное имя поля (без изменений):

```text
"report_date"
```

---

## 9. Автокомплит в редакторе.

Нужно изменить поведение автокомплита.

Поиск полей и мер должен идти идти по `alias` и/или name, а отображение в подсказках должны идти по `alias` (пользователь скорее всего не знает системных имён). Однако, если пользователь начинает вводить системное имя поля или меры, то в предлагаемых вариантах также должны появляться подходящие поля и/или меры. Поис происходит по логическому оператору ИЛИ - ищи или по name, или по alias.

Например, пользователь начинает вводить:

```text
Дата
```

В автокомплите он должен видеть варианты по alias:

```text
Дата отчёта
Дата региона
Дата начала
```

После выбора варианта в редактор вставляется системное имя.

Для меры:

```text
"Мера.Дата_отчёта"
```

Или для поля ользователь начинает вводить:

```text
repor
```

В автокомплите он должен видеть подходящие варианты, а, после выбора одного варианта, в редактор вставляется системное имя.

```text
"report_date"
```

---

## 10. Различение поля и меры в автокомплите.

Если у поля и меры одинаковый alias, в подсказках нужно визуально различать тип сущности.

Например, допустимо выделять меры красной контрастной иконкой меры.


Если возможности редактора ограничены и можно указать только иконку или дополнить текстовым пояснением.


---

## 11. Вставка из автокомплита.

Нужно отдельно зафиксировать важный технический нюанс:

> Значение, отображаемое в списке автокомплита, может отличаться от значения, вставляемого в редактор.

Отображаем:

```text
alias
```

Вставляем:

```text
name
```

Пример:

В подсказке:

```text
Дата отчёта
```

После выбора:

```text
"Мера.Дата_отчёта"
```

---

## 13. Кавычки в редакторе.

Нужно зафиксировать, что системные имена полей и мер вставляются в редактор в кавычках.

Для меры:

```text
"Мера.Дата_отчёта"
```

Для поля:

```text
"report_date"
```

Формулировка:

> При вставке поля или меры в редактор через дроп или автокомплит системное наименование вставляется в кавычках.

---

## 13. Валидация alias меры.

Из обсуждения также следует добавить ограничение на ввод alias меры.

Для `Алиас Меры` разрешены:

```text
буквы
цифры
пробел
знак подчёркивания
```

Нельзя разрешать символы, которые могут ломать выражения или выглядеть как синтаксис:

```text
кавычки
скобки
операторы
спецсимволы
```

Формулировка:

> В поле `Алиас Меры` разрешены только буквы, цифры, пробелы и знак подчёркивания. Не позволять ввод иных символов.

---

## 14. Уникальность системного имени меры name в рамках одного набора данных.

Так как `name` используется в редакторе и в визуализациях, оно должно быть уникальным.

Нужно добавить в постановку:

> Системное наименование меры `name` должно быть уникальным в рамках набора данных, к которому данная мера принадлежит.

Также нужно явно описать, что делать при коллизии.

Например, если пользователь создаёт две меры:

```text
Дата отчёта
Дата_отчёта
```

обе могут привести к одному `name`:

```text
Мера.Дата_отчёта
```

В такой ситуации backend должен разрешать конфликт. Например, допустимым может быть автоматическое добавление суффикса к конфликтующему name;

Системное имя должно быть уникальным. Конкретное правило обработки дублей может обсуждаться.

---

## 15. Редактирование alias меры.

Поведение при редактировании alias.

Поле `name` формируется из `alias`, но изменение alias не ведёт к изменению `name`.
Поле name не меняется после создания меры, т.к. name используется для связей в визуализациях и выражениях.
