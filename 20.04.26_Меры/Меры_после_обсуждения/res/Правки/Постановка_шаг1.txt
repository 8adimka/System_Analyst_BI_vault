h3. Контекст и цель истории.
Полное и комплексное описание данной задачи приведено в Эпике ([https://jira.modusbi.ru/browse/MB-4364]).

Настоящая История реализует управление Мерами на уровне *произвольного* набора данных:
создание, редактирование, удаление из метаданных набора данных, типизацию, признак агрегированности {{aggregation_kind}}, группировку и валидационный статус Меры.

На данном этапе Меры *ещё не используются в визуализациях*: не отображаются в панели полей конструктора, не размещаются на полках и не участвуют в построении SQL-запросов визуализаций.

История должна создать завершённый и устойчивый объект модели данных — «Меру», который в следующих историях будет использован в визуализациях.

----
h3. Границы истории.
В рамках Истории реализуется:
* секция «Меры» в настройках *произвольного* набора данных;
* создание новой Меры;
* редактирование Меры;
* удаление Меры;
* хранение расширенных метаданных Меры;
* валидация при сохранении;
* display-группировка Мер по «Иерархии» и «Уровню»;
* жизненный цикл статуса {{valid}} / {{invalid}} при изменении SQL набора данных.

В рамках Истории *не реализуется*:
* отображение Мер в конструкторе визуализаций;
* использование Мер на полках;
* SQL-инъекция Мер во внешний запрос визуализации;
* поддержка Мер для простых и составных наборов данных.

----
h3. Пользовательский интерфейс.
h4. Секция «Меры».
Во вкладке «Наборы данных» для *произвольного* набора данных под секцией «Описание полей набора данных» 
добавляется новая секция «Меры».

h4. Доступность кнопки «+ Добавить меру».
Кнопка «+ Добавить меру» активна *только* если одновременно выполнены все условия:
# для набора задан SQL-запрос;
# SQL-запрос успешно прошёл проверку;
# система получила и сохранила актуальный состав полей набора данных.

Если хотя бы одно условие не выполнено:
* кнопка находится в состоянии {{disabled}};
* при наведении отображается пояснение: _«Задайте и проверьте SQL-запрос набора данных»_.

h4. Создание и редактирование Меры.
При нажатии «+ Добавить меру» открывается модальное окно увеличенного размера.

В модальном окне одновременно доступны:
* поля формы Меры;
* редактор выражения;
* список полей текущего набора данных для вставки в выражение.

Для редактирования существующей Меры используется то же модальное окно с предзаполненными значениями.

Форма содержит следующие поля:
* *Название* (обязательное, строка) — отображаемое имя Меры; должно быть уникальным в рамках одного набора данных.
* *Описание* (необязательное, строка) — пояснительный текст; отображается в tooltip при наведении на Меру.
* *Тип данных* (обязательное) — логический тип результата Меры: {{number}}, {{string}}, {{date}}, {{datetime}}, {{boolean}} и т.д. Система может предложить значение по умолчанию, но пользователь обязан иметь возможность изменить тип вручную. Если для выбранного типа доступны дополнительные настройки (например, для дат), они отображаются условно.
* *Признак агрегированности* (обязательное, переключатель/флаг) — задаётся пользователем явно: {{агрегированная}} / {{неагрегированная}}. Используется для UX-валидации при размещении на полки.
* *Иерархия* (необязательное, строка) — имя группы/иерархии, в которой Мера отображается в панели полей.
* *Уровень* (необязательное, целое число) — порядок отображения Меры внутри иерархии.
* *Выражение* (обязательное) — редактор выражений, эквивалентный редактору вычисляемых полей виджета. Требования к редактору:
** Синтаксис и функции — идентичны вычисляемым полям.
** В редакторе доступен список полей текущего набора данных. Поля подставляются в выражение, обёрнутые в двойные кавычки: {{"field_name"}}.
** *(Опционально)* Автодополнение, подсветка синтаксических ошибок и другие продвинутые возможности нового редактора кода.
* *Кнопки формы:* «Сохранить» / «Отмена».

Требования к редактору:
* семантически эквивалентен редактору вычисляемых полей виджета;
* содержит список полей текущего набора данных;
* поля подставляются в двойных кавычках: {{"field_name"}};
* автодополнение, подсветка ошибок и другие продвинутые возможности _нового редактора кода_ допустимы, но не обязательны для этапа реализации этой Истории.

----
h3. Валидация при сохранении.
При сохранении выполняются следующие проверки:
* заполнены обязательные поля;
* название Меры уникально в рамках одного набора данных;
* выражение синтаксически валидно в рамках редактора/парсера;
* выражение ссылается только на доступные поля текущего набора данных;
* для набора известен актуальный состав полей.

При успешном сохранении:
* новая Мера получает стабильный {{id}};
* Мера сохраняется в метаданные набора данных;
* для Меры устанавливается статус {{valid}}.

----
h3. Список Мер набора данных.
Сохранённые Меры отображаются в табличном списке.

Набор отображаемых колонок:

|| *Название* || *Тип данных* || *Агрегация* || *Иерархия* || *Уровень* || *Выражение* (кратко) || *Действия* ||
| <название меры> | <тип> | AGR / — | <иерархия> | <порядок> | <первые N символов> | [иконка редактировать] [иконка удалить] |

Дополнительные правила:
* для Мер с {{aggregation_kind = 1}} в колонке «Агрегация» отображается ярлык *AGR*;
* для Мер с {{aggregation_kind = 0}} отображается прочерк "—";
* описание Меры выводится в tooltip (при наведении на Меру);
* если заполнена «Иерархия», Мера относится к соответствующей display-группе;
* внутри группы Меры сортируются по {{level}} по возрастанию, затем по названию (по алфавиту);
* Меры без «Иерархии» отображаются в корневом уровне секции «Меры».

----
h3. Статус валидации Меры.
Для каждой Меры хранится статус:
* {{valid}} — Мера валидна в контексте текущего набора данных;
* {{invalid}} — выражение Меры больше невалидно в контексте текущего набора данных.

Если Мера получает статус {{invalid}}:
* строка в списке подсвечивается как ошибочная (красный ореол, иконка ⚠);
* отображается предупреждающая иконка;
* в tooltip указывается причина невалидности.

----
h3. Жизненный цикл Меры при изменении SQL набора данных.
При каждом сохранении SQL-запроса набора данных система заново определяет состав полей и автоматически валидирует все Меры этого набора.

Если Мера ссылается на отсутствующее поле или её выражение не может быть интерпретировано в контексте текущего набора данных:
* Мера *не удаляется* автоматически;
* получает статус {{invalid}};
* остаётся в метаданных набора;
* отображается как невалидная до исправления.

После исправления выражения или восстановления нужных полей:
* Мера снова получает статус {{valid}}.

Если пользователь очистил SQL набора данных (либо SQL перестал проходить проверку):
* кнопка «+ Добавить меру» становится недоступной ({{disabled}});
* существующие Меры не удаляются;
* повторная полноценная валидация откладывается до появления корректного SQL и актуального состава полей;
* в UI существующие Меры могут показываться как недоступные для использования.

----
h3. Структура метаданных Меры.
Мера сохраняется в метаданных набора данных в следующем виде:

{code:json}
{
  "measures": [
    {
      "id": "measure_001",
      "name": "Валовая прибыль",
      "description": "Разница между выручкой и себестоимостью",
      "expression": "SUM(\"revenue\") - SUM(\"cost\")",
      "aggregation_kind": 1,
      "data_type": "number",
      "hierarchy": "Финансовые показатели",
      "level": 10,
      "status": "valid"
    }
  ]
}
{code}

|| Поле || Тип || Описание ||
| {{id}} | string | Стабильный идентификатор Меры |
| {{name}} | string | Отображаемое название |
| {{description}} | string | Необязательное описание |
| {{expression}} | string | SQL-выражение |
| {{aggregation_kind}} | int (0/1) | Признак агрегированности |
| {{data_type}} | string | Логический тип результата |
| {{hierarchy}} | string | Display-группа |
| {{level}} | int | Порядок внутри группы |
| {{status}} | enum | {{valid}} / {{invalid}} |

----
h3. Удаление Меры.
На данном этапе Меры ещё не используются в визуализациях, поэтому удаление Меры:
* удаляет её из метаданных набора данных;
* не требует проверки зависимостей визуализаций;
* не требует каскадного удаления из визуализаций.

Расширенная логика удаления используемой Меры реализуется в следующей Истории.

----
h3. Критерии приёмки.
*AC.1* — Секция «Меры» доступна только для *произвольного* набора данных.
* *Дано*: аналитик открыл настройки *произвольного* набора данных.
* *Тогда*: секция «Меры» отображается.
* *И*: для *простого* и *составного* набора данных секция не отображается.

*AC.2* — Кнопка «+ Добавить меру» зависит от состояния SQL набора.
* *Дано*: SQL-запрос не задан, либо не прошёл проверку, либо состав полей не получен.
* *Тогда*: кнопка «+ Добавить меру» находится в состоянии {{disabled}}.
* *И*: при наведении отображается пояснение пользователю.

*AC.3* — Модальное окно создания/редактирования Меры.
* При создании и редактировании Меры открывается увеличенное модальное окно.
* В окне доступны поля: {{name}}, {{description}}, {{data_type}}, {{aggregation_kind}}, {{hierarchy}}, {{level}}, {{expression}}.
* В редакторе доступен список полей текущего набора данных для вставки в выражение.

*AC.4* — Валидация при сохранении.
* При сохранении выполняются проверки обязательных полей, уникальности названия, синтаксической валидности выражения и ссылок только на доступные поля.
* При успешном сохранении Мера получает стабильный {{id}} и статус {{valid}}.

*AC.5* — Табличный список Мер.
* Сохранённые Меры отображаются в табличном списке схожем с табличным списком секции «Описание полей набора данных».
* Для каждой Меры видны: название, тип данных, признак агрегированности, иерархия, уровень, краткое выражение, действия.
* Для агрегированных Мер отображается ярлык {{AGR}}.

*AC.6* — Группировка и сортировка Мер.
* *Дано*: у части Мер заполнена «Иерархия» и «Уровень».
* *Тогда*: Меры группируются по «Иерархии».
* *И*: внутри группы сортируются по {{level}}, затем по названию (по алфавиту).
* *И*: Меры без «Иерархии» отображаются в корневом уровне секции.

*AC.7* — Редактирование Меры.
* *Дано*: пользователь открывает существующую Меру на редактирование.
* *Тогда*: форма открывается с предзаполненными значениями.
* *И*: после сохранения обновлённые значения отображаются в списке Мер и метаданных набора данных.

*AC.8* — Статус {{invalid}} после изменения SQL набора данных.
* *Дано*: после изменения SQL набора одна из Мер стала ссылаться на отсутствующее поле (либо перестала быть валидной).
* *Тогда*: такая Мера не удаляется автоматически.
* *И*: получает статус {{invalid}}.
* *И*: подсвечивается в списке Мер корректным образом.
* *И*: показывает причину ошибки.

*AC.9* — Восстановление статуса {{valid}}.
* *Дано*: причина невалидности устранена — выражение SQL исправлено (либо нужные поля снова появились в наборе данных).
* *Тогда*: Мера снова автоматически получает статус {{valid}}.

*AC.10* — Удаление Меры.
* *Дано*: пользователь удаляет Меру в рамках этой Истории.
* *Тогда*: Мера удаляется из метаданных набора данных.
* *И*: на данном этапе не выполняется проверка использования Меры в визуализациях, так как использование в визуализациях ещё не реализовано.
