Есть документ ./41_внедрение_Мер_Граф.txt изначально в нём был написан промпт для создания постановки для визуализации "Контейнер с переключениями".

Нужно подготовить новый промпт для написания постановки на внедрения Мер в визуализацию "Граф связей" (graphECharts).

Пример настроек визуализации "Граф связей" в режиме отладки записаны в файл ./Настройки_Граф связей_в_режиме_отладки.txt

Нужно изучить пример настроек и исправить промпт для написания новой постановки о внедрении мер в визуализации "Граф связей". Не требуется писать постановки, нужно только сформировать обновлённый промпт.

Дополнительная информация по визуализации "Граф связей" для внесения корректных изменений в текущий промпт ->

В визуализации "Граф связей" есть 6 полок, на которых можно разместить пилюли (колонки из выбранного в визуализации набора данных):
# Полка "Узел" - тут мы располагаем поле из набора данных с полным списком узлов, которые диаграмма "Граф" должна отрисовать. В случае если один и тот же узел повторяется в колонке несоклько раз - диаграмма будет рассматривать его как один узел и отрисует его один раз. Как мы можем видеть в примере данных узел "Хэндисофт, ООО" повторяется три раза, но будет дедуплицирован и отрисован только один раз на диаграмме.
# Полка "Связь" - на эту полку мы будем размещать пилюлю (колонку) "Узел-приёмник", для каждой строки в наборе данных из этой колонки диаграмма "Граф" будет пытаться извлечь наименование узла к которому нужно построить связь от узла, указанного в колонке "Узел". Т.е. пилюля "Узел-приёмник", размещённая на полке "Связь", содержит наименования узлов к которым нужно построить связь -> диаграмма попарно обрабатывает два эти узла и строит между ними связь, а если есть строка в которой "Узел" назначен, а "Узел-приёмник" отсутсвует, то связь просто не строиться.
# Полка "Свойства узлов" -  свойство узла должно рассчитываться по всем строкам одного узла-источника [node], независимо от узлов-приёмников,	Для каждой пилюли применяется её настроенная агрегация по всем прошедшим фильтры исходным строкам данного узла, независимо от [linkage]. Возвращается одна запись на узел.
# Полка "Свойства связей" -  свойство связи должно рассчитываться отдельно для каждой упорядоченной пары [node] + [linkage],	Для каждой пилюли применяется её настроенная агрегация только по строкам данной упорядоченной пары. Возвращается одна запись на связь.
# Полка "Фильтры" - стандартное поведение для фильтрации отображаемых данных визуализации.

Как видно из примера настроек в визуализации активно используются "вычисляемые поля" и также будут активно использоваться Меры.

Меры стандартно добавляются в левую боковую панель, могут использоваться на полках визуализации (с сохранением текущей функциональности, которую дают обычные и вычисляемые поля в аналогичных сценариях) в настройках, на полках "Свойства узлов" и "Свойства связей" (аналоги полки "Значения") для Меры также можно назначить локальную агрегацию (по аналогии с обычными полями) и назначить тип:
* для полки "Свойства узлов" доступны типы - "Значение", "Цвет", "Размер";
* для полки "Свойства связей" доступны типы - "Значение", "Цвет", "Тип линии";

Также Меры могут быть выбраны в правой боковой панеле настроек визуализации во всех селекторах наравне с обычными и вычисляемыми полями, среди них:
* Раздел "Подписи" ->
** Настройка "Текст подсказки", при выбраном "Шаблон" - "Текст подсказки" в селектор попадают все пилюли с полки "Свойства узлов".
* Раздел "Подсказки узлов" ->
** Настройка "Текст подсказки", при выбраном "Шаблон" - "Текст подсказки" в селектор попадают все пилюли с полки "Свойства узлов".
* Раздел "Подсказки связей" ->
** Настройка "Текст подсказки", при выбраном "Шаблон" - "Текст подсказки" в селектор попадают все пилюли с полки "Свойства связей".
