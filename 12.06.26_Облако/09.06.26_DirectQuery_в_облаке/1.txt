Необходимо описать доработку аналитического портала Modus BI Cloud, которая позволит пользователям с ролью «аналитик» в облачной версии использовать созданные ими подключения к внешним СУБД не только для загрузки данных во внутреннее облачное хранилище через «Правила загрузки данных», но и для прямых запросов DirectQuery при создании произвольных наборов данных.

Дополнительный контекст:
В Modus BI Cloud сторонние пользователи работают с ролью «аналитик». Вкладка «Источники» доступна только администраторам, поэтому аналитики не могут самостоятельно создавать и видеть источники данных. При этом у аналитиков уже есть доступ к вкладке «Подключения», где они создают подключения к внешним источникам для загрузки данных в облако.

Сейчас есть два близких, но разных сценария:
1. «Источники» → «Наборы данных»:
   запросы могут выполняться напрямую к внешней СУБД; это сценарий DirectQuery.
2. «Подключения» → «Правила загрузки данных» → «Наборы данных»:
   пользователь создаёт подключение, задаёт правило загрузки, данные перекладываются во внутренний ClickHouse, затем используются в наборах данных.

Проблема:
Для упрощённой облачной версии, условно «Старт», нужно дать аналитику возможность использовать подключения к внешним СУБД для DirectQuery, но без изменения ролевой модели и без открытия вкладки «Источники» для аналитика. Ролевую модель на этом этапе менять нельзя, чтобы не увеличивать трудозатраты.

Основная идея решения:
Добавить в форму создания/редактирования подключения для поддерживаемых СУБД специальный признак/галочку:
«Использовать для прямых запросов (DirectQuery)» 
или
«Доступно для DirectQuery».

Если пользователь-аналитик создаёт или редактирует подключение к поддерживаемой СУБД и включает эту галочку, система должна автоматически создать связанный источник данных в разделе «Источники» под капотом. Сам аналитик вкладку «Источники» по-прежнему не видит, но созданный под капотом источник должен быть доступен ему в сценарии создания произвольного набора данных, где выбирается источник для DirectQuery.

Поддерживаемые типы подключений в рамках первой реализации:
- ClickHouse;
- PostgreSQL / Postgres;
- Vertica;
- MS SQL Server.

Не включать в первую реализацию:
- Excel;
- Google Sheets;
- 1С;
- другие файловые или табличные источники, для которых DirectQuery через источник неактуален в рамках этой задачи.

MySQL и StarRocks:
В контексте продукта есть отдельные работы по добавлению поддержки MySQL и добавлению типа СУБД StarRocks в метаданные. Почему задача нужна:
- в облаке пользователи с ролью «аналитик» не видят вкладку «Источники»;
- изменение ролевой модели сейчас не планируется;
- при этом нужно дать возможность использовать внешние СУБД для DirectQuery;
- для этого предлагается использовать вкладку «Подключения» как пользовательскую точку входа, а источник создавать автоматически под капотом.

Описание ориентировочного целевого поведения (уточни по транскрипции обсуждений):
Опиши целевой пользовательский сценарий:
- аналитик открывает вкладку «Подключения»;
- создаёт новое подключение или редактирует существующее;
- если тип подключения относится к поддерживаемым СУБД, в форме отображается галочка DirectQuery;
- пользователь заполняет стандартные параметры подключения: наименование, сервер/host, порт, база данных, схема, пользователь, пароль и другие текущие поля формы;
- пользователь включает галочку DirectQuery;
- при сохранении подключения система сохраняет само подключение и автоматически создаёт связанный источник данных;
- источник создаётся с минимально необходимыми настройками, достаточными для прямых запросов;
- дополнительные настройки источников, неактуальные для облака (например MDX, ФВД и прочее) не являются обязательными и не задействуются для этого сценария;
- аналитик не видит вкладку «Источники», но при создании произвольного набора данных может выбрать созданный под капотом источник и использовать его для DirectQuery.
