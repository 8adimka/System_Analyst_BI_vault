При написании постановки ./Редактор_кода_Шаг_4_Правила_загрузки_данных.txt я не указал, что, при открытии модального окна с редактором, сразу должна быть доступна боковая панель с полями набора данных, сверху будет поле с кнопками с частоиспользуемыми функциями (SUM, AVG, MIN, MAX, COUNT, DISTINCT и т.д. по аналогии с другими), т.е. редактор сразу доступен в своём "расширенном" виде при открытии модального окна со всеми "расширенными" функциями (включая боковую панель с полями для {{Drag-and-Drop}} полей в зону ввода редактора (зона ввода по центру занимает основную часть модального окна).

Вот описание функционала:
В рамках реализации этого редактора также будет использоваться боковая панель с полями редактируемого набора данных:

Редактор должен открываться в модальном окне укрупнённого вида с регулировкой по высоте и с рабочим пространством, удобным для написания длинных SQL-запросов.
* Внутри редактора должна быть реализована трехзонная компоновка:
** *центральная основная зона* — редактор {{CodeMirror}};
** *левая вспомогательная зона* — панель метаданных выбранного источника данных;
** *верхняя вспомогательная зона* — располагается над центральной зоной редактора - панель шаблонов и служебных вставок.
* Основная площадь рабочего пространства должна быть отдана редактору.
* Левая панель должны иметь адаптивно-фиксированную ширину, достаточную для чтения содержимого, с возможностью её настройки/регулировки (потянув за край боковой панели).
* Для длинного SQL-скрипта и длинного содержимого боковых панелей должны работать *внутренние скроллы* соответствующих областей.
* Для удобства работы на узких экранах боковые панель должна иметь возможность сворачиваться, но должна оставаться доступной без выхода из редактора.

h4. 2.3. Левая панель с метаданными источника данных.
* В левой части редактора должен отображаться список метаданных *выбранного источника данных*.
* Источником данных для этой панели должны быть метаданные текущего подключенного источника, а не результат последней успешной проверки SQL.
* В панели должны быть доступны как минимум:
** схемы;
** таблицы/объекты источника;
** поля таблиц;
** при наличии — типы полей.
* Панель должна поддерживать:
** поиск;
** разворачивание и сворачивание узлов;
** корректное состояние загрузки;
** корректную пустую заглушку или сообщение об ошибке, если метаданные временно недоступны.
* Метаданные должны быть доступны пользователю без обязательного предварительного успешного выполнения текущего SQL-запроса.

h4. 2.4. Переиспользование дерева метаданных из составного набора данных.

* По информации от коллег, функционал дерева метаданных уже частично реализован в рамках интерфейса {{составного набора данных}}.

* Перед разработкой необходимо провести техническую проверку существующей реализации: источник получения метаданных, структура дерева, поиск, разворачивание/сворачивание узлов, состояния загрузки/ошибки/пустого результата, механизм выбора/перетаскивания элементов и ограничения по типам источников.
* Пригодные части реализации должны быть переиспользованы или вынесены в переиспользуемый компонент/адаптер без изменения пользовательского сценария {{составных наборов данных}}.
* Если часть функциональности из составного набора данных не покрывает требования текущего редактора, недостающие возможности дорабатываются точечно в рамках требований п. 2.3, 2.6 и 2.8, без дублирования уже существующей логики.
* Переиспользование существующих наработок не должно менять границы задачи: доработка внедряется для *произвольных* наборов данных, а сценарии создания/редактирования {{составных}} наборов данных в рамках этой истории не изменяются.

h4. 2.5. Верхняя панель вспомогательных вставок.
* Над центральной зоной редактора должна отображаться вспомогательная панель служебных вставок.
* Минимально обязательный состав кнопок:
* список распространённых агрегирующих функций: SUM, AVG, MIN, MAX, COUNT, DISTINCT и т.д.

При нажатии на кнопку в поле ввода редактора должен вставляться соответствующий шаблон кода.

h4. 2.6. Вставка объектов из боковой панели в редактор.
* Объекты из боковой панели должны быть доступны для вставки в SQL в области ввода редактора кода.
* Базовый способ вставки — {{Drag-and-Drop}} в область редактора.
* Дополнительно допускается поддержка альтернативного действия вставки (например, двойной клик), если это не усложняет UX.
* Из левой панели в редактор должны вставляться:
** имена таблиц/объектов источника;
** имена полей.
* Вставка должна происходить *в текущую позицию каретки*:
** Если редактор временно потерял фокус, должна использоваться последняя известная позиция каретки.
** Если пользователь ранее не фокусировался в редактор, вставка допускается в конец SQL-скрипта.
** Если в редакторе включен мультикурсор, вставка должна выполняться по всем активным курсорам.
** Если для корректной SQL-вставки требуется экранирование/кавычки в соответствии с диалектом текущего источника, вставка должна использовать синтаксически безопасную форму идентификатора.
