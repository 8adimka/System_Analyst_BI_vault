## Ограничения и следующее действие

1. Сначала необходимо восстановить маршрутизацию ChatGPT-аккаунта, используемую SDK. Диагностика без модели: `PY agent-system/run.py account-check`. После успешной проверки повторить `PY agent-system/run.py smoke`, затем проверить сохранённые Thread после рестарта. Авторизация, глобальные конфигурации и существующие сессии пользователя не исправлялись автоматически.
2. Файловая изоляция требует Linux и работающего bubblewrap. Обхода через full_access или незащищённый запуск нет.
3. Runtime читает текущую авторизацию через неизменяемый mount; она технически доступна текущей роли. Брокер credentials не реализован. Это ограничение подтверждено отдельным тестом с вымышленными данными; реальное содержимое auth не читалось строителем.
4. Материалы подключаются явно. URL без локальной копии или нераспознанный путь становятся вопросом, а не выдуманным фактом. Добавление/изменение первоисточников требует нового прогона.
5. Синтаксический контроль Jira и подтверждение существования файла/версии не доказывают смысл каждого утверждения; за доказательный анализ отвечает независимый ревьюер. Успешные mock-тесты не заменяют реальную приёмку с моделью.
6. Реальная metadata-проверка SDK 0.163.0 прошла 11 тестов, но его `close()` вывел ResourceWarning о незакрытых Python pipe wrappers. Пакет в venv не исправлялся вручную; это наблюдение сохранено отдельно от результата тестов.

Передача проекта не означает успешного сквозного запуска: незавершённые реальные проверки явно перечислены выше.
