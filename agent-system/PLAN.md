# План и критерии готовности

Источник требований: полный `17.10.26_Агенская_система/1.txt` (файла `1(2).txt` нет); актуальное сообщение пользователя имеет приоритет. Архивные пять файлов остаются без изменений.

1. Проверить среду, Git-исключения и SDK. Результат: подтверждённые версии, чистота приватного Git-периметра.
2. Исследовать три локальных репозитория только чтением. Результат: приватный индекс Wiki, статьи с проверенными ссылками, SHA и границами исследования.
3. Перенести архивные правила в короткое оглавление AGENTS, стандарты, шесть skills и две роли. Результат: матрица переноса, Jira wiki и сохранённая терминология.
4. Реализовать Python-координатор через официальный SDK. Результат: отдельные Thread, read-only, физически ограниченное представление исходных материалов, слепое исследование до первого черновика, безопасный файловый шлюз, сохранение состояния и восстановление.
5. Проверить конечный автомат, 5+1, вопросы пользователю, отказ SDK, прерывание, невалидный ответ, симлинки, попытки записи в репозитории и независимость ревью.
6. Выполнить реальный синтетический прогон с SDK; описать воспроизводимую установку, первый запуск, результаты, возобновление и обновление Wiki. Проверить публичный diff без commit/push.

## Решения реализации

- Ревьюер завершает и фиксирует независимое исследование **до запуска аналитика**. Поэтому черновик этого прогона не существует во время слепого этапа.
- Каждая задача получает отдельное представление файлов и истории SDK. Входные файлы перечислены явно; исторические результаты не включаются автоматически. Обе роли видят одинаковые первоисточники. Ссылки внутри промпта разрешаются от корня workspace.
- Запись результатов по умолчанию приватная: содержание постановок и ревью может быть производным корпоративного кода. Перенос в тематическую папку выполняется отдельной командой после проверки пользователем допустимости публикации.
- Итог с незакрытыми существенными вопросами не маркируется согласованным. Секция «Открытые вопросы» обязательна для такого результата.
- Внешние модельные проверки при разработке используют только синтетические данные. Боевой запуск требует явного флага подтверждения права передачи корпоративных материалов провайдеру модели.
- Нет обещания строго однократного выполнения сетевого запроса: сбой между ответом SDK и фиксацией checkpoint требует восстановления сохранённого Thread. Завершённые локальные переходы не повторяются.

Текущее состояние проверок и ограничения фиксируются в `ACCEPTANCE.md` после выполнения.
