По итогам данного обсуждения нужно подготовить постановку для реализации (в виде плагина) новой визуализации "Воронка" (Funnel Chart) в рамках нашего аналитического портала.

Стандартные полки в нашей BI аналитической системе для визуализаций - это:
1) "Значения",
2) "Категории",
3) "Фильтры".

Принцип работы визуализации:

Одна визуализация в нашем портале всегда работает только с одним "Набором данных". Для создания "Набора данных" пишется произвольный SQL-запрос, который отправляется бэкендом в одну из доступных баз данных.
 
* Пилюля (т.е. колонка из "Набора данных), содержащая визуализируемую величину, добавляется на полку "Значения" -> определяет "ширину" каждой, соответствующей данному значению, "категории" (например, количество компаний на этап), 
* Пилюля, содержащая визуализируемые категории или этапы (например, этап 1 = "лидогенерация" → этап 2 = "обзвон" → этап 3 = "контракт") добавляется на полку "Категории" -> определяет категории и их колличество.

Каждое уникальное значение «Категории» формирует один сегмент воронки с шириной, пропорциональной агрегированному «Значению» этого этапа. Данные сортируются по пилюле с полки «Значения» по убыванию *по умолчанию* (стандартная логика, например, для воронки продаж), но пользователь может задать собственный порядок через настройки пилюли с полки «Категории». В настройках пилюли с полки "Категории" есть выпадающий список "Сортировка по другому полю", который позволяет выбрать любую пилюлю или Меру из текущего набора данных и задать сортировку категорий в "Воронке" по данному полю, в соответствии с выбранной стратегией сортировки для основной пилюли (от большего к меньшему или наоборот от меньшего к большему). Эта настройка является критичной, поскольку реальный порядок этапов не всегда совпадает с порядком убывания значений в воронке и позволяет задать порядок категорий в воронке пользователю вручную.

Первый этап в отсортированном порядке принимается за базу расчёта конверсии «от первого этапа»; каждый следующий этап сравнивается также с непосредственно предыдущим для расчёта «от предыдущего этапа». Оси отсутствуют полностью — идентификация этапа и значения происходит через подпись внутри сегмента и всплывающую подсказку, а не через шкалу координат.

Предлагаемая архитектура для постановки.

| Полка           | Размещение пилюль             | Назначение                                 |
| --------------- | --------------- | ------------------------------------------ |
| **Значения**    | **1 основная пилюля. + "n" вспомогательных** | Числовое значение, определяет размер этапа. Также на этой полке могут располагаться дополнительные значения - это могут быть различные вспомогательные значения (можем задать "Тип" пилюли "Значение", "Подзаголовок", "Подсказка"). |
| **Категории**   | **ровно 1**     | Этап процесса                              |
| **Фильтры**     | стандартная функциональность, без изменений | Фильтрация исходной выборки                |

Доступные "полки" для размещения "пилюль":
* "Значения" - для построения визуализации обязательно должна быть хотя бы 1 пилюля - числовое поле, вычисляемое поле или "Мера" с вычисляемым числовым значением. Также на этой полке могут располагаться дополнительные значения, например, чтобы иметь возможность задать категориям разный цвет (выбираем "Тип" пилюли "Цвет").
В настройках пилюль с этой полки, кроме стандартных настроек, мы можем задать "Тип" пилюли:
** "Значение",
** "Цвет" (задаётся на уровне всей категории),
** "Подзаголовок" (позволяет задать динамический подзаголовок визуализации),
** "Подсказка" (чтобы мы могли расширить шаблон всплывающей подсказки и показывать дополнительную информацию в подсказке (например, значение, определяющее размер) для дополнительной информативности).
* Категории (обязательно 1 пилюля) — задаёт группы, по которым строятся этапы Воронки.
* Фильтры — стандартна функциональность полки для нашего аналитического портала.

Раскраска сегментов реализуется автоматически по палитре на основе значений пилюли "Категории" и переопределяется вручную в разделе "Стиль элементов" (см. ниже). Тип пилюли "Цвет" (окраска сегмента по значению отдельного поля, а не по категории) выносится в раздел дополнительных возможностей за пределами базового объёма трудозатрат и не входит в обязательный реализауемый объём.

Расчёт данных.

После фильтрации и агрегации для каждого этапа имеется:

V[i]

где i — позиция после сортировки.

Из этого не нужно получать дополнительные показатели из БД.

Плагин может вычислить их на фронтенде.

Абсолютное значение
Value[i] = V[i]
Конверсия относительно предыдущего этапа
ConversionPrev[i] =
    V[i] / V[i-1] × 100%

Например:

500 → 350

350 / 500 = 70%
Конверсия относительно первого этапа
ConversionFirst[i] =
    V[i] / V[1] × 100%

Например:

500 → 350 → 100

100 / 500 = 20%
Абсолютное изменение относительно предыдущего
DeltaPrev[i] =
    V[i] - V[i-1]
Абсолютное изменение относительно первого
DeltaFirst[i] =
    V[i] - V[1]
    
Если для одного значения «Категории» в выборке присутствует несколько строк, V[i] рассчитывается как агрегат (стандартная агрегация, выбранная в настройках пилюли полки "Значения", по умолчанию SUM) по всем строкам этой категории. GROUP BY выполняется по полю "Категории".

Если V[i-1] или V равно 0 или null, соответствующая метрика конверсии (ConversionPrev/ConversionFirst) не рассчитывается и не отображается для этого этапа (вместо значения — прочерк или скрытие метки), без прерывания отрисовки остальных сегментов.

Конверсия и абсолютное изменение могут быть положительными (рост относительно предыдущего/первого этапа) — форматирование подписи должно корректно отображать такие случаи (например, со знаком "+"), а не предполагать исключительно убывание.

Как определять размер сегмента: "
1) maxValue = MAX(V[1...N]) 
2) relativeSize[i] = V[i] / maxValue".
Конверсию при этом всё равно считаем относительно первого этапа.

Настройки (конфигурация визуализации) - правая боковая панель в режиме настройки для визуализации "Воронка" включает стандартные настройки и разделы:
* Общие настройки,
* Подписи данных,
** Вкл/Выкл;
** Название этапа;
** Значение;
** Название + значение;
* Всплывающая подсказка,
* Легенда,
* Основной стиль,
* Стиль элементов,
* Настройки клика,
* Инфо.

Стиль элементов (по категориям): цвет по умолчанию берётся из палитры портала по «Категории»; ручное переопределение цвета/стиля для конкретного этапа через существующий механизм «Стиль элементов» имеет приоритет над автопалитрой — то есть та же логика приоритетов.

Легенда: опциональна, по умолчанию выключена (основной способ идентификации этапов — подписи внутри/у сегментов). Включение легенды осмысленно при многоцветной раскраске (авто-палитра или ручной стиль по категориям), так как она сопоставляет цвет сегмента с названием этапа. При монохромной воронке легенда не несёт информации (все элементы легенды имеют одинаковый цвет) и должна быть скрыта или неактивна.

Подписи данных: переключатель видимости + позиция (внутри/снаружи сегмента), значение = «Значение» + опционально выбранный шаблон метки конверсии.

Среди настроек и разделов нужно выделить следующие:

* Раздел "Общие настройки", тогл (toggle) "Ориентация": Вертикальная/Горизонтальная.
* Раздел "Общие настройки" → выпадающий список "Метка конверсии":
** Не показывать,
** % от предыдущего этапа,
** % от первого этапа,
** Изменение от предыдущего этапа,
** Изменение от первого этапа.
* Раздел "Общие настройки", тогл (toggle) "Вид": Ступени/Сглаженная.
* Раздел "Стиль элементов" → выпадающий список "Объект данных" = Категория - Dropdown содержит уникальные значения пилюли с полки «Категории» и позволяет задать цвета и настройки стиля для каждой категории отдельно вручную.
