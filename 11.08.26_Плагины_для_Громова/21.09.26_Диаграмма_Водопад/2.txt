**1. Входные данные и построение диаграммы**

Для настроек визуализации используется четыре полки:

#* "Все" - при активном режиме "Все" визуализация может обрабатывать все пилюли, размещенные на этой полке, но для визуализации значений используется только первая пилюля, размещённая на полке "Значения" - при выборе для неё типов "Цвет" или "Подзаголовок", визуализируются значения получаемые из этой пилюли (то есть первая пилюля обрабатывается как тип "Значение", независимо от выбранного для неё типа). Однако, при выборе вспомогательного типа "Подсказка" для первой пилюли на полке "Значения" - визуализация не строится и отображает стандартное ошибочное состояние визуализации - "Что-то пошло не так, но мы обязательно разберемся" (даже при наличие других пилюль типа "Значение" на этой полке). Остальные пилюли обрабатываются в соответствии с их выбранным типом (то есть обрабатываются только вспомогательные типы пилюль). 
# **«Категории»** (обязательная для отображения диаграммы) — размещается одна пилюля (колонка набора данных), содержащая наименования этапов. Она определяет состав, подписи и порядок отображаемых столбцов диаграммы.
# **«Серии»** (опциональная) — размещается одна пилюля (колонка набора данных), содержащая наименования детализации этапов. Для данной полки доступен тумблер со значениями:

#** Пример использования полки "Серии" с данными -> (Разбиение "шагов" по «Сериям» (breakdown).

При активной полке «Серии» каждый шаг категории раскладывается на вклады значений серии.

Пример исходных данных:

|| Фактор || Регион || Значение ||
| Рост продаж | Север | +210 |

Без «Серий»:

{code}

{code}

При «Серии» = «Регион»:

{code}

Скидки
├── Север -40
└── Юг    -20

└── Юг    -60
{code}

Серии являются детализацией шага и не меняют его итоговое значение: сумма вкладов серии должна совпадать с рассчитанным значением категории.

В правой панели добавить специализированный раздел настроек «Серии» - содержит настройку:
* «Максимум серий на шаг» — целое положительное число; значение по умолчанию — {{5}}.

Для каждого шага показываются не более *указанного количества* крупнейших _уникальных_ вкладчиков по абсолютной величине. Все остальные значения серии объединяются в группу «Прочие». Значение «Прочих» равно арифметической сумме объединённых вкладов; его знак определяется полученной суммой.

Если количество серий шага не превышает установленный максимум, группа «Прочие» не создаётся.

Т.е. например, при значении *2* отображается _2_ уникальных вкладчика для каждого шага (при наличии) и дополнительно группа «Прочие», если вкладчиков более двух.

Отбор Top-N выполняется независимо для каждого шага после применения фильтров и агрегации. При изменении фильтров состав крупнейших вкладчиков и «Прочих» пересчитывается.
Ограничение «Максимум серий на шаг» не должно увеличивать фактически доступное количество серий после применения общих лимитов данных/показа платформы.

Каждая отображаемая Серия является отдельным Breakdown-элементом внутри логического шага категории.

Положительные и отрицательные вклады внутри одного шага допускаются.).
#* "Выкл" - не обрабатывается визуализацией в таком сценарии, наличие пилюль на данной полке не влияет на визуализацию в таком сценарии.
# **«Фильтры»** (опциональная) — позволяет задать как будет происходить фильтрация данных. Общая функциональность полки без изменений.

Далее рассмотрим использование визуализации при активной полке "Категории".
Каждому этапу соответствует числовое изменение: положительное — увеличение, отрицательное — уменьшение. Если одному этапу соответствует несколько записей, значения обрабатываются и агрегируются в соответствии с текущей реализацией.

Визуализация самостоятельно рассчитывает накопленный итог последовательным применением дельт. Обычные столбцы отображаются «плавающими»: начинаются от накопленного значения предыдущего этапа и заканчиваются на новом уровне, отражая направление и величину изменения. Соединительные линии показывают переход между уровнями накопленных значений.

**2. Логика формирования и отображения подытогов**

Сохранить существующий принцип выбора категорий для формирования подытогов, но изменить способ их отображения.

При назначении категории подытогом её исходный столбец остаётся обычным столбцом изменения (дельты). **Сразу после него добавляется отдельный столбец подытога**, отображающий накопленное значение с учётом дельты выбранной категории.

Столбец подытога:
- Начинается от нулевой линии и заканчивается на уровне рассчитанного накопленного значения.
- Имеет подпись с числовым значением накопленного подытога, а не дельты.
- Отличается цветом от обычных столбцов увеличения и уменьшения.
- Не участвует в повторном суммировании и не изменяет расчёт последующих этапов.
- Сохраняет непрерывность соединительных линий: следующий обычный столбец начинается от того же уровня накопленного значения.

Например: начальное значение 100, поступления +40, расходы −25. Если для этапа «Расходы» включён подытог, после обычного столбца −25 появляется дополнительный столбец «Расходы (подытог)» со значением 115, построенный от нулевой линии. Следующий этап продолжает накопление от 115.

**3. Раздел «Подытоги» в настройках визуализации**

Предусмотреть раскрываемый раздел **«Подытоги»** со следующими элементами:

- **Общий тумблер раздела** — включает или отключает отображение всех настроенных подытогов, не удаляя их настройки.
- **Выпадающий список категорий** — позволяет выбрать один из этапов, представленных на полке «Категории» с учётом текущих данных и сортировки.
- **Тумблер «Показывать подытог»** — управляет добавлением отдельного столбца подытога после выбранного этапа.
- **«Наименование столбца подытога»** — подчинённое текстовое поле, появляющееся при включении подытога для выбранной категории. По умолчанию используется название «{Название категории} (подытог)». Пользователь может задать произвольное название.
- **Настройка цвета** — подчинённый color picker для изменения цвета конкретного подытога. По умолчанию все подытоги используют единый цвет, но каждый можно переопределить индивидуально.

Настройки наименования и цвета должны храниться независимо для каждой категории с включённым подытогом. При выборе другой категории в выпадающем списке отображаются её собственные настройки.

Отключение подытога для отдельной категории скрывает только соответствующий дополнительный столбец. Выключение общего тумблера скрывает все подытоги, но сохраняет их индивидуальные настройки для последующего включения.

**4. Дополнительные требования**

- Поддерживать произвольное количество подытогов для разных категорий.
- Не создавать дубликаты подытога при повторном выборе одной категории.
- Подытоги всегда располагаются непосредственно после соответствующих обычных столбцов.
- При изменении данных, фильтрации или сортировки пересчитывать накопленные значения и положения подытогов в соответствии с текущей реализацией.
- Подытоги не должны нарушать геометрию обычных столбцов, соединительные линии и логику накопления.

**1. Входные данные и построение диаграммы**

Для настроек визуализации используется четыре полки:

# **«Значения»** (обязательная для отображения диаграммы) — размещается одна пилюля (числовая колонка набора данных, например «Сумма»), содержащая значения изменений (дельты) для соответствующих этапов. Для полки доступен тумблер:
#* "Первое" - тогда визуализация обрабатывает только первую пилюлю, размещённую на данной полке. Если для первой пилюли на полке "Значения" назначен вспомогательный тип "Цвет" или "Подзаголовок", визуализируются значения получаемые из этой пилюли, даже при наличие других необрабатываемых пилюль типа "Значение" на этой полке (то есть первая пилюля обрабатывается как тип "Значение", независимо от выбранного для неё типа). Однако, при выборе вспомогательного типа "Подсказка" для первой пилюли на полке "Значения" - визуализация не строится и отображает стандартное ошибочное состояние визуализации - "Что-то пошло не так, но мы обязательно разберемся" (даже при наличие других необрабатываемых пилюль типа "Значение" на этой полке).
#* "Все" - при активном режиме "Все" визуализация может обрабатывать все пилюли, размещенные на этой полке, но для визуализации значений используется только первая пилюля, размещённая на полке "Значения" - при выборе для неё типов "Цвет" или "Подзаголовок", визуализируются значения получаемые из этой пилюли (то есть первая пилюля обрабатывается как тип "Значение", независимо от выбранного для неё типа). Однако, при выборе вспомогательного типа "Подсказка" для первой пилюли на полке "Значения" - визуализация не строится и отображает стандартное ошибочное состояние визуализации - "Что-то пошло не так, но мы обязательно разберемся" (даже при наличие других пилюль типа "Значение" на этой полке). Остальные пилюли обрабатываются в соответствии с их выбранным типом (то есть обрабатываются только вспомогательные типы пилюль). 
# **«Категории»** (обязательная для отображения диаграммы) — размещается одна пилюля (колонка набора данных), содержащая наименования этапов. Она определяет состав, подписи и порядок отображаемых столбцов диаграммы.
# **«Серии»** (опциональная) — размещается одна пилюля (колонка набора данных), содержащая наименования детализации этапов. Для данной полки доступен тумблер со значениями:
#* "Вкл" - Визуализацией активно обрабатывается только первая пилюля, размещённая на данной полке. Активная пилюля, размещённая на полке "Серии", используется для определения отображаемых подкатегорий - значения распределяются по этим подкатегориям, а категории теперь выполняют роль "Подытогов".
#** Пример использования полки "Серии" с данными -> (Разбиение "шагов" по «Сериям» (breakdown).

При активной полке «Серии» каждый шаг категории раскладывается на вклады значений серии.

Пример исходных данных:

|| Фактор || Регион || Значение ||
| Рост продаж | Север | +210 |
| Рост продаж | Юг | +140 |
| Скидки | Север | −40 |
| Скидки | Юг | −20 |
| Логистика | Север | −90 |
| Логистика | Юг | −60 |

Без «Серий»:

{code}
Рост продаж   +350
Скидки         -60
Логистика     -150
{code}

При «Серии» = «Регион»:

{code}
Рост продаж
├── Север +210
└── Юг    +140

Скидки
├── Север -40
└── Юг    -20

Логистика
├── Север -90
└── Юг    -60
{code}

Серии являются детализацией шага и не меняют его итоговое значение: сумма вкладов серии должна совпадать с рассчитанным значением категории.

В правой панели добавить специализированный раздел настроек «Серии» - содержит настройку:
* «Максимум серий на шаг» — целое положительное число; значение по умолчанию — {{5}}.

Для каждого шага показываются не более *указанного количества* крупнейших _уникальных_ вкладчиков по абсолютной величине. Все остальные значения серии объединяются в группу «Прочие». Значение «Прочих» равно арифметической сумме объединённых вкладов; его знак определяется полученной суммой.

Если количество серий шага не превышает установленный максимум, группа «Прочие» не создаётся.

Т.е. например, при значении *2* отображается _2_ уникальных вкладчика для каждого шага (при наличии) и дополнительно группа «Прочие», если вкладчиков более двух.

Отбор Top-N выполняется независимо для каждого шага после применения фильтров и агрегации. При изменении фильтров состав крупнейших вкладчиков и «Прочих» пересчитывается.
Ограничение «Максимум серий на шаг» не должно увеличивать фактически доступное количество серий после применения общих лимитов данных/показа платформы.

Каждая отображаемая Серия является отдельным Breakdown-элементом внутри логического шага категории.

Положительные и отрицательные вклады внутри одного шага допускаются.).
#* "Выкл" - не обрабатывается визуализацией в таком сценарии, наличие пилюль на данной полке не влияет на визуализацию в таком сценарии.
# **«Фильтры»** (опциональная) — позволяет задать как будет происходить фильтрация данных. Общая функциональность полки без изменений.

Далее рассмотрим использование визуализации при активной полке "Категории".
Каждому этапу соответствует числовое изменение: положительное — увеличение, отрицательное — уменьшение. Если одному этапу соответствует несколько записей, значения обрабатываются и агрегируются в соответствии с текущей реализацией.

Визуализация самостоятельно рассчитывает накопленный итог последовательным применением дельт. Обычные столбцы отображаются «плавающими»: начинаются от накопленного значения предыдущего этапа и заканчиваются на новом уровне, отражая направление и величину изменения. Соединительные линии показывают переход между уровнями накопленных значений.

**2. Логика формирования и отображения подытогов**

Сохранить существующий принцип выбора категорий для формирования подытогов, но изменить способ их отображения.

При назначении категории подытогом её исходный столбец остаётся обычным столбцом изменения (дельты). **Сразу после него добавляется отдельный столбец подытога**, отображающий накопленное значение с учётом дельты выбранной категории.

Столбец подытога:
- Начинается от нулевой линии и заканчивается на уровне рассчитанного накопленного значения.
- Имеет подпись с числовым значением накопленного подытога, а не дельты.
- Отличается цветом от обычных столбцов увеличения и уменьшения.
- Не участвует в повторном суммировании и не изменяет расчёт последующих этапов.
- Сохраняет непрерывность соединительных линий: следующий обычный столбец начинается от того же уровня накопленного значения.

Например: начальное значение 100, поступления +40, расходы −25. Если для этапа «Расходы» включён подытог, после обычного столбца −25 появляется дополнительный столбец «Расходы (подытог)» со значением 115, построенный от нулевой линии. Следующий этап продолжает накопление от 115.

**3. Раздел «Подытоги» в настройках визуализации**

Предусмотреть раскрываемый раздел **«Подытоги»** со следующими элементами:

- **Общий тумблер раздела** — включает или отключает отображение всех настроенных подытогов, не удаляя их настройки.
- **Выпадающий список категорий** — позволяет выбрать один из этапов, представленных на полке «Категории» с учётом текущих данных и сортировки.
- **Тумблер «Показывать подытог»** — управляет добавлением отдельного столбца подытога после выбранного этапа.
- **«Наименование столбца подытога»** — подчинённое текстовое поле, появляющееся при включении подытога для выбранной категории. По умолчанию используется название «{Название категории} (подытог)». Пользователь может задать произвольное название.
- **Настройка цвета** — подчинённый color picker для изменения цвета конкретного подытога. По умолчанию все подытоги используют единый цвет, но каждый можно переопределить индивидуально.

Настройки наименования и цвета должны храниться независимо для каждой категории с включённым подытогом. При выборе другой категории в выпадающем списке отображаются её собственные настройки.

Отключение подытога для отдельной категории скрывает только соответствующий дополнительный столбец. Выключение общего тумблера скрывает все подытоги, но сохраняет их индивидуальные настройки для последующего включения.

Серии являются детализацией шага и не меняют его итоговое значение: сумма вкладов серии должна совпадать с рассчитанным значением категории.

В правой панели добавить специализированный раздел настроек «Серии» - содержит настройку:
* «Максимум серий на шаг» — целое положительное число; значение по умолчанию — {{5}}.

Для каждого шага показываются не более *указанного количества* крупнейших _уникальных_ вкладчиков по абсолютной величине. Все остальные значения серии объединяются в группу «Прочие». Значение «Прочих» равно арифметической сумме объединённых вкладов; его знак определяется полученной суммой.

Если количество серий шага не превышает установленный максимум, группа «Прочие» не создаётся.

Т.е. например, при значении *2* отображается _2_ уникальных вкладчика для каждого шага (при наличии) и дополнительно группа «Прочие», если вкладчиков более двух.

Отбор Top-N выполняется независимо для каждого шага после применения фильтров и агрегации. При изменении фильтров состав крупнейших вкладчиков и «Прочих» пересчитывается.
Ограничение «Максимум серий на шаг» не должно увеличивать фактически доступное количество серий после применения общих лимитов данных/показа платформы.

**2. Логика формирования и отображения подытогов**

Сохранить существующий принцип выбора категорий для формирования подытогов, но изменить способ их отображения.

При назначении категории подытогом её исходный столбец остаётся обычным столбцом изменения (дельты). **Сразу после него добавляется отдельный столбец подытога**, отображающий накопленное значение с учётом дельты выбранной категории.

Столбец подытога:
- Начинается от нулевой линии и заканчивается на уровне рассчитанного накопленного значения.
- Имеет подпись с числовым значением накопленного подытога, а не дельты.
- Отличается цветом от обычных столбцов увеличения и уменьшения.
- Не участвует в повторном суммировании и не изменяет расчёт последующих этапов.
- Сохраняет непрерывность соединительных линий: следующий обычный столбец начинается от того же уровня накопленного значения.

Например: начальное значение 100, поступления +40, расходы −25. Если для этапа «Расходы» включён подытог, после обычного столбца −25 появляется дополнительный столбец «Расходы (подытог)» со значением 115, построенный от нулевой линии. Следующий этап продолжает накопление от 115.

**3. Раздел «Подытоги» в настройках визуализации**

Предусмотреть раскрываемый раздел **«Подытоги»** со следующими элементами:

- **Общий тумблер раздела** — включает или отключает отображение всех настроенных подытогов, не удаляя их настройки.
- **Выпадающий список категорий** — позволяет выбрать один из этапов, представленных на полке «Категории» с учётом текущих данных и сортировки.
- **Тумблер «Показывать подытог»** — управляет добавлением отдельного столбца подытога после выбранного этапа.
- **«Наименование столбца подытога»** — подчинённое текстовое поле, появляющееся при включении подытога для выбранной категории. По умолчанию используется название «{Название категории} (подытог)». Пользователь может задать произвольное название.
- **Настройка цвета** — подчинённый color picker для изменения цвета конкретного подытога. По умолчанию все подытоги используют единый цвет, но каждый можно переопределить индивидуально.

Настройки наименования и цвета должны храниться независимо для каждой категории с включённым подытогом. При выборе другой категории в выпадающем списке отображаются её собственные настройки.

Отключение подытога для отдельной категории скрывает только соответствующий дополнительный столбец. Выключение общего тумблера скрывает все подытоги, но сохраняет их индивидуальные настройки для последующего включения.

**4. Дополнительные требования**

- Поддерживать произвольное количество подытогов для разных категорий.
- Не создавать дубликаты подытога при повторном выборе одной категории.
- Подытоги всегда располагаются непосредственно после соответствующих обычных столбцов.
- При изменении данных, фильтрации или сортировки пересчитывать накопленные значения и положения подытогов в соответствии с текущей реализацией.
- Подытоги не должны нарушать геометрию обычных столбцов, соединительные линии и логику накопления.
- Не изменять существующее поведение итогового столбца и других настроек визуализации, не относящихся к данной доработке.
