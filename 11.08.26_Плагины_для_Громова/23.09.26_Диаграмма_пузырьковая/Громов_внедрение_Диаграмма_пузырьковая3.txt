Доработка визуализации «Диаграмма пузырьковая»

h3. 1. Контекст и проблематика.

В основном портале Modus BI реализована «Диаграмма пузырьковая» ({{chartType = "bubble"}}, {{visualType = "bubble"}}), используемая в том числе как Scatter Plot.

Для закрытия согласованного объёма требований необходимо доработать управление размером пузырей: обеспечить настройку общего фиксированного размера без показателя размера и возможность вручную переопределять размер для отдельных категорий и групп пузырей.

Также требуется реализовать динамические вертикальные и горизонтальные опорные линии (отсечки), рассчитываемые по числовому или вычисляемому полю, с возможностью задания подписей.

Одновременно требуется исправить сочетания существующих механизмов, при которых визуализация не строится, пропадают пузыри, некорректно работают легенды, пользовательская подсказка и выбор агрегации для полок «ЗначенияX» и «ЗначенияY».

----

h3. 2. Цель и рамки задачи.

*Требуется:*
# Доработать существующую визуализацию «Диаграмма пузырьковая», сохранив существующие полки, размер по показателю, динамический цвет, подзаголовок, фильтрацию и zoom.
# Добавить в правую панель разделы настройки внешнего вида:
#* «Основной стиль» — для общих настроек визуализации, включая общий размер пузырей;
#* «Стиль элементов» — для переопределения размера выбранных категорий и групп пузырей.
# Обеспечить два сценария ручной настройки размера без показателя типа «Значение»:
#* единый фиксированный размер всех пузырей;
#* индивидуальный фиксированный размер выбранной категории или Серии.
# Добавить раздел «Всплывающая подсказка» в правую панель настроек визуализации.
# Расширить полки «ЗначенияX» и «ЗначенияY»: добавить для размещённых на них пилюль тип «Отсечка» и обеспечить одновременную обработку основной координатной пилюли и нескольких опорных линий.
# Обеспечить настройку подписи каждой опорной линии и возможность одновременно использовать несколько горизонтальных и вертикальных опорных линий.
# Исправить совместную работу полки «Серии», режима «Все» полки «Значения»; согласовать доступные агрегации и их применимость.
# Привести разрешение конфликтов стилей и динамического оформления к единому приоритету (в том числе для новых настроек).
# Сохранить работоспособность существующих отчётов.

_Пользовательская история:_
Как аналитик, я хочу на одной пузырьковой диаграмме сопоставлять показатели по осям X/Y, вручную управлять размерами и цветом пузырей и их отдельных групп, видеть понятные легенды, пользовательские подсказки и динамические опорные линии по обеим осям, чтобы гибко настраивать визуализацию без необходимости обхода несовместимых настроек.

----

h3. 3. Текущее и целевое поведение полок.

---
h4. 3.1. Назначение полок.

|| Полка || Сохраняемое поведение || Изменение в рамках задачи ||
| «ЗначенияX» | Числовая пилюля определяет координату X; числовое поле поддерживает агрегацию. AS-IS визуализация обрабатывает только первую пилюлю полки. | Расширить обработку нескольких пилюль. Первая по порядку пилюля типа «Значение» определяет координату X. Все валидные пилюли типа «Отсечка» формируют вертикальные опорные линии, другие вспомогательные типы для этой полки не отображаются. Для новой пилюли на данной полке использовать тип «Значение». Согласовать агрегацию с поведением полки «Значения» - при добавлении новой пилюли на данную полку и отсутствии пилюль на полках «Категории» и «Серии» агрегация не ставится («—»), при наличии - ставится стандартная агрегация во избежании ошибок. |
| «ЗначенияY» | Числовая пилюля определяет координату Y; числовое поле поддерживает агрегацию. AS-IS визуализация обрабатывает только первую пилюлю полки. | Расширить обработку нескольких пилюль. Первая по порядку пилюля типа «Значение» определяет координату Y. Все валидные пилюли типа «Отсечка» формируют горизонтальные опорные линии, другие вспомогательные типы для этой полки не отображаются. Для новой пилюли на данной полке использовать тип «Значение». Согласовать агрегацию с поведением полки «Значения» - при отсутствии пилюль на полках «Категории» и «Серии» при добавлении новой пилюли на данную полку агрегация не ставится («—»), при наличии - ставится стандартная агрегация. |
| «Значения» | Поля набора данных и вычисляемые поля; локальное отображаемое имя, сортировка, агрегация и тип. Режимы «Первое»/«Все». | Обеспечить совместимость существующих типов и фактическое использование «Подсказки» через шаблон. Тип «Отсечка» на данной полке не вводится. |
| «Категории» | Используется первая пилюля; определяет идентификацию/группировку объектов. Сохраняются локальное отображаемое имя, сортировка, «Подсказка по другому полю» и «Сортировка по другому полю». Уникальная категория для каждой исходной строки позволяет показывать отдельные исходные точки. | Значения активной пилюли должны быть доступны в «Стиле элементов» («Объект данных:») для индивидуальной настройки отображения. Базовая семантика полки не меняется. |
| «Серии» | Участвует построении визуализации только при режиме «Вкл» и наличии валидной пилюли на полке; задаёт дополнительную разбивку. При «Выкл» либо отсутствии валидной пилюли не влияет на построение. | Исправить конфликт с полкой «Значения» при режиме «Все» и настройкой «Легенда для цвета». Значения активной Серии должны быть доступны как группы в «Стиле элементов» («Объект данных:») для индивидуальной настройки отображения. |
| «Фильтры» | Стандартная фильтрация портала. | Базовая семантика не меняется. |

Для построения визуализации минимально должны быть доступны валидные числовые координаты X и Y. Отсутствие пилюль значений, категорий и серий - не препятствует построению визуализации.

Наличие пилюль типа «Отсечка» не заменяет обязательную пилюлю типа «ЗначениеY/X» соответствующей координатной полки.

---
h4. 3.2. Режимы и типы полки «Значения».

Под *участвующей пилюлей* далее понимается пилюля, обрабатываемая с учётом активности и режима полки:
* «Первое» — обрабатывается только первая пилюля полки по её типу.
* «Все» — обрабатываются все _участвующие_ пилюли поддерживаемых типов.
* Переключение режима не удаляет пилюли и их настройки. При возвращении в «Все» они снова участвуют, согластно своим типам.

|| Тип || Функциональное назначение ||
| «Значение» | Числовой показатель размера пузыря; не задаёт X или Y. |
| «Цвет» | Динамический цвет пузыря из данных, в том числе строковый HEX. |
| «Подзаголовок» | Источник существующего подзаголовка визуализации; штатная семантика сохраняется. |
| «Подсказка» | Источник пользовательского tooltip, используемый при явном выборе шаблона «Подсказка». |

При неизменном составе участвующих пилюль остальных типов добавление вспомогательной пилюли не создаёт новые пузыри, не меняет их группировку, X/Y и размер по другой пилюле.

При отсутствии участвующей пилюли типа «Значение» размер пузырей может определяться настройками разделов «Основной стиль» и «Стиль элементов» по правилам раздела 4.

Несколько пилюль одного типа обрабатываются по действующему контракту — сверка В3.

---
h4. 3.3. Типы и обработка пилюль полок «ЗначенияX» и «ЗначенияY».

Для пилюль, размещённых на полках «ЗначенияX» и «ЗначенияY», в настройке *«Тип»* должны быть доступны только:

# «Значение»;
# «Отсечка».

Для каждой из полок действует следующий контракт:

* одновременно на полке может находиться несколько пилюль;
* первая по порядку размещения валидная пилюля типа «Значение» является основной координатной пилюлей;
* все валидные пилюли типа «Отсечка» являются участвующими вспомогательными пилюлями;
* порядок отсечек относительно основной пилюли не влияет на их участие;
* отсечка, расположенная выше основной пилюли типа «Значение», не становится источником координаты;
* дополнительные пилюли типа «Значение» после первой не участвуют в расчёте координаты.

Для «ЗначенияX/Y»:
* первая участвующая пилюля типа «Значение» задаёт координату X/Y;
* каждая участвующая пилюля типа «Отсечка» задаёт отдельную вертикальную/горизонтальную опорную линию.

При изменении типа пилюли необходимо пересчитывать состав участвующих объектов полки.

Тип «Отсечка» на полке «Значения» *не предоставляется*.

----

h3. 4. Размер и стиль пузырей.

---
h4. 4.1. Текущее поведение.

* В соответствии с текущим поведением, показатель типа «Значение» управляет относительными размерами пузырей.
* Настройка «Радиус (px)» в правой панели задаёт минимальную и максимальную границы визуального размера.
* При изменении границ размеры пузырей масштабируются с сохранением относительного различия значений.
* При одинаковой нижней и верхней границе все пузыри отображаются одинакового размера.
* Если пилюля типа «Значение» отсутствует, диаграмма продолжает строиться, и все пузыри получают одинаковый фиксированный размер.
* AS-IS изменение существующей настройки «Радиус (px)» при отсутствии показателя размера не влияет на этот фиксированный размер.

Следовательно, текущая реализация не позволяет:
* изменить единый фиксированный размер пузырей без показателя;
* вручную назначить другой фиксированный размер выбранной категории или группе пузырей.

---
h4. 4.2. Раздел «Основной стиль».

Добавить в правой панели визуализации раздел *«Основной стиль»*.

Раздел задаёт общие параметры внешнего вида всех пузырей, если они не переопределены более приоритетным уровнем настройки.

Приоритет настроек определяется стандартным поведением портала и отражён в п. 11.2.

В рамках данной задачи обязательными настройками раздела являются размер пузыря, общий цвет пузырей и стандартные настройки раздела также допускаются к добавлению для поддержания единообразия настроек в рамках портала.

Т.е. настройка «Радиус (px)» переносится из раздела «Общие настройки» в раздел «Основной стиль».

|| Состояние || Целевое поведение ||
| Участвует пилюля типа «Значение» на полке «Значения» | Размер кодирует значение показателя. В «Основном стиле» доступен диапазон радиуса: минимальное и максимальное значение в px. Сохраняется действующее преобразование показателя в относительные размеры. |
| Пилюля типа «Значение» на полке «Значения» не участвует | В «Основном стиле» доступен единый фиксированный радиус пузыря в px. Значение применяется ко всем пузырям, для которых не действует более приоритетное индивидуальное переопределение. |

Тип «Значение» на полках «ЗначенияX»/«ЗначенияY» является координатным и не считается показателем размера.

Конкретный вид контрола определяется общим компонентом и технической проработкой.
Допустимый диапазон, способ ввода и валидацию значений переиспользовать из общего механизма портала.

---
h4. 4.3. Раздел «Стиль элементов».

Добавить в правой панели раздел *«Стиль элементов»* для настройки внешнего вида отдельных объектов данных.

В рамках текущей задачи обязательным индивидуально настраиваемым параметром является *размер пузыря*. Цвет пузырей и стандартные настройки раздела также допускаются к добавлению для поддержания единообразия настроек в рамках портала.

В разделе должен быть доступен выпадающий список *«Объект данных»*.

Доступные объекты:
* значения первой используемой пилюли полки «Категории»;
* при включённой валидной полке «Серии» — значения первой используемой пилюли «Серии».

Значения должны быть однозначно различимы по источнику.

Например:
* «Категории:»
** «Группа A»;
** «Группа B»;
* «Серии:»
** «Сегмент 1»;
** «Сегмент 2».

Для выбранного объекта пользователь может задать фиксированный размер пузыря и другие настройки в рамках выбранной группы.

Индивидуальные настройки применяются только в сценарии, когда показатель типа «Значение» на полке «Значения» не участвует.

При отсутствии индивидуального значения объект наследует св-ва из «Основного стиля».

Необходимо предоставить штатную возможность сбросить индивидуальное переопределение и вернуться к наследованию общего значения.

---
h4. 4.4. Область действия индивидуальных настроек.

* Настройка для значения «Категории» применяется ко всем пузырям соответствующей категории.
* Настройка для значения «Серии» применяется ко всем пузырям соответствующей Серии.
* При выключенной полке «Серии» индивидуальные настройки Серий не участвуют в отображении.
* При отсутствии полки «Категории» индивидуальные настройки Категорий не участвуют в отображении.
* Изменение фильтра не удаляет сохранённые индивидуальные настройки объекта.
* Если объект временно отсутствует в текущей выборке, настройка должна примениться снова после его появления.

Если один пузырь одновременно подпадает под настройку Категории и настройку Серии, применяется следующий приоритет внутри уровня «Стиль элементов»:
# индивидуальный стиль Категории (низкий приоритет);
# индивидуальный стиль Серии (высокий приоритет).

При отсутствии обоих переопределений применяется «Основной стиль».

Настройка отдельной комбинации «Категория × Серия» как самостоятельного третьего уровня в рамках данной задачи не требуется.

---
h4. 4.5. Взаимодействие с показателем размера.

При появлении участвующей пилюли типа _«Значение»_ на полке «Значения» диапазон допустимых размеров пузырей определяется диапазоном из «Основного стиля».

Динамически вычисляемый размер имеет более высокий приоритет, чем общий и индивидуальный _фиксированный_ размер.

Индивидуальные фиксированные размеры Категорий и Серий начинают снова применяться после того, как пилюля размера перестаёт участвовать.

---
h4. 4.6. Обратная совместимость.

Для старых отчётов без новых настроек должно сохраняться прежнее фактическое поведение и размер пузырей.

Новые параметры «Основного стиля» и «Стиля элементов» не должны автоматически менять внешний вид существующего отчёта до явного изменения пользователем (либо до штатной миграции, воспроизводящей прежнее значение).

Существующее поведение одинаковых, нулевых, отрицательных и пустых значений показателя размера сохраняется и не является предметом изменения в данной задаче.

----

h3. 5. Цвет и легенда цвета.

*Сейчас:* тип «Цвет» окрашивает пузыри, в том числе по HEX. Легенда может показывать HEX как подпись, а контрол «Подпись по другому полю» - недоступен.

* Сохранить действующий механизм динамического цвета.
* Валидный явный цвет из участвующей пилюли типа «Цвет» является динамическим оформлением и имеет наивысший приоритет относительно базовых цветов, «Основного стиля», «Стиля элементов» и автоматической окраски по Серии.
* При отсутствии участвующей пилюли «Цвет» применяется оформление следующего доступного уровня по правилам раздела 11.2.
* Сделать «Легенда для цвета → Подпись по другому полю» доступной для поддерживаемого сценария: пользователь выбирает поле текущего набора данных и получает предметную подпись соответствующего цвета, например «Группа A», вместо использования HEX как единственного названия.
* Использовать общую семантику выбора поля, сопоставления цвета и подписи, форматирования, пустых значений и сортировки.
* Поле подписи не должно самостоятельно менять группировку пузырей.
* Маркер каждого элемента легенды соответствует фактическому цвету обозначаемых пузырей.
* Повторения одной и той же пары «цвет — подпись» не создают повторяющиеся элементы.
* При отсутствии выбранного поля подписи сохраняется стандартная подпись по источнику цвета.
* Если данные дают несколько подписей одному цвету или несколько цветов одной подписи, применять правило общего компонента.
* Недопустимый или пустой динамический цвет обрабатывается стандартным механизмом портала и не должен приводить к исчезновению всех валидных пузырей.

----

h3. 6. Серии и совместимость типов полки «Значения».

*Исправляемый дефект:* при включённых валидных Сериях добавление пилюли типа «Цвет» на полку «Значения» вызывает конфликт определения цвета и скрывает пузыри. Оси остаются, ошибки запроса нет; легенда цвета может превратиться в один чёрный квадрат без корректной подписи.

Серии должны сохранять дополнительную разбивку данных, но не вызывать конфликт цветокодировки - приоритет цветокодировки требует дополнительное проработки и принятия решения, поэтому вынесен в Открытые вопросы - вопрос В4.

Отключение Серий возвращает штатную гранулярность без Серий. Настройки остальных пилюль при этом сохраняются.

Индивидуальные настройки размера Серий перестают участвовать при отключении Серий, но не удаляются из конфигурации.

----

h3. 7. Легенда размера.

*Сейчас:* подтверждён рабочий сценарий с выключенными Сериями, показателем размера и включённой настройкой «Графическим представлением»: несколько эталонных пузырей с числовыми значениями. При Сериях и в других режимах воспроизводимое *информативное* поведение не обеспечено.

* Устранить отдельную настройку «Графическое представление» (по умолчанию всегда включена).
* Включение валидных Серий и совместимых вспомогательных типов не делает поддерживаемый режим легенды неработоспособным.
* Легенда при показателе размера соответствует фактическому преобразованию «значение — размер».
* Нельзя показывать разные эталонные радиусы, если фактически всем значениям назначен *один радиус* через «Основной стиль» - легенда должна отражать актуальный заданный размер.
* Изменение данных, фильтров и диапазона размера обновляет легенду вместе с пузырями.

----

h3. 8. Всплывающая подсказка.

*Сейчас:* отсутствует раздел настроек «Всплывающая подсказка» правой панели; пилюля типа «Подсказка» не влияет на отображаемый tooltip.

Добавить стандартный раздел «Всплывающая подсказка», переиспользовав общий компонент, для возможности выбора шаблона и назначения применимых настроек отображения.

|| Условие || Целевое поведение ||
| Шаблон по умолчанию | Используется существующая стандартная подсказка (доступны несколько возможных настроек шаблонов). Само добавление/удаление пилюли типа «Подсказка» не заменяет её содержимое. |
| Шаблон явно задан как «Подсказка», валидная пилюля этого типа участвует | Содержимое пользовательской подсказки формируется из значения пилюли для наведённого пузыря по правилам общего шаблона. |
| «Шаблон = Подсказка», участвующего валидного источника нет либо его значение пусто | Применяется штатное резервное поведение общего компонента. Не выводятся устаревшее значение, {{undefined}} или текст другого пузыря. |
| «Шаблон = Подсказка», режим «Первое», пилюля «Подсказка» размещена после первой | Такая пилюля не является источником tooltip. |

Резервное поведение и обработку нескольких источников сверить по общему компоненту — Открытые вопросы, В3.

h3. 9. Опорные линии — тип «Отсечка».

---
h4. 9.1. Общая модель.

Опорные линии реализуются через пилюли типа *«Отсечка»* на полках соответствующих осей:

* «ЗначенияX» — вертикальные опорные линии;
* «ЗначенияY» — горизонтальные опорные линии.

Тип «Отсечка» на полке «Значения» не используется.

Ось линии определяется полкой, поэтому отдельная настройка X/Y для отсечки не требуется.

Опорная линия является вспомогательным объектом соответствующей оси и не заменяет основную координатную пилюлю типа «Значение».

---
h4. 9.2. Добавление и участие отсечек.

Для пилюль на «ЗначенияX» и «ЗначенияY» в меню «Тип» доступны:

# «Значение»;
# «Отсечка».

* «Отсечка» на «ЗначенияX» формирует вертикальную линию {{X = значение отсечки}}.
* «Отсечка» на «ЗначенияY» формирует горизонтальную линию {{Y = значение отсечки}}.
* Одна валидная пилюля типа «Отсечка» формирует одну линию.
* Несколько отсечек могут одновременно находиться как на одной, так и на обеих координатных полках.

Если на полке находится несколько пилюль типа «Значение», координату определяет только первая по порядку; остальные пилюли этого типа не участвуют в построении визуализации.

---
h4. 9.3. Источник и динамический расчёт.

Источником отсечки может быть:
* числовое поле набора данных;
* вычисляемое поле с числовым результатом.

Для обычного числового поля поддерживаются применимые числовые агрегации по стандартному механизму портала, включая:
* {{AVG}};
* {{MIN}};
* {{MAX}};
* {{SUM}}.

Результатом одной пилюли типа «Отсечка» должно являться одно числовое значение, определяющее положение одной линии.

Фильтры визуализации должны влиять на расчёт динамической отсечки по тем же правилам, что и на остальные вычисляемые значения визуализации.

Категории и Серии сами по себе не должны автоматически создавать несколько линий из одной пилюли типа «Отсечка».

---
h4. 9.4. Подпись линии.

Для каждой пилюли типа «Отсечка» необходимо обеспечить подчинённую настройку человекочитаемой подписи опорной линии.

Подпись относится только к соответствующей отсечке и не должна изменять подписи других линий.

---
h4. 9.5. Отображение и совместимость.

* Опорная линия отображается независимо от наведения курсора.
* Существующий crosshair при наведении сохраняется и не является опорной линией.
* Вертикальная отсечка отображается относительно числовой шкалы X.
* Горизонтальная отсечка отображается относительно числовой шкалы Y.
* При zoom линия остаётся привязана к своему числовому значению на соответствующей оси.
* Отсечки не изменяют координаты пузырей, количество объектов, размер, цвет, Категории, Серии, tooltip и обработку клика.
* Отсечки должны корректно работать совместно с Сериями и всеми допустимыми типами полки «Значения».

---
h4. 9.6. Некорректные результаты отсечки.

Для каждой отсечки ожидается один конечный числовой результат.

При пустом, {{NULL}}, нечисловом или неконечном результате:
* соответствующая линия не строится, а остальные валидные отсечки продолжают работать;
* построение валидных пузырей сохраняется.

Ошибка конфигурации или вычисления конкретной отсечки обрабатывается по стандартному механизму ошибочных состояний пилюль/вычислений портала.

---
h4. 9.7. Количество опорных линий.

Требование Громова требует явно определить максимальное количество одновременно поддерживаемых опорных линий.

На текущем этапе ограничение не согласовано, а вопрос о необходимости лимита и его значении выносится в В2.

----

h3. 10. Агрегации и дефолтные настройки.

*Исправляемая несогласованность:* автоматический выбор агрегации {{-}} для пилюль основных координат X/Y при наличии пилюль на полках «Категории» и «Серии» может нарушать построение визуализации и проводить к ошибкам.

Требуется согласовать поведение полок «ЗначенияX» и «ЗначенияY» с поведением полки «Значения».

При отсутствии пилюль на полках «Категории» и «Серии»:
* Для новых пилюль на полках «ЗначенияX» и «ЗначенияY» использовать агрегацию {{-}} как стандартную.
* При добавлении пилюль на полки «Категории» и «Серии», переключать пилюли на полках «ЗначенияX» и «ЗначенияY» в стандартное агрегированное состояние, по аналогии с текущим поведением полки «Значения».

При наличии пилюль на полках «Категории» и «Серии»:
* Для новых пилюль на полках «ЗначенияX» и «ЗначенияY» использовать стандартный режим агрегации в соответствии с текущими правилами для полки «Значения».
* При удалении всех пилюль с полок «Категории» и «Серии» - режим агрегации не переключать. Ранее выбранные допустимые агрегации сохранять.

h3. 11. Общие контракты и совместимость.

---
h4. 11.1. Фронтенд и сохранение настроек.

* Переиспользовать общие компоненты полок, пилюль, «Основного стиля», «Стиля элементов», динамического цвета, легенд, tooltip и опорных линий.
* Сохранять существующие работающие настройки осей, сортировку, форматирование, «Подсказку по другому полю», подзаголовок, действия по клику, фильтрацию, выделение и снятие выбора.
* Существующий zoom сохраняется: близкие точки остаются самостоятельными объектами и могут перекрываться.
* После сохранения, повторного открытия и копирования виджета/отчёта воспроизводятся:
** полки;
** порядок пилюль;
** типы пилюль;
** активное/неактивное состояние пилюль согласно правилам полок;
** режимы;
** агрегации;
** общий фиксированный размер либо диапазон размера по показателю;
** индивидуальные размеры Категорий/Серий;
** источник подписи легенды;
** шаблон tooltip;
** отсечки и их подписи.
* Для старых отчётов без новых параметров сохранять прежнее работоспособное отображение.
* Исправляемые дефектные сочетания должны начать работать; их ошибочное отображение сохранять *не требуется*.

---
h4. 11.2. Приоритеты оформления.

При конфликте нескольких источников стиля «Диаграмма пузырьковая» должна применять стандартный для портала приоритет от наименьшего к наибольшему:

# базовые цвета и стили дашборда;
# общие настройки визуализации в разделе «Основной стиль»;
# частные настройки конкретных Категорий/Серий в разделе «Стиль элементов»;
# динамически задаваемое оформление из данных посредством пилюль и вычисляемых полей.

Более высокий уровень переопределяет только конфликтующее свойство более низкого уровня, но не сбрасывает и не удаляет сохранённую настройку нижнего уровня.

В частности:
* динамическая пилюля типа «Цвет» имеет приоритет над цветом «Стиля элементов», «Основного стиля» и темой дашборда;
* динамический размер по пилюле типа «Значение» на полке «Значения» имеет приоритет над индивидуальными и общими фиксированными размерами;
* после прекращения участия динамической пилюли снова применяется наиболее приоритетная из сохранённых статических настроек;
* отсутствие динамического значения обрабатывается стандартным механизмом fallback портала и не должно самопроизвольно изменять остальные стилевые свойства.

Для конфликта двух настроек одного уровня «Стиль элементов» внутри визуализации:
# Серия имеет приоритет над Категорией;
# при отсутствии обеих заданная настройка в «Основной стиль» и т.д.

---
h4. 11.3. Бэкенд, данные и API.

* Использовать штатное получение данных набора данных.
* Передавать и возвращать достаточные данные для X/Y, Категории, активных Серий, размера, цвета, подписи легенды, подзаголовка, tooltip и отсечек.
* Значения активных Категорий/Серий должны позволять однозначно применить сохранённые настройки «Стиля элементов».
* Вспомогательные поля не должны непреднамеренно менять гранулярность основных точек.
* Расчёт отсечки должен возвращать один числовой результат для одной пилюли и не размножаться автоматически из-за визуальной группировки.
* Переиспользовать действующие фильтры, права доступа к данным и правила {{WHERE}}/{{HAVING}}.
* Не вводить специфичную семантику общей фильтрации или SQL одного диалекта.
* Техническая структура хранения стилей, типов пилюль и отсечек определяется разработкой при соблюдении функционального контракта.

h3. 12. Открытые вопросы и необходимая сверка контрактов.

*В1. Неподтверждённые состояния легенды размера — разработка, при отсутствии общего контракта владелец продукта.*

Какое представление предусматривает общий компонент при выключенном «Графическом представлении» требуется ли оно?

Как рабочий вариант предлагаю убрать пока настройку «Графическое представление» (по умолчанию всегда включено).

Сценарий без показателя размера определяется однозначно: количественная легенда размера не должна изображать числовую зависимость, которой нет.

---
*В2. Максимальное количество одновременно активных опорных линий — владелец требования совместно с разработкой.*

Требование Громова требует указать максимальное количество опорных линий.

Необходимо определить:
* требуется ли отдельное ограничение количества отсечек в "Диаграмма пузырьковая";
* если требуется — какое максимальное число одновременно активных отсечек допускается;
* является ли ограничение общим для X/Y либо отдельным для каждой полки.

До согласования конкретное числовое ограничение в постановке не фиксируется.

---
*В3. Недокументированные общие правила — техническая сверка у разработки.*

Зафиксировать:
* действующее правило нескольких пилюль одного типа в режиме «Все» для полки «Значения»;
* резервное поведение шаблона «Подсказка» при отсутствии соответствующей пилюли;
* разрешение неоднозначного соответствия «цвет — подпись».

Если правила уже существуют, переиспользовать их. При отсутствии правила согласовать недостающий случай.

---
*В4. Приоритет определения цветокодировки между «Сериями» и пилюлей типа «Цвет» — разработка, владелец продукта.*

При наличии активной и заполненной полки «Серии» и явно заданной пилюли типа «Цвет» - кто должен иметь приоритет и определять распределение цветов пузырей.

Важно заметить, что независимо от выбранного приоритета «Легенда для цвета» должна расшифровывать именно приоритетную цветокодировку, например:
* Если приоритет отдан динамическим цветам пилюли, а внутри одной Серии пузыри имеют разные динамические цвета, легенда не должна ошибочно представлять их как окрашенные одним цветом Серии.

h3. 14. Критерии приёмки (AC):

*AC.1 — Полки «ЗначенияX» и «ЗначенияY»:*
* *Дано:* на координатной полке размещено несколько числовых пилюль;
* *Когда:* для них задаются типы «Значение» и «Отсечка» и изменяется порядок размещения;
* *Тогда:* в меню «Тип» доступны только «Значение» и «Отсечка»; первая по порядку валидная пилюля типа «Значение» определяет координату соответствующей оси; все валидные пилюли типа «Отсечка» участвуют одновременно;
* *И:* последующие пилюли типа «Значение» не участвуют и обозначаются штатным способом как неиспользуемые; при отсутствии пилюли типа «Значение» наличие одних отсечек не считается настроенной координатой.

*AC.2 — Агрегации X/Y:*
* *Дано:* на «ЗначенияX»/«ЗначенияY» добавляется новая пилюля типа «Значение»;
* *Когда:* полки «Категории» и «Серии» не требуют агрегирования данных;
* *Тогда:* для новой координатной пилюли применяется {{-}} по правилам раздела 10;
* *Когда:* конфигурация изменяется так, что наличие Категорий/Серий требует агрегирования;
* *Тогда:* координатные пилюли переводятся в стандартное агрегированное состояние по общему механизму;
* *И:* удаление Категорий/Серий не сбрасывает ранее установленную допустимую агрегацию; штатная работа с агрегациями не приводит к ошибке построения визуализации.

*AC.3 — Фиксированный и динамический размер пузырей:*
* *Дано:* показатель типа «Значение» на полке «Значения» не участвует;
* *Когда:* пользователь изменяет фиксированный размер в «Основном стиле»;
* *Тогда:* новый размер применяется ко всем пузырям без индивидуального переопределения;
* *Когда:* для Категории или Серии задаётся размер в «Стиле элементов»;
* *Тогда:* он применяется к соответствующей группе, а сброс настройки возвращает наследование «Основного стиля»;
* *Когда:* начинает участвовать показатель размера типа «Значение»;
* *Тогда:* размеры определяются значениями показателя и диапазоном «Радиус (px)», а сохранённые фиксированные переопределения временно не применяются и восстанавливаются после отключения показателя.

*AC.4 — Серии, режим «Все» и вспомогательные типы:*
* *Дано:* полка «Серии» включена и содержит валидную пилюлю;
* *Когда:* на полке «Значения» используются режим «Все» и допустимые комбинации типов «Значение», «Цвет», «Подзаголовок» и «Подсказка»;
* *Тогда:* визуализация продолжает строиться, пузыри не исчезают и каждый участвующий тип выполняет своё назначение;
* *И:* выключение Серий возвращает штатное построение без Серий, не удаляя настройки остальных пилюль; совместная цветокодировка и соответствующая ей легенда работают по решению В4.

*AC.5 — Легенды цвета и размера:*
* *Дано:* используется динамический цвет;
* *Когда:* включается «Легенда для цвета» и выбирается «Подпись по другому полю»;
* *Тогда:* контрол выбора поля доступен, а легенда отображает фактические цвета с человекочитаемыми подписями вместо технических значений цвета;
* *И:* одинаковые пары «цвет — подпись» не дублируются;
* *Дано:* участвует показатель размера;
* *Когда:* включается «Легенда для размера»;
* *Тогда:* легенда соответствует фактическому преобразованию «значение — размер» и продолжает корректно работать при Сериях и допустимых вспомогательных типах;
* *И:* при одинаковом фактическом радиусе легенда не показывает фиктивное различие размеров; окончательный состав настроек раздела соответствует решению В1.

*AC.6 — Всплывающая подсказка:*
* *Дано:* в правой панели доступен раздел «Всплывающая подсказка»;
* *Когда:* используется стандартный шаблон;
* *Тогда:* сохраняется штатная подсказка;
* *Когда:* явно выбран шаблон «Подсказка» и участвует валидная пилюля соответствующего типа;
* *Тогда:* tooltip отображает значение этой пилюли для наведённого пузыря;
* *И:* при отсутствии валидного источника применяется согласованное резервное поведение В3 без {{undefined}}, устаревшего или относящегося к другому пузырю значения.

*AC.7 — Опорные линии:*
* *Дано:* на «ЗначенияX» и/или «ЗначенияY» размещены одна или несколько валидных пилюль типа «Отсечка»;
* *Когда:* визуализация построена;
* *Тогда:* каждая отсечка на X отображается отдельной вертикальной линией, каждая отсечка на Y — отдельной горизонтальной; для каждой линии отображается относящаяся к ней подпись в случае её настройки; изменение данных, применимого фильтра, исходного поля или агрегации пересчитывает положение соответствующей линии.

*AC.8 — Ошибочные состояния и количество отсечек:*
* *Дано:* настроено несколько опорных линий;
* *Когда:* одна отсечка возвращает пустой, {{NULL}}, нечисловой либо некорректный результат;
* *Тогда:* проблемная линия не строится, остальные валидные линии и пузыри сохраняются;
* *И:* ошибочное значение не подменяется нулём.
