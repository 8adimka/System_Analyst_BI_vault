# Разработчик и HTML-макеты

В `/home/v/desk/work` обычная новая сессия Codex следует корневому `AGENTS.md` и инструкции full-stack разработчика `AGENT.md`. Название для автоматического обнаружения — **AGENTS.md**; запрошенный `AGENT.md` подключается из него. Роль `.codex/agents/fullstack.toml` доступна для явной делегации и сама по себе не переключает основную сессию.

После изменения инструкций начните новую сессию Codex в корне workspace. Локальный `.codex/config.toml` задаёт `workspace-write`, запрос разрешения при необходимости и отключённую сеть shell. Управляемые ограничения среды и настройки доверия имеют приоритет; глобальные конфигурации и авторизация не менялись. При запуске из старой тематической папки учитывайте её вложенный `AGENTS.md`.

Примеры запросов:

- «Изучи реализацию этого экрана и исправь поведение. Код подготовь в отдельной приватной копии, покажи diff и результаты проверок».
- «Сделай интерактивный HTML-макет по оформлению портала для сценария …; используй вариант … и этот локальный скриншот …».
- «Исследуй механизм … и добавь подтверждённые выводы в приватную Wiki».
- «Используй агентскую систему для написания постановок по `Новая_тема/промпт.txt`» — отдельный маршрут по основному README, с прежним требованием разрешения на модельную обработку корпоративных материалов.

Код пишется в `.private/development/<задача>/`, макеты — в `.private/mockups/<задача>/`. Оригиналы `.private/repositories/` защищены правилами только для чтения; автоматической установки, сборки и изменения оригиналов нет. При подготовке рабочей копии не переносите секреты и `.git`, не используйте ссылки на исходники. Права `workspace-write` сами по себе не создают OS-защиту каждого вложенного каталога: разработчик соблюдает эту границу инструкциями и проверкой путей. Аналитическая система дополнительно использует физические read-only mounts и SDK sandbox.

Wiki доступна локально через `.private/knowledge/index.md`. Новые страницы содержат карту full-stack кода, визуальные ориентиры и команды, проверенные по исходникам. Это начальная подтверждённая карта, а не исчерпывающее знание продукта. Правила в `SCHEMA.md`, журнал в `log.md`; базовый `sources.json` и отдельный `fullstack-sources.json` хранят ссылки/версии/хеши. Команда `agent-system/.venv/bin/python agent-system/run.py wiki-check` проверяет базовый реестр; новый реестр также нужно сверять при обновлении затронутых файлов по правилам навыка `codebase-wiki`.

Подход Wiki адаптирован из [LLM Wiki Андрея Карпати](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f): неизменяемые источники, связанные Markdown-страницы, правила ведения, индекс, журнал, ingest/query/lint и сохранение полезных проверенных выводов. Эмбеддинги и внешний сервис для этой базы не требуются. Технические факты, корпоративные ресурсы и результаты разработки остаются внутри `.private/`.

Для системы постановок координатор монтирует отдельный `agent-system/runtime/AGENTS.md` как корневую инструкцию и предоставляет только аналитические роли/навыки. Инструкции full-stack разработчика, рабочие копии и макеты в это представление не входят. Два Thread, независимое исследование ревьюера и ограничения 5+1 сохранены.

Автообнаружение инструкций и границы конфигурации сверены с [OpenAI Docs: AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) и [subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents). Никакого автоматического commit/push или публикации Wiki/кода/макетов нет.
