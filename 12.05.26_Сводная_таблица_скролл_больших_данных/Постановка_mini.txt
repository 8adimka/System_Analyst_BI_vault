h2. [PIVOT-XXX] Оптимизация сводной таблицы при больших объёмах данных: управление отрисовкой строк

----
h3. Контекст и проблема

h4. Описание проблемы

В текущей реализации сводная таблица портала Modus BI отрисовывается целиком на одном «листе»: все строки загружаются и рендерятся единовременно, без каких-либо ограничений на количество отображаемых записей.

При работе с большими наборами данных (проект ФКТ — тысячи строк; теоретический предел — сотни тысяч записей) это приводит к следующим негативным эффектам:

* Значительные задержки при первичной отрисовке таблицы.
* Зависание и «подтормаживание» UI при добавлении детальных полей на полку детализации.
* Критическое падение производительности при использовании функции «Развернуть до уровня N»: при датасете ~9 800 строк и полном разворачивании иерархии интерфейс становится практически неотзывчивым.

h4. Скрытая функциональность «Развернуть до уровня»

Функциональность разворачивания иерархии до заданного уровня реализована (автор — Алексей Меркушенко), однако в настоящий момент скрыта из UI. Задача оптимизации отрисовки является предварительным условием для корректного и производительного возврата этой функциональности пользователям.

----
h3. Цель задачи

Обеспечить корректную и производительную работу сводной таблицы при больших объёмах данных за счёт ограничения количества одновременно отрисовываемых строк и предоставления пользователю механизма навигации по данным.

*Задача не включает* финальный выбор подхода к реализации — он будет определён совместно с командой разработки на встрече-обсуждении. Данная постановка описывает проблему и два возможных пути решения для подготовки к этому обсуждению.

----
h3. Контекст: особенности иерархической структуры сводной таблицы

Перед описанием вариантов решения необходимо зафиксировать ключевое ограничение, влияющее на любой подход:

* Сводная таблица имеет многоуровневую иерархию строк (N уровней вложенности).
* Нижний уровень вложенности является «листовым» — именно по нему предлагается считать количество строк для пагинации/подгрузки.
* Верхние уровни иерархии являются группирующими заголовками. При переходе между страницами/блоками родительские заголовки (группы), к которым относятся отображаемые строки, *должны дублироваться* в начале каждой страницы/блока — чтобы пользователь понимал контекст видимых данных.
* Итоговые строки (subtotals) требуют отдельного решения по отображению при разбивке на страницы (дублировать / не показывать / показывать только на последней странице группы).
* При использовании функции «Развернуть до уровня N» расчёт и лимитирование строк должны применяться к итоговому количеству *видимых* строк (включая развёрнутые уровни), а не только к строкам верхнего уровня.

----
h3. Варианты решения

{note}Финальный выбор варианта будет принят на встрече с разработчиками. Ниже описаны оба подхода для оценки трудоёмкости и рисков.{note}

h4. Вариант А: Постраничная пагинация (Pagination)

*Суть:* Данные сводной таблицы разбиваются на страницы фиксированного размера. Пользователь явно переключается между страницами с помощью элементов управления.

*Элементы управления (UI):*

* Панель пагинации в нижней части виджета сводной таблицы, содержащая:
** Индикатор текущей позиции: «Строки X–Y из Z» (где Z — общее количество строк по нижнему уровню).
** Кнопки: «В начало», «Назад», «Вперёд», «В конец».
** Поле ввода номера страницы с валидацией (значение < 1 → переход на первую страницу; значение > max → переход на последнюю страницу).
** Выпадающий список (или компактный селектор) «Строк на странице»: набор значений, например, 10 / 50 / 100 / 500 / 1000.

*Настройки виджета:*

* Тумблер «Пагинация» в панели настроек сводной таблицы (включить / выключить).
* При включении тумблера появляется подсекция с настройкой значения по умолчанию «Строк на странице».
* При выключенной пагинации — поведение таблицы остаётся legacy (текущее, полная отрисовка).

*Логика подсчёта строк:*

* Строки считаются по нижнему (листовому) уровню иерархии.
* Родительские группирующие строки, к которым относится контент страницы, дублируются в начале страницы.
* Скрытые (свёрнутые) строки в подсчёт не включаются — учитываются только видимые строки.

*Преимущества:*

* Предсказуемое поведение для пользователя.
* Полный контроль над объёмом загружаемых данных на каждый запрос.
* При нажатии «Развернуть до уровня N» обрабатывается только текущая страница — остальные загружаются по требованию.
* Прецедент реализации: аналогичный подход реализован на ресурсе УФК (постраничная навигация с выбором количества строк и стратегии пагинации).

*Риски и открытые вопросы:*

* Сложность отображения иерархии при разбивке группы между страницами (дублирование заголовков).
* Необходимость хранения/передачи информации о состоянии развёрнутости между страницами.
* Выбор стратегии пагинации на уровне бэкенда: offset-based / keyset / фильтр в памяти — влияет на производительность при больших объёмах и произвольном переходе к странице.

----
h4. Вариант Б: Бесконечный скролл с дозагрузкой (Infinite Scroll / Virtual Scroll)

*Суть:* Таблица изначально отрисовывает ограниченный блок строк. При прокрутке пользователем вниз автоматически подгружается следующий блок данных. Уже просмотренные блоки могут выгружаться из DOM для экономии памяти (виртуализация).

*Поведение:*

* При загрузке виджета отрисовывается первый блок строк (размер блока — конфигурируемый параметр).
* По мере прокрутки к нижней границе видимой области — подгружается следующий блок.
* Ползунок скроллбара отражает только загруженную часть данных; после подгрузки нового блока он пересчитывается.
* При включённой виртуализации: строки, ушедшие за пределы видимой области более чем на N блоков, выгружаются из DOM, сохраняя их место-заполнитель нужной высоты.

*Настройки:*

* Активация режима — аналогично варианту А через тумблер в настройках (или является поведением по умолчанию).
* Размер подгружаемого блока строк — конфигурируемый параметр (возможно, скрытый от пользователя).

*Преимущества:*

* Привычная и «бесшовная» UX-парадигма (аналог бесконечных лент в современных приложениях).
* Не требует явного управления страницами от пользователя.
* Может быть проще с точки зрения логики отображения иерархии — данные просто добавляются снизу без разрыва контекста.

*Риски и открытые вопросы:*

* Навигация: отсутствует возможность быстрого перехода к произвольному участку данных (аналог «перейти на страницу 128 из 199»).
* При частичной виртуализации DOM — сложность реализации корректной высоты скроллбара и позиционирования.
* Взаимодействие с «Развернуть до уровня N»: при разворачивании всей иерархии на бесконечном скролле объём данных может резко возрасти — необходима отдельная стратегия обработки.
* Потенциально более сложная реализация корректного виртуального скролла с иерархическими строками переменной высоты.

h3. Вопросы для обсуждения с разработчиками

Следующие вопросы должны быть рассмотрены на встрече для принятия финального решения:

# *Трудоёмкость:* Какой вариант (А или Б) требует меньше времени на реализацию с учётом текущей архитектуры фронтенда и бэкенда?
# *Бэкенд-стратегия пагинации* (актуально для варианта А): Какую стратегию использовать — offset, keyset или иную? Как это влияет на производительность при произвольном переходе к странице?
# *Виртуализация DOM* (актуально для варианта Б): Поддерживает ли текущая реализация сводной таблицы виртуальный скролл? Какова трудоёмкость его внедрения с учётом иерархических строк?
# *Совместимость с «Развернуть до уровня N»:* Как каждый из вариантов взаимодействует с разворачиванием иерархии? Какие ограничения возникают?
# *Реализация обоих режимов одновременно:* Реалистично ли (по срокам и ресурсам) реализовать оба варианта с переключением — или необходимо выбрать один?
# *Итоги и subtotals:* Как отображать итоговые строки при разбивке данных на блоки/страницы?

h3. Критерии приёмки (Acceptance Criteria)

{note}AC будут уточнены и дополнены после выбора финального варианта реализации на встрече с разработчиками. Ниже приведены общие AC, применимые к обоим вариантам, и специфичные — для каждого подхода.{note}

h4. Общие AC (применимы к любому выбранному варианту)

* [AC-1] При открытии сводной таблицы с датасетом более установленного порога строк (TBD) — в UI не происходит «зависания»; первичная отрисовка завершается не более чем за X секунд (конкретное значение — по итогам нагрузочного тестирования).
* [AC-2] Функция «Развернуть до уровня N» при активированном механизме ограничения отрисовки не вызывает зависания интерфейса при датасете ~10 000 строк.
* [AC-3] Строки считаются по нижнему (листовому) уровню иерархии; свёрнутые строки в подсчёт не входят.
* [AC-4] При разбивке иерархической группы между блоками/страницами — родительские группирующие заголовки дублируются в начале нового блока/страницы.
* [AC-5] Механизм ограничения отрисовки можно включить/выключить в настройках виджета через тумблер «Пагинация» (или аналогичный элемент управления).
* [AC-6] При отключённом механизме — таблица работает в legacy-режиме (текущее поведение без изменений).
* [AC-7] Все существующие функции виджета (сортировка, фильтрация, группировка, переименование полей и т.д.) работают корректно при включённом механизме.

h4. AC, специфичные для Варианта А (Пагинация)

* [AC-A1] Панель пагинации отображается в нижней части виджета при активированном тумблере.
* [AC-A2] Пользователь может выбрать количество строк на странице из предустановленного набора значений.
* [AC-A3] Пользователь может перейти на произвольную страницу через поле ввода номера страницы.
* [AC-A4] При вводе значения меньше 1 — осуществляется переход на первую страницу; при вводе значения больше максимального — на последнюю страницу.
* [AC-A5] Индикатор отображает текущий диапазон строк («Строки X–Y из Z»).
* [AC-A6] Настройка «Строк на странице по умолчанию» сохраняется в конфигурации виджета.

h4. AC, специфичные для Варианта Б (Бесконечный скролл)

* [AC-B1] При прокрутке к нижней границе видимой области — следующий блок строк подгружается автоматически без явного действия пользователя.
* [AC-B2] В процессе подгрузки отображается индикатор загрузки.
* [AC-B3] Скроллбар корректно отображает текущую позицию относительно уже загруженного объёма данных.
* [AC-B4] (Если реализуется виртуализация) Выгрузка ушедших из области видимости строк из DOM не приводит к «прыжкам» позиции скролла или искажению layout таблицы.
