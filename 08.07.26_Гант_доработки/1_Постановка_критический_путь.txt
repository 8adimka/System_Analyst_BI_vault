Требуется составить постановку для отрисовки критического пути в диаграмме Ганта на нашем аналитическом портале.

*Цель.* Добавить в визуализацию «Гант» отображение критического пути — последовательности связанных задач, изменение сроков которых сдвигает итоговую длительность выполнения общей цепочки заданий (проекта); задачи, допускающие параллельное выполнение и не влияющие на итоговый срок, критическими не считаются, если не увеличивают общее время необходимое для реализации проекта. Постановка формулируется как бизнес-задача для оценки разработчиками, без погружения в расчётный алгоритм — фокус на пользовательском поведении, управлении интерфейсом и ожидаемом результате.

*Текущая логика Ганта (контекст, обязательный для учёта):*

- Диаграмма строится на полках:
* «Значения» - для каждой пилюли, размещённой на этой полке, можно выбрать "Тип": 
** "Значение" (в "Значениях" обязательно нужно указать "дата начала" и "дата окончания", чтобы понимать когда планируется начать задание и когда планируется его окончание), 
** "Отсечка",
** "Цвет";
* «Строки» - на этой полке мы задаём задачи для выполнения, а также можем обозначить иерархию: Этап -> Подэтап -> Задача. На полку «Строки» можно поместить до 4 уровней иерархии (например, проект → этап → подэтап → задача), уровни сворачиваются/разворачиваются, при отображении в диаграмме;
* «Фильтры» (на этой полке мы указываем по чему проводим фильтрацию данных для отображения на диаграмме).

- Раздел настроек «Диаграмма Ганта» содержит: "Дата начала", "Дата окончания" (обязательные), "% выполнения" (progress bar внутри полосы), "ID задачи" и "ID родительской задачи" (для связей).

*Модель связей:*

- Связь задаётся через пару "ID задачи" и "ID родительской задачи"; у задачи может быть только один родитель, но у одного родителя — несколько дочерних задач.
- Несколько родителей у одной задачи не поддерживаются и не требуются.
- Связь может «перескакивать» через несколько строк/уровней, если так указаны ID (например, последняя задача одного этапа — родитель не первой, а третьей задачи другого этапа, если первые задачи можно выполнять параллельно).
- Связи существуют только на уровне задач; между этапами/подэтапами как отдельными сущностями связей нет и не предполагается — зависимость этапов выражается только через связи их дочерних задач.

Поведение при отсутствии ID задачи/ID родителя:
Базовый принцип: критический путь — это производная от графа связей, а не от одной лишь длительности задач.

Если у задач не заданы ID/ID родителя, критический путь не рассчитывать и тумблер делать неактивным (с поясняющей подсказкой).

т.е.
* если для задачи не настроены "ID задачи" и "ID родительской задачи", определение критического пути не проводится; Логика должна опираться на связи задач.

*Управление в интерфейсе:*
Во вкладку настроек «Диаграмма Ганта» добавляется новая настройка «Отображать критический путь» (галочка/тумблер) - разместить ниже настройки "ID родительской задачи", данная настройка должна быть доступна при наличии данных для расчёта; По умолчанию тумблер выключен — критический путь не должен навязываться пользователю, который не настроил связи. При недостаточности данных — недоступность настройки и пояснительная подсказка.

*Отображение:*

- Уже существует управление цветом: цвет полосы и цвет progress bar берутся из палитры (первые два цвета) или из данных (аналитик может задать вычисляемым полем цвет полосы отдельно и цвет progress bar отдельно); цвет из данных имеет наивысший приоритет и не должен перезаписываться.
- Простое перекрашивание в фиксированный цвет (например, красный) рискует конфликтовать с уже настроенными пользователем цветами проектов/статусов, поэтому предпочтительно искать способ, не ломающий текущую цветовую логику.

Оформление:

Цвет/стиль подсветки критического пути должен быть настраиваемым, а не жёстко зашитым - при активации настройки «Отображать критический путь» — появляется дополнительная вспомогательная настройка «Выбор цвета критического пути". Дополнительно можно предусмотреть CSS-классы, которые можно переопределить.

Также вводится дополнительная настройка отображения (два режима использования, галочка/тумблер): «Только критические задачи» (по умолчанию - выключен, в выключенном положении подсветка критического пути происходит в общем плане) — это два разных пользовательских сценария: «увидеть путь в контексте всего плана» и «сфокусироваться только на нём».

Что подсвечивать:

Подсвечивать одновременно: полосу задачи (заливку/рамку) и линию связи между критическими задачами выбранным цветом. Это даёт пользователю визуальную «нить» пути, а не разрозненные полосы.

Progress bar внутри полосы не менять по цвету критичности — он должен сохранять свою самостоятельную визуальную роль (% выполнения), иначе конфликт двух смыслов на одном элементе.

Не подсвечивать этапы/подэтапы как отдельные критические сущности — только листовые задачи и их связи, так как связи в нашей модели существуют только на уровне задач. Этап может визуально «наследовать» индикатор (например, тонкая полоска-маркер), если внутри него есть хотя бы одна критическая задача.

*Что исключено из скоупа:* отступы уровней, нумерация уровней, сортировка задач, отсечки и их отображение, детальный backend-алгоритм расчёта.

Сохраняй оптимальную разметку и структуру документов, которая уже используется в существующих постановках, для публикации в Jira.

Разработчик не должен знать о том, что ему не нужно реализовывать, но должен понимать, что нужно.
