Разработчик подчеркнул, что:
Фронтенд не содержит отдельной StarRocks-специфичной логики отображения, скрытия или блокировки элементов формы источника.
Список доступных типов подключения и параметры отображения формы определяются существующим единым механизмом. Если список типов подключений формируется бэкендом, фронтенд отображает StarRocks в общем списке на основании данных, полученных от бэкенда.
При выборе StarRocks фронтенд отображает стандартную карточку SQL-источника по текущей общей схеме: тип подключения, имя источника, отображаемое название, хост, порт, имя БД, схема БД, логин, пароль и прочие поля текущей формы.
Фронтенд может отображать общие элементы карточки источника, в том числе связанные с ФВД, отчётными формами, RLS и другими функциями, если они присутствуют в общей форме для источников. Отдельно скрывать или отключать эти элементы для StarRocks в рамках данной доработки не требуется.
Пользовательские действия по установке или подключению дополнительных функций, например ФВД, отчётных форм, RLS и аналогичных механизмов, обрабатываются через существующие запросы фронтенда к бэкенду.
Бэкенд по типу источника определяет, поддерживается ли запрошенная операция для StarRocks.
Если операция поддерживается — бэкенд выполняет её и возвращает штатный успешный ответ.
Если операция не поддерживается для StarRocks — бэкенд возвращает контролируемую функциональную ошибку о неподдерживаемой операции. Фронтенд отображает эту ошибку в существующем UX-паттерне.
Поля/переключатели общей формы, которые технически могут быть отображены для всех источников, не должны приводить к выполнению неподдерживаемой логики для StarRocks. Бэкенд должен либо игнорировать неприменимые признаки согласно текущему поведению системы, либо возвращать контролируемую ошибку при попытке выполнить неподдерживаемую операцию.
Основная зона ответственности доработки — бэкенд: регистрация типа {{starrocks}}, проверка подключения, чтение метаданных, маппинг типов, генерация SQL в StarRocks-диалекте, выполнение запросов, обработка ошибок и backend-валидация неподдерживаемых операций.
Фронтенд не должен дорабатываться специально под StarRocks, кроме случаев, когда в текущей реализации список типов подключений, порт по умолчанию или другие справочники жёстко зашиты на клиенте. В таком случае правка фронта ограничивается техническим подключением StarRocks к уже существующей общей схеме, без отдельной логики доступности функций.

Ключевая правка по смыслу: не «фронт должен скрыть/заблокировать всё неподдерживаемое для StarRocks», а «фронт работает как сейчас, бэк является источником истины и возвращает успех/контролируемую ошибку по типу источника».
