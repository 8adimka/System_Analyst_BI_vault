h3. Контекст и цель.

В рамках расширения возможностей аналитического портала необходимо реализовать поддержку {*}StarRocks{*} как отдельного типа подключения к источнику данных.

StarRocks использует {*}MySQL wire-протокол{*}, поэтому на транспортном уровне допускается общий с MySQL драйвер. При этом StarRocks не является MySQL-источником: это OLAP-СУБД с колоночным хранением, MPP-архитектурой, собственной SQL-семантикой, типами данных, DDL и особенностями аналитических запросов. Использование StarRocks через тип {{mysql}} приводит к некорректной генерации SQL, ошибкам выполнения запросов, неверному маппингу типов и риску искажения данных.

StarRocks должен быть зарегистрирован как отдельный тип подключения {{StarRocks}}, наравне с PostgreSQL, ClickHouse, MySQL и другими поддерживаемыми источниками:

Поддержка StarRocks реализуется как отдельная обёртка над драйвером: отдельная регистрация типа, отдельная логика чтения метаданных, отдельный маппинг типов и отдельный построитель SQL. Наследование MySQL-диалекта, MySQL-DDL и MySQL-маппинга для StarRocks недопустимо.

Минимальная поддерживаемая версия StarRocks для данной доработки — {*}4.xx{*}. Приёмку проводить с учётом окружений заказчика: Dev — StarRocks {{4.01}}, Prod — StarRocks {{4.04}}.

----
h3. 1. Входит в рамки задачи.

* Добавить StarRocks как отдельный тип источника данных на уровне бэкенда, фронтенда и метаданных.
* Обеспечить подключение к StarRocks через MySQL wire-протокол с портом по умолчанию {{9030}}.
* Реализовать отдельную SQL-семантику {{SQL/StarRocks}} для построения запросов платформы.
* Реализовать чтение схемы, таблиц, представлений и полей StarRocks-источника.
* Реализовать StarRocks-специфичный маппинг типов данных во внутренние типы платформы.
* Обеспечить создание наборов данных на базе StarRocks-источника.
* Обеспечить работу предпросмотра, пользовательского SQL-запроса, фильтрации, сортировки, агрегаций, {{GROUP BY}}, {{HAVING}}, вычисляемых полей и производных полей даты.
* Подключить StarRocks к механизму возможностей СУБД, чтобы фронтенд и бэкенд единообразно ограничивали неподдерживаемые функции.
* Провести регрессионную проверку MySQL и других существующих источников данных.

----
h3. 2. Требования к реализации.

---
h4. 2.1. Фронтенд.

* В разделе {*}«Источники» → «Добавить источник»{*} добавить тип подключения {*}StarRocks{*}.
* StarRocks отображается в группе основных SQL/OLAP-источников рядом с PostgreSQL, ClickHouse, MySQL, MS SQL Server и другими в соответствии с принятой сортировкой.
* При выборе StarRocks отображается стандартная карточка SQL-источника с полями: тип подключения, имя источника, отображаемое название, хост БД, порт, имя БД, схема БД, логин, пароль и другие обязательные поля текущей формы.
* Порт по умолчанию для нового StarRocks-источника — {{9030}}, если пользователь не указал иное.
* Кнопка проверки подключения работает для StarRocks и возвращает успешный или ошибочный статус в текущем UX-паттерне.
* В карточке StarRocks-источника скрыты или недоступны: MDX, MDX-сервер, ФВД, отчётные формы, коррекция данных, импорт Excel, стандартный RLS и активность RLS. Доступность элементов определяется через единый механизм.
* В мастере создания набора данных StarRocks-источник доступен как источник аналитических данных.
* В конструкторе ФВД StarRocks не отображается как доступное хранилище.
* В мастере импорта Excel StarRocks не отображается как целевой источник.
* В интерфейсе набора данных корректно отображаются таблицы, поля, типы и ошибки чтения схемы StarRocks.
* Для наборов данных на StarRocks доступны: пользовательский SQL-запрос, предпросмотр, вычисляемые поля, фильтрация и инструмент извлечения частей даты в рамках поддерживаемых возможностей платформы.

---
h4. 2.2. Бэкенд и API.

* Зарегистрировать StarRocks как отдельный тип источника с техническим типом {{starrocks}}.
* Общий транспортный драйвер допустим, но SQL-диалект и маппинг должны выбираться строго по типу {{starrocks}}, без наследования MySQL-логики.
* Для StarRocks реализовать отдельные компоненты: {{drivers/starrocks}}, {{modeltranslator/starrocks}}, {{planbuilder/starrocks}} или их актуальные эквиваленты в структуре кодовой базы.
* Затронутые backend-объекты и сценарии:
** {{connection}} — проверка подключения, включая сценарий нового подключения с {{id = 0}}, если он используется текущим API;
** {{datasources}} — создание, чтение, обновление, список источников с типом {{starrocks}};
** {{datasets}} — создание и использование наборов данных на базе StarRocks-источника;
** {{reports}} / {{reportgroup}} — получение данных для отчётов и визуализаций на StarRocks-наборах;
** {{extraction_rules}} — в сценариях, где платформа использует правила извлечения для чтения StarRocks как внешнего источника.
* Перед обновлением существующего источника бэкенд читает текущее состояние через {{get}}/{{list}} и не затирает параметры, которые пользователь не редактировал.
* Секреты подключения не возвращаются в ответах API и не попадают в тексты ошибок. Пароль изменяется только при явной передаче нового значения; если пароль не менялся — существующее значение сохраняется.
* Ошибки подключения (неверный хост, порт, имя БД, логин, пароль, недоступность кластера, недостаточные права) возвращаются контролируемо.
* Для неподдерживаемых операций StarRocks бэкенд возвращает контролируемую функциональную ошибку, а не пытается выполнить операцию через MySQL-ветку.

---
h4. 2.3. Чтение схемы и метаданных.

* Бэкенд читает список доступных баз/схем, таблиц, представлений и полей StarRocks через {{information_schema}} или поддерживаемый StarRocks-механизм.
* Необходимо различать:
** исходные имена типов из метаданных StarRocks ({{information_schema}});
** имена типов, которые возвращает транспортный драйвер при чтении результата {{SELECT}}.
Логика маппинга не должна полагаться только на один из этих путей.
* Для определения identity-признака нельзя использовать только {{information_schema.COLUMNS.EXTRA}}: в StarRocks он не содержит ожидаемого значения. При необходимости использовать StarRocks-совместимый способ, например {{SHOW CREATE TABLE}}.
* Для каждого поля возвращаются: имя, исходный тип StarRocks, внутренний тип платформы, признак {{nullable}}, порядок полей.
* Пустая схема, отсутствие таблиц, ошибки прав на отдельные объекты не должны приводить к аварийному завершению backend-сервиса.

---
h4. 2.4. Маппинг типов данных.

||Группа типов||Типы StarRocks||Требование||
|Строковые|{{CHAR}}, {{VARCHAR}}, {{STRING}}|Сопоставить с внутренним строковым типом платформы.|
|Числовые|{{TINYINT}}, {{SMALLINT}}, {{INT}}, {{BIGINT}}, {{LARGEINT}}, {{DECIMAL}}, {{NUMERIC}}, {{FLOAT}}, {{DOUBLE}}|Обрабатывать без неконтролируемой потери точности. {{LARGEINT}} не приводить к {{float64}}; если числовое представление невозможно — возвращать строкой.|
|Логический|{{BOOLEAN}}|Сопоставить с внутренним логическим или совместимым типом платформы.|
|Дата и время|{{DATE}}, {{DATETIME}}|Сопоставить с внутренними датовыми типами платформы.|
|Полуструктурированные и аналитические|{{JSON}}, {{ARRAY}}, {{MAP}}, {{STRUCT}}, {{BITMAP}}, {{HLL}}|Обрабатывать предсказуемо: сопоставить с поддерживаемым типом, вернуть строкой или пометить как ограниченно поддерживаемые. Наличие таких полей не должно блокировать работу с остальными полями таблицы.|

---
h4. 2.5. SQL-семантика и генерация запросов.

* Для StarRocks использовать отдельный диалект {{SQL/StarRocks}}. Не использовать MySQL-специфичные функции и конструкции там, где они отсутствуют в StarRocks.
* Генератор должен формировать корректный SQL для: предпросмотра, пользовательского SQL-запроса, фильтрации (включая {{AND}}/{{OR}}, {{NULL}}, пустые значения), сортировки, агрегаций, {{GROUP BY}}, {{HAVING}}, вычисляемых полей и производных полей даты.
* Идентификаторы таблиц и полей экранировать в синтаксисе StarRocks (обратные кавычки, если применимо).
* Приведение к строке: использовать {{CAST(... AS STRING)}}, совместимый со StarRocks.
* Регулярные выражения: использовать оператор {{REGEXP}} StarRocks; не использовать MySQL-функцию {{regexp_like}}, если она не поддерживается целевой версией StarRocks.
* {{LIKE}}: экранировать {{%}}, {{_}}, {{\}} в соответствии с StarRocks-семантикой; не добавлять клаузу {{ESCAPE}}, если она вызывает ошибку StarRocks.
* {{HAVING}}: условия по агрегированным значениям размещать в {{HAVING}}, а не в {{WHERE}}.
* Ошибки SQL возвращать пользователю как контролируемые ошибки без повреждения набора данных и без сброса введённого SQL.

---
h4. 2.6. Производные поля даты.

* Поддерживать те же варианты извлечения частей даты, что доступны для аналогичных SQL-источников: год, квартал, месяц, неделя, день, день недели, год-квартал, год-месяц, год-неделя, год-день и другие варианты, доступные в текущем UI.
* Если интерфейс ожидает русские названия месяцев или дней недели — генерировать значения явно через {{CASE}} по номеру месяца/дня недели. Нельзя полагаться на локаль StarRocks или функции типа {{DATE_FORMAT}} для получения русскоязычных значений.
* Производные датовые поля доступны для предпросмотра, фильтрации, сортировки и построения отчётов.

---
h4. 2.7. DDL и операции записи.

* Если сценарий платформы предполагает создание таблицы-приёмника в StarRocks — использовать StarRocks-совместимый DDL с учётом key-модели и {{DISTRIBUTED BY}}. Не использовать {{ENGINE=InnoDB}}, MySQL-индексы, MySQL-FK, {{AUTO_INCREMENT}} и другие MySQL-конструкции.
* Тихое выполнение операций записи через MySQL-ветку недопустимо.

---
h4. 2.9. Обратная совместимость.

* Добавление StarRocks не изменяет поведение MySQL-источников, их SQL-диалект, маппинг типов и порт по умолчанию.
* PostgreSQL, ClickHouse, MS SQL Server, SQLite, Vertica и другие поддерживаемые источники продолжают работать без изменений.
* Существующие наборы данных и отчёты на других типах источников не требуют миграции.
* Если в системе ранее были технически созданы источники StarRocks через тип {{mysql}}, автоматическая их миграция в рамках данной задачи не предполагается; для штатной работы создаётся новый источник с типом {{starrocks}}.

h3. 5. Критерии приёмки (AC).

*AC-1 — Отображение StarRocks в списке типов подключения:*
* *Дано:* пользователь с правами на создание источников открывает «Источники» и запускает создание нового источника.
* *Когда:* пользователь раскрывает список «Тип подключения».
* *Тогда:* в списке присутствует отдельный пункт StarRocks.
* *И:* StarRocks не заменяет и не переименовывает MySQL, PostgreSQL, ClickHouse и другие существующие типы.

*AC-2 — Создание карточки StarRocks-источника:*
* *Дано:* пользователь выбрал тип подключения StarRocks.
* *Когда:* отображается карточка нового источника.
* *Тогда:* доступны стандартные поля SQL-источника: тип подключения, имя источника, отображаемое название, хост, порт, имя БД, схема БД, логин, пароль и другие обязательные поля формы.
* *И:* порт по умолчанию — {{9030}}, если пользователь не указал иное.

*AC-3 — Сохранение StarRocks как отдельного типа источника:*
* *Дано:* пользователь заполнил карточку валидными параметрами.
* *Когда:* пользователь сохраняет источник.
* *Тогда:* источник сохраняется с типом {{starrocks}}, а не {{mysql}}.
* *И:* последующие операции (чтение схемы, предпросмотр, запросы) используют StarRocks-логику.

*AC-4 — Валидация обязательных параметров подключения:*
* *Дано:* пользователь создаёт или изменяет StarRocks-источник.
* *Когда:* в payload отсутствуют обязательные параметры или переданы значения некорректного формата.
* *Тогда:* API возвращает контролируемую ошибку валидации.
* *И:* текст ошибки позволяет определить поле, требующее исправления, без раскрытия секретов.

*AC-5 — Успешная проверка подключения:*
* *Дано:* StarRocks-источник с корректными параметрами, доступным кластером и валидными учётными данными.
* *Когда:* пользователь запускает проверку подключения.
* *Тогда:* система возвращает успешный статус проверки.
* *И:* проверка не изменяет данные в StarRocks и не требует предварительного создания набора данных.

*AC-6 — Ошибки подключения:*
* *Дано:* параметры содержат ошибку в хосте, порте, имени БД, логине, пароле или кластер недоступен.
* *Когда:* пользователь запускает проверку подключения.
* *Тогда:* API возвращает контролируемую ошибку с диагностическим сообщением.
* *И:* пароль, токены и полная строка подключения не раскрываются в тексте ошибки.

*AC-7 — Ограниченные права пользователя БД:*
* *Дано:* пользователь БД может подключиться, но не имеет прав на чтение части объектов схемы.
* *Когда:* выполняется проверка подключения и чтение метаданных.
* *Тогда:* проверка подключения отрабатывает в соответствии с фактической доступностью БД.
* *И:* ошибки доступа к отдельным объектам возвращаются как контролируемые ошибки без аварийного завершения backend-сервиса.

*AC-8 — Сохранение и повторное открытие StarRocks-источника:*
* *Дано:* пользователь создал StarRocks-источник с валидными параметрами.
* *Когда:* источник сохраняется, закрывается и открывается повторно.
* *Тогда:* источник отображается как StarRocks-источник, несекретные параметры отображаются корректно, пароль не раскрывается.
* *И:* проверка подключения продолжает работать, если пароль не изменялся.

*AC-9 — Редактирование StarRocks-источника:*
* *Дано:* StarRocks-источник создан и используется в наборе данных.
* *Когда:* пользователь меняет несекретные параметры или вводит новый пароль.
* *Тогда:* изменения сохраняются корректно, проверка подключения выполняется по актуальным параметрам.
* *И:* если пароль не менялся — существующее рабочее значение не сбрасывается.

*AC-10 — Недоступность неподдерживаемых функций в карточке StarRocks:*
* *Дано:* пользователь открыл карточку StarRocks-источника.
* *Когда:* отображается карточка источника.
* *Тогда:* настройки MDX, ФВД, отчётных форм, коррекции данных, импорта Excel, стандартного RLS отсутствуют или недоступны.
* *И:* пользователь не может сохранить источник с активными признаками этих функций.

*AC-11 — Backend-валидация недоступных функций:*
* *Дано:* для StarRocks недоступны RLS, ФВД, отчётные формы, коррекция данных, MDX, импорт Excel.
* *Когда:* через прямой API-вызов или подмену payload выполняется попытка включить недоступную функцию.
* *Тогда:* бэкенд возвращает контролируемую функциональную ошибку.
* *И:* недоступная функция не сохраняется в метаданных источника, источник остаётся в консистентном состоянии.

*AC-12 — Чтение списка таблиц и представлений:*
* *Дано:* StarRocks-источник подключён, в доступной схеме есть таблицы и представления.
* *Когда:* платформа запрашивает метаданные источника.
* *Тогда:* бэкенд возвращает список доступных объектов в формате, совместимом с мастером набора данных.
* *И:* недоступные по правам объекты не приводят к падению операции чтения всей схемы.

*AC-13 — Чтение полей таблицы:*
* *Дано:* таблица StarRocks содержит поля разных типов, nullable-поля, заданный порядок следования.
* *Когда:* платформа запрашивает структуру таблицы.
* *Тогда:* бэкенд возвращает имена полей, исходные типы StarRocks, внутренние типы платформы, признаки {{nullable}} и порядок полей.
* *И:* порядок полей соответствует метаданным StarRocks.

*AC-14 — Пустая схема и отсутствие прав:*
* *Дано:* подключение успешно, но в схеме нет таблиц или нет прав на их чтение.
* *Когда:* платформа запрашивает список таблиц.
* *Тогда:* API возвращает корректный пустой результат или понятную ошибку доступа.
* *И:* операция не завершается технической ошибкой сервера.

*AC-15 — Маппинг строковых типов:*
* *Дано:* таблица содержит поля {{CHAR}}, {{VARCHAR}}, {{STRING}}.
* *Когда:* бэкенд читает метаданные и выполняет предпросмотр.
* *Тогда:* строковые поля сопоставляются с внутренним строковым типом платформы.
* *И:* значения на кириллице, латинице, со спецсимволами, пустые строки и {{NULL}} возвращаются без искажения.

*AC-16 — Маппинг числовых типов:*
* *Дано:* таблица содержит поля {{TINYINT}}, {{SMALLINT}}, {{INT}}, {{BIGINT}}, {{DECIMAL}}, {{FLOAT}}, {{DOUBLE}}.
* *Когда:* бэкенд читает метаданные и выполняет запросы.
* *Тогда:* поля сопоставляются с корректными внутренними типами платформы.
* *И:* целые, дробные, отрицательные значения и значения с заданной точностью возвращаются без потери в пределах поддерживаемой точности платформы.

*AC-17 — Безопасная обработка {{LARGEINT}}:*
* *Дано:* таблица содержит поле {{LARGEINT}} со значением за пределами безопасного диапазона {{int64}}/{{float64}}.
* *Когда:* бэкенд выполняет предпросмотр или запрос набора данных.
* *Тогда:* значение не преобразуется в {{float64}} с потерей точности.
* *И:* значение возвращается в безопасном согласованном представлении (например, строкой), а метаданные поля позволяют фронтенду обработать его без искажения.

*AC-18 — Маппинг {{BOOLEAN}}:*
* *Дано:* таблица содержит поле {{BOOLEAN}}.
* *Когда:* бэкенд читает метаданные и выполняет предпросмотр.
* *Тогда:* поле сопоставляется с внутренним логическим или совместимым типом платформы.
* *И:* значения {{true}}/{{false}} и {{NULL}} возвращаются без искажения.

*AC-19 — Маппинг дата/время:*
* *Дано:* таблица содержит поля {{DATE}} и {{DATETIME}}.
* *Когда:* бэкенд читает метаданные, выполняет предпросмотр и запросы.
* *Тогда:* поля сопоставляются с внутренними датовыми типами платформы.
* *И:* значения отображаются и фильтруются без синтаксических ошибок SQL.

*AC-20 — Обработка сложных и ограниченно поддерживаемых типов:*
* *Дано:* таблица содержит поля {{JSON}}, {{ARRAY}}, {{MAP}}, {{STRUCT}}, {{BITMAP}}, {{HLL}}.
* *Когда:* бэкенд читает метаданные и выполняет предпросмотр.
* *Тогда:* такие поля обрабатываются предсказуемо: сопоставляются с поддерживаемым внутренним типом, возвращаются строкой или помечаются как ограниченно поддерживаемые.
* *И:* наличие таких полей не блокирует работу с поддерживаемыми полями таблицы.

*AC-21 — Корректное экранирование идентификаторов:*
* *Дано:* таблицы или поля StarRocks имеют имена со смешанным регистром, зарезервированными словами или допустимыми спецсимволами.
* *Когда:* платформа строит запросы предпросмотра, фильтрации, сортировки или агрегации.
* *Тогда:* бэкенд формирует синтаксически корректный SQL в диалекте StarRocks.
* *И:* запрос выполняется без ошибок из-за некорректного экранирования.

*AC-22 — Предпросмотр таблицы StarRocks:*
* *Дано:* создан StarRocks-источник и выбрана таблица с поддерживаемыми полями.
* *Когда:* пользователь запускает предпросмотр.
* *Тогда:* бэкенд формирует корректный SQL в диалекте StarRocks и возвращает ограниченную выборку.
* *И:* предпросмотр корректно работает для таблиц с разными типами, для пустых таблиц и таблиц с {{NULL}}-значениями.

*AC-23 — Пользовательский SQL-запрос в наборе данных:*
* *Дано:* аналитик создаёт набор данных на StarRocks-источнике с корректным SQL-запросом.
* *Когда:* выполняется проверка/сохранение запроса и предпросмотр.
* *Тогда:* запрос выполняется на StarRocks, результат возвращается в платформу, поля получают корректные имена и типы.

*AC-24 — Ошибка пользовательского SQL:*
* *Дано:* аналитик указывает SQL с синтаксической ошибкой, несуществующей таблицей/полем или нарушением прав.
* *Когда:* выполняется проверка или предпросмотр.
* *Тогда:* API возвращает контролируемую ошибку.
* *И:* ошибка не падает в 500, не очищает введённый SQL и не блокирует последующие корректные запросы к источнику.

*AC-25 — Сохранение и повторное открытие набора данных:*
* *Дано:* создан набор данных на StarRocks-источнике с таблицей или пользовательским SQL.
* *Когда:* набор данных сохраняется, закрывается и открывается повторно.
* *Тогда:* связь с источником, SQL-запрос, список и типы полей сохраняются.
* *И:* повторный предпросмотр выполняется без пересоздания источника.

*AC-26 — Фильтрация по строковым, числовым и датовым полям:*
* *Дано:* набор данных StarRocks содержит строковые, числовые и датовые поля.
* *Когда:* пользователь применяет фильтры по одному полю каждого типа.
* *Тогда:* бэкенд формирует корректные условия SQL для StarRocks.
* *И:* результат содержит только записи, соответствующие фильтру; пустой результат возвращается как пустой набор без технической ошибки.

*AC-27 — Комбинированная фильтрация (AND / OR):*
* *Дано:* набор данных содержит несколько полей разных типов.
* *Когда:* применяются несколько фильтров одновременно с условиями {{AND}}/{{OR}}.
* *Тогда:* бэкенд формирует корректный SQL для StarRocks.
* *И:* итоговая выборка соответствует ожидаемому результату по тестовым данным.

*AC-28 — Фильтрация по NULL и пустым значениям:*
* *Дано:* таблица содержит строки с {{NULL}} и пустыми значениями в разных типах полей.
* *Когда:* применяются фильтры на пустые/{{NULL}}-значения и фильтры, их исключающие.
* *Тогда:* бэкенд формирует корректный SQL с учётом различия {{NULL}} и пустой строки.
* *И:* результат соответствует ожидаемой выборке.

*AC-29 — Экранирование спецсимволов в LIKE:*
* *Дано:* таблица содержит строковые значения с символами {{%}}, {{_}}, {{\\}}.
* *Когда:* пользователь применяет фильтр частичного совпадения по таким значениям.
* *Тогда:* бэкенд формирует корректное условие {{LIKE}} для StarRocks.
* *И:* спецсимволы ищутся как обычные символы; SQL не содержит клаузы {{ESCAPE}}, вызывающей ошибку StarRocks.

*AC-30 — Регулярные выражения в StarRocks-диалекте:*
* *Дано:* фильтр или вычисляемое поле требует проверки строки регулярным выражением.
* *Когда:* бэкенд строит SQL для StarRocks.
* *Тогда:* используется оператор {{REGEXP}}, поддерживаемый StarRocks.
* *И:* MySQL-функция {{regexp_like}} не используется, если она не поддерживается целевой версией StarRocks.

*AC-31 — Агрегации и GROUP BY:*
* *Дано:* набор данных содержит поля для группировки и расчёта агрегатов.
* *Когда:* отчёт или предпросмотр запрашивает {{COUNT}}, {{SUM}}, {{AVG}}, {{MIN}}, {{MAX}} с группировкой.
* *Тогда:* бэкенд формирует корректный SQL с {{GROUP BY}} для StarRocks.
* *И:* результат агрегации соответствует данным в StarRocks.

*AC-32 — HAVING для агрегированных условий:*
* *Дано:* запрос к StarRocks-набору использует фильтр по агрегированному значению.
* *Когда:* выполняется запрос с агрегацией.
* *Тогда:* условие по агрегату размещается в {{HAVING}}, а не в {{WHERE}}.
* *И:* результат соответствует ожидаемой выборке.

*AC-33 — Сортировка:*
* *Дано:* набор данных содержит поля разных типов.
* *Когда:* запрос использует сортировку по строковому, числовому, датовому или вычисляемому полю.
* *Тогда:* бэкенд формирует корректный {{ORDER BY}} для StarRocks.
* *И:* порядок строк соответствует заданному направлению сортировки.

*AC-34 — Вычисляемые поля:*
* *Дано:* в наборе данных создано вычисляемое поле на основе строковых, числовых или датовых полей.
* *Когда:* выполняется предпросмотр или построение отчёта.
* *Тогда:* выражение транслируется в синтаксис StarRocks и рассчитывается на стороне БД.
* *И:* вычисляемое поле доступно в ответе платформы.

*AC-35 — Ошибка в вычисляемом поле:*
* *Дано:* вычисляемое поле содержит некорректное выражение или несовместимые типы.
* *Когда:* выполняется предпросмотр или построение отчёта.
* *Тогда:* API возвращает контролируемую ошибку выполнения.
* *И:* ошибка не повреждает источник и не блокирует работу с другими полями набора.

*AC-36 — Производные поля даты:*
* *Дано:* набор данных StarRocks содержит поле дата/дата-время.
* *Когда:* пользователь создаёт производные поля через инструмент извлечения частей даты.
* *Тогда:* для StarRocks корректно работают все варианты, доступные в текущем UI (год, квартал, месяц, неделя, день, день недели, год-квартал, год-месяц, год-неделя, год-день и другие).
* *И:* значения возвращаются в ожидаемых форматах.

*AC-37 — Русские названия месяцев и дней недели:*
* *Дано:* производные поля даты должны возвращать название или сокращённое название месяца/дня недели.
* *Когда:* выполняется предпросмотр или построение отчёта.
* *Тогда:* значения возвращаются на русском языке через явную генерацию SQL (например, через {{CASE}} по номеру).
* *И:* результат не зависит от локали StarRocks.

*AC-38 — Фильтрация и сортировка по производным датовым полям:*
* *Дано:* в наборе создано производное поле даты (год, месяц, неделя, год-месяц и др.).
* *Когда:* пользователь применяет фильтр или сортировку по производному датовому полю.
* *Тогда:* бэкенд формирует корректный SQL для StarRocks.
* *И:* фильтрация по исходному и производному датовым полям не конфликтуют.

*AC-39 — Построение отчёта на StarRocks-наборе данных:*
* *Дано:* создан и сохранён набор данных на базе StarRocks-источника.
* *Когда:* пользователь строит отчёт/визуализацию на его основе.
* *Тогда:* портал получает данные из StarRocks без SQL-ошибок.
* *И:* базовые сценарии отчёта, фильтрации и отображения данных возвращают ожидаемые значения.

*AC-40 — StarRocks недоступен в конструкторе ФВД:*
* *Дано:* в системе есть сохранённый StarRocks-источник.
* *Когда:* пользователь открывает конструктор ФВД и выбирает хранилище.
* *Тогда:* StarRocks-источник отсутствует в списке доступных хранилищ.
* *И:* пользователь не может создать ФВД-таблицу на базе StarRocks.

*AC-41 — StarRocks недоступен в мастере импорта Excel:*
* *Дано:* в системе есть сохранённый StarRocks-источник.
* *Когда:* пользователь открывает сценарий импорта Excel.
* *Тогда:* StarRocks-источник недоступен как целевой источник.

*AC-42 — Контролируемое поведение операций записи и DDL:*
* *Дано:* через API или интерфейс запускается сценарий создания таблицы, массовой загрузки или записи данных в StarRocks.
* *Когда:* такой сценарий не поддержан в текущем релизе.
* *Тогда:* система возвращает контролируемую ошибку о неподдерживаемой операции для типа {{starrocks}}.
* *И:* система не выполняет операцию через MySQL-DDL или MySQL-ветку записи.

*AC-43 — Регрессия: MySQL-источник:*
* *Дано:* в системе есть существующий MySQL-источник и набор данных на его базе.
* *Когда:* выполняются сценарии подключения, чтения схемы, предпросмотра, фильтрации, агрегации, вычисляемых и производных датовых полей.
* *Тогда:* поведение MySQL не изменилось, MySQL-источник продолжает сохраняться и использоваться с типом {{mysql}}.
* *И:* MySQL не получает StarRocks-специфичных правил генерации SQL.

*AC-44 — Регрессия: прочие типы источников:*
* *Дано:* в системе есть источники PostgreSQL, ClickHouse, MS SQL Server, SQLite, Vertica и другие.
* *Когда:* выполняются существующие сценарии подключения, чтения схемы, предпросмотра, фильтрации, агрегации и построения отчётов.
* *Тогда:* добавление StarRocks не меняет их поведение, маппинг типов, SQL-генерацию и обработку ошибок.

*AC-45 — Права пользователя портала:*
* *Дано:* пользователь не имеет прав на создание или редактирование источников данных.
* *Когда:* пользователь открывает раздел «Источники» или карточку StarRocks-источника.
* *Тогда:* действия создания, редактирования, проверки подключения и сохранения ограничены так же, как для других типов источников.
* *И:* добавление StarRocks не создаёт обхода существующей модели прав.

----
h3. 6. Допущения.

* StarRocks используется в данной доработке как внешний OLAP-источник для аналитических выборок, наборов данных, отчётов и визуализаций.
* Транспортное подключение может переиспользовать MySQL wire-драйвер, но это не означает переиспользования MySQL-диалекта и MySQL-логики.
* Конкретные имена backend-компонентов и структура capability-флагов определяются по текущей реализации платформы; в постановке зафиксирована требуемая логика, а не жёсткий API-контракт.
* Если в тестовом окружении недоступны сложные типы ({{JSON}}, {{ARRAY}}, {{MAP}}, {{STRUCT}}, {{BITMAP}}, {{HLL}}), соответствующие AC проверяются в той мере, в которой позволяет окружение.
