Доработать форму источника данных для скрытия полей, кнопок, переключателей для различных типов СУБД

h3. Контекст и цель.

В рамках расширения возможностей Портала и ETL-контура необходимо обновить интерфейс работы с источниками данных так, чтобы пользователю был доступен {*}MySQL{*}-источник, а форма карточки источника и связанные мастера динамически отображали только поддерживаемые для данной СУБД элементы.

Также требуется реализовать {*}универсальный механизм передачи возможностей СУБД{*} от бэкенда к фронтенду, чтобы UI мог скрывать или отображать элементы в зависимости от типа источника, а бэкенд — валидировать API-вызовы для недоступных функций.

На текущем этапе базовый функционал для MySQL должен быть доступен, а *RLS, Формы ввода данных (ФВД), импорт из Excel, MDX и другие нерелевантные настройки* должны быть скрыты.

----

h3. 1. Бизнес требования.

h4. 1.1. Добавление типа подключения MySQL в интерфейсе источников.
В разделе {*}«Источники» → «Добавить источник»{*}:

* В выпадающий список «Тип подключения» добавить пункт {*}MySQL{*}.
* *Позиция в списке:* MySQL должен располагаться в верхней группе основных СУБД — примерный порядок:
  ** PostgreSQL, ClickHouse, MySQL, MS SQL Server, SQLite и т.д.
* Для MySQL отображать стандартный набор полей подключения:
  ** {{{}Тип подключения{}}},
  ** {{{}Имя источника{}}},
  ** {{Отображаемое название}},
  ** {{{}Хост БД{}}},
  ** {{{}Порт{}}},
  ** {{{}Имя БД{}}},
  ** {{{}Схема БД{}}},
  ** {{{}Логин подключения к БД{}}},
  ** {{{}Пароль подключения к БД{}}},
  ** {{URL БД}} и т.д.
* Кнопка *«Проверить» подключение* должна корректно работать для MySQL.

h4. 1.2. Ограничение нерелевантных настроек в карточке источника.
Так как ряд функций платформы для MySQL на текущем этапе не поддерживается, соответствующие настройки в карточке MySQL-источника должны быть *убраны* (недоступны для взаимодействия и не видны):

||Настройка||Поведение для MySQL||
|MDX-сервер|Убрать|
|MDX|Убрать|
|Формы ввода данных|Убрать|
|Отчётные формы|Убрать|
|Коррекция данных|Убрать|
|Импорт из Excel|Убрать|
|Дополнительные опции (все)|Убрать|
|Поддержка RLS|Убрать|
|Активность RLS|Убрать|
|ФВД/Отчётные формы|Убрать|

Форма карточки источника должна динамически перестраиваться в зависимости от выбранного типа СУБД: при переключении типа подключения в выпадающем списке форма показывает только релевантные поля.

h4. 1.3. Создание набора данных на основе MySQL-источника.
Аналитик должен иметь возможность создавать набор данных, выбирая MySQL-источник, с полноценной поддержкой базового рабочего сценария:

* В мастере создания набора данных "MySQL-источник" доступен для выбора.
* В редакторе набора данных работает консоль SQL-запросов с предпросмотром данных.
* Список таблиц и полей источника корректно отображается в UI (подтягивается схема БД).
* *Настройки RLS* внутри набора данных не отображаются (поведение наследуется из настроек источника, где RLS отключён).

h4. 1.4. Поддержка фильтрации и вычисляемых полей в UI.

* Фильтрация в дашбордах и отчётах по полям из MySQL-источника должна работать корректно.
* Вычисляемые поля, созданные в наборе данных, должны корректно отображаться и использоваться в интерфейсе.

h4. 1.5. Полноценная поддержка преобразования дат.
В наборах данных есть инструмент извлечения частей даты («шестерёнка» рядом с полем типа {*}Дата{*}).
Этот функционал должен полностью работать для MySQL-источника: платформа должна транслировать UI-выбор аналитика в синтаксически корректный SQL-запрос для MySQL.

Набор вариантов и форматов дат должен полностью соответствовать текущей реализации для PostgreSQL — пользователь не должен замечать разницы в поведении при переключении между типами источников.

h4. 1.6. Системные ограничения (ФВД и загрузка из Excel).

* *ФВД:* при создании новой формы ввода данных в разделе «ФВД» MySQL-источник *не должен отображаться* в выпадающем списке выбора хранилища.
* *Загрузка из Excel:* в мастере импорта файлов Excel MySQL-источник {*}не должен быть доступен для выбора{*}.
* Настройка «Импорт из Excel» в карточке источника для MySQL недоступна.

----

h3. 2. Технические требования.

h4. 2.1. Механизм передачи возможностей СУБД.

* Бэкенд должен предоставлять фронтенду структуру с набором флагов/параметров для каждого типа СУБД — какие функции доступны для данного источника.
* Набор возможностей должен быть универсальным и пригодным для любых СУБД и других источников.
* На основе этих данных фронтенд должен динамически отображать или скрывать соответствующие элементы UI в карточке источника и наборе данных.

h4. 2.2. Адаптация API-вызовов под возможности источника.

* Бэкенд должен использовать тот же набор флагов при валидации API-вызовов.
* Запросы к недоступным для MySQL функциям должны возвращать корректную ошибку.
* Механизм должен быть унифицированным и применяться не только к MySQL, но и к другим СУБД.

h4. 2.3. Сортировка типов подключений.

* Скорректировать порядок сортировки типов подключений в списке «Источники» в соответствии с п. 1.1.
* MySQL должен отображаться в верхней группе основных СУБД.

h4. 2.4. Нефункциональные требования.

* Поведение UI должно быть согласовано с backend-флагами доступности функций.
* При переключении типа источника форма должна обновляться без отображения недоступных элементов.
* Ограничения должны соблюдаться как в UI, так и на уровне API.

----

h3. 3. Критерии приёмки (AC):

Перед выполнением приёмки должны быть подготовлены:
* пользователь с правами на создание и редактирование источников данных;
* пользователь без прав на создание/редактирование источников для проверки ограничений доступа;
* валидный MySQL-сервер с тестовой схемой и таблицами;
* MySQL-источник с корректными параметрами подключения;
* MySQL-источник с некорректными параметрами подключения для проверки ошибок;
* существующие источники PostgreSQL, MS SQL Server, SQLite, ClickHouse или других поддерживаемых типов для регрессионной проверки формы;
* тестовые наборы данных на MySQL-источнике со строковыми, числовыми и датовыми полями.

AC-1 — *Отображение MySQL в списке типов подключения:*
* *Дано:* пользователь открывает раздел «Источники» и запускает создание нового источника.
* *Когда:* пользователь раскрывает список «Тип подключения».
* *Тогда:* в списке присутствует пункт MySQL.
* *И:* MySQL расположен в верхней группе основных СУБД рядом с PostgreSQL, ClickHouse, MS SQL Server и SQLite в соответствии с принятой сортировкой. Добавление MySQL не удаляет и не переименовывает ранее доступные типы подключений.

AC-2 — *Создание карточки MySQL-источника:*
* *Дано:* пользователь выбрал тип подключения MySQL.
* *Когда:* отображается карточка нового источника.
* *Тогда:* пользователю доступны стандартные поля подключения, необходимые для MySQL: тип подключения, имя источника, отображаемое название, хост БД, порт, имя БД, схема БД, логин, пароль и другие обязательные поля текущей формы подключения.
* *И:* обязательные поля визуально определены и валидируются до сохранения или проверки подключения, карточка не содержит элементов, не относящихся к MySQL на текущем этапе.

AC-3 — *Валидация обязательных полей карточки:*
* *Дано:* пользователь создаёт или редактирует MySQL-источник.
* *Когда:* пользователь оставляет обязательные поля пустыми или вводит значения некорректного формата.
* *Тогда:* интерфейс отображает контролируемые сообщения валидации.
* *И:* источник не сохраняется с некорректными обязательными параметрами, а пользователь может исправить значения без закрытия карточки.

AC-4 — *Проверка успешного подключения из карточки источника:*
* *Дано:* в карточке MySQL-источника заполнены корректные параметры подключения.
* *Когда:* пользователь нажимает кнопку проверки подключения.
* *Тогда:* система выполняет проверку подключения к MySQL.
* *И:* пользователю отображается успешный результат проверки, после успешной проверки источник можно сохранить и использовать для создания набора данных.

AC-5 — *Проверка ошибки подключения из карточки источника:*
* *Дано:* в карточке MySQL-источника указан неверный хост, порт, логин, пароль, имя БД или недоступный сервер.
* *Когда:* пользователь нажимает кнопку проверки подключения.
* *Тогда:* пользователю отображается ошибка подключения в понятном виде.
* *И:* пароль, токены и полная строка подключения с секретами не отображаются в тексте ошибки. Форма остаётся доступной для исправления параметров без пересоздания источника.

AC-6 — *Сохранение и повторное открытие MySQL-источника:*
* *Дано:* пользователь создал MySQL-источник с валидными параметрами.
* *Когда:* пользователь сохраняет источник, закрывает карточку и открывает её повторно.
* *Тогда:* источник отображается как MySQL-источник.
* *И:* несекретные параметры отображаются корректно. Пароль не раскрывается в открытом виде, но источник продолжает работать, если пароль не изменялся.

AC-7 — *Редактирование MySQL-источника:*
* *Дано:* MySQL-источник уже создан и используется в наборе данных.
* *Когда:* пользователь меняет несекретные параметры подключения или вводит новый пароль через защищённое поле.
* *Тогда:* изменения сохраняются корректно.
* *И:* проверка подключения выполняется по актуальным параметрам. Если пароль не менялся, сохранение карточки не сбрасывает существующий рабочий пароль.

AC-8 — *Отсутствие RLS-настроек в карточке MySQL-источника:*
* *Дано:* пользователь выбрал или открыл MySQL-источник.
* *Когда:* отображается карточка источника.
* *Тогда:* настройки поддержки RLS и активности RLS визуально отсутствуют в карточке MySQL-источника.
* *И:* пользователь не может включить стандартный RLS для MySQL через интерфейс - при сохранении MySQL-источника признаки RLS не передаются как активные и не сохраняются в метаданных источника.

AC-9 — *Отсутствие настроек ФВД и отчётных форм в карточке MySQL-источника:*
* *Дано:* пользователь выбрал или открыл MySQL-источник.
* *Когда:* отображается карточка источника.
* *Тогда:* настройки ФВД, отчётных форм и связанных с ними возможностей визуально отсутствуют.
* *И:* пользователь не может сохранить MySQL-источник как источник, поддерживающий ФВД или отчётные формы.

AC-10 — *Отсутствие коррекции данных и импорта из Excel:*
* *Дано:* пользователь выбрал или открыл MySQL-источник.
* *Когда:* отображается карточка источника.
* *Тогда:* настройки коррекции данных и импорта из Excel визуально отсутствуют.
* *И:* сохранение источника не создаёт признаков, позволяющих использовать MySQL-источник для коррекции данных или загрузки Excel-файлов.

AC-11 — *Отсутствие MDX и нерелевантных дополнительных опций:*
* *Дано:* пользователь выбрал или открыл MySQL-источник.
* *Когда:* отображается карточка источника.
* *Тогда:* настройки MDX, MDX-сервера и нерелевантные дополнительные опции визуально отсутствуют.
* *И:* пользователь не может включить для MySQL функции, которые на текущем этапе не поддержаны.

AC-12 — *Динамическая перестройка формы при переключении на MySQL:*
* *Дано:* пользователь находится в форме создания источника и выбран тип подключения, для которого отображаются дополнительные настройки.
* *Когда:* пользователь переключает тип подключения на MySQL.
* *Тогда:* форма перестраивается под MySQL без необходимости сохранять промежуточный источник.
* *И:* отображаются только применимые для MySQL поля подключения, а ранее включённые для другого типа источника неподдерживаемые опции не остаются активными для MySQL.

AC-13 — *Динамическая перестройка формы при переключении с MySQL на другой тип:*
* *Дано:* пользователь находится в форме источника с выбранным типом MySQL.
* *Когда:* пользователь переключает тип подключения на PostgreSQL, MS SQL Server, SQLite, ClickHouse или другой поддерживаемый тип.
* *Тогда:* форма перестраивается под выбранный тип источника.
* *И:* доступность полей и опций соответствует возможностям выбранной СУБД, поведение формы для существующих типов источников не ухудшается из-за добавления MySQL.

AC-14 — *Согласованность payload при сохранении MySQL-источника:*
* *Дано:* пользователь сохраняет карточку MySQL-источника.
* *Когда:* frontend формирует payload создания или обновления источника.
* *Тогда:* payload содержит параметры подключения MySQL и не содержит активных признаков RLS, ФВД, отчётных форм, коррекции данных, MDX и импорта из Excel.
* *И:* секреты передаются только в рамках защищённого ввода и не отображаются в интерфейсе после сохранения.

AC-15 — *Получение возможностей СУБД от бэкенда:*
* *Дано:* frontend запрашивает данные, необходимые для построения формы источника и связанных мастеров.
* *Когда:* бэкенд возвращает информацию по типам источников.
* *Тогда:* для MySQL возвращается набор признаков доступных и недоступных функций.
* *И:* признаки позволяют определить доступность RLS, ФВД, отчётных форм, коррекции данных, MDX, импорта из Excel, SQL-редактора, предпросмотра и создания набора данных.

AC-16 — *Использование возможностей СУБД на фронтенде:*
* *Дано:* бэкенд возвращает для MySQL признаки доступных и недоступных функций.
* *Когда:* frontend строит карточку источника, мастер набора данных, список источников для ФВД и список источников для импорта Excel.
* *Тогда:* интерфейс использует эти признаки и не показывает/не активирует недоступные для MySQL функции.
* *И:* базовые доступные функции MySQL остаются доступны пользователю.

AC-17 — *Backend-валидация недоступных функций:*
* *Дано:* для MySQL недоступны RLS, ФВД, отчётные формы, коррекция данных, MDX и импорт из Excel.
* *Когда:* через ручную подмену frontend-состояния или прямой API-вызов выполняется попытка включить недоступную функцию для MySQL.
* *Тогда:* бэкенд возвращает контролируемую функциональную ошибку.
* *И:* недоступная функция не сохраняется в метаданных источника, источник остаётся в консистентном состоянии.

AC-18 — *Выбор MySQL-источника в мастере набора данных:*
* *Дано:* в системе создан и сохранён валидный MySQL-источник.
* *Когда:* пользователь создаёт набор данных и выбирает источник данных.
* *Тогда:* MySQL-источник доступен для выбора в мастере набора данных.
* *И:* выбор MySQL-источника не приводит к ошибкам интерфейса и позволяет перейти к настройке запроса или выбору таблиц в рамках текущего сценария платформы.

AC-19 — *Отображение схемы MySQL в наборе данных:*
* *Дано:* выбран MySQL-источник с доступными таблицами и полями.
* *Когда:* пользователь открывает мастер набора данных или редактор SQL.
* *Тогда:* список таблиц и полей MySQL-источника отображается в интерфейсе.
* *И:* названия таблиц и полей соответствуют метаданным MySQL. Пустая схема или отсутствие прав на таблицы отображаются как контролируемое состояние/ошибка, а не как зависание или падение интерфейса.

AC-20 — *SQL-редактор набора данных:*
* *Дано:* пользователь создаёт набор данных на базе MySQL-источника.
* *Когда:* пользователь вводит корректный SQL-запрос к MySQL-таблице и запускает проверку/предпросмотр.
* *Тогда:* запрос выполняется, предпросмотр возвращает данные, а набор данных можно сохранить.
* *И:* при синтаксической ошибке SQL пользователь получает понятное сообщение об ошибке без потери введённого текста запроса.

AC-21 — *Сохранение и повторное открытие MySQL-набора данных:*
* *Дано:* пользователь настроил набор данных на базе MySQL-источника и получил корректный предпросмотр.
* *Когда:* пользователь сохраняет набор данных и открывает его повторно.
* *Тогда:* набор данных сохраняет связь с MySQL-источником, SQL-запрос, поля и типы данных.
* *И:* повторный предпросмотр после открытия возвращает данные без необходимости пересоздавать набор данных.

AC-22 — *Отсутствие RLS-настроек в наборе данных MySQL:*
* *Дано:* пользователь создаёт или редактирует набор данных на базе MySQL-источника.
* *Когда:* отображаются настройки набора данных.
* *Тогда:* настройки стандартного RLS для такого набора данных визуально отсутствуют.
* *И:* пользователь не может сохранить MySQL-набор данных с активным стандартным RLS.

AC-23 — *Работа фильтрации по данным MySQL в интерфейсе:*
* *Дано:* создан набор данных на базе MySQL-источника и отчёт/визуализация на его основе.
* *Когда:* пользователь применяет фильтры по строковым, числовым и датовым полям.
* *Тогда:* данные в отчёте фильтруются согласно выбранным значениям.
* *И:* пустой результат фильтрации отображается корректно и не приводит к ошибке визуализации.

AC-24 — *Работа вычисляемых полей в интерфейсе:*
* *Дано:* пользователь создаёт вычисляемое поле в наборе данных на базе MySQL-источника.
* *Когда:* пользователь запускает предпросмотр набора данных или строит отчёт с этим полем.
* *Тогда:* вычисляемое поле отображается в списке полей и возвращает рассчитанные значения.
* *И:* ошибка в формуле вычисляемого поля отображается пользователю как контролируемая ошибка и не ломает набор данных целиком.

AC-25 — *Инструмент извлечения частей даты:*
* *Дано:* в наборе данных MySQL есть поле типа «Дата» или «Дата-время».
* *Когда:* пользователь открывает инструмент извлечения частей даты рядом с полем.
* *Тогда:* инструмент доступен для датового поля.
* *И:* пользователь может создать производные поля даты в тех вариантах, которые доступны для PostgreSQL: год, квартал, месяц, неделя, день, день недели, год-квартал, год-месяц, год-неделя, год-день и другие поддержанные варианты.

AC-26 — *Форматы производных датовых полей:*
* *Дано:* пользователь создаёт производные поля даты для MySQL-набора данных.
* *Когда:* выбраны строковые и числовые форматы отображения, например год числом, месяц числом, месяц названием, сокращённый месяц, квартал числом или строкой, год-месяц.
* *Тогда:* значения производных полей отображаются в тех же смысловых форматах, что и для аналогичного набора данных PostgreSQL.
* *И:* производные поля доступны для предпросмотра, отчётов и фильтрации в рамках текущих возможностей платформы.

AC-27 — *MySQL-источник недоступен при создании ФВД-таблицы:*
* *Дано:* в системе есть сохранённый MySQL-источник.
* *Когда:* пользователь открывает конструктор ФВД и выбирает хранилище/источник для создания таблицы ФВД.
* *Тогда:* MySQL-источник отсутствует в списке доступных хранилищ/источников для ФВД.
* *И:* пользователь не может создать ФВД-таблицу на базе MySQL-источника.

AC-28 — *MySQL-источник недоступен в мастере импорта Excel:*
* *Дано:* в системе есть сохранённый MySQL-источник.
* *Когда:* пользователь открывает сценарий загрузки/импорта файлов Excel в БД.
* *Тогда:* MySQL-источник недоступен для выбора как целевой источник/хранилище.
* *И:* пользователь не может запустить импорт Excel в MySQL-источник через текущий механизм платформы.

AC-29 — *Поведение при ошибке backend-флагов возможностей:*
* *Дано:* frontend не получил признаки возможностей источника или получил ошибку при их загрузке.
* *Когда:* пользователь открывает форму создания или редактирования источника.
* *Тогда:* интерфейс не показывает пользователю недостоверно доступные функции для MySQL.
* *И:* пользователь получает контролируемое состояние загрузки/ошибки в соответствии с текущими UI-паттернами портала. Недоступные функции не могут быть включены до получения валидных данных о возможностях источника.

AC-30 — *Регрессия по существующим типам источников:*
* *Дано:* в системе есть существующие источники PostgreSQL, MS SQL Server, SQLite, ClickHouse или другие поддерживаемые типы.
* *Когда:* пользователь открывает их карточки, проверяет подключение, создаёт набор данных и использует ранее доступные настройки.
* *Тогда:* поведение существующих типов источников не меняется из-за добавления MySQL и механизма возможностей СУБД.
* *И:* настройки, которые были доступны для других типов источников до доработки, остаются доступными в соответствии с их текущими возможностями.

AC-31 — *Проверка прав пользователя в интерфейсе источников:*
* *Дано:* пользователь не имеет прав на создание или редактирование источников данных.
* *Когда:* пользователь открывает раздел «Источники» или карточку существующего MySQL-источника.
* *Тогда:* действия создания, редактирования, проверки подключения и сохранения ограничены так же, как для других типов источников.
* *И:* добавление MySQL не создаёт обхода существующей модели прав.

AC-32 — *Достаточность проверки перед релизом:*
* *Дано:* функциональность формы источника и MySQL-источника передана на релизную проверку.
* *Когда:* тестировщик выполняет проверку по критериям AC-1 — AC-31.
* *Тогда:* MySQL можно добавить как источник, проверить подключение, сохранить, открыть повторно, использовать для создания набора данных, выполнить SQL-запрос, получить предпросмотр, использовать фильтрацию, вычисляемые поля и производные поля даты.
* *И:* неподдерживаемые сценарии RLS, ФВД, отчётных форм, коррекции данных, MDX и импорта Excel недоступны пользователю и не могут быть включены обходным путём через UI/API.
