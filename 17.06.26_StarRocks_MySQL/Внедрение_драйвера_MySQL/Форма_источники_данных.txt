h3. Контекст и проблематика.

Сейчас форма создания и редактирования источника данных отображает одинаковый набор параметров для разных типов подключений. В результате пользователю доступны поля и функции, которые не участвуют в настройке выбранного источника.

Требуется сохранить текущий визуальный стиль формы, но сделать состав её полей и дополнительных опций актуальным для выбранного типа подключения.

----

h3. Цель задачи.

*Требуется:*

# Реализовать единую форму создания и редактирования источников данных, которая динамически отображает только применимые к выбранному типу подключения поля и функции.
# Ограничить список типов подключения утверждёнными вариантами и зафиксировать их порядок.
# Исключить из формы неиспользуемые поля {{URL БД}}, {{MDX-сервер}} и {{MDX}}.
# Сохранить текущую компоновку, цветовую палитру, стили элементов и действующую логику поддерживаемых настроек.

_Как пользователь аналитического портала, я хочу видеть в форме управления источниками данных только параметры применимые для выбранного типа подключения, чтобы настраивать источник данных без нерелевантных полей._

----

h3. 1. Описание текущего поведения.

* Для разных типов подключения отображается общий набор полей и переключателей независимо от их применимости.
* В списке типов подключения присутствуют нерелевантные варианты, которые не должны быть доступны в интерфейсе.
* В карточке отображаются неиспользуемые поля {{URL БД}}, {{MDX-сервер}} и {{MDX}}.
* Пользователю приходится самостоятельно определять, какие параметры фактически участвуют в создании подключения выбранного типа.

----

h3. 2. Описание целевого поведения.

---
h4. 2.1. Компоновка формы.

Необходимо сохранить текущую табличную компоновку формы и внести только изменения, необходимые для динамического отображения элементов.

* *Верхняя панель навигации* не изменяется.
* Под верхней панелью располагается строка выбора источника:
** подпись «Выберите источник данных» с текущей подсказкой;
** выпадающий список существующих источников;
** кнопка «Добавить источник» и кнопка «Удалить».
* Ниже располагается табличная секция «Поля источника» с колонками «Поле» и «Значение».
* Справа сохраняется боковая панель «Дополнительные опции». Её компоновка, элементы управления и текущая логика не изменяются, а видимость определяется матрицей из раздела 3.
* Если для выбранного типа недоступны все элементы боковой панели, панель не отображается. Основная таблица при этом сохраняет ширину и расположение, показанные на макете [^Форма_источники_данных_макет_SQLite.png].
* Последовательность строк основной таблицы:
** системные и общие поля;
** применимые параметры подключения;
** применимые функциональные настройки;
** «Краткое описание»;
** «Порядок сортировки».

Цветовая палитра, шрифты, размеры, переключатели, подсказки и стили кнопок не изменяются и остаются в текущей стилистике аналитического портала.

---
h4. 2.2. Список типов подключения.

В выпадающем списке «Тип подключения» должны отображаться только следующие значения и строго в указанном порядке:

# PostgreSQL;
# ClickHouse;
# ClickHouse HTTPS;
# ClickHouse+SSL;
# StarRocks;
# MS SQL Server;
# MS SQL Server Instance;
# MySQL;
# Vertica;
# SQLite;
# Метаданные.

Фронтенд должен отфильтровывать типы, не входящие в этот перечень, даже если они получены от бэкенда. OLAP (XMLA) и Полиматика в списке «Тип подключения» не отображаются.

ClickHouse, ClickHouse HTTPS и ClickHouse+SSL остаются тремя самостоятельными вариантами выбора.

---
h4. 2.3. Общие поля и их редактируемость.

Для каждого допустимого типа подключения отображаются:

|| Поле || Режим создания || Режим редактирования ||
| ID | Только чтение; пользователь не заполняет значение | Только чтение |
| Тип подключения | Выпадающий список, доступен для выбора | Выпадающий список, доступен для изменения; при выборе другого значения форма перестраивается по матрице |
| Имя источника | Доступно для ввода при создании нового подключения | В режиме редактирования только чтение, отображается в текущем приглушённом стиле |
| Отображаемое название | Доступно для ввода | Доступно для изменения |
| Краткое описание | Доступно для ввода | Доступно для изменения |
| Порядок сортировки | Доступно для ввода | Доступно для изменения |

Матрица из раздела 3 определяет только состав и видимость элементов. Действующие правила обязательности, форматы значений, значения по умолчанию и взаимозависимости поддерживаемых настроек не изменяются.

h4. 3.1. Правила применения матрицы.

* {{RLS}} в матрице означает весь текущий блок управления RLS в боковой панели, включая «Поддержка RLS» и «Активность RLS».
* Для типов с доступными формами одновременно отображаются:
** строки «Формы ввода» и «Отчётные формы» в основной таблице;
** текущий объединённый блок «ФВД/Отчётные формы» в боковой панели.
* «Формы ввода» и «Отчётные формы» всегда отображаются или скрываются совместно. Действующая логика значений и установки форм не изменяется.
* Для PostgreSQL, MS SQL Server, MS SQL Server Instance и Vertica отображается боковая панель с блоками RLS и «ФВД/Отчётные формы».
* Для остальных типов боковая панель не отображается, поскольку доступных для неё элементов нет.
* Строка «Коррекция данных» отображается только для типов, отмеченных в матрице. Её действующая зависимость от RLS, включая недоступное состояние при соответствующей настройке RLS, сохраняется.
* {{URL БД}}, {{MDX-сервер}} и {{MDX}} не отображаются ни для одного допустимого типа подключения.

h3. 4. Требования к пользовательским сценариям.

---
h4. 4.1. Создание и редактирование источника.

* По кнопке «Добавить источник» открывается режим создания источника с возможностью выбрать тип подключения и заполнить применимые поля.
* Заполнение поля «Имя источника» доступно при создании. После создания источника поле становится недоступным для изменения и отображается в приглушённом стиле.
* «Отображаемое название» остаётся редактируемым после создания источника.
* При выборе существующего источника форма загружает его тип, сохранённые значения и состояния доступных настроек.
* Для существующего источника сохранённый пароль не раскрывается и не загружается в форму как доступное пользователю значение. Поле отображается в защищённом маскированном состоянии и используется только для ввода нового пароля. Если пользователь не ввёл новое значение, сохранение других изменений не должно передавать пустой пароль, очищать или заменять действующий пароль.
* После успешного создания нового источника, источник остаётся выбранным, получает актуальный {{ID}}, а индикатор несохранённых изменений сбрасывается.
* После повторного открытия отображаются сохранённые значения всех применимых несекретных полей и настроек.

---
h4. 4.2. Динамическое перестроение формы.

* При выборе или изменении типа подключения форма перестраивается сразу, без сохранения промежуточного состояния и без перезагрузки страницы.
* Отображаются только применимые для выбранного типа поля и элементы.
* Неприменимые поля и блоки скрываются полностью и не оставляют пустых строк.
* Скрытые поля не участвуют в клиентской валидации и проверке подключения выбранного типа.
* Значения одного источника не должны попадать в форму другого источника.
* При смене типа подключения значения и активные признаки, неприменимые к новому типу, не должны использоваться для проверки подключения или сохраняться как активные настройки нового типа.
* Возврат к сохранённому источнику без сохранения изменений должен восстанавливать его фактическое сохранённое состояние по действующему сценарию формы.
* Состояния переключателей и кнопок на макетах являются примером конкретных источников и не задают значения по умолчанию.

---
h4. 4.3. Сохранение.

* Кнопка «Сохранить» не создаёт новый источник, а обновляет выбранный источник с использованием текущих API-контрактов.
* Перед сохранением валидируются только поля, применимые к выбранному типу подключения.
* При ошибке валидации или бэкенда источник не считается сохранённым; введённые значения остаются в форме и доступны для исправления.
* При обновлении источника без изменения его типа сохранённые технические значения, не должны очищаться.
* При сохранении источника с изменённым типом, недоступные целевому типу поля и элементы не должны передаваться как активные или заполненные.

---
h4. 4.4. Проверка подключения.

* Кнопка «Проверить» сохраняет текущую стилистику и располагается справа в строке «Хост БД».
* Кнопка отображается после ввода хотя бы одного символа в поле «Хост БД», включая значение, загруженное у существующего источника.
* Если «Хост БД» пуст или очищен, кнопка не отображается.
* Для «Метаданных» кнопка не отображается.
* Для сохранённого источника без несохранённых изменений нажатие «Проверить» сразу запускает действующую проверку подключения.
* Для нового источника или источника с несохранёнными изменениями нажатие «Проверить» открывает предупреждение:

{panel}
«Настройки источника данных были изменены. Сохранить?»

В предупреждении доступны две кнопки:
* «Сохранить» — запускает сохранение; после успешного сохранения проверка подключения запускается автоматически;
* «Отмена» — закрывает предупреждение без сохранения и без запуска проверки, сохраняя введённые значения в форме.
{panel}

* Если сохранение завершилось ошибкой, проверка подключения не запускается.
* Результат успешной и неуспешной проверки отображается по текущему UI-паттерну портала. Ошибка не должна раскрывать пароль или полную строку подключения с секретными данными.

---
h4. 4.5. Выбор и удаление источника.

* Выпадающий список «Выберите источник данных» позволяет загрузить выбранный существующий источник для настройки.
* Существующие источники типов OLAP (XMLA) и Полиматика не отображаются в списке «Выберите источник данных». Их записи на бэкенде при этом не удаляются и не изменяются.
* При выборе другого источника или переходе к созданию нового источника несохранённые изменения не должны теряться без действующего в портале предупреждения.
* Кнопка «Удалить» применяется только к текущему сохранённому источнику и использует действующие проверку прав и подтверждение удаления.
* После успешного удаления источник исключается из списка. При ошибке источник остаётся выбранным, а пользователю выводится контролируемое сообщение.
* Кнопка «Удалить» не должна приводить к удалению другого источника при переключении выбора или обновлении формы.

----

h3. 5. Требования к фронтенду и API.

---
h4. 5.1. Фронтенд.

* Реализовать единое правило формирования формы по типу подключения на основании матрицы из раздела 3.
* Применять одно и то же правило в режимах создания, открытия и редактирования источника.
* Отфильтровать и отсортировать полученный от бэкенда список типов подключения в соответствии с п. 2.2.
* Не переносить параметры подключения в новые карточки, аккордеоны или отдельные шаги: используется текущая табличная форма.
* Сохранить текущие подсказки и взаимозависимости доступных настроек.

---
h4. 5.2. API и данные.

* Логически форма использует объект {{datasources}} и его действующие операции {{list/get/create/update/delete}} для получения, создания, обновления и удаления источника.
* Перед обновлением получать актуальное состояние источника через действующую операцию {{get}} или {{list}}, чтобы не потерять значения, не изменяемые пользователем.
* Для кнопки «Проверить» использовать действующую операцию проверки объекта {{connection}}.
* Если фактические имена объектов или команд текущей формы отличаются от логических имён выше, используются существующие имена без изменения. Доработка не вводит и не переименовывает API-контракты.
* Не изменять назначение {{object.id}}, {{command.id}} и полей {{data}} в существующих контрактах.
* Для SQLite значение «Путь к файлу» передаётся в соответствии с текущим контрактом (в {{db_name}}).
* {{db_url}} может оставаться в модели бэкенда, но не используется для построения подключения и не отображается в форме.
* Для ClickHouse, ClickHouse HTTPS и ClickHouse+SSL сохраняется действующее формирование строки подключения для каждого отдельного UI-типа.
* Для «Форм ввода» и «Отчётных форм» сохраняется действующая работа с общим признаком бэкенда {{form}}.
* Новое значение пароля передавать только после явного ввода пользователем; при отсутствии нового ввода параметр изменения пароля не передавать.
* Новые API-контракты или отдельный механизм флагов доступности на бэкенде в рамках этой формы не требуются.

----

h3. 6. Ограничения и обратная совместимость.

* Доработка не изменяет работу самих драйверов, формирование SQL, создание наборов данных и работу источников за пределами формы их создания и редактирования.
* Существующие источники допустимых типов должны открываться, сохраняться, проверяться и удаляться через обновлённую форму.
* Скрытие OLAP (XMLA) и Полиматики в интерфейсе не должно удалять или изменять сохранённые записи на бэкенде.
* Удаление полей из интерфейса не является миграцией или очисткой сохранённых значений {{db_url}} и других легаси-параметров.
* Действующая модель прав на просмотр, создание, редактирование, проверку и удаление источников сохраняется. Доработка не должна предоставлять действия пользователю, которому они недоступны.
* При ошибках загрузки, сохранения, удаления или проверки форма не должна зависать или терять введённые пользователем несекретные значения.

h3. 8. Критерии приёмки (AC):

Для проверки должны быть подготовлены пользователь с правом управления источниками, пользователь без такого права.

*AC.1 — Сохранение текущей компоновки:*
* *Дано:* пользователь открыл форму источника данных;
* *Когда:* форма загрузилась;
* *Тогда:* верхняя панель, строка выбора источника, таблица «Поля источника», кнопки и подсказки соответствуют п. 2.1, п. 3 и целевым макетам.

*AC.2 — Список типов подключения:*
* *Дано:* пользователь открыл список «Тип подключения»;
* *Когда:* список значений загружен;
* *Тогда:* отображаются 11 типов в точном порядке из п. 2.2;
* *И:* OLAP (XMLA), Полиматика и другие отсутствующие в утверждённом перечне типы не отображаются; сохранённые источники OLAP (XMLA) и Полиматика отсутствуют в списке «Выберите источник данных», но их записи на бэкенде не удаляются.

*AC.3 — Общие поля и режим редактирования:*
* *Дано:* пользователь создаёт новый источник, а затем сохраняет и открывает его повторно;
* *Когда:* отображается форма источника;
* *Тогда:* общие поля соответствуют п. 2.3;
* *И:* поле «Имя источника» после сохранения недоступно и визуально приглушено; «Отображаемое название» остаётся доступным для изменения.

*AC.4 — Соответствие финальной матрице:*
* *Дано:* для каждого из 11 допустимых типов открыт режим создания или редактирования;
* *Когда:* пользователь последовательно выбирает каждый тип подключения;
* *Тогда:* параметры подключения, функциональные настройки и блок RLS отображаются строго по матрице из раздела 3;
* *И:* неприменимые строки и пустая боковая панель не отображаются; поля {{URL БД}}, {{MDX-сервер}} и {{MDX}} отсутствуют для каждого из 11 допустимых типов.

*AC.5 — SQLite:*
* *Дано:* выбран тип SQLite;
* *Когда:* отображается форма;
* *Тогда:* из параметров подключения доступно только поле «Путь к файлу» с кнопкой «Обзор...»; путь сохраняется и после повторного открытия отображается в поле «Путь к файлу»;
* *И:* из функциональных настроек доступен только «Импорт из Excel»; боковая панель не отображается.

*AC.6 — MS SQL Server Instance и Метаданные:*
* *Дано:* пользователь последовательно выбирает MS SQL Server Instance и «Метаданные»;
* *Когда:* форма перестраивается;
* *Тогда:* для MS SQL Server Instance доступен «Хост БД» в формате {{server\instance}}, но отсутствует «Порт»;
* *И:* для «Метаданных» отображаются только общие поля, без пользовательских параметров подключения, функций и кнопки «Проверить».

*AC.7 — Варианты ClickHouse:*
* *Дано:* пользователь последовательно выбирает ClickHouse, ClickHouse HTTPS и ClickHouse+SSL;
* *Когда:* форма перестраивается;
* *Тогда:* каждый вариант остаётся отдельным значением типа и отображает полный набор отдельных SQL-параметров подключения из матрицы;
* *И:* из функциональных настроек отображается только «Импорт из Excel»; {{URL БД}}, формы, коррекция данных и RLS не отображаются.

*AC.8 — Динамическое переключение типа:*
* *Дано:* в форме заполнены поля одного типа подключения;
* *Когда:* пользователь выбирает другой тип;
* *Тогда:* форма перестраивается без перезагрузки и показывает только элементы нового типа;
* *И:* скрытые значения не участвуют в валидации, проверке и сохранении новых настроек выбранного типа; данные не переносятся между разными выбранными источниками.

*AC.9 — Дополнительные опции:*
* *Дано:* выбран PostgreSQL, MS SQL Server, MS SQL Server Instance или Vertica;
* *Когда:* форма отображена;
* *Тогда:* справа присутствуют текущие блоки RLS и «ФВД/Отчётные формы», а в таблице присутствуют обе настройки форм и коррекция данных;
* *И:* действующие состояния, зависимости и операции установки/отмены установки работают без изменения.

*AC.10 — Создание и повторное открытие:*
* *Дано:* пользователь нажал на кнопку «Добавить источник», заполнил неоходимые поля нового источника;
* *Когда:* пользователь сохраняет источник и открывает его повторно;
* *Тогда:* отображаются тип, применимые несекретные значения и состояния доступных функций;
* *И:* имя созданного источника становится недоступно для редактирования; неизменённый пароль не сбрасывается и не раскрывается.
* *Когда:* сохранение завершается ошибкой валидации или бэкенда;
* *Тогда:* источник не считается сохранённым, а введённые значения остаются доступны для исправления.

*AC.11 — Отображение кнопки «Проверить»:*
* *Дано:* выбран тип с полем «Хост БД»;
* *Когда:* поле пусто, заполнено, а затем очищено;
* *Тогда:* кнопка «Проверить» отсутствует, появляется и снова скрывается;
* *И:* для «Метаданных» кнопка отсутствует.

*AC.12 — Проверка при несохранённых изменениях:*
* *Дано:* у нового или изменённого источника заполнено поле «Хост БД»;
* *Когда:* пользователь нажимает «Проверить»;
* *Тогда:* отображается предупреждение «Настройки источника данных были изменены. Сохранить?» с кнопками «Сохранить» и «Отмена»;
* *И:* «Сохранить» успешно сохраняет источник и автоматически запускает проверку; при ошибке сохранения проверка не запускается;
* *И:* «Отмена» не сохраняет и не запускает проверку, но оставляет введённые значения в форме.

*AC.13 — Результат проверки и обработка ошибок:*
* *Дано:* сохранён источник с корректными либо некорректными параметрами подключения;
* *Когда:* пользователь запускает проверку;
* *Тогда:* при отсутствии несохранённых изменений предупреждение о сохранении не отображается; система отображает контролируемый результат успешного или неуспешного подключения;
* *И:* при ошибке форма остаётся доступной для исправления; пароль и полная строка подключения с секретами не отображаются в сообщении или интерфейсе.

*AC.14 — Удаление источника:*
* *Дано:* выбран сохранённый источник и пользователь подтвердил его удаление;
* *Когда:* удаление завершилось успешно;
* *Тогда:* удалённый источник исчезает из списка, а другой источник не удаляется;
* *Когда:* бэкенд вернул ошибку;
* *Тогда:* источник остаётся в списке и отображается контролируемое сообщение.

*AC.15 — Права и регрессия:*
* *Дано:* форма открывается для существующих источников допустимых типов и для пользователей с разными правами;
* *Когда:* выполняются просмотр, создание, редактирование, проверка, сохранение и удаление;
* *Тогда:* действующие ограничения прав сохраняются; источники допустимых типов продолжают открываться и выполнять доступные операции;
* *И:* скрытие элементов интерфейса не удаляет сохранённые записи на бэкенде и легаси-значения.
