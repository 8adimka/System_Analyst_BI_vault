Внедрение драйвера MySQL. Поддержка источников данных по протоколу MySQL

h3. Контекст и цель.

В рамках расширения возможностей Портала и ETL-контура необходимо реализовать поддержку источников данных, совместимых с протоколом {*}MySQL{*}, на уровне бэкенда.

На текущем этапе требуется реализовать {*}техническую основу интеграции{*}: подключение к MySQL-источнику, чтение схемы БД, корректное сопоставление типов данных, генерацию SQL-запросов в диалекте MySQL, а также поддержку базовых сценариев работы с данными.

*RLS, Формы ввода данных (ФВД), импорт из Excel и UI-ограничения карточки источника* в рамках данной истории *не реализуются*.

----

h4. 1. Требования.

h4. 1.1. Подключение MySQL как поддерживаемого источника на бэкенде.

* Бэкенд должен поддерживать тип источника {*}MySQL{*} как полноценный источник данных.
* Должна быть обеспечена возможность подключения к MySQL-серверу по стандартным параметрам соединения.
* Проверка подключения должна корректно отрабатывать для MySQL:
  ** при успешном соединении возвращается статус успешного подключения,
  ** при ошибке — возвращается текст ошибки, полученный от БД или драйвера.

h4. 1.2. Чтение схемы и метаданных MySQL-источника.

* Бэкенд должен получать и отдавать информацию о таблицах и полях MySQL-источника.
* Чтение схемы должно выполняться через {*}information_schema{*} MySQL.
* Должно быть обеспечено корректное отображение структуры БД для последующего использования в мастере набора данных и в редакторе SQL.

h4. 1.3. Поддержка типов данных MySQL.

* Необходимо обеспечить корректное сопоставление типов MySQL с внутренними типами платформы.
* В рамках маппинга должны корректно обрабатываться, в том числе:
  ** {{{}+TINYINT+{}}},
  ** {{{}+DATETIME+{}}},
  ** {{{}+VARCHAR+{}}},
  ** {{{}+BLOB+{}}},
  ** и другие распространённые типы MySQL.
* Поведение сопоставления должно быть аналогично уже реализованному маппингу для PostgreSQL.

h4. 1.4. Поддержка SQL-диалекта MySQL.

* Модуль генерации SQL должен быть расширен поддержкой MySQL-диалекта.
* Должна быть обеспечена корректная генерация запросов для:
  ** фильтрации,
  ** агрегации,
  ** вычисляемых полей,
  ** предпросмотра данных,
  ** работы с датами.
* Особое внимание должно быть уделено преобразованию даты и времени: UI-выбор аналитика должен транслироваться в синтаксически корректный SQL-запрос для MySQL.
* Набор вариантов и форматов должен соответствовать текущей реализации для PostgreSQL по смыслу и поведению.

h4. 1.5. Поддержка вычисляемых полей и фильтрации на стороне MySQL.

* Вычисляемые поля, созданные в наборе данных на базе MySQL-источника, должны корректно вычисляться.
* Фильтрация по полям MySQL-источника должна корректно транслироваться в SQL и возвращать ожидаемый результат.

h4. 1.6. Системные ограничения на уровне бэкенда.

* Бэкенд должен быть готов к тому, что часть возможностей платформы для MySQL на этом этапе не используется.
* Для функций, которые пока не поддерживаются этим источником, API должно возвращать корректную ошибку при попытке вызова.

h4. 1.7. Драйвер подключения.

* Рекомендуется подключение через нативный Go-драйвер (например, {{{}go-sql-driver/mysql{}}}) для максимальной производительности в ETL-слое.
* Если интеграция нативного драйвера потребует неоправданно высоких трудозатрат, допускается переиспользование существующего ODBC-моста.

----

h3. 2. Нефункциональные требования.

* Для MySQL-диалекта необходимо разработать тест-план, покрывающий:
  ** корректность генерации SQL-запросов,
  ** корректность маппинга типов данных,
  ** корректность преобразования дат,
  ** корректность работы соединения в сценариях успеха и ошибок.
* Тестирование должно проводиться на реальной MySQL-базе данных.

----

h3. 3. Критерии приёмки (AC):

*AC-1 — Подключение:*
Бэкенд поддерживает создание MySQL-источника и проверку подключения. При успешном соединении возвращается статус «Успешно», при ошибке — текст ошибки от БД/драйвера.

*AC-2 — Чтение схемы:*
Бэкенд корректно получает список таблиц и полей MySQL-источника через {{information_schema}} и передаёт эти данные для дальнейшего использования платформой.

*AC-3 — Типы данных:*
Типы MySQL (например, {{{}+TINYINT+{}}}, {{{}+DATETIME+{}}}, {{{}+VARCHAR+{}}}, {{+BLOB+}}) корректно сопоставляются с внутренними типами платформы.

*AC-4 — SQL и предпросмотр:*
Для MySQL-источника корректно генерируются SQL-запросы для предпросмотра, фильтрации, агрегации и вычисляемых полей, без синтаксических ошибок.

*AC-5 — Преобразование дат:*
Преобразования дат, выбранные в UI набора данных, транслируются в синтаксически корректный SQL для MySQL и возвращают ожидаемый результат.

*AC-6 — Вычисляемые поля:*
Вычисляемые поля на базе MySQL-источника корректно рассчитываются на стороне БД и доступны в ответах платформы.

*AC-7 — Тестирование:*
Для MySQL-диалекта подготовлен и выполнен тест-план на реальной MySQL-базе, покрывающий основные сценарии работы.
