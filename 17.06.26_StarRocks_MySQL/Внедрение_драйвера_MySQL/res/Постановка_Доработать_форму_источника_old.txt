Доработать форму источника данных для скрытия полей, кнопок, переключателей для различных типов СУБД

h3. Контекст и цель.

В рамках расширения возможностей Портала и ETL-контура необходимо обновить интерфейс работы с источниками данных так, чтобы пользователю был доступен {*}MySQL{*}-источник, а форма карточки источника и связанные мастера динамически отображали только поддерживаемые для данной СУБД элементы.

Также требуется реализовать {*}универсальный механизм передачи возможностей СУБД{*} от бэкенда к фронтенду, чтобы UI мог скрывать или отображать элементы в зависимости от типа источника, а бэкенд — валидировать API-вызовы для недоступных функций.

На текущем этапе базовый функционал для MySQL должен быть доступен, а *RLS, Формы ввода данных (ФВД), импорт из Excel, MDX и другие нерелевантные настройки* должны быть скрыты.

----

h3. 1. Бизнес требования.

h4. 1.1. Добавление типа подключения MySQL в интерфейсе источников.
В разделе {*}«Источники» → «Добавить источник»{*}:

* В выпадающий список «Тип подключения» добавить пункт {*}MySQL{*}.
* *Позиция в списке:* MySQL должен располагаться в верхней группе основных СУБД — примерный порядок:
  ** PostgreSQL, ClickHouse, MySQL, MS SQL Server, SQLite и т.д.
* Для MySQL отображать стандартный набор полей подключения:
  ** {{{}Тип подключения{}}},
  ** {{{}Имя источника{}}},
  ** {{Отображаемое название}},
  ** {{{}Хост БД{}}},
  ** {{{}Порт{}}},
  ** {{{}Имя БД{}}},
  ** {{{}Схема БД{}}},
  ** {{{}Логин подключения к БД{}}},
  ** {{{}Пароль подключения к БД{}}},
  ** {{URL БД}} и т.д.
* Кнопка *«Проверить» подключение* должна корректно работать для MySQL.

h4. 1.2. Ограничение нерелевантных настроек в карточке источника.
Так как ряд функций платформы для MySQL на текущем этапе не поддерживается, соответствующие настройки в карточке MySQL-источника должны быть *убраны* (недоступны для взаимодействия и не видны):

||Настройка||Поведение для MySQL||
|MDX-сервер|Убрать|
|MDX|Убрать|
|Формы ввода данных|Убрать|
|Отчётные формы|Убрать|
|Коррекция данных|Убрать|
|Импорт из Excel|Убрать|
|Дополнительные опции (все)|Убрать|
|Поддержка RLS|Убрать|
|Активность RLS|Убрать|
|ФВД/Отчётные формы|Убрать|

Форма карточки источника должна динамически перестраиваться в зависимости от выбранного типа СУБД: при переключении типа подключения в выпадающем списке форма показывает только релевантные поля.

h4. 1.3. Создание набора данных на основе MySQL-источника.
Аналитик должен иметь возможность создавать набор данных, выбирая MySQL-источник, с полноценной поддержкой базового рабочего сценария:

* В мастере создания набора данных "MySQL-источник" доступен для выбора.
* В редакторе набора данных работает консоль SQL-запросов с предпросмотром данных.
* Список таблиц и полей источника корректно отображается в UI (подтягивается схема БД).
* *Настройки RLS* внутри набора данных не отображаются (поведение наследуется из настроек источника, где RLS отключён).

h4. 1.4. Поддержка фильтрации и вычисляемых полей в UI.

* Фильтрация в дашбордах и отчётах по полям из MySQL-источника должна работать корректно.
* Вычисляемые поля, созданные в наборе данных, должны корректно отображаться и использоваться в интерфейсе.

h4. 1.5. Полноценная поддержка преобразования дат.
В наборах данных есть инструмент извлечения частей даты («шестерёнка» рядом с полем типа {*}Дата{*}).
Этот функционал должен полностью работать для MySQL-источника: платформа должна транслировать UI-выбор аналитика в синтаксически корректный SQL-запрос для MySQL.

Набор вариантов и форматов дат должен полностью соответствовать текущей реализации для PostgreSQL — пользователь не должен замечать разницы в поведении при переключении между типами источников.

h4. 1.6. Системные ограничения (ФВД и загрузка из Excel).

* *ФВД:* при создании новой формы ввода данных в разделе «ФВД» MySQL-источник *не должен отображаться* в выпадающем списке выбора хранилища.
* *Загрузка из Excel:* в мастере импорта файлов Excel MySQL-источник {*}не должен быть доступен для выбора{*}.
* Настройка «Импорт из Excel» в карточке источника для MySQL недоступна.

----

h3. 2. Технические требования.

h4. 2.1. Механизм передачи возможностей СУБД.

* Бэкенд должен предоставлять фронтенду структуру с набором флагов/параметров для каждого типа СУБД — какие функции доступны для данного источника.
* Набор возможностей должен быть универсальным и пригодным для любых СУБД и других источников.
* На основе этих данных фронтенд должен динамически отображать или скрывать соответствующие элементы UI в карточке источника и наборе данных.

h4. 2.2. Адаптация API-вызовов под возможности источника.

* Бэкенд должен использовать тот же набор флагов при валидации API-вызовов.
* Запросы к недоступным для MySQL функциям должны возвращать корректную ошибку.
* Механизм должен быть унифицированным и применяться не только к MySQL, но и к другим СУБД.

h4. 2.3. Сортировка типов подключений.

* Скорректировать порядок сортировки типов подключений в списке «Источники» в соответствии с п. 1.1.
* MySQL должен отображаться в верхней группе основных СУБД.

h4. 2.4. Нефункциональные требования.

* Поведение UI должно быть согласовано с backend-флагами доступности функций.
* При переключении типа источника форма должна обновляться без отображения недоступных элементов.
* Ограничения должны соблюдаться как в UI, так и на уровне API.

----

h3. 3. Критерии приёмки (AC):

*AC-1 — Тип подключения MySQL:*
В разделе «Источники» → «Добавить источник» в списке типов подключений присутствует MySQL и отображается в корректной группе сортировки.

*AC-2 — Карточка источника:*
При выборе MySQL карточка источника отображает только релевантные поля подключения, а настройки «RLS», «ФВД», «Импорт из Excel», «MDX» и прочие нерелевантные элементы визуально отсутствуют.

*AC-3 — Динамическая перестройка формы:*
При переключении типа подключения форма источника автоматически перестраивается и показывает только доступные для выбранной СУБД поля и опции.

*AC-4 — Мастер набора данных:*
MySQL-источник доступен для выбора в мастере создания набора данных, схема БД отображается корректно, SQL-редактор и предпросмотр данных работают.

*AC-5 — Ограничения ФВД и Excel:*
В интерфейсе создания ФВД MySQL-источник отсутствует в списке хранилищ. В мастере импорта из Excel MySQL-источник недоступен для выбора.

*AC-6 — Передача возможностей СУБД:*
Бэкенд возвращает фронтенду структуру с флагами доступных возможностей для типа СУБД, а фронтенд использует её для скрытия/отображения элементов UI.

*AC-7 — Валидация API:*
Попытка вызвать API для функций, недоступных для MySQL, возвращает корректную ошибку, соответствующую ограничению источника.
