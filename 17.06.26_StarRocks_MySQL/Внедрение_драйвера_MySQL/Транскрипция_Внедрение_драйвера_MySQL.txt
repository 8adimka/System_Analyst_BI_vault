h3. Критерии приёмки (AC) по итогам обсуждения

Перед выполнением приёмки должны быть доступны:
* пользователь с правами на создание и редактирование источников данных;
* тестовый MySQL-сервер с валидными и невалидными параметрами подключения для проверки успешных и ошибочных сценариев;
* MySQL-БД с таблицами, строковыми, числовыми, датовыми и nullable-полями;
* данные, позволяющие проверить фильтрацию, вычисляемые поля, агрегации и извлечение частей даты;
* существующие источники других типов для регрессионной проверки формы источника.

*AC-1 — Отображение MySQL в списке типов подключения:*
* *Дано:* пользователь открывает раздел «Источники» и запускает создание нового источника.
* *Когда:* пользователь раскрывает список «Тип подключения».
* *Тогда:* в списке присутствует пункт MySQL.
* *Тогда:* MySQL расположен в верхней группе основных СУБД рядом с PostgreSQL, MS SQL Server, ClickHouse и другими основными подключениями.
* *Тогда:* добавление MySQL не удаляет и не переименовывает ранее доступные типы подключений.

*AC-2 — Базовая карточка MySQL-источника:*
* *Дано:* пользователь выбрал тип подключения MySQL.
* *Когда:* отображается карточка источника.
* *Тогда:* пользователю доступны стандартные поля подключения: тип подключения, имя источника, отображаемое название, хост БД, порт, имя БД, схема БД, логин, пароль и другие обязательные поля, используемые текущей формой подключения.
* *Тогда:* значения в обязательных полях валидируются так же, как для аналогичных SQL-источников.

*AC-3 — Проверка успешного подключения из карточки источника:*
* *Дано:* в карточке MySQL-источника заполнены корректные параметры подключения.
* *Когда:* пользователь нажимает кнопку проверки подключения.
* *Тогда:* система выполняет проверку подключения к MySQL.
* *Тогда:* пользователю отображается успешный результат проверки.
* *Тогда:* после успешной проверки источник можно сохранить и использовать для создания набора данных.

*AC-4 — Проверка ошибки подключения из карточки источника:*
* *Дано:* в карточке MySQL-источника указан неверный хост, порт, логин, пароль или имя БД.
* *Когда:* пользователь нажимает кнопку проверки подключения.
* *Тогда:* пользователю отображается ошибка подключения в понятном виде.
* *Тогда:* пароль и другие секреты не отображаются в тексте ошибки.
* *Тогда:* форма остаётся доступной для исправления параметров без пересоздания источника.

*AC-5 — Сохранение и повторное открытие MySQL-источника:*
* *Дано:* пользователь создал MySQL-источник с валидными параметрами.
* *Когда:* пользователь сохраняет источник, закрывает карточку и открывает её повторно.
* *Тогда:* источник отображается как MySQL-источник.
* *Тогда:* несекретные параметры отображаются корректно.
* *Тогда:* пароль не раскрывается в открытом виде, но источник продолжает работать, если пароль не изменялся.

*AC-6 — Недоступность RLS в карточке MySQL-источника:*
* *Дано:* пользователь выбрал или открыл MySQL-источник.
* *Когда:* отображается карточка источника.
* *Тогда:* настройки поддержки RLS и активности RLS недоступны для включения.
* *Тогда:* если элементы RLS отображаются по принятому UX-решению, они находятся в disabled-состоянии; если скрываются механизмом возможностей источника, они отсутствуют в форме.
* *Тогда:* при сохранении MySQL-источника RLS не включается в метаданных источника.

*AC-7 — Недоступность ФВД и отчётных форм в карточке MySQL-источника:*
* *Дано:* пользователь выбрал или открыл MySQL-источник.
* *Когда:* отображается карточка источника.
* *Тогда:* настройки ФВД, отчётных форм и связанных с ними возможностей недоступны для включения.
* *Тогда:* пользователь не может сохранить MySQL-источник как источник, поддерживающий ФВД или отчётные формы.

*AC-8 — Недоступность коррекции данных и импорта из Excel:*
* *Дано:* пользователь выбрал или открыл MySQL-источник.
* *Когда:* отображается карточка источника.
* *Тогда:* настройки коррекции данных и импорта из Excel недоступны для включения.
* *Тогда:* сохранение источника не создаёт признаков, позволяющих использовать MySQL-источник для коррекции данных или загрузки Excel-файлов.

*AC-9 — Недоступность MDX и нерелевантных дополнительных опций:*
* *Дано:* пользователь выбрал или открыл MySQL-источник.
* *Когда:* отображается карточка источника.
* *Тогда:* настройки MDX, MDX-сервера и нерелевантные дополнительные опции недоступны для взаимодействия.
* *Тогда:* пользователь не может включить для MySQL функции, которые на текущем этапе не поддержаны.

*AC-10 — Переключение типа подключения в форме источника:*
* *Дано:* пользователь находится в форме создания или редактирования источника.
* *Когда:* пользователь переключает тип подключения с другого источника на MySQL.
* *Тогда:* форма перестраивается под MySQL и показывает только применимые поля и опции.
* *Тогда:* ранее включённые для другого типа источника неподдерживаемые опции не сохраняются как активные для MySQL.
* *Тогда:* обратное переключение на другой тип источника восстанавливает поведение формы для выбранного типа и не ломает его настройки.

*AC-11 — Выбор MySQL-источника в мастере набора данных:*
* *Дано:* в системе создан и сохранён валидный MySQL-источник.
* *Когда:* пользователь создаёт набор данных и выбирает источник данных.
* *Тогда:* MySQL-источник доступен для выбора в мастере набора данных.
* *Тогда:* выбор MySQL-источника не приводит к ошибкам интерфейса и позволяет перейти к настройке запроса/таблиц.

*AC-12 — Отображение схемы MySQL в наборе данных:*
* *Дано:* выбран MySQL-источник с доступными таблицами и полями.
* *Когда:* пользователь открывает мастер набора данных или редактор SQL.
* *Тогда:* список таблиц и полей MySQL-источника отображается в интерфейсе.
* *Тогда:* названия таблиц и полей соответствуют метаданным MySQL.
* *Тогда:* пустая схема или отсутствие прав на таблицы отображаются как контролируемое состояние/ошибка, а не как зависание или падение интерфейса.

*AC-13 — SQL-редактор набора данных:*
* *Дано:* пользователь создаёт набор данных на базе MySQL-источника.
* *Когда:* пользователь вводит корректный SQL-запрос к MySQL-таблице и запускает проверку/предпросмотр.
* *Тогда:* запрос выполняется, предпросмотр возвращает данные, а набор данных можно сохранить.
* *Тогда:* при синтаксической ошибке SQL пользователь получает понятное сообщение об ошибке без потери введённого текста запроса.

*AC-14 — Сохранение набора данных на MySQL-источнике:*
* *Дано:* пользователь настроил набор данных на базе MySQL-источника и получил корректный предпросмотр.
* *Когда:* пользователь сохраняет набор данных и открывает его повторно.
* *Тогда:* набор данных сохраняет связь с MySQL-источником, SQL-запрос, поля и типы данных.
* *Тогда:* повторный предпросмотр после открытия возвращает данные без необходимости пересоздавать набор данных.

*AC-15 — Отсутствие RLS-настроек в наборе данных MySQL:*
* *Дано:* пользователь создаёт или редактирует набор данных на базе MySQL-источника.
* *Когда:* отображаются настройки набора данных.
* *Тогда:* настройки RLS для такого набора данных не доступны для включения.
* *Тогда:* пользователь не может сохранить MySQL-набор данных с активным стандартным RLS.

*AC-16 — Работа фильтрации по данным MySQL:*
* *Дано:* создан набор данных на базе MySQL-источника и отчёт/визуализация на его основе.
* *Когда:* пользователь применяет фильтры по строковым, числовым и датовым полям.
* *Тогда:* данные в отчёте фильтруются согласно выбранным значениям.
* *Тогда:* пустой результат фильтрации отображается корректно и не приводит к ошибке визуализации.

*AC-17 — Работа вычисляемых полей в UI:*
* *Дано:* пользователь создаёт вычисляемое поле в наборе данных на базе MySQL-источника.
* *Когда:* пользователь запускает предпросмотр набора данных или строит отчёт с этим полем.
* *Тогда:* вычисляемое поле отображается в списке полей и возвращает рассчитанные значения.
* *Тогда:* ошибка в формуле вычисляемого поля отображается пользователю как контролируемая ошибка и не ломает набор данных целиком.

*AC-18 — Инструмент извлечения частей даты:*
* *Дано:* в наборе данных MySQL есть поле типа «Дата» или «Дата-время».
* *Когда:* пользователь открывает инструмент извлечения частей даты рядом с полем.
* *Тогда:* инструмент доступен для датового поля.
* *Тогда:* пользователь может создать производные поля даты в тех вариантах, которые доступны для PostgreSQL: год, квартал, месяц, неделя, день, день недели, год-квартал, год-месяц, год-неделя, год-день и другие поддержанные варианты.

*AC-19 — Форматы производных датовых полей:*
* *Дано:* пользователь создаёт производные поля даты для MySQL-набора данных.
* *Когда:* выбраны строковые и числовые форматы отображения, например год числом, месяц числом, месяц названием, сокращённый месяц, квартал числом или строкой, год-месяц.
* *Тогда:* значения производных полей отображаются в тех же смысловых форматах, что и для аналогичного набора данных PostgreSQL.
* *Тогда:* производные поля доступны для предпросмотра, отчётов и фильтрации в рамках текущих возможностей платформы.

*AC-20 — MySQL-источник недоступен при создании ФВД-таблицы:*
* *Дано:* в системе есть сохранённый MySQL-источник.
* *Когда:* пользователь открывает конструктор ФВД и выбирает хранилище/источник для создания таблицы ФВД.
* *Тогда:* MySQL-источник отсутствует в списке доступных хранилищ/источников для ФВД.
* *Тогда:* пользователь не может создать ФВД-таблицу на базе MySQL-источника.

*AC-21 — MySQL-источник недоступен в мастере импорта Excel:*
* *Дано:* в системе есть сохранённый MySQL-источник.
* *Когда:* пользователь открывает сценарий загрузки/импорта файлов Excel в БД.
* *Тогда:* MySQL-источник недоступен для выбора как целевой источник/хранилище.
* *Тогда:* пользователь не может запустить импорт Excel в MySQL-источник через текущий механизм платформы.

*AC-22 — Согласованность UI с возможностями источника:*
* *Дано:* бэкенд возвращает для MySQL набор признаков доступных и недоступных функций.
* *Когда:* frontend строит карточку источника, мастер набора данных, список источников для ФВД и список источников для Excel-импорта.
* *Тогда:* интерфейс использует эти признаки и не показывает/не активирует недоступные для MySQL функции.
* *Тогда:* ручная подмена frontend-состояния не позволяет успешно сохранить недоступную функцию, если backend валидирует её как запрещённую.

*AC-23 — Регрессия по существующим типам источников:*
* *Дано:* в системе есть существующие источники PostgreSQL, MS SQL Server, SQLite, ClickHouse или другие поддерживаемые типы.
* *Когда:* пользователь открывает их карточки, проверяет подключение, создаёт набор данных и использует ранее доступные настройки.
* *Тогда:* поведение существующих типов источников не меняется из-за добавления MySQL.
* *Тогда:* настройки, которые были доступны для других типов источников до доработки, остаются доступными в соответствии с их текущими возможностями.

*AC-24 — Отсутствие блокирующих дефектов перед релизом:*
* *Дано:* функциональность MySQL передана на релизную проверку.
* *Когда:* тестировщик выполняет проверку по критериям AC-1 — AC-23.
* *Тогда:* MySQL можно добавить как источник, проверить подключение, создать набор данных, выполнить SQL-запрос, получить предпросмотр, использовать фильтрацию, вычисляемые поля и производные поля даты.
* *Тогда:* неподдерживаемые сценарии RLS, ФВД, отчётных форм, коррекции данных, MDX и импорта Excel недоступны пользователю и не могут быть включены обходным путём через UI/API.
