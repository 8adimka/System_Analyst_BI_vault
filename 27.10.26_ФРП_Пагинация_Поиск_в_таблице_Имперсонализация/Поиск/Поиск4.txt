h3. Контекст и цель.
Пользователям ФРП необходимо отбирать данные непосредственно по колонкам визуализации «Таблица» аналитического портала. Сейчас фильтрация доступна через существующие элементы управления фильтрами; отдельного раздела настройки строки поиска нет.

*Требуется:* добавить опциональную строку поиска под заголовками колонок как дополнительный интерфейс управления локальными и общими фильтрами.

----
h3. 1. Настройка поиска.
В правой боковой панели настроек визуализации «Таблица» разместить отдельный раздел «Поиск» с общим тумблером (по аналогии, например, с разделом «Сортировка»). Для новых таблиц и сохранённых таблиц без настройки поиска общий тумблер по-умолчанию выключен.

При включении общего тумблера «Поиск» показывать строку поиска непосредственно под заголовками колонок. Элементы поиска сохраняют соответствие колонкам при изменении ширины, порядка и горизонтальной прокрутке.

В открытом разделе «Поиск» показывать выпадающий список «Выберите колонку». Список содержит поля набора данных, используемые для формирования колонок данных этой таблицы. После выбора колонки первой настройкой под списком показывать «Поиск для колонки». Основные значения по умолчанию:

|| Настройка || Значение по умолчанию || Назначение ||
| «Поиск для колонки» | «Вкл» | Отображение элемента поиска под этой колонкой. При выключении место под колонкой остаётся без элемента поиска. |
| «Тип фильтра» | «По значению» | При «Локальный» - «Вкл» определяет форму и способ задания условия фильтра. |
| «Зависит от» | «Все» | Доступно только при «Локальный» - «Вкл». По-умолчанию доступные значения выпадающего списка локального фильтра зависят от всех фильтров, воздействующих на эту таблицу на момент применения фильтра. Настройку можно изменить вручную. |
| «Сортировка по другому полю» | «-» | Доступно только при «Локальный» - «Вкл». По-умолчанию сортировка списка значений по другому полю не проводится. |
| «Локальный» | «Вкл» | Определяет область действия фильтра. |

При «Локальный» - «Вкл» после «Поиск для колонки» показывать настройки в следующем порядке, с сохранением действующих условий применимости к типу данных и типу фильтра:
* «Тип фильтра»;
** «Режим» при «Тип фильтра» - «По диапазону» и типе данных «Дата»;
* «Условие», «Логика», «Динамическое значение» и остальные подчинённые настройки соответствующей конфигурации;
* «Автофильтр»;
* «Зависит от»;
* «Сброс»;
** «Значение при сбросе»;
* «Сортировка по другому полю», включая применимые подчинённые настройки;
* «Невидимый»;
* «Локальный».

«Уровень отбора» в локальном режиме скрыт. При «Локальный» - «Выкл» после «Поиск для колонки» показывать только «Уровень отбора» и «Локальный» в указанном порядке; все остальные настройки фильтра скрыть. «Локальный» находится внизу списка в обоих режимах. Состав и порядок настроек фильтра согласованы с меню пилюли на полке «Фильтры» по связанной постановке MB-6329; «Поиск для колонки» остаётся отдельной настройкой раздела «Поиск».

* При первой активации общего тумблера поиск должен быть включён для всех колонок, исходный режим — локальный. 
* Настройки фильтра должны браться из соответствующей локальной пилюли на полке «Фильтры» этой таблицы, если она есть; иначе применяются значения по умолчанию. 
* При переключении колонки в режим «Локальный» - «Выкл» настройки общего фильтра берутся из боковой панели фильтров, визуализации «Контейнер с фильтрами» или «Иерархический фильтр». Для доступного в разделе «Поиск» параметра «Уровень отбора» используются настройки соответствующей нелокальной пилюли, если она есть; иначе действует значение по умолчанию обычного общего фильтра. Повторное включение поиска не переинициализирует уже заданные настройки.

* При «Локальный» - «Вкл» и выборе «Тип фильтра» - «По диапазону», в разделе «Поиск» должна быть возможность настроить два условия и задать их связь через И/ИЛИ. Данные подчинённые настройки отображаются в разделе, только при «Тип фильтра» - «По диапазону».
** Для даты дополнительно появляется возможность задать «Режим» («Произвольный диапазон»; «Последние N дней»; «До текущей даты»).
* Набор локальных настроек согласуется с типом данных поля и выбранным параметром «Тип фильтра».

* Связанные фильтры определяются по {{alias}}. Совпадение отображаемых заголовков колонок само по себе не устанавливает связь. 
* Пилюля без соответствующей колонки продолжает работать как фильтр, но отдельного элемента строки поиска не создаёт. После изменения состава колонок строка поиска и список «Выберите колонку» должны соответствовать обновлённому составу таблицы.

----
h3. 2. Фильтрация и синхронизация.
h4. 2.1. Область действия и выбранные значения.
* При включении «Поиск» может работать без обязательного размещения пилюли на полке «Фильтры». При включённом «Локальный» он фильтрует только свою таблицу. При выключенном режиме «Локальный» - управляет обычным общим фильтром и воздействует на связанные визуализации по действующим правилам, как при размещённой нелокальной пилюле на полке «Фильтры».
* Для общего фильтра строка поиска, «Контейнер с фильтрами», «Иерархический фильтр» и боковая панель фильтров показывают согласованные выбранные значения для общих полей. Изменение через любой из этих интерфейсов отражается в остальных интерфейсах того же фильтра, в соответствии с текущим поведением. Поиск позволяет изменить общий выбор, включая значения, заданные извне визуализации «Таблица» (в соовтетствии с текущим поведением для поиска в «Таблица сводная»); независимое дополнительное условие поверх этого общего фильтра не создаётся.
* При локальном режиме выбранные значения не синхронизируются с общими фильтрами. Действующие общие фильтры и ограничения доступа продолжают воздействовать на таблицу.
* При «Локальный» - «Вкл» необходимо обеспечить одновременное действие локального поиска и общего фильтра по логическому И, в том числе по одному исходному полю с совпадающим {{alias}}: таблица показывает только строки, удовлетворяющие обоим условиям, независимо от порядка их задания. Условия должны обрабатываться раздельно, без конфликта или подмены одного другим из-за одинакового имени. Действующие правила зависимостей, предфильтрации списков, автофильтра и настроенного сброса зависимого фильтра сохраняются.
* При выключении настройки «Поиск для колонки» для определённого поля и отсутствии связанной пилюли на полке «Фильтры» - для данной колонки из строки поиска исключается якрык поиска и на таблицу перестаёт действовать фильтрация по данному полю, даже при наличии фильтра по этому полю, заданного через «Контейнер с фильтрами». Однако, для других полей/колонок фильтрация может продолжать действовать и связанная строка поиска в таблице продолжит работать.
* Настройки локальных и общих фильтров, а также их выбранные значения хранятся раздельно. При переходе в общий режим показывается действующий общий выбор, при возврате в локальный — прежний локальный. Выбор автоматически между режимами не переносится; поиск управляет фильтром только выбранного режима локальный/общий.

Возможный вариант реализации — дополнительная виртуальная (скрытая от пользователя) колонка данных с отличающимся техническим именем для локального отбора, отделённого от общего фильтра. Этот вариант необязателен: разработчики могут выбрать другое оптимальное решение, обеспечивающее требуемый результат без добавления пользовательской колонки и ручного изменения {{alias}} пользователем.

---
h4. 2.2. Конфигурация фильтра.
При совпадении {{alias}} и режима «Локальный» настройки колонки и соответствующей пилюли на полке «Фильтры» синхронизируются в обе стороны в пределах доступных настроек: в локальном режиме — «Тип фильтра» и остальные применимые настройки из раздела 1; в общем — «Уровень отбора». При несовпадающем режиме конфигурация не синхронизируется.

При «Локальный» - «Выкл» строка поиска использует действующую конфигурацию общего фильтра, заданную в боковой панели фильтров, «Контейнере с фильтрами» или «Иерархическом фильтре». Тип фильтра, условия, логика, режим даты и остальные применимые настройки общего фильтра определяют работу поиска с исключением для экранной формы общего типа «По сравнению», описанным ниже. Изменение этих настроек через общий интерфейс учитывается при следующем открытии формы поиска колонки. Прежняя нелокальная конфигурация пилюли не определяет форму поиска и не заменяет настройки общего фильтра.

При действующем общем типе «По сравнению» поиск колонки доступен и открывает существующую экранную форму «По значению» для соответствующего типа данных. Это исключение из наследования типа формы: выбор типа в настройках не добавляется, сохранённый тип общего фильтра остаётся «По сравнению». Простое открытие формы не меняет общий выбор и отбор. После применения выбранного в списке набора значений заменяются общий выбор и прежний общий отбор; связанные интерфейсы и визуализации используют новый общий выбор по действующим правилам. Независимое локальное условие не создаётся, сохранённый локальный выбор не подмешивается.

Допустимо сохранить действующее временное отображение общего фильтра как «По значению» с возможностью перевыбора списка. После сброса, перезагрузки страницы или потери контекста фильтрации общий фильтр снова отображается как «По сравнению»; значения определяются действующей логикой сброса и восстановления. Отдельная доработка общих фильтров, переходов между отчётами или хранения для этого поведения не требуется. При наличии действующего общего типа «По сравнению» поиск таблицы использует указанное исключение экранной формы.

Например, если общий фильтр даты настроен «По диапазону», а у нелокальной пилюли ранее сохранён тип «По значению», в строке поиска отображается действующее общее условие, а при открытии поиска появляется форма диапазона даты по настройкам общего фильтра.

Скрытые локальные настройки сохраняются, но в общем режиме не применяются и не перезаписывают конфигурацию общего фильтра. Это правило действует для новых и ранее сохранённых таблиц, при переключении режима, сохранении и повторном открытии отчёта. При возврате в локальный режим восстанавливаются сохранённые локальные настройки с учётом условий их применимости.

Список доступных значений для локальных фильтров предфильтровывается согласно настройке «Зависит от». 
* Например, при зависимости организаций от региона и выбранной «Москве», в выпадающем списке будут доступны только московские организации. Изменение родительского фильтра обновляет варианты и выполняет настроенное поведение сброса зависимого фильтра.

Сортировка вариантов, автофильтр и другие применимые настройки используют правила фильтра выбранного режима: локального либо общего.

----
h3. 3. Формы поиска и применение условий.
При клике на активный элемент колонки строки поиска открывается форма, соответствующая типу данных и настройкам фильтра выбранного режима: локальным при «Локальный» - «Вкл», настройкам общего фильтра при «Локальный» - «Выкл», с исключением для общего типа «По сравнению» по разделу 2.2. Сохраняются все перечисленные ниже сочетания экранных форм; новые формы для способов отображения общих фильтров не добавляются.

Внешний вид каждой перечисленной формы — Согласно *[макету|^Макет_пагинация_и_поиск14.html]*:
# Тип данных — «Строка».
#* Тип фильтра — «По значению»;
#* Тип фильтра — «По диапазону».
# Тип данных — «Число».
#* Тип фильтра — «По значению»;
#* Тип фильтра — «По диапазону».
# Тип данных — «Дата».
#* Тип фильтра — «По значению»;
#* Тип фильтра — «По диапазону»:
#** Режим — «Произвольный диапазон»;
#** Режим — «Последние N дней»;
#** Режим — «До текущей даты».

Для «По значению» предоставляется список с поиском по вариантам и выбором значений. Ввод поискового текста сокращает перечень вариантов, но сам по себе не фильтрует данные таблицы. Пользователь может выбирать и снимать отдельные значения, выбирать все и снимать выбор со всех найденных значений.

Для «По диапазону» используются действующие операторы и условия фильтра соответствующего типа: для строки доступен поиск по фрагменту, для числа — числовые условия, для даты — ввод или выбор календарём в применимом режиме. Если настроены два условия, сохраняется их связь через И/ИЛИ, заданная в настройках.

Режимы дат используют действующую семантику обычного фильтра. «Последние N дней» задаёт включённые границы от начала дня за N дней до текущего до конца текущего дня; «До текущей даты» — верхнюю включённую границу конца текущего дня без нижнего ограничения.

Элемент строки поиска показывает действующее условие и позволяет отличить активное ограничение от отсутствия выбора. Очистка снимает условие связанного фильтра в выбранном режиме; для общего фильтра это отражается и в других интерфейсах.

Неполный или некорректный ввод не заменяет последнее применённое допустимое условие; пользователь видит необходимость исправления и может продолжить редактирование. Сохраняются действующие правила обязательных фильтров: очистка обязательного общего фильтра показывает необходимость заполнения и не пересчитывает данные до допустимого выбора.

----
h3. 4. Выключение и сохранение.
Общий тумблер раздела «Поиск» управляет отображением интерфейса строки поиска таблицы. Его выключение скрывает строку поиска и не изменяет настроенные фильтры или применённые условия. Общим фильтром можно продолжать управлять через «Контейнер с фильтрами» или боковую панель фильтров; повторное включение поиска показывает актуальное состояние.

Состояние общего тумблера и настройки поиска колонок сохраняются с настройками визуализации. Ввод и выбор пользователя в фильтрах в режиме просмотра отчёта являются временными и не сохраняются с отчётом. После перезагрузки страницы, повторного входа в отчёт или открытия отчёта другим пользователем - восстанавливается последнее сохранённое состояние фильтров, заданное аналитиком в режиме редактирования отчёта. Временные раздельные состояния локального и общего выбора также сбрасываются при повторном открытии отчёта. Общая модель сохранения назначенных фильтров остаётся действующей.

----
h3. 5. Совместимость и пограничные сценарии.
* Фильтрация распространяется на весь результат таблицы до разбиения на страницы. При изменении фильтра открывается первая страница, пересчитывается число страниц, выбранный размер страницы сохраняется. Итоги соответствуют всему отфильтрованному результату и отображаются отдельно от страниц.
* Если совпадений нет, показывается пустое состояние таблицы; поиск остаётся доступным для изменения и очистки условия. При включённой пагинации переходы на страницы недоступны.
* При ошибке загрузки данных или вариантов списка показывается сообщение о невозможности загрузки и доступна повторная попытка. Ошибка не представляется как отсутствие совпадений; после восстановления данные соответствуют действующим условиям.
* Для нового выбора типа локального фильтра колонки доступны «По значению» и «По диапазону» с учётом применимости к полю. «По сравнению» не предлагается. В общем режиме выбор типа в разделе «Поиск» и меню нелокальной пилюли отсутствует.
* Если в локальном режиме связанная пилюля имеет ранее сохранённый тип «По сравнению», сохраняются её настройки, выбранные значения и прежняя работа. Поиск этой колонки недоступен с пояснением до ручной смены локального типа на допустимый. В общем режиме при действующем типе «По сравнению» поиск доступен с экранной формой «По значению» по разделу 2.2; отдельная форма «По сравнению» не добавляется. Для остальных общих типов поиск определяется общим фильтром независимо от ранее сохранённого типа нелокальной пилюли. Открытие или включение поиска не преобразует старый фильтр автоматически и не препятствует сохранению отчёта без смены типа.
* Ручная смена типа выполняется через доступный интерфейс настройки соответствующего фильтра: локального — при «Локальный» - «Вкл», общего — через общие элементы управления в пределах их действующих возможностей. Показывать скрытый выбор типа при «Локальный» - «Выкл» не требуется. Ограничения повторного выбора «По сравнению» и исключения для «Таблицы сравнения», «Контейнера с фильтрами», «Иерархического фильтра» и боковой панели фильтров сохраняются по MB-6321; поиск таблицы не расширяет возможности выбора типа и допускает замену общего отбора через список по разделу 2.2.

h3. 6. Опция «Показать пустые значения».

h4. 6.1. Назначение и применимость.
В модальном окне поиска колонки предусмотреть флажок «Показать пустые значения». Он включает в условие фильтра записи, в которых значение этой колонки не заполнено. Отдельно выбирать пункт «(Пусто)», {{NULL}} или пустую строку в списке для этого не требуется.

Флажок доступен для типов данных «Строка», «Число» и «Дата» в формах «По значению» и «По диапазону». Для даты правило действует в режимах «Произвольный диапазон», «Последние N дней» и «До текущей даты», а также при выборе конкретной даты и односторонней границы в применимой форме. В формах диапазона строки и числа флажок необходимо добавить.

Опция применяется в локальном и общем режимах поиска. Исключения для типа «По сравнению» сохраняются по разделам 2.2 и 5: в общем режиме флажок доступен в экранной форме «По значению», в прежнем локальном режиме «По сравнению» поиск остаётся недоступным.

В части этой опции требования раздела 6 имеют приоритет над поведением макета: одного показа пустого варианта в списке недостаточно; флажок должен менять условие отбора.

---
h4. 6.2. Какие значения считать незаполненными.
|| Тип данных колонки || Незаполненное значение || Значения, которые не считаются незаполненными ||
| «Строка» | {{NULL}} или пустая строка длиной 0 — {{''}}. При включении флажка включаются оба вида незаполненности. | Строки из пробелов и других пробельных символов; текст «NULL» или «null»; строка «0». |
| «Число» | Только {{NULL}}. | Число {{0}}, отрицательные и остальные допустимые числа. |
| «Дата» | Только {{NULL}}. Поле содержит конкретную дату либо {{NULL}}; пустая строка не является значением типа «Дата». | Любая допустимая дата, в том числе дата вне выбранного периода. |

Проверка выполняется по значению и типу поля набора данных, а не по подписи, которой значение отображается в интерфейсе. Пробелы в исходных строковых значениях не обрезаются для определения незаполненности. {{NULL}} не подменяется текстом «NULL», пустой строкой, нулём или условной датой.

---
h4. 6.3. Логика отбора.
Под основным условием далее понимается выбор обычных значений в форме «По значению» либо полное допустимое условие формы «По диапазону». Если заданы два условия, основное условие включает оба и их связь через И/ИЛИ. Текст поиска по списку вариантов основным условием не является.

|| Основное условие || Флажок || Условие отбора по колонке ||
| Задано | Снят | Действует основное условие. |
| Задано | Установлен | Основное условие ИЛИ значение этой колонки не заполнено по правилам раздела 6.2. |
| Отсутствует | Снят | Ограничение по этой колонке отсутствует. |
| Отсутствует | Установлен | Только записи с незаполненным значением этой колонки. |

Ветка незаполненности добавляется через ИЛИ к основному условию целиком. Например, при числовых условиях «не меньше 10» И «не больше 20» результатом является «(число от 10 до 20 включительно) ИЛИ число не указано». Нельзя заменять внутреннюю связь И на ИЛИ или соединять незаполненность только с одной границей.

Остальные применимые фильтры и ограничения доступа продолжают действовать. Итоговая логика: «(основное условие колонки ИЛИ незаполненность этой колонки) И остальные ограничения». В том числе локальное условие с флажком пересекается с общим условием по тому же полю согласно разделу 2.1; флажок не возвращает строки, исключённые другим действующим условием.

Пример для «Организации»: при отсутствии выбранных организаций установленный флажок оставляет записи с {{NULL}} или {{''}}. При выборе организации «Альфа» и установке флажка остаются «Альфа», {{NULL}} и {{''}} с учётом остальных ограничений.

Пример для «Даты отгрузки»: при выбранном октябре 2026 года и установленном флажке остаются записи с датой отгрузки в октябре ИЛИ с {{NULL}} в этой колонке. Заполненные даты вне октября не добавляются. Для автоматических режимов даты ветка {{NULL}} добавляется к рассчитанному периоду; правила границ из раздела 3 сохраняются.

Снятие флажка убирает только добавленную ветку незаполненности, сохраняя основное условие. Само по себе оно не задаёт отбор «только заполненные». Если пустая строка удовлетворяет действующему основному условию, например строковому оператору «не содержит», снятый флажок дополнительно её не исключает.

---
h4. 6.4. Работа формы и состояние фильтра.
* В формах «По значению» обычные варианты выбираются отдельно от флажка «Показать пустые значения». Поисковый текст, «Поиск с начала строки», выбор и снятие выбора со всех найденных обычных значений не переключают флажок. Незаполненные значения включаются независимо от поискового текста и наличия пустого варианта в загруженной части списка. Управление ими в этой форме выполняется флажком, без второго независимого выбора в списке.
* Флажок остаётся доступным, даже если незаполненные значения отсутствуют в текущем списке или в результате. Выбор «только незаполненные» в таком случае даёт пустой результат по обычным правилам раздела 5.
* В формах «По значению» и в модальном окне диапазона даты флажок, выбранные значения и границы применяются вместе по кнопке «Применить». До нажатия таблица сохраняет прежний результат. «Отмена», крестик, Esc и закрытие окна без применения отбрасывают неприменённые изменения. Установленного флажка достаточно для доступности «Применить» без выбора обычных значений или задания даты.
* В формах «По диапазону» для строки и числа сохраняется применение допустимых условий во время ввода, предусмотренное макетом. Переключение флажка применяется сразу вместе с допустимым основным условием. Закрытие такого окна не отменяет уже применённый отбор.
* Для отбора только незаполненных в форме диапазона допускается отсутствие всех значений основного условия. Полностью незаданные условия или границы при установленном флажке считаются отсутствием основного условия. Частично заполненное условие, некорректное число или дата, а также нарушенный порядок границ остаются ошибкой: ни новое основное условие, ни новое состояние флажка не заменяют последнее применённое допустимое состояние до исправления ввода.
* Отбор только незаполненных является заданным условием фильтра, включая обязательный общий фильтр. Он отличается от отсутствия выбора; пустой результат такого отбора не означает, что обязательный фильтр не заполнен.
* «Очистить» снимает основное условие и флажок связанного фильтра в выбранном локальном или общем режиме. Дальнейшее поведение обязательного общего фильтра соответствует разделу 3.
* Элемент строки поиска показывает включение незаполненных значений: без основного условия — «Только незаполненные»; вместе с основным условием — его обычное представление с дополнением «+ незаполненные». Состояние не должно отображаться как «Все» или отсутствие ограничения. Повторное открытие формы восстанавливает действующее условие и состояние флажка.
* У нового фильтра без заданного отбора флажок снят. У существующего фильтра он отражает действующий отбор; простое открытие окна не меняет выбор. Для строкового общего фильтра, в котором через другой интерфейс выбрана только часть пустот — только {{NULL}} или только {{''}}, — показать промежуточное состояние флажка. Пока флажок не переключён, сохраняется именно этот частичный выбор. Явное включение выбирает оба вида пустот, выключение исключает оба из добавляемой ветки. Это не отменяет правило сохранения основного условия из раздела 6.3.
* Состояние включения незаполненных значений принадлежит соответствующему фильтру, а не только открытому окну. Для одного {{alias}} локальный и общий отбор хранят его раздельно; при переключении локальности восстанавливается состояние выбранного режима. В общем режиме состав отбора согласован со связанными интерфейсами по разделу 2.1, включая изменения пустых значений извне строки поиска. Новое независимое локальное условие вместо общего не создаётся.
* Скрытие всей строки поиска не снимает включение незаполненных значений. Сохранение и восстановление этого состояния подчиняются разделу 4: сохранённый аналитиком отбор восстанавливается, временные изменения режима просмотра сбрасываются при повторном открытии отчёта. Ранее сохранённые отборы без незаполненных значений автоматически их не включают.
* При штатном или настроенном сбросе фильтра состояние включения незаполненных значений меняется как часть отбора: сброс в «Все» снимает флажок и добавленную ветку; MIN/MAX устанавливает состояние по фактически выбранному значению, без сохранения прежней добавленной ветки (при заполненном выбранном значении флажок снят). Восстановление исходного или сохранённого отбора возвращает соответствующее ему состояние пустот. Если сброс не настроен, само изменение родительского фильтра не переключает флажок; применимые ограничения и обновление доступных вариантов сохраняются.

Включение незаполненных значений должно сохранять смысл при передаче условия от интерфейса до обработки запроса данных. Для {{NULL}} требуется проверка отсутствия значения, а не сравнение с текстом «NULL» или равенство {{NULL}}. Пустой ввод даты или числа не используется как кодировка такого отбора. Правило ИЛИ должно поддерживаться и для списка, и для диапазона; одной доработки видимости вариантов недостаточно.

Отбор выполняется по всему результату до пагинации, независимо от текущей страницы и загруженной части списка вариантов. Применение флажка обновляет страницы и итоги по разделу 5. При ошибке загрузки сохраняются признаки действующего отбора и возможность повторной попытки; ошибка не подменяется пустым результатом.

---
h4. 6.5. Быстрые подсказки.
Рядом с флажком разместить значок подсказки. Подсказка открывается при наведении, получении значком фокуса с клавиатуры и нажатии на него. Текст зависит от типа данных колонки и одинаков для локального и общего режимов:

|| Тип данных || Текст подсказки ||
| «Строка» | Включает записи с незаполненным значением: NULL или пустая строка. Они добавляются к заданному отбору. Если отбор не задан, показываются только такие записи. |
| «Число» | Включает записи без числового значения (NULL). Они добавляются к заданному отбору. Если отбор не задан, показываются только такие записи. |
| «Дата» | Включает записи без даты (NULL). Они добавляются к выбранным датам или периоду. Если даты не заданы, показываются только записи без даты. |

h3. 8. Критерии приёмки (AC):
AC.1 — *Начальная настройка:*
* *Дано:* новая таблица либо сохранённая таблица без настройки поиска; полка «Фильтры» пуста; общий тумблер поиска выключен;
* *Когда:* аналитик открывает раздел «Поиск» и впервые включает общий тумблер;
* *Тогда:* строка поиска появляется под заголовками, поиск включён для всех колонок, а настройки выбранной колонки соответствуют значениям по умолчанию раздела 1.

AC.2 — *Состав и расположение:*
* *Дано:* включён поиск таблицы с несколькими колонками;
* *Когда:* аналитик выбирает колонку через «Выберите колонку», выключает для неё «Поиск для колонки», меняет состав, ширину и порядок колонок, выполняет горизонтальную прокрутку;
* *Тогда:* список соответствует полям колонок данных; под выключенной колонкой элемент поиска отсутствует, остальные элементы остаются под своими колонками; пилюля без колонки не создаёт элемент поиска и продолжает фильтровать таблицу.

AC.3 — *Наследование и синхронизация настроек:*
* *Дано:* локальная пилюля «Регион» с типом «По диапазону» и заданными зависимостями; нелокальная пилюля другого поля;
* *Когда:* аналитик впервые включает поиск и затем меняет настройки через поиск и меню локальной пилюли;
* *Тогда:* «Регион» получает настройки локальной пилюли, изменения применимых настроек отражаются в обоих интерфейсах; для колонки с нелокальной пилюлей исходный локальный поиск использует значения по умолчанию;
* *И:* при переходе этой колонки в нелокальный режим форма поиска использует настройки общего фильтра с исключением для общего типа «По сравнению» по разделу 2.2, а изменение «Уровень отбора» отражается в разделе «Поиск» и соответствующей нелокальной пилюле. Скрытые локальные настройки не действуют и не изменяют общий фильтр; конфигурация пилюли с несовпадающим режимом не меняется.

AC.4 — *Локальный и общий выбор:*
* *Дано:* поиск «Регион» работает без пилюли на полке; общий фильтр «Регион» связан с другой визуализацией и представлен в «Контейнере с фильтрами» и боковой панели;
* *Когда:* пользователь меняет регион в локальном поиске, затем выключает «Локальный» и меняет общий выбор через каждый из трёх интерфейсов;
* *Тогда:* локальное изменение затрагивает только таблицу и не меняет общий выбор; в общем режиме все три интерфейса показывают одинаковый выбор, а связанные визуализации обновляются по действующим правилам;
* *И:* связь определяется {{alias}}; одинаковый видимый заголовок при разных {{alias}} не объединяет фильтры.

AC.5 — *Переключение режима:*
* *Дано:* локально выбрана «Казань», в общем фильтре — «Москва»;
* *Когда:* пользователь переключается в общий режим, добавляет «Самару» и возвращается в локальный;
* *Тогда:* в общем режиме первоначально показана «Москва», после изменения — «Москва» и «Самара»; при возврате восстановлена локальная «Казань», общий выбор не перезаписан.

AC.6 — *Список, зависимости и сортировка:*
* *Дано:* организации зависят от региона, для «Москвы» доступны две московские организации; локально настроена сортировка по другому полю;
* *Когда:* пользователь выбирает «Москву», открывает поиск организаций, вводит фрагмент, выбирает отдельные либо все найденные значения, затем меняет регион;
* *Тогда:* варианты ограничены настроенной зависимостью и упорядочены по настройке; ввод меняет только перечень, выбор фильтрует таблицу, смена региона обновляет варианты и выполняет настроенный сброс;
* *И:* при «Зависит от» — «Все» учитываются все фильтры, воздействующие на таблицу на момент применения локального фильтра; после ручного изменения зависимости учитывается заданный набор.

AC.7 — *Экранные формы и условия:*
* *Дано:* колонки типов «Строка», «Число» и «Дата»;
* *Когда:* пользователь открывает поиск для каждого сочетания типа данных, типа фильтра и режима даты из раздела 3 отдельно в локальном и общем режимах;
* *Тогда:* открывается соответствующая форма согласно макету; выбор значений, строковый поиск по фрагменту, числовые условия и календарный ввод дают результат по настройкам фильтра; два условия соблюдают заданную связь И/ИЛИ;
* *И:* в локальном режиме настройки берутся из раздела «Поиск», в общем — из общего фильтра с исключением для общего типа «По сравнению» по разделу 2.2; после изменения общих настроек через боковую панель фильтров, «Контейнер с фильтрами» или «Иерархический фильтр» следующее открытие поиска соответствует изменённым настройкам с учётом этого исключения;
* *И:* «Последние N дней» и «До текущей даты» используют границы из раздела 3, включая записи на границах и исключая записи за их пределами.

AC.8 — *Исправление и очистка:*
* *Дано:* применено допустимое условие;
* *Когда:* пользователь вводит неполное или некорректное число либо дату, затем исправляет ввод и очищает условие;
* *Тогда:* ошибочный ввод не заменяет применённое условие и доступен для исправления; допустимое условие применяется, очистка снимает его, а для общего фильтра обновляет связанные интерфейсы;
* *И:* очистка обязательного общего фильтра обозначает необходимость заполнения и сохраняет ранее показанные данные до допустимого выбора.

AC.9 — *Скрытие без сброса:*
* *Дано:* через поиск заданы локальное условие и выбор общего фильтра;
* *Когда:* поиск выключают, общий выбор меняют через внешний интерфейс, затем поиск включают повторно;
* *Тогда:* выключение скрывает строку без изменения условий; после включения показаны сохранившееся локальное условие и актуальный общий выбор, настройки колонок не переинициализированы.

AC.10 — *Сохранение и повторное открытие:*
* *Дано:* аналитик сохранил настройки поиска и стандартный выбор «Москва» через обычный интерфейс фильтра в режиме редактирования;
* *Когда:* пользователь в режиме просмотра временно выбирает «Казань», затем перезагружает или повторно открывает отчёт; отчёт также открывает другой пользователь;
* *Тогда:* настройки раздела и колонок восстановлены, временный выбор отсутствует, применено сохранённое стандартное состояние фильтров.

AC.11 — *Пагинация и итоги:*
* *Дано:* открыта страница 5 по 20 строк, включены итоги; искомые строки находятся в том числе за пределами текущей страницы;
* *Когда:* поиск оставляет 23 строки;
* *Тогда:* доступны все 23 строки на двух страницах, открыта первая страница, размер 20 сохранён; итоги рассчитаны по всем 23 строкам и не меняются при переходе на вторую страницу.

AC.12 — *Пустой результат и ошибка:*
* *Дано:* поиск и пагинация включены;
* *Когда:* условие не находит строк либо загрузка данных или вариантов завершается ошибкой;
* *Тогда:* отсутствие строк отображается как пустое состояние без переходов по страницам с доступным поиском; ошибка обозначается отдельно и допускает повторную попытку;
* *И:* после изменения условия или успешной повторной загрузки показаны данные и варианты, соответствующие действующим фильтрам.

AC.13 — *Прежний локальный тип «По сравнению»:*
* *Дано:* сохранённая связанная локальная пилюля «По сравнению»;
* *Когда:* пользователь открывает отчёт, включает поиск при «Локальный» - «Вкл» и сохраняет отчёт без смены типа;
* *Тогда:* прежние настройки, значения и работа фильтра сохраняются, поиск колонки недоступен с пояснением, новая форма поиска не появляется;
* *И:* для локальной пилюли после ручного выбора допустимого типа при «Локальный» - «Вкл» поиск доступен, а повторный выбор «По сравнению» запрещён по связанной постановке, в том числе после сохранения и повторного открытия; в общем режиме скрытый выбор типа не появляется и возможности выбора типа в общих элементах управления не расширяются.

AC.14 — *Состав настроек по режиму:*
* *Дано:* выбрана колонка в разделе «Поиск»; проверяются типы данных и конфигурации из раздела 3;
* *Когда:* аналитик переключает «Локальный» и открывает настройки колонки и связанной пилюли того же режима;
* *Тогда:* в локальном режиме применимые настройки расположены в порядке раздела 1, «Уровень отбора» скрыт; в общем режиме доступны только «Уровень отбора» и «Локальный»;
* *И:* в разделе «Поиск» первой под выбором колонки остаётся «Поиск для колонки», а «Локальный» находится внизу обоих списков в каждом режиме.

AC.15 — *Сохранённые настройки и общий источник формы:*
* *Дано:* новая либо ранее сохранённая таблица; локально заданы автофильтр MAX, зависимость от «Региона», сброс в MIN и сортировка по другому полю по убыванию; общий фильтр того же {{alias}} имеет варианты А, Б, В в этом порядке, выбор Б, без этих локальных настроек;
* *Когда:* аналитик выключает локальность, сохраняет отчёт, повторно открывает его, меняет «Регион» и открывает поиск;
* *Тогда:* доступны А, Б, В в общем порядке, выбран Б; локальные MAX, зависимость, сброс и сортировка не применены, конфигурация общего фильтра не перезаписана;
* *И:* при возврате в локальный режим восстановлены прежние локальные настройки по условиям их применимости;
* *И:* если у нелокальной пилюли ранее сохранён тип «По значению» либо «По сравнению», а действующий общий фильтр даты настроен «По диапазону», открывается форма диапазона даты по общим настройкам, без изменения общего типа и условия из-за старой конфигурации пилюли.

AC.16 — *Одновременный локальный и общий отбор по одному полю:*
* *Дано:* таблица содержит данные Центрального, Приволжского и Южного федеральных округов; поиск колонки «Федеральный округ» включён при «Локальный» - «Вкл»; общий фильтр воздействует на таблицу по тому же исходному полю с совпадающим {{alias}}; оба фильтра имеют тип «По значению»; настройки зависимостей обеспечивают доступность указанных ниже вариантов на каждом шаге, автофильтр и настроенный сброс не изменяют другой выбор в этих сценариях;
* *Когда:* в первом независимом сценарии пользователь выбирает локально Центральный и Приволжский округа, затем в общем фильтре — Центральный; во втором сценарии из исходного состояния без применённых условий выбирает в общем фильтре Приволжский, Центральный и Южный округа, затем локально — Центральный;
* *Тогда:* в обоих сценариях таблица показывает только данные Центрального округа; в первом сценарии локально остаются выбраны Центральный и Приволжский, в общем фильтре — Центральный; во втором локально выбран Центральный, в общем фильтре — Приволжский, Центральный и Южный; ни одно условие не подменяет другое из-за совпадающего {{alias}}.

AC.17 — *Только незаполненные значения и различия типов:*
* *Дано:* независимые наборы тестовых записей: для строки — {{NULL}}, {{''}}, строка из одного пробела, текст «NULL», «0», «Альфа»; для числа — {{NULL}}, {{0}}, {{10}}; для даты — {{NULL}}, {{05.10.2026}}, {{05.11.2026}}; другие фильтры не ограничивают результат;
* *Когда:* пользователь в форме «По значению» каждого типа включает только флажок и нажимает «Применить»;
* *Тогда:* для строки остаются ровно записи с {{NULL}} и {{''}}, для числа и даты — только с {{NULL}}; дополнительный выбор пустого пункта не требуется; «Применить» доступна при отсутствии обычного выбора;
* *И:* тот же отбор только незаполненных доступен в форме «По диапазону» без заданного основного условия, для даты — в режиме «Произвольный диапазон» с незаданными границами; он считается заполненным условием обязательного общего фильтра.

AC.18 — *Список: обычные значения ИЛИ незаполненность:*
* *Дано:* организации «Альфа», «Бета», {{NULL}}, {{''}}; другие фильтры не ограничивают результат;
* *Когда:* пользователь выбирает «Альфа», включает флажок и применяет отбор, затем снимает флажок и снова применяет;
* *Тогда:* сначала показаны записи «Альфа», {{NULL}} и {{''}}, затем только «Альфа»; выбор обычного значения сохранён;
* *И:* изменение текста поиска, «Поиск с начала строки», выбор и снятие выбора со всех найденных обычных значений не меняют флажок; текст поиска сам по себе не становится условием таблицы и не ограничивает добавление пустот.

AC.19 — *Диапазон: группировка условий и типизированная пустота:*
* *Дано:* числовые значения {{NULL}}, {{0}}, {{10}}, {{15}}, {{20}}, {{30}}; включены два условия «не меньше 10» И «не больше 20»;
* *Когда:* пользователь включает флажок;
* *Тогда:* показаны {{NULL}}, {{10}}, {{15}}, {{20}}; {{0}} и {{30}} не добавляются;
* *И:* при проверке двух условий со связью ИЛИ ветка незаполненности также добавляется ко всему основному условию; для строкового диапазона добавляются оба вида пустот по разделу 8.2;
* *И:* снятие флажка сохраняет семантику основного оператора, в том числе не исключает пустую строку, если она сама удовлетворяет этому оператору.
