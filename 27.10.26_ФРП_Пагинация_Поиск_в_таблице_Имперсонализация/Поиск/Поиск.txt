h3. Контекст и цель.
Пользователям ФРП необходимо быстро искать и отбирать данные по колонкам визуализации «Таблица». В текущем виде таблицы возможность включения встроенной строки поиска отсутствует; фильтрация настраивается через полку «Фильтры» и доступна через внешние элементы управления.

*Требуется:* добавить под заголовками колонок опциональную строку поиска — дополнительный интерфейс управления связанными фильтрами таблицы.

----
h3. 1. Настройка и отображение.	
* В соответствии с [макетом|^Макет_пагинация_и_поиск3.html] в разделе «Режимы» настроек визуализации «Таблица» разместить переключатель «Поиск в таблице» (по-умолчанию выключен). Состояние переключателя сохраняется в настройках конкретной визуализации.
* При включении показывать строку поиска непосредственно под заголовками колонок. Элементы поиска должны оставаться под соответствующими колонками при изменении их ширины, порядка и горизонтальной прокрутке.
* Для каждой отображаемой колонки использовать *первую* (слева направо) подходящую пилюлю на полке «Фильтры» с её заданными настройками фильтрации. Сопоставление связанных фильтров происходит в соответствии с текущей реализацией (по совпадающим {{alias}}). Совпадение видимых заголовков колонок само по себе не является основанием для сопоставления.
* Если подходящей пилюли нет либо у первой подходящей пилюли включена настройка «Невидимый», место под колонкой остаётся без элемента поиска. К следующей пилюле с тем же {{alias}} не переходить.
* Пилюля без отображаемой колонки продолжает работать как фильтр, но отдельного элемента строки поиска не создаёт. После изменения состава колонок, порядка пилюль или их настроек строка поиска должна соответствовать новой конфигурации.
* Элемент поиска показывает действующее условие связанного фильтра и позволяет отличить активное ограничение от состояния отсутствия выбора.

----
h3. 2. Управление связанными фильтрами.

h4. 2.1. Состояние и область действия.
* Настройки поля поиска в таблице (тип, локальность, поведение) определяются настройками соответствующей пилюли на полке «Фильтры» и связанного фильтра. Локальный фильтр влияет на отбор данных только своей визуализации; общий — на данные связанных визуализаций, где соответствующая пилюля размещена на полке «Фильтры».
* Строка поиска редактирует действующее условие связанного фильтра, а не добавляет поверх него независимое ограничение. Для общего фильтра с одним {{alias}} строка поиска в таблице, визуализация «Контейнер с фильтрами» и боковая панель фильтров отображают согласованное состояние. Изменения через любой из этих интерфейсов отражаются в остальных доступных интерфейсах того же фильтра, в соответствии с текущим поведением.
** Например, если для общего фильтра «Регион» выбрана «Москва», при открытии списка поиска таблицы «Москва» уже отмечена. Пользователь может добавить «Казань» или снять выбор с «Москвы».
* Набор доступных значений, автофильтр, настройка «Зависит от», настроенный сброс и сортировка вариантов поля поиска в таблице работают по правилам заданным для связанного фильтра. В частности, при выборе в настройке «Зависит от» зависимости «Регион» для поля «Организация» - список организаций определяется этой настройкой.
** Например, если для общего фильтра «Регион» выбрана «Москва», то при открытии списка поля «Организация» будут отображаться только организации г.Москва.
* Действующие ограничения доступа к данным и остальные фильтры продолжают применяться.

---
h4. 2.2. Виды поиска и применение.
|| Настройка связанного фильтра || Поведение элемента поиска ||
| «По значению» | Список значений с поиском по перечню и выбором значений. При множественном выборе доступны установка и снятие отметок, а также выделение всех найденных значений. Ввод в поиске списка меняет только перечень вариантов; данные изменяются после выбора. |
| «По диапазону», текстовое поле | Ввод условия с поддержкой поиска по фрагменту строки и действующих операторов фильтра. Если настроены два условия, сохраняется их связь И/ИЛИ, которая задаётся аналитиком при настройке фильтров визуализации. |
| «По диапазону», числовое поле | Ввод числовых условий с действующими операторами. Если настроены два условия, сохраняется их связь И/ИЛИ, которая задаётся аналитиком при настройке фильтров визуализации. |
| «По диапазону», поле даты | Выбор календарём или ввод даты в режимах «На дату», «С», «До», «Период». «На дату» охватывает весь календарный день, включая значения со временем; «С» и «До» включают указанный день; «Период» включает оба граничных дня. |
| «По сравнению» | Два отдельных одиночных выбора значений с сохранением штатной семантики этого режима фильтра. |

* В данной постановке мы не меняем семантику фильтрации, а предоставляем дополнительный интерфейс для работы с фильтрами прямо в таблице.
* Выбор или снятие выбора значения применяется по клику; текстовое условие — после короткой паузы во вводе; числовое условие, дата или период — после корректного ввода. Отдельное подтверждение пользователем для строки поиска не требуется.
* Неполный или некорректный ввод, в том числе несуществующая дата и период с началом позже окончания, не заменяет последнее применённое условие. Пользователь видит, что ввод требует исправления, и может продолжить редактирование.
* Команда «Очистить» снимает всё условие связанного фильтра, в соответствии с заданными настройками фильтра, включая ранее заданный через другой интерфейс выбор. 
** Очистка обязательного общего фильтра снимает выбор, показывает обязательность заполнения и оставляет ранее показанные данные без пересчёта до ввода допустимого значения. 
* Работоспособность и жизненный цикл обязательных фильтров, с учётом новых интерфейсов фильтров таблицы, должны быть поддержаны полностью.

---
h4. 2.3. Выключение и время жизни условий.
* Выключение поиска скрывает только строку поиска. Применённые условия продолжают действовать; при повторном включении показывается их актуальное состояние. Связанным фильтром можно продолжать управлять через «Контейнер с фильтрами» или боковую панель фильтров, если они предусмотрены в отчёте.
* Изменения условий через строку поиска действуют только в текущем открытии отчёта. Они не записываются как сохранённые условия отчёта или пользовательские предпочтения, в том числе при последующем сохранении настроек визуализации или отчёта.
* При повторном открытии отчёта и при открытии другим пользователем применяются исходные настройки фильтрации отчёта (назначенные аналитиком настраивающим дашборд) с учётом штатных условий открытия. Временные несохранённые изменения из предыдущего сеанса работы с отчётом не восстанавливаются. При этом сохранённое состояние переключателя «Поиск» сохраняется в метаданных визуализации и строка поиска отображается в таблице при повторном открытии отчёта.

----
h3. 3. Данные и совместная работа с пагинацией.
* Поиск применяется к результату визуализации до его разделения на страницы, а не только к показанной странице или уже отображённым строкам. Сохраняются действующие правила фильтрации и агрегации связанных полей.
* При включённой пагинации после применения нового условия или очистки фильтра показывать первую страницу, пересчитывать количество страниц и сохранять выбранный размер страницы. Итоги рассчитываются по всему отфильтрованному результату согласно постановке по пагинации [MB-6289|https://jira.modusbi.ru/browse/MB-6289].
* Пустой результат отображается как пустая таблица; элементы поиска остаются доступны для изменения или очистки условия. При состоянии пустой таблицы, при включённой пагинации, переходы по страницам недоступны.
* При ошибке получения данных таблицы или вариантов списка показывать сообщение о невозможности загрузки и давать возможность повторить получение. Ошибку нельзя отображать как отсутствие совпадений. После восстановления загрузки, данные и варианты должны соответствовать актуальным условиям фильтра.

h3. 5. Критерии приёмки (AC):
AC.1 — *Настройка отображения:*
* *Дано:* новая таблица либо сохранённая таблица без настройки поиска;
* *Когда:* аналитик открывает раздел «Режимы»;
* *Тогда:* переключатель «Поиск» выключен; после включения появляется строка под заголовками, а после сохранения и повторного открытия состояние переключателя восстанавливается;
* *И:* изменение ширины, порядка колонок и горизонтальная прокрутка сохраняют соответствие элементов поиска своим колонкам.

AC.2 — *Сопоставление с пилюлями:*
* *Дано:* колонки «Регион» и «Продукция», две пилюли с {{alias}} колонки «Регион» и пилюля «Организация» без отображаемой колонки; для «Продукции» подходящей пилюли нет;
* *Когда:* поиск включён;
* *Тогда:* для «Региона» используется первая подходящая пилюля, для «Продукции» элемент отсутствует, а пилюля «Организация» продолжает фильтровать данные без отдельного элемента поиска;
* *И:* включение «Невидимый» у первой пилюли скрывает элемент «Региона» без перехода ко второй; изменение порядка или удаление пилюли обновляет сопоставление.

AC.3 — *Общее состояние и локальность:*
* *Дано:* общий фильтр «Регион» с выбранной «Москвой» представлен в строке поиска и «Контейнере с фильтрами»; другая таблица связана с тем же общим фильтром;
* *Когда:* пользователь добавляет «Казань» в строке поиска, затем снимает «Москву» через «Контейнер с фильтрами»;
* *Тогда:* оба интерфейса последовательно показывают одинаковый выбор, а связанные визуализации обновляются по общему фильтру;
* *И:* при локальном режиме фильтра изменение через строку поиска затрагивает только его таблицу.

AC.4 — *Выбор и зависимости:*
* *Дано:* список организаций зависит от региона; для «Москвы» настроен соответствующий набор вариантов;
* *Когда:* пользователь открывает список организаций, вводит фрагмент наименования и выбирает отдельное значение либо все найденные;
* *Тогда:* варианты соответствуют настроенной зависимости; ввод сокращает только перечень, а выбор применяется по клику и отражается в данных; снятие отметки изменяет выбор;
* *И:* изменение родительского фильтра обновляет варианты и выполняет настроенный сброс зависимого фильтра.

AC.5 — *Текстовые и числовые условия:*
* *Дано:* текстовый фильтр «Продукция» и числовой фильтр «Количество, шт.» в режиме «По диапазону»; для текстового фильтра выбран оператор поиска по вхождению фрагмента;
* *Когда:* пользователь вводит фрагмент «автомобиль» и допустимое числовое условие;
* *Тогда:* текстовое условие применяется после короткой паузы и отбирает значения, содержащие фрагмент; числовое условие применяется после корректного ввода; при двух условиях соблюдается настроенная связь И/ИЛИ;
* *И:* некорректное числовое условие не заменяет последнее применённое и доступно для исправления.

AC.6 — *Даты и период:*
* *Дано:* записи со значениями 27.10.2026 00:00, 27.10.2026 23:59, 28.10.2026 12:00 и 29.10.2026 00:00;
* *Когда:* пользователь выбирает «На дату» 27.10.2026, затем период 27–28.10.2026;
* *Тогда:* первый отбор включает обе записи за 27 октября, второй — первые три записи; режимы «С» и «До» включают весь указанный граничный день;
* *И:* неполный период, несуществующая дата или начало позже окончания не меняют последнее применённое условие и позволяют исправить ввод.

AC.7 — *Режим сравнения:*
* *Дано:* выбранная пилюля настроена «По сравнению»;
* *Когда:* пользователь открывает её элемент в строке поиска и меняет одно из двух значений;
* *Тогда:* доступны два одиночных выбора, изменение применяется по клику с той же семантикой, что у связанного фильтра.

AC.8 — *Очистка и обязательность:*
* *Дано:* условие общего фильтра задано через боковую панель;
* *Когда:* пользователь нажимает «Очистить» в строке поиска;
* *Тогда:* условие полностью снято и это отражено в обоих интерфейсах;
* *И:* для необязательного фильтра данные пересчитываются без снятого ограничения; для обязательного общего фильтра показана обязательность заполнения, ранее показанные данные сохраняются до нового допустимого выбора, после которого пересчитываются.

AC.9 — *Выключение и несохранение условий:*
* *Дано:* аналитиком сохранён выбор «Москва»; пользователь временно заменил его на «Казань» через строку поиска;
* *Когда:* пользователь выключает и снова включает поиск;
* *Тогда:* условие «Казань» продолжает действовать и отображается при повторном включении;
* *И:* после сохранения настройки поиска и повторного открытия отчёта без дополнительных условий открытия восстанавливается «Москва», как и при открытии другим пользователем; временная «Казань» не становится сохранённым условием.

AC.10 — *Полный результат, страницы и итоги:*
* *Дано:* поиск и пагинация включены, открыта страница 5 по 20 строк, допустимое условие оставляет 23 строки, часть которых находилась на других страницах; включены итоги;
* *Когда:* пользователь применяет условие;
* *Тогда:* доступны все 23 строки в действующем порядке сортировки, показывается первая из двух страниц по 20 строк, итоги соответствуют всему отфильтрованному результату;
* *И:* при отсутствии совпадений показано пустое состояние без переходов по страницам с доступным поиском; очистка возвращает результат без снятого ограничения, первую страницу и пересчитанные итоги.

AC.11 — *Ошибка загрузки и восстановление:*
* *Дано:* пользователь изменяет условие поиска или открывает список вариантов;
* *Когда:* получение соответствующих данных завершается ошибкой;
* *Тогда:* показано сообщение об ошибке с возможностью повторить получение, а ошибка не представлена как пустой результат;
* *И:* после успешной повторной попытки показанные данные соответствуют актуальному условию, действующим правам и остальным фильтрам.
