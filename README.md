# BI Analysis Vault и агентская система Modus BI

Локальная система готовит постановку на русском в Jira wiki: независимое исследование ревьюера → аналитик → ревью → исправления → повторная проверка. Корпоративный код доступен только для чтения. Истории двух Codex Thread и состояние сохраняются между запусками.

## Подготовка компьютера

Нужны Linux, Python 3.11+, Git, `rg`, установленный `bubblewrap` (`bwrap`) и действующий вход Codex через ChatGPT. Установку системных пакетов выполняйте штатным способом своего дистрибутива. Глобальные настройки, авторизацию и старые сессии система не меняет; runtime SDK использует существующую авторизацию только для чтения.

Из корня workspace:

```bash
python3 -m venv agent-system/.venv
agent-system/.venv/bin/python -m pip install -r agent-system/requirements.txt
agent-system/.venv/bin/python agent-system/run.py doctor
agent-system/.venv/bin/python agent-system/check.py
agent-system/.venv/bin/python agent-system/run.py smoke
```

Зависимости зафиксированы, включая официальный `openai-codex==0.163.0` и его согласованный runtime. Smoke обращается к модели только с синтетическим примером в отдельном файловом представлении. Доступность модели и лимиты определяет ваш аккаунт. При необходимости задайте доступную модель: `run.py --model ИМЯ smoke`.

На другом компьютере отдельно восстановите корпоративные клоны в `.private/repositories/{bi_react,bi-forms,modusbi}`, плагины — в `.private/repositories/plugins/`. Клонирование и обновление репозиториев координатор не выполняет. `.private/` целиком исключена из публичного Git; Wiki переносится отдельно или исследуется заново.

## Новая постановка

1. Создайте тематическую папку, например `Новая_тема/`. Положите туда материалы и вводный `промпт.txt`.
2. Опишите проблему, требуемый результат и границы. Пути к материалам задавайте от корня workspace, например `Источник: Новая_тема/обсуждение.md`. Пути с пробелами заключайте в обратные кавычки либо передавайте через `--source`.
3. Запустите из центральной директории:

```bash
agent-system/.venv/bin/python agent-system/run.py run \
  --prompt 'Новая_тема/промпт.txt' \
  --source 'Новая_тема/обсуждение.md' \
  --company-approved
```

`--source` повторяется для дополнительных файлов. Явные существующие ссылки в обратных кавычках, строки `Источник:` и простые относительные пути также обнаруживаются в промпте. Удалённые URL автоматически не скачиваются: сохраните доступные материалы локально. Исторические черновики и результаты прошлых прогонов не подключаются. Для проверки существующей постановки включите её как первичный материал под обычным именем и прямо опишите задачу проверки; содержимое blind-входа тогда задано вами.

`--company-approved` означает, что разрешение компании на обработку этих материалов провайдером модели у вас есть. Без него боевой модельный запуск не выполняется. Содержимое готовых документов по умолчанию сохраняется приватно.

В чате Codex в VS Code можно написать: «Запусти координатор для `Новая_тема/промпт.txt`, материалы …; обработка корпоративных материалов разрешена». Нужен именно запуск `agent-system/run.py`; обычный ответ одного агента не создаёт независимые Thread. Текст из буфера можно передать через `run --stdin --source 'Новая_тема/материал.md' --company-approved`; завершите ввод Ctrl+D.

## Результат и уточнения

Команда печатает `run_id`, статус и пути к результату и ревью. Все материалы прогона — `.private/runtime/<run_id>/`: `state.json`, ответы в `responses/`, итоговый `results/*.jira.txt`, читаемые отчёты `reviews/v*.md`, вопросы в `questions/`. В `state.json` сохранены независимое исследование и история ревью с доказательствами. `APPROVED` означает, что последняя версия прошла ревью без незакрытых существенных замечаний, вопросов и ошибок Jira-разметки.

```bash
agent-system/.venv/bin/python agent-system/run.py status RUN_ID --show-questions
agent-system/.venv/bin/python agent-system/run.py resume RUN_ID \
  --answer-file 'Новая_тема/ответы.txt' --company-approved
```

Если ответ пока не предоставляется, `finalize RUN_ID` сохраняет несогласованный итог с «Открытыми вопросами». Не выдавайте `NEEDS_USER`/`INCOMPLETE` за согласованную постановку. Автоматически допускается до пяти проверок; после ответа на эскалацию — ещё одна. Повторный спор без новых доказательств передаётся вам раньше.

После проверки допустимости публикации можно отдельно перенести итог в исходную тематическую папку:

```bash
agent-system/.venv/bin/python agent-system/run.py export RUN_ID \
  --to 'Новая_тема/постановка.txt' --reviewed-for-publication
```

Существующий файл не перезаписывается. Ревью и служебные данные остаются приватными. Git add/commit/push система не выполняет.

## Возобновление, ошибки и Wiki

После сетевого сбоя, ошибки формата, отсутствия авторизации или лимита аккаунта устраните причину и выполните `resume RUN_ID --company-approved`. После Ctrl+C добавьте `--continue-cancelled`. Код возврата: `0` — согласовано/успешная служебная команда; `2` — требуется решение либо результат не согласован; `1` — ошибка. Ошибки провайдера не печатаются целиком. `--timeout СЕКУНДЫ` перед подкомандой ограничивает модельный вызов; запуск SDK имеет отдельный предел 60 секунд.

Для диагностики авторизации и маршрутизации без модельного запроса: `agent-system/.venv/bin/python agent-system/run.py account-check`. Команда не обновляет вход в аккаунт и не выводит его персональные сведения. Если она возвращает `Workspace routing discovery failed`, сначала требуется восстановить доступность маршрутизации SDK; успешные локальные тесты этого не заменяют.

Изменение входных файлов или версии исходников требует нового прогона. Добавление нового материала после начала задачи также оформляйте новым прогоном; ответ на вопросы передавайте через `--answer-file`. Разные задачи могут выполняться параллельно; один run защищён блокировкой.

Wiki начинается с `.private/knowledge/index.md`. Проверка актуальности: `agent-system/.venv/bin/python agent-system/run.py wiki-check`. При изменении SHA поручите Codex исследовать затронутые источники только чтением и обновить приватные статьи и `sources.json`, сохранив ссылки, символы, строки и версии. Команда проверки сама статьи не переписывает.

Архитектура, протокол и ограничения: [agent-system/ARCHITECTURE.md](agent-system/ARCHITECTURE.md). Фактические результаты приёмки: [agent-system/ACCEPTANCE.md](agent-system/ACCEPTANCE.md). Обычные тематические материалы и прежняя структура этого персонального хранилища сохранены.
